# 채팅에서 모델 선택 메뉴 열기

ezShell 2.34.0 dev에서 Codex CLI 0.172.0으로 재현했다. 채팅에서 `/mcp` 뒤에 `/model`을 보내면 확인 카드가 나오고, 카드의 Esc로 메뉴를 닫을 수 없었다. 화면에 남아 있던 MCP 서버 목록도 카드에 표시됐다.

## 원인

Codex와 Claude는 모델 목록에서도 번호와 선택 화살표를 쓴다. `agentInboxWake.js`의 일반 확인 질문 판정은 이 모양을 받아들였다. 선택지 위 16줄에서 질문이나 구분선을 찾는 동안 이전 `/mcp` 출력까지 읽어, 그 내용이 설명과 화면 서명에 포함됐다. Codex의 추론 수준 화면에서는 `enter default` 바닥 안내 때문에 현재 선택 행을 입력칸으로 보기도 했다.

## 수정

- 사용량 줄에서 쓰는 `agentPicker.js`의 모델·노력 수준 파서에 현재 화면을 확인하는 함수를 추가했다. 제목과 선택 표시를 읽고 마지막 키 안내를 함께 확인한다. 터미널이 좁아 자동 줄바꿈된 행은 이어서 읽는다.
- 이 화면은 입력칸과 확인 질문이 없는 상태로 전달된다. 기존 슬래시 명령 처리기가 터미널과 `채팅으로` 안내를 띄우고, 사용자가 Esc로 닫으면 입력칸이 돌아오는 것을 감지해 채팅으로 복귀한다.
- Orca의 native chat 구현은 PTY로 옵션 명령을 보내고, 권한 요청은 대화 저널의 요청 정보로 표시한다. ezShell은 현재 CLI 화면의 제목과 키 안내로 선택 메뉴를 판단한다. 터미널에서 메뉴를 직접 연 경우에도 같은 판정이 적용된다. 실제 확인 질문의 설명과 서명은 기존 방식으로 읽는다.

## 검증

단위 테스트는 Codex의 모델과 추론 수준, Claude의 모델과 노력 수준 화면을 검사한다. Codex의 좁은 칸에서 하단 안내가 단어 중간에 줄바꿈된 경우와, 모델 목록 뒤에 실제 확인 질문이 뜬 경우도 포함한다. 화면 테스트 `local-agent-chat`은 Codex의 `/model`이 터미널을 열고 Esc로 채팅에 돌아오는 흐름을 검사한다.

수정한 dev 앱을 임시 프로필로 다시 띄웠다. 실제 Codex CLI 0.172.0에서 `/mcp` 다음 `/model`, Claude Code 2.1.331에서 `/model`과 `/effort`를 확인했다. 세 경우 모두 터미널과 `채팅으로` 안내가 나타났고, Esc를 누르면 채팅 입력칸에 포커스가 돌아왔다.

관련 단위 테스트 218개와 `local-agent-chat`의 화면 검사 293개가 모두 통과했다. `npm run typecheck`와 `npm run build`도 통과했다.
