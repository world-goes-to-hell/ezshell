# Windows 재시작과 강제 종료 뒤의 탭 복원

Windows 재시작 뒤 잠금을 풀었을 때 복원 안내가 없었다. 기존 구현은 일반 창 닫기와 앱 종료에서 렌더러에 탭 목록을 요청했다. Windows 세션 종료에는 일반 앱 종료 이벤트가 생략될 수 있고, 강제 종료에는 저장할 시간을 주는 신호가 없다.

본창은 탭이나 분할 배치, SFTP 위치, 로컬 에이전트 세션·채팅 상태가 바뀌면 `buildRestoreRecord`의 결과를 500ms씩 모아 main에 보낸다. main은 추가로 1.25초씩 모으고 직전 저장 내용과 달라졌을 때 마스터 비밀번호로 비동기 암호화한다. 임시 파일에 쓰고 동기화한 뒤 `restore-tabs.json`으로 이름을 바꾼다. 탭을 모두 닫으면 기록을 지운다.

일반 종료 응답, 잠그기 직전, Windows 세션 종료는 같은 기록 경로를 사용한다. Windows의 `query-session-end`와 `session-end`는 main이 받은 최신 기록을 그 자리에서 쓴다. 업데이트 설치용 기록은 우선하며, 암호화 도중 더 최신 기록이 들어오면 이전 결과는 폐기한다. 본창의 주 프레임에서 잠금을 푼 상태로 보낸 기록만 받는다.

새 프로세스의 첫 잠금 해제에서 지난 기록을 한 번 읽고 지운다. 실행 중인 렌더러의 새로고침은 같은 프로세스의 기록을 소비하지 않는다. 강제 종료 직전의 변경이 아직 main에 전달되거나 디스크에 반영되지 않았다면 마지막으로 저장된 배치가 복원된다.

`local-restore-checkpoint`는 실행 중 기록 변경과 암호화, 같은 프로필로 다시 시작한 뒤 탭 복원, 렌더러를 다시 불러왔을 때 중복 안내 방지를 확인한다. 단위 테스트는 Windows 세션 종료 이벤트의 동기 저장과 잠금·업데이트 우선순위, 원자적 교체 실패 시 기존 파일 보존을 확인한다.
