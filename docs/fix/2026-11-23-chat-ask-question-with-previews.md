# 미리보기가 달린 Claude 질문을 채팅이 알아보지 못함

2026-11-23 사용자 보고: Claude 가 선택지마다 미리보기 상자를 붙인 질문(`AskUserQuestion` 의 `preview`)을 띄웠다. 그런데 채팅에는 카드도 "대기 중" 표시도 나오지 않았다. 입력칸은 보였지만 보낼 수 없었고, 사이드바의 에이전트 칩도 작업 중으로 보였다.

## 원인
- `agentInboxWake.readApprovalScreen` 은 터미널이 접힌 줄(`isWrapped`)로 표시한 줄을 앞줄에 이어 붙인다.
- Claude 는 구분선과 미리보기 상자 줄을 칸 끝까지 공백으로 채운 뒤 줄바꿈 없이 다음 줄을 그린다. 그래서 다음 줄들이 모두 접힌 줄로 표시되었다.
- 그 결과 탭 줄(`☐ 머리말`)이 구분선 뒤에 붙었고, 선택지 줄끼리도 붙었다. 질문 화면으로 판정되지 않아 `approval` 이 비었고, 그 때문에 카드·대기 표시(`blocked`)가 모두 빠졌다. 입력칸이 없으니 채팅 보내기도 거부되었다.

## 수정
- 앞줄의 글자가 오른쪽 끝(마지막 두 칸)까지 닿을 때만 잇고, 구분선 뒤에는 잇지 않는다.
- 드라이버(`claudeQuestions.js`)가 미리보기 화면을 읽고 누를 수 있게 했다.
  - 화면 읽기: 상자가 시작되는 자리부터 줄을 자르고, 다음 줄로 이어진 선택지 이름을 함께 비교한다.
  - 키 동작: 이 화면에서는 숫자가 선택만 옮기므로, 숫자를 누르고 표시가 옮겨진 것을 확인한 뒤 Enter 를 누른다.
- 질문 정의(`askQuestions.js`)가 선택지의 `preview` 를 들여쓰기째 남긴다. 이 질문에는 `Type something` 줄이 없으므로 직접 입력한 답은 거부한다.
- 카드는 가리키거나 고른 선택지의 미리보기를 옆에 보여 준다. 직접 입력을 숨기고, 고르기만 해서는 보내지 않고 `보내기` 를 눌러야 보낸다.
- 화면 모양이 또 바뀌는 경우에 대비했다. 기록에 답하지 않은 질문이 있는데 화면에서 2초 동안 읽지 못하면, 채팅이 `터미널에서 답하기` 안내 줄을 띄운다.

## 확인
- 실제 Claude CLI(110×30, 64×26)에서 질문 화면을 알아보는 것과 대기 상태 보고, 드라이버의 답(숫자 → Enter, 고른 답이 기록됨)을 확인했다.
- 단위 테스트를 추가했다(접힌 줄 함정, 미리보기 화면 읽기와 키, 미리보기 보존과 직접 입력 거부).
- 화면 테스트 `local-agent-chat` 에 미리보기 카드 구간을 추가했다.
