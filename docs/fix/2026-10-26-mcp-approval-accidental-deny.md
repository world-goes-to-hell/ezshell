# MCP 확인 창이 잘못된 입력·클릭으로 거부되는 문제

- 날짜: 2026-10-26

## 증상
MCP 확인 요청이 오면 앱 창이 맨 위로 올라온다. 그때 채팅을 입력하고 있었거나 마우스를 잘못 누르면 요청이 그냥 거부되었다.

## 원인
확인 창이 거부로 끝나는 길이 버튼 말고도 있었다.
1. `Dialog.Root` 의 `onOpenChange` 가 닫힘을 거부로 처리했다. Radix Dialog 는 창 바깥(배경)을 누르거나 Esc 를 누르면 닫히므로, 배경 클릭 한 번이 거부가 되었다.
2. 창이 뜨면 포커스가 "거부" 버튼에 놓였다. 앱 창을 누른 뒤 입력하던 스페이스나 Enter 가 그대로 "거부" 를 눌렀다.
3. "허용" 만 0.8초 동안 막혀 있고 "거부" 는 바로 눌렸다. 또 앱 창이 포커스 없이 올라오므로, 앱 창을 앞으로 가져오려고 누른 첫 클릭이 그대로 버튼에 들어갔다.

## 수정 (`McpApprovalDialog.tsx`, `lib/approvalArming.ts`)
- 바깥 클릭과 Esc 로는 닫지 않는다 (`onPointerDownOutside`, `onInteractOutside`, `onEscapeKeyDown` 에서 막고 `onOpenChange` 를 없앰). 응답은 두 버튼과 제한 시간(시간이 지나면 거부)뿐이다.
- 처음 포커스는 버튼이 아니라 확인 창 자체에 둔다. 키보드로는 Tab 으로 버튼을 고른 뒤 응답한다.
- 두 버튼 모두, 앱 창에 포커스가 있고 창이 뜬 때와 포커스를 받은 때 중 늦은 시각부터 0.8초가 지나야 눌린다 (`isApprovalArmed`). 포커스가 없을 때는 "이 창을 한 번 누르면 잠시 뒤 응답할 수 있습니다." 를 보여 준다.

## 왜 이렇게 했나
거부는 안전한 쪽이라 쉽게 눌려도 된다고 봤지만, Claude 의 작업이 실패하고 다시 요청해야 하므로 사용자에게는 손해다. 확인 창은 사용자가 의도해서 누른 버튼으로만 끝나야 한다.
포커스를 받은 뒤 0.8초를 세는 이유: 다른 프로그램을 쓰다가 앱 창을 누르는 첫 클릭이 응답이 되면 안 된다 (2.5.1 에서 창을 포커스 없이 올리기로 한 것과 짝을 이룬다).
