# 브라우저 탭 페이지가 겹쳐 열린 사이드바를 가림

## 증상

사이드바를 접어 둔 채 포인터를 올려 사이드바를 겹쳐 열면, 브라우저 탭의 페이지가 사이드바 위에 그려져 사이드바 대부분이 보이지 않았다 (2026-11-20 사용자 보고).

## 원인

브라우저 탭의 페이지는 앱 화면(렌더러) 위에 놓인 별도 `WebContentsView` 다. CSS 의 `z-index` 와 무관하게 항상 앱 화면 위에 그려진다. `BrowserReview.tsx` 는 메뉴·대화상자처럼 화면 위에 뜨는 것(`appOverlays`)이 보이면 페이지를 숨겼지만, 터미널 위로 미끄러져 나오는 옆 패널(접힌 사이드바의 겹쳐 열기, MCP 활동 패널, 분할 배치 그림)은 목록에 없었다.

## 수정

- 옆 패널(`sidePanels`)은 페이지를 숨기지 않고, 패널이 덮지 않는 부분으로 페이지를 줄인다 (`lib/browserViewClip.ts` 의 `uncoveredBox`). 패널이 페이지의 왼쪽 절반에 있으면 왼쪽을, 오른쪽 절반에 있으면 오른쪽을 깎는다. 남는 폭이 80px 보다 작으면 숨긴다.
- 숨기지 않고 줄이는 이유: 사이드바는 포인터만 올려도 열리므로, 열릴 때마다 페이지가 통째로 사라지면 깜빡이는 것처럼 보인다.
- 패널이 아직 미끄러져 나오는 중이면(그 요소에 실행 중인 애니메이션) 끝 위치를 모르므로 잠시 숨기고, `transitionend` 에서 다시 잰다. 처음 잰 폭으로 줄이면 열리는 동안 페이지가 패널 일부를 계속 덮는다.
- 접힘 상태의 MCP 패널은 `transform` 으로 화면 밖에 있어 겹치지 않으므로 그대로 둔다.

## 확인

- 단위 테스트 `browserViewClip.test.ts` 5개.
- 화면 테스트 `browser-tab-title`: 사이드바를 접고 겹쳐 열면 페이지의 `innerWidth` 가 패널이 덮는 만큼 줄고, 다시 닫으면 원래 폭으로 돌아온다. `browser-review` 도 통과.
