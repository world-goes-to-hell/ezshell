# 경로 목록(바로 가기·드라이브)의 아래쪽이 보이지 않던 문제

날짜: 2026-11-17

## 증상
SFTP 패널의 로컬 주소줄을 눌러 뜨는 목록(즐겨찾기 → 바로 가기 → 내 PC)에서, 아래에 항목이 더 있는데도 내려가지 않았다. macOS 테마에서 보고됐다.

## 원인 (코드로 본 것, 실제 화면에서 재현하지는 못함)
- 목록은 `max-height: min(360px, 55vh)` 이고, SFTP 패인(`.sftp-pane`)은 `overflow: hidden` 이다. 패인의 남은 높이가 목록보다 낮으면 목록의 아래쪽이 패인에 잘린다. 목록 자체는 끝까지 스크롤되지만 마지막 줄들은 잘린 영역에 있어 보이지 않는다. 보고된 화면에서 스크롤 손잡이가 보이는 높이를 거의 다 차지한 것이 이 경우와 맞는다.
- 테마와는 무관한 구조다. 다른 테마에서도 패널이 낮으면 같다.
- 함께 본 것: 목록의 스크롤 막대를 누르면 입력칸이 포커스를 잃고(`onBlur`) 목록이 닫혔다. 줄에는 `mousedown` 기본 동작 막기가 있었지만 목록 자체(스크롤 막대)에는 없었다.

## 수정 (`Sftp/PathBookmarkSuggestions.tsx`)
- 목록이 뜰 때와 창 크기가 바뀔 때, 내용을 자르는 가장 가까운 상위 요소의 아래 끝까지 남은 높이를 재서 `max-height` 를 그만큼으로 낮춘다 (최소 90px).
- 목록의 `mousedown` 기본 동작을 막아 스크롤 막대를 눌러도 닫히지 않게 했다.
- 방향키로 강조 줄을 옮길 때 그 줄이 보이도록 스크롤한다 (이전에는 보이는 범위 밖으로 강조가 나갔다).

## 확인
typecheck 통과. SFTP 패널은 실제 SSH 연결이 있어야 열려서 화면 확인은 사용자에게 요청.

## 정정 (같은 날): 실제 원인은 클래스 이름 충돌
위의 원인 분석은 틀렸다. 실제 원인은 같은 날 추가한 사이드바 로컬 터미널 목록의 CSS 였다. 그 목록의 클래스 이름을 `local-pane` 으로 지었는데, SFTP 의 로컬 패인이 이미 `sftp-pane local-pane` 이었다 (`SftpPanel.tsx`, `SftpWindow.tsx`). 그래서 목록용 규칙(`max-height: 50%`, `border-top: 1px`, `flex: none`)이 SFTP 로컬 패인에 적용됐다.
- 로컬 패인의 높이가 패널의 절반이 되어 파일 목록이 잘렸다 (측정: 패널 안쪽 246px 중 로컬 패인 123px, 원격 패인 246px).
- 경로 목록도 그 절반 높이의 패인에 잘렸다 (이 문서의 첫 증상).
- 위쪽 테두리 1px 때문에 로컬 쪽과 원격 쪽의 머리줄 높이가 1px 어긋났다.

수정: 사이드바 목록의 클래스를 `local-terms*` 로 바꿨다 (`Sidebar/LocalTerminalList.tsx`, `.css`). 수정 뒤 측정: 로컬·원격 패인 모두 246px, 파일 목록 201px.

위에서 넣은 세 가지(남은 높이에 맞추기, 스크롤 막대 누름, 방향키 따라가기)는 원인과는 무관했지만 패널이 낮을 때 필요한 동작이라 그대로 둔다.

교훈: 새 컴포넌트의 클래스 이름은 짓기 전에 코드 전체에서 같은 이름을 찾아본다 (이 프로젝트는 전역 CSS 다).
