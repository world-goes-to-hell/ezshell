# Claude 대기열이 있을 때 작업 중 알림이 밀림

Windows ConPTY의 59×15 칸에서 실제 Claude Code 2.1.332에 진행 중인 작업과 대기 메시지를 하나씩 넣었다. Claude는 빈 입력칸에 `Press up to edit queued messages`를 일반 글자로 그렸다. ezShell 2.36.0과 2.36.1은 이 안내를 사용자 초안(`draft`, `ours: false`)으로 판단해 7.5초 동안 키를 보내지 않았다. 2.36.1에서 일반 채팅도 `composer-not-empty`로 거절됐고 키를 보내지 않았다.

Claude 입력칸의 구분선과 바닥줄, 인접한 대기 항목을 함께 보면 이 안내를 빈 입력칸으로 판정할 수 있다. 붙여넣은 뒤에는 실제 입력칸에 본문 전체가 보일 때만 알림의 Enter를 한 번 보낸다. 빈 칸에서 Enter를 보내면 Claude가 기존 대기열을 즉시 제출한다. 안내가 계속 그려지는 동안 알림을 다시 붙이지 않는다. 사용자가 위쪽 화살표나 Ctrl+P로 대기 항목을 열면 사용자 초안으로 기록한다. 공식 Stop 훅은 기존 대기열이 비기를 기다린다.

수정 후 Claude Code에서 일반 커서와 Ctrl+A로 커서를 처음에 둔 경우를 각각 시험했다. 앱은 기존 작업을 진행하는 동안 알림을 대기열에 추가했다. 로컬 모델 서버 응답을 재개한 뒤 기존 요청이 작업 중 알림보다 앞에 있었고 후속 알림까지 원문 그대로 도착했다. 두 알림 모두 Enter는 한 번이었다. 일반 채팅도 같은 두 경우에서 기존 요청 뒤에 추가됐고 원문 그대로 도착했다. 임시 프로필과 로컬 모델 응답으로 시험했다. [실제 CLI 표본](../../src/ipc/fixtures/agent-inbox-pty/README.md)

관련 단위 테스트 305개, 숨김 화면의 메시지 검사 167개와 채팅 검사 308개, 타입 검사와 빌드가 통과했다. 채팅 화면을 메시지 화면과 함께 실행했을 때 답변 별도 창 검사에서 한 번 실패했고, 채팅 화면만 다시 실행했을 때 통과했다.
