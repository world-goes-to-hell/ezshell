# Claude 질문 카드가 플러그인 알림 상자 밑에서 멈추던 문제 (2026-11-27)

## 증상

사용자 보고: Claude 가 `AskUserQuestion` 을 4개씩 두 번 연속으로 물었다 ([1/8]~[4/8], [5/8]~[8/8]). 채팅 카드로 답했는데, 터미널에서도 다시 답해야 했다. 이전에도 같은 일이 있었다.

대화 기록(`7a193ef3-….jsonl`)에는 두 질문의 `tool_use` 와 답이 모두 정상으로 있었다. 채팅 파서는 두 질문을 모두 질문 항목으로 읽었고, main 의 화면 판독(`inspect_agent`)도 [5/8] 을 읽었다.

## 원인

이 PC 의 ko-ui 플러그인이 화면 오른쪽 위에 알림 상자(`╭──╮ / │ ko-ui … │ / ╰──╯`)를 그린다. 칸이 낮으면 이 상자가 질문 대화 상자 위에 겹친다.

- 상자의 아래 테두리 `╰───╯` 가 탭 줄 아래 빈 줄에 놓이면, 질문 문장을 읽는 두 곳이 모두 그 테두리를 질문 문장의 첫 줄로 읽었다.
  - `claudeQuestions.js`(카드의 키 입력): 첫 답을 누른 뒤 다음 질문을 `startsWith` 로 찾지 못해 `changed` 로 멈추고, 창이 칸을 터미널로 넘겼다. 그래서 채팅에서 한 번, 터미널에서 나머지를 답하게 됐다.
  - `agentInboxWake.claudeQuestionPrompt`(채팅에 넘기는 질문 문장): 문장 앞에 테두리가 붙어 창의 `answerableAskItem` 이 어느 질문과도 맞추지 못했다. 그러면 카드도 `터미널에서 답하기` 안내도 뜨지 않고 터미널이 채팅 아래에 열린다.
- 상자가 더 아래에 놓이면 질문 문장 줄의 오른쪽 끝을 덮어서 문장 일부가 아예 보이지 않는다.

재현: `node-pty` + `@xterm/headless` 로 실제 `claude --model haiku`(2.1.332)에 같은 질문 4개를 내게 하고 카드의 키 입력(`createClaudeQuestionAnswerer`)을 붙였다. 110×30 은 성공했고, 110×20 은 첫 키 뒤 `changed`, 90×18 은 첫 질문부터 `changed` 였다.

## 수정

- `src/ipc/cliOverlayBox.js` (새 파일): 줄 끝에 놓인 상자 조각(위·아래 테두리, `│…│` 글자 줄)을 떼고, 뗐는지(`cut`)를 알려 준다. 줄 맨 앞(3칸 안)에서 시작하는 상자는 그 줄 자신의 틀로 보고 떼지 않는다. `piecesInOrder` 는 가려진 줄의 남은 조각이 원문에 차례대로 들어 있는지 본다 (첫 조각은 원문의 시작).
- `claudeQuestions.js`:
  - 모든 줄에서 상자를 먼저 뗀다.
  - 질문 문장이 가려졌으면(`cut`) 남은 조각이 차례대로 맞고 선택지 이름이 같은 질문이 이번 묶음에서 하나일 때만 같은 질문으로 본다. 가려진 선택지는 이름의 앞부분으로 비교한다.
  - 검토 화면(`Review your answers`)의 가려진 항목도 조각으로 비교한다. 한 항목이 여러 질문에 맞으면 어느 쪽으로도 인정하지 않는다.
- `agentInboxWake.js`: 판독 전에 상자를 뗀다. 질문 문장 줄이 가려졌으면 문장을 알 수 없음(`null`)으로 넘기거나 상자가 오기 전에 읽은 문장을 그대로 둔다. 창은 문장이 없으면 기다리는 질문의 카드를 띄운다.

같은 재현에서 드러난, 상자와 상관없는 낮은 칸의 검토 화면 문제도 고쳤다:
- `↑ 2 more lines` 줄이 마지막 답에 붙어 `mismatch` 가 났다 (90×18). 이 줄은 답으로 읽지 않는다.
- 제목 `Review your answers` 가 위로 밀려나면 검토 화면을 찾지 못해 `stuck` 이었다 (80×16). `Submit answers` 바로 위에 `↑ N more lines` 가 있으면 화면 전체가 검토 목록이므로 제목 없이 읽는다. 질문마다 항목이 하나씩 맞아야 제출한다는 확인은 그대로다.

## 확인

- 단위 시험: `claudeQuestions.test.js`(실제 CLI 화면 두 개, 상자를 겹친 가짜 대화 상자 4문항, 두 질문에 맞는 조각 거부, 검토 화면 두 경우), `agentInboxWake.test.js`(상자 아래의 질문 판독).
- 실제 CLI(2.1.332): 두 질문 묶음을 120×40, 110×20, 90×18, 80×16 에서 카드의 키 입력으로 끝까지 답했다. 같은 화면에서 채팅이 카드를 띄울 조건도 맞았다.
- 화면 시험 `local-agent-chat` 통과.

## 남은 것

- 상자가 직접 입력 줄(`Type something`)의 입력한 글자를 가리면, 글자가 들어갔는지 확인하지 못해 `stuck` 으로 터미널에 넘긴다 (재현한 크기에서는 생기지 않았다).
- 상자 모양이 다른 알림(테두리 문자가 다른 것)은 떼지 못한다.
