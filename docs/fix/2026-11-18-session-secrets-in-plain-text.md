# 세션 파일에 평문으로 남던 비밀 값

## 증상

`sessions.json` 에서 마스터 비밀번호로 암호화되는 것은 `password`, `passphrase`, `privateKeyPath` 셋뿐이었다. 다음 값은 평문으로 저장되었다.

- root 전환 비밀번호 `suPassword`
- 점프 호스트 `jumpPassword`, `jumpPassphrase`, `jumpPrivateKeyPath`
- 저장한 DB 계정 `dbConnections` (계정마다 호스트·사용자·비밀번호)

CLAUDE.md 는 DB 계정이 "세션 파일과 함께 마스터 비밀번호로 암호화" 된다고 적고 있었지만, 저장 코드(`save-sessions`)는 위 세 값만 골라 암호화하고 나머지는 그대로 썼다. 새 비밀 필드가 생길 때마다 저장 코드의 목록에 더해야 했는데 더해지지 않았다.

사용자 PC 의 실제 파일(2026-11-18, 사용자 허락 하에 값은 출력하지 않고 개수만 확인): 세션 41개, DB 계정 3개의 비밀번호가 평문. root 전환·점프 호스트 비밀번호는 칸만 있고 값은 비어 있었다.

## 수정

- 비밀 필드 목록과 암호화·복호화를 `src/sessionSecrets.js` 한 곳으로 모았다 (`SECRET_FIELDS`). 저장은 목록의 값을 모두 하나의 암호화 묶음에 넣고, 읽기는 옛 형식(평문이 묶음 밖에 있는 것)도 연다.
- 평문이 남은 파일은 세션을 읽기 직전(`load-sessions`)과 잠금 해제·세션 백업 가져오기 직후에 다시 암호화해 쓴다 (`resealSessionsFile`). 이 비밀번호로 열리지 않는 세션은 손대지 않는다. 실패해도 잠금 해제는 막지 않는다.
- `sessions.json` 쓰기는 임시 파일에 쓴 뒤 이름을 바꾼다 (`writeSessionsFile`): 다시 암호화하다 중간에 멈춰도 파일이 반쪽이 되지 않게.

## 확인

- 단위 테스트 `src/sessionSecrets.test.js` 8개: 저장한 파일에 비밀 값 글자가 없음, 다시 열면 같은 세션, 옛 형식 열기·다시 암호화, 다른 비밀번호의 세션은 그대로.
- 화면 테스트 `session-secrets`: 시험 프로필에 옛 형식 파일(평문 3개)을 넣고 창을 다시 불러와 잠금을 풀면 평문이 사라지고, 앱이 읽는 값은 같으며, 다시 저장해도 평문이 없다. `ssh-restore-tabs`, `ssh-sftp`, `ui-settings`, `ssh-reconnect` 다시 통과.

## 남은 것

- 사용자의 실제 파일은 이 수정이 들어간 앱으로 잠금을 풀 때 다시 암호화된다. 그 전에는 평문이 그대로다 (마스터 비밀번호 없이는 바꿀 수 없다). 고치기 전 판의 앱이 세션을 저장하면 DB 계정은 다시 평문으로 써진다 (새 판이 다음에 읽을 때 다시 암호화).
- 설정 > 세션 백업의 내보내기 파일은 사용자가 고른 곳에 비밀번호를 평문으로 담는다 (의도된 백업 형식인지 따로 정해야 한다).
