# 새 Codex의 역할 저장

Windows를 다시 시작한 뒤 새 Codex에서 지정한 역할이 사라졌다. 역할은 확인된 대화 UUID에 저장된다. Codex가 명시적 재개로 시작한 경우에는 UUID를 확인했지만, 새 대화는 역할을 메모리에만 보관했다.

## 확인 조건

- main이 셸과 에이전트에 묶인 훅에서 첫 세션 UUID를 받는다. 앱에서 시작한 Codex의 시각은 main의 실행 등록에서, 셸에서 직접 시작한 Codex의 시각은 확인한 Codex 프로세스에서 얻는다.
- 사용량 감시기는 시작 시각과 작업 폴더를 기준으로 루트 롤아웃을 찾는다. 후보가 하나이고, 파일명과 `session_meta`의 UUID가 인증된 훅 UUID와 같아야 한다. 후보가 여럿이거나 이미 고른 파일을 다시 골랐다면 그 실행의 자동 역할 저장은 보류한다.
- 기존 사용량 감시기가 같은 파일을 해당 에이전트에 연결하고, main이 현재 훅 UUID와 실행 시각을 다시 확인하면 기존 역할 바인딩을 적용한다. 사용자 역할과 에이전트 역할, 관계도 배치 키에 이 대화 키가 쓰인다. 명시적 재개와 잠재우기 복귀는 기존 검증 경로를 사용한다.

자동으로 저장한 Codex의 훅 UUID가 바뀌면 이전 대화의 역할을 보관한 채 현재 역할을 메모리로 옮긴다. 새 대화에서 이름을 바꿔도 이미 저장한 이전 대화의 역할에 반영되지 않는다. 같은 OS 사용자가 훅 입력과 롤아웃 파일을 모두 위조할 수 있는 기존 한계는 남는다.

## 보안 검토 반영

- 앱이 실행한 Codex는 main에 등록된 작업 폴더를 쓴다. 셸에서 직접 실행한 경우에는 요청 폴더를 main이 받은 셸의 현재 폴더와 비교한다. 현재 폴더 보고가 없으면 셸 실행 폴더를 비교에 쓴다. 폴더를 확인할 수 없거나 두 값이 다르면 역할을 메모리에 둔다.
- 명시적 재개나 두 신호로 이미 확인된 다른 에이전트의 파일만 후보 수에서 뺀다. 시간과 작업 폴더로 추정 배정된 파일도 후보 수에 포함한다.
- 잠금 중에는 새 역할 키 확정을 거부한다. 확인 도중에 잠겼다면 잠금 해제 뒤 증거를 다시 검사한다.
- 같은 파일 핸들에서 파일 식별자(`dev`·`ino`)와 첫 `session_meta` 레코드를 읽는다. 파일 식별자는 `BigInt`로 비교해 Windows에서도 정밀도를 유지한다. 저장 직전에 파일을 다시 열어 식별자·UUID·폴더·시각을 대조하고, 경로가 같은 파일을 가리키는지 확인한다. 파일 헤더나 검색 기간 전체를 확인할 수 없으면 자동 저장을 보류한다.

## 검증

단위 테스트는 두 신호가 같을 때 양쪽 역할이 파일에 저장되고 다시 읽히는 경우를 확인한다. 보안 검토에서는 외부 MCP에서 main으로 전달한 폴더의 일치 여부, 추정으로 연결된 경쟁 후보, 잠금 전후 검증, 파일 교체와 헤더 변경, 날짜 검색 한도를 테스트했다. `local-agent-messages`는 가짜 Codex가 인증된 훅을 보내기 전후로 디스크에 저장된 역할과 관계도 키를 확인한다.

관련 단위 테스트 146개와 `local-agent-messages` 화면 검사 163개가 모두 통과했다. `npm run typecheck`와 `npm run build`도 통과했다.
