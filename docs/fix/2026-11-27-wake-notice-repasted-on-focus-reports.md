# 새 Codex 세션에 메시지 알림이 다섯 번 들어가고 Enter 가 눌리지 않던 문제

## 증상 (2026-11-27 사용자 제보, 2.40.1)

바로작업에서 `새 세션에 요청`으로 Codex 를 고르면 세션은 뜨지만, 입력칸에 `New ezShell message: read it with read_inbox, then handle it.` 가 다섯 번 이어 붙은 채 멈췄다. 바닥줄은 `100% context left · ⚠ 1 warning · f2 to view` 였다.

같은 날 고친 "알림이 두 번 들어가던 문제"(`2026-11-27-wake-notice-pasted-twice.md`)가 들어간 2.40.1 에서 났다 (`last-version.json` 확인). 그 수정은 보이지 않은 붙여넣기를 30초 동안 다시 넣지 않게 했다. 하지만 Codex 기록(`~/.codex/sessions/.../rollout-...01a21b9c...jsonl`)을 보면 세션은 15:06:34 에 시작했다. 다섯 번 붙은 줄은 15:07:57 에 사용자의 Enter 로 제출되었다. 1분 남짓한 사이에 다섯 번이 붙었으므로 30초 규칙과는 다른 경로였다.

## 원인

`src/ipc/agentInboxWake.js` 의 `userInput()`.

1. 탭의 터미널에 들어온 입력은 모두 `localShell.write` → `inbox.userInput()` 을 지난다. 여기에는 xterm 이 스스로 보내는 응답도 섞인다.
2. Codex 0.172 는 시작할 때 포커스 보고(`ESC[?1004h`)를 켠다. 그러면 창이나 칸의 포커스가 바뀔 때마다 xterm 이 `ESC[O`/`ESC[I` 를 보낸다. 바로작업은 캡처 창에서 본창의 새 탭으로 포커스가 옮겨 가는 흐름이다.
3. `userInput()` 은 이 응답을 사용자 입력으로 보고 진행 중인 시도(`stage`)를 지웠다.
4. Codex 는 붙여 넣은 글을 수백 ms 늦게 그린다. 그 사이의 다음 `advance()` 는 입력칸이 비어 보이므로 알림을 다시 붙였다. 포커스가 바뀔 때마다 이 과정이 되풀이되었다.
5. 붙여넣기가 모두 그려지면 알림이 4~5번 겹쳐 보인다. Enter 는 알림이 1~3번 반복된 입력칸에만 누르므로 눌리지 않았다. `userInput()` 이 복구도 막아서(`suppressWakeRecovery`) 그 뒤로도 그대로 남았다.

### 재현 (실제 Codex CLI 0.172.0)

앱 밖의 ConPTY(node-pty)에서 실제 Codex 를 앱과 같은 인자(`--no-daemon`, ezShell 훅 인자)로 띄우고 `createAgentInboxWake` 를 붙였다. 감시기의 Enter 는 Codex 로 보내지 않고 기록만 했다 (모델 호출 없음). 메시지 MCP 는 실행 중인 앱에 붙지 않도록 없는 명령으로 바꿨다.

| 경우 | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 포커스 보고 없음 (메시지 도착 0·5·12초, 칸 크기 변경 4가지) | 붙여넣기 1, Enter 1 | 같음 |
| 붙여 넣은 뒤 포커스 보고 4번 (268×59) | 붙여넣기 4, Enter 0 | 붙여넣기 1, Enter 1 |
| 붙여넣기마다 60ms 뒤 포커스 나감·들어옴 | 붙여넣기 15, Enter 0 | 붙여넣기 1, Enter 1 |
| 시작 중 포커스 보고 6번 | 붙여넣기 3, Enter 1 | 붙여넣기 1, Enter 1 |
| 좁은 칸(59×15)에서 포커스 보고 4번 | (미실행) | 붙여넣기 1, Enter 1 |

고치기 전에 다시 붙이던 순간의 화면은 모두 `› Ask Codex to do anything`(빈 입력칸)이었다.

## 수정

- **터미널이 스스로 보내는 응답은 입력으로 보지 않는다.** `TERMINAL_REPORTS` 는 포커스 보고, 장치 속성(DA) 응답, OSC 응답(색 조회 등), 모드(DECRPM)·키보드 플래그 응답, DCS 응답이다. 입력 덩어리 전체가 이것뿐이면 `userInput()` 은 아무것도 바꾸지 않는다. 같은 이유로 채팅 보내기 중의 포커스 변화가 보내기를 `interrupted` 로 끝내던 경로도 함께 막힌다. 커서 위치 응답(`ESC[행;열R`)은 Ctrl+F3 키(`ESC[1;5R`)와 모양이 같아서 넣지 않았다. ConPTY 가 커서 위치 조회에 직접 답하므로 Codex 에서는 이 응답이 오지 않는다.
- **아직 그려지지 않은 붙여넣기는 실제 키 입력으로 취소돼도 다시 넣지 않는다.** 사용자가 키를 누르거나 IME 조합을 시작해 시도가 지워질 때, 그 붙여넣기가 한 번도 보이지 않았다면 `visibleUntil`(30초)까지 새 붙여넣기를 미룬다. 입력칸에 글이 보이면 바로 풀린다. 사용자 글 위에 알림이 한 번 더 겹치는 것을 막는다.

## 검증

- `agentInboxWake.test.js` 에 재현 시험 2개를 더했다. 그려지기 전 포커스·OSC·DA 응답이 와도 한 번만 붙이고 Enter 를 누르는지, 그려지기 전 사용자 키 입력 뒤 다시 붙이지 않는지 본다. 고치기 전에는 둘 다 실패했고, 고친 뒤 이 파일의 시험 310개가 통과했다 (`vitest related` 도 같은 310개).
- 위 표의 실제 Codex 재현을 고친 코드로 다시 돌렸다.
- `npm run typecheck`, `npm run build`, 화면 시험 `local-agent-messages` 가 통과했다.
- 확인하지 못한 것: 실제 앱에서 바로작업 → 새 세션 Codex 경로를 처음부터 다시 밟아 보지는 않았다. 재현 도구는 메시지 MCP 대신 없는 명령을 썼고, 세션 보관 프로세스를 거치지 않았다.
