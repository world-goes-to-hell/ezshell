# 브라우저 탭: 새 창 링크, 우클릭 메뉴, 검사

2026-11-23 사용자 보고: 앱의 브라우저 탭에서 링크를 눌러도 이동하지 않았다. Chrome 처럼 우클릭으로 링크 주소를 복사할 수도, 요소를 검사할 수도 없었다(Nginx Proxy Manager 의 도메인 링크).

## 원인
- 페이지(`WebContentsView`)의 `setWindowOpenHandler` 가 모든 새 창을 거부했다. 그래서 `target="_blank"`, `window.open`, Ctrl·가운데 클릭으로 여는 링크가 아무 일도 하지 않았다. 같은 탭에서 이동하는 링크는 원래 동작했다.
- 페이지의 `context-menu` 이벤트를 받는 곳이 없었다. 개발자 도구는 F12 와 도구 버튼으로만 열렸다.

## 수정 (`src/ipc/browserReview.js`, 메뉴는 `src/ipc/browserContextMenu.js`)
- 새 창으로 여는 링크는 앱의 새 브라우저 탭에서 연다. 기존 `openLink` 경로를 그대로 쓰고, http(s) 만 연다. 따로 창을 띄우지는 않는다.
- 우클릭 메뉴를 추가했다. 페이지가 앱 화면 위에 그려져 HTML 메뉴는 그 아래에 가려지므로 Electron 기본 메뉴로 띄운다. 누른 자리에 따라 항목이 달라진다.
  - 링크: 새 탭에서 열기, 기본 브라우저에서 열기, 링크 주소 복사, 링크 텍스트 복사
  - 이미지: 새 탭에서 열기, 이미지 복사, 이미지 주소 복사
  - 입력칸: 실행 취소·다시 실행·잘라내기·복사·붙여넣기·모두 선택
  - 선택한 글자: 복사
  - 빈 곳: 뒤로·앞으로·새로고침·페이지 주소 복사
  - 어디서나 맨 아래: 검사 (개발자 도구를 따로 띄운 창으로 열고 그 요소를 고른다)
- 메뉴에 적힌 키가 실제로 동작하도록 페이지 안에서 `Alt+←/→`, `F5`·`Ctrl+R` 을 받게 했다.
- 여는 것은 http(s) 주소만이다(`linkUrl`). 복사는 4096자까지만 한다.

## 확인
- 단위 테스트 `browserContextMenu.test.js` 5개
- 화면 테스트 `browser-review`: `target="_blank"` 링크를 누르면 새 브라우저 탭이 그 주소로 열리고, 원래 탭은 그대로인지 확인한다.
- 같은 명세의 "choosing Fill enters the selected account" 실패는 이번 변경과 무관하다. 우클릭 메뉴를 빼고 돌려도 똑같이 실패했다. 다른 세션이 고치는 중인 비밀번호 가져오기 작업으로 보인다.
- 우클릭 메뉴가 화면에 뜨는 것은 기본 메뉴라서 화면 테스트로는 확인하지 못했다.
