# 새 세션에 메시지 알림이 두 번 들어가고 Enter 가 눌리지 않던 문제

## 증상 (2026-11-27 사용자 제보)

새 에이전트 세션에 메시지를 보내면 세션은 뜨지만, 입력칸에 `New ezShell message: read it with read_inbox, then handle it.` 가 두 번 이어 붙은 채 멈췄다. Enter 가 눌리지 않아 에이전트가 메시지를 읽지 않았다.

## 원인

`src/ipc/agentInboxWake.js` 의 `advance()`.

1. 막 뜬 Claude 는 입력칸을 먼저 그리고, 입력은 조금 뒤에 읽는다. 상태를 아직 알리지 않은 에이전트는 빈 입력칸이 1.5초 조용하면 알림을 붙여 넣는다.
2. 붙여 넣은 글이 1.5초(`INPUT_TIMEOUT`) 안에 화면에 안 보이면 시도는 `expiredWake` 로 넘어간다. 그 뒤에도 입력칸이 비어 보이면 새 붙여넣기 단계로 흘러가 알림을 한 번 더 붙여 넣었다.
3. CLI 가 입력을 읽기 시작하면 두 붙여넣기가 모두 들어가 알림이 두 번 보였다. Enter 는 입력칸이 알림 한 번과 정확히 같을 때만 누르므로, 끝내 눌리지 않았다.

## 수정

- **아직 한 번도 보이지 않은 붙여넣기는 다시 넣지 않는다.** 시도가 화면에 보이면 `attempt.seen` 을 켠다. 보인 적 없는 시도는 `visibleUntil`(30초)까지 기다리고, 그 뒤에야 새로 붙여 넣는다. 한 번 보였다가 사라진 경우(사용자가 지움 등)는 예전처럼 다시 넣는다.
- **알림이 여러 번 들어가 있어도 우리 글이면 보낸다.** 입력칸이 알림을 1~3번 반복한 것뿐이면 우리 글로 보고 Enter 를 누른다 (`ours`). 30초가 지나 다시 넣은 뒤 늦게 앞의 것이 들어온 경우에도 멈추지 않는다.

## 검증

- `agentInboxWake.test.js`: 재현 시험 2개를 더했다. 늦게 보이는 시작 중 Claude 에 한 번만 붙여 넣고 Enter 를 누르는지, 두 번 들어간 알림을 보내는지 본다. 고치기 전에는 둘 다 실패했고, 고친 뒤 전체 308개가 통과했다.
- 화면 시험 `local-agent-messages` 가 통과했다.
