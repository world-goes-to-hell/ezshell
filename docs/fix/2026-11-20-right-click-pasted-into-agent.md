# 터미널 우클릭이 에이전트 입력칸에 클립보드를 붙여 넣던 문제

2026-11-20 사용자 보고: 로컬 터미널의 Codex·Claude 칸을 우클릭해 `채팅으로 보기` 로 들어가면, 우클릭하는 순간 클립보드의 글이 에이전트 입력칸에 들어갔다. 채팅 보기에서 보내면 "에이전트 입력칸에 쓰던 글이 있습니다" 로 거절됐다 (채팅 보내기는 입력칸이 비어 있을 때만 붙여 넣는다).

## 원인

- Codex·Claude Code 는 마우스 보고(`ESC[?1000h`·`1003h`·`1006h`)를 켠다. 그러면 xterm 은 마우스 누름·뗌을 셸 입력(`ESC[<2;열;행M`/`m`)으로 보낸다. 앱이 우클릭으로 메뉴를 여는 것과 상관없이 오른쪽 버튼도 보낸다 (앱에서 기록해 확인).
- Codex 0.170.0 은 오른쪽 버튼 보고를 받으면 클립보드를 입력칸에 붙여 넣는다 (Windows 콘솔의 우클릭 붙여넣기 관례). 실제 Codex 를 pty 로 띄우고 보고를 보내 입력칸이 클립보드 글로 바뀌는 것을 확인했다.

## 수정

- `lib/rightClickReports.ts` 의 `createRightClickFilter`: xterm 이 셸로 보내는 입력에서 오른쪽 버튼의 보고(누름·끌기·뗌, SGR 과 기본 인코딩)만 빼고 나머지(왼쪽·가운데 버튼, 휠, 움직임, 키 입력)는 그대로 둔다. 기본 인코딩의 뗌은 어느 버튼인지 말하지 않으므로, 뺀 오른쪽 누름 다음의 뗌 하나를 함께 뺀다.
- 우클릭 메뉴가 있는 터미널 셋에 건다: 로컬 터미널(`LocalTerminalTab`), SSH 탭의 주 터미널(`TerminalPanel`), 분할 칸(`SplitTerminal`). 서버에서 돌리는 Codex·vim 도 같은 우클릭을 받았다. 메뉴가 없는 분리 터미널 창(`TerminalWindow`)은 지금처럼 우클릭을 프로그램에 넘긴다.
- DOM 의 `mousedown` 을 막는 방식은 쓰지 않았다: 화면의 포커스 처리(`.tab-host-content` 의 `onMouseDown`) 같은 앱의 다른 처리기까지 막힌다.

## 확인

- 단위 `rightClickReports.test.ts` 4개.
- 임시 화면 테스트로, 빌드한 앱의 실제 Codex 칸을 CDP 로 우클릭했을 때 xterm 이 `ESC[<2;…M`/`m` 을 보내는 것과 채팅 보내기가 되는 것을 확인했다. CDP 로 낸 우클릭은 수정 전에도 Codex 가 붙여 넣지 않아서, 이 시험으로는 수정 전 실패를 재현하지 못했다 (이유는 확인하지 못함). 그래서 화면 테스트로 남기지 않았다.
