# 채팅에서 `\` 로 끝나는 글을 보내면 Claude 에 전송되지 않던 문제

## 증상 (2026-11-27 사용자 제보)

채팅 보기에서 `버그인가\` 처럼 마지막이 `\` 인 글을 보내면 말풍선 아래에 `전송 확인 안 됨` 이 뜨고, Claude 는 질문을 받지 않았다.

## 원인

Claude Code 는 입력칸의 마지막 글자가 `\` 일 때 Enter 를 줄바꿈으로 처리한다 (`\` 를 지우고 새 줄을 만든다). 채팅 보기는 글을 붙여 넣고 Enter 를 보내므로, 이 Enter 가 제출이 아닌 줄바꿈이 되었다.

실제 CLI 로 확인했다 (ConPTY 에서 붙여 넣은 뒤 Enter):

| CLI | 붙여 넣은 글 | Enter 뒤 |
| --- | --- | --- |
| Claude Code 2.1.332 | `버그인가\` | `\` 가 지워지고 입력칸에 빈 줄이 하나 더 생김, 제출 안 됨 |
| Claude Code 2.1.332 | `버그인가\ ` (끝에 공백) | 제출됨. 대화 기록에는 `버그인가\` 로 남음 (공백 없음) |
| Codex 0.172.0 | `버그인가\` | 그대로 제출됨 |

Orca 는 이 동작을 알고 있지만 막지 않는다. CLI 가 마지막 `\` 를 먹고 다음에 보낸 글과 한 차례로 합쳐지는 것을 전송 확인에서 받아들인다 (`native-chat-continuation-send.ts`). 사용자는 그대로 보내지기를 원했으므로 Orca 와 다르게 처리했다.

## 수정

`src/ipc/agentInboxWake.js` 의 `submitText()`: Claude 에 붙여 넣는 글이 `\` 로 끝나면 끝에 공백 하나를 더해 붙여 넣는다. 화면 대조는 원래부터 공백을 뺀 글로 하므로 바뀌지 않는다. 입력칸을 지울 때 쓰는 글자 수(`eraseCount`)는 공백을 더한 길이로 센다. Codex 와 Antigravity 는 그대로 둔다.

## 검증

- `agentInboxWake.test.js`: Claude 는 공백을 붙여 붙여 넣고 Enter 를 누르는지, Codex 는 그대로 붙여 넣는지 보는 시험 2개를 더했다. 고치기 전에는 Claude 시험이 실패했고, 고친 뒤 312개가 모두 통과했다.
- 실제 Claude Code 2.1.332 에 고친 `submitText('버그인가\\')` 로 보냈다. 결과는 `{ ok: true }` 였고, 붙여넣기 뒤 Enter 한 번으로 제출되어 Claude 가 답을 시작했다.
- `npm run typecheck`, `npm run build`, 화면 시험 `local-agent-chat` 가 통과했다. 첫 실행에서는 관계없는 항목 하나(긴 붙여넣기의 강제 보내기 버튼 대기)가 시간 초과로 실패했고, 다시 돌리자 전부 통과했다.
