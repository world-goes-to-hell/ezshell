# 메인 PC를 방해하지 않는 화면 시험

`npm run e2e`는 각 시험 앱을 별도 프로필에서 열고 기본으로 `EZSHELL_TEST_HIDDEN_WINDOWS=1`을 켠다. 직접 실행하는 개발 앱도 같은 변수를 쓸 수 있다. 설치본은 이 변수를 읽지 않는다. 실제 창이 필요한 시험은 사용자가 동의한 뒤 `npm run e2e -- --visible <명세>`로 실행한다.

## 동작

- 앱의 모든 BrowserWindow는 연결된 모니터 영역 오른쪽 밖에 만든다. 창을 비활성 상태로 표시하고 작업 표시줄 버튼을 만들지 않는다. 창 이동은 화면 밖의 좌표로 처리하고 전체 화면 요청은 막는다. 최대화와 복원은 화면 밖에서 창 크기와 관련 이벤트로 재현한다.
- 테스트 앱의 개발자 도구·네이티브 메뉴·파일 선택 창·Windows 알림을 막는다. MCP 확인과 에이전트 알림은 앱 내부 표시로 확인한다. 파일 선택과 캡처 시험은 프로필 내부 자료를 쓰는 기존 fixture로 확인한다.
- CDP는 OS 창을 활성화하는 대신 페이지에 포커스를 에뮬레이션한다. 화면 캡처와 입력은 같은 페이지에 보낸다. 실제 전역 키보드 후크는 시작하지 않는다. `quick-capture`가 쓰는 가짜 도우미는 실제 키를 읽지 않는다.
- Windows에서 화면 밖 창의 애니메이션 프레임 요청이 약 1초 대기하는 경우를 확인했다. `local-split`은 첫 탭이 열리는 애니메이션을 검사하는 동안 CDP 캡처를 잠깐 열어 실제 프레임을 받는다.

## 실제 화면이 필요한 검사

| 명세 | 이유 |
| --- | --- |
| `local-work-overview` | 실제 모니터의 전체 화면 크기와 창 복원을 비교한다. |
| `window-place` | 실제 모니터에서 창을 옮기고 저장·복원된 위치를 비교한다. |

`browser-tab-title`은 기본 실행에서도 제목·탭·즐겨찾기를 검사한다. 분리 개발자 도구 창 열기와 닫기는 `--visible`일 때 검사하며, 기본 실행에서는 분리 창이 열리지 않는지를 확인한다.

## 확인

- Windows에서 연결된 모니터 5대의 영역과 창 위치를 대조했다. 본창·시작 창·별도 검증 창이 모두 모니터 영역 밖에 있었다. 전면 창 표본 191개에서 시험 앱이 전면에 온 경우는 0건이었으며 네이티브 키보드 후크 프로세스도 시작하지 않았다.
- CDP로 임시 프로필의 잠금을 해제했고, CDP PNG와 Electron `capturePage` 이미지가 실제 내용을 담는 것을 확인했다. 별도 검증 창은 화면 밖에서만 크기가 커졌다가 원래 크기로 돌아왔다.
- 관련 단위 테스트 14개와 타입 검사, 빌드가 통과했다.
- 전체 `npm run e2e`는 65개 명세 중 60개 통과, 3개 실패, 실제 화면이 필요한 2개 생략이었다.
  - `local-split`은 화면 밖의 프레임 지연으로 첫 탭 애니메이션을 놓쳤다. 공용 CDP 연결과 짧은 캡처를 적용한 뒤 전체 명세를 개별 재실행해 통과했다.
  - `local-agent-chat-timestamps`는 좁은 말풍선 포인터 검사 두 건이 실패했다. 앱과 이 명세의 소스를 바꾸지 않고 재실행했을 때 모두 통과했다.
  - `ssh-usability`는 닫기 버튼을 누른 직후 이미 존재하는 자동 체크포인트를 읽었다. 진단 재실행에서 직후 기록에는 최종 상태가 없었고 창이 닫힌 뒤에는 이름과 SFTP 경로가 저장됐다. 기존 시험이 저장 완료 대신 파일 존재 여부를 기다린 데서 발생했다.
