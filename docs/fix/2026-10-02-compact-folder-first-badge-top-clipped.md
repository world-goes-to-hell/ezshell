# 축소 사이드바에서 폴더 바로 아래 첫 세션의 탭 개수 배지 윗 테두리가 잘리던 문제

## 증상
- 축소(아이콘) 사이드바에서 폴더 마커 바로 아래 첫 세션의 탭 개수 배지(초록/빨강 네모)가 윗 테두리 없이 보였다.
- 폴더 밖 세션이나 폴더 안 두 번째 이후 세션은 정상이었다.

## 원인
- `.folder-contents` 는 framer-motion 접힘 애니메이션 때문에 `overflow: hidden` 이다 (`globals.css`).
- 축소 사이드바의 세션 행은 높이 50px, 타일은 44px 라서 타일 위 여백이 3px 이다. 배지는 타일 모서리에 걸치도록 타일보다 4px 위(`inset: -4px ...`)에 놓인다.
  그래서 배지가 세션 행 위로 1px 튀어나온다.
- 폴더의 첫 세션은 행 윗변이 곧 `.folder-contents` 윗변이므로, 튀어나온 1px(배지 윗 테두리)이 잘렸다.
  두 번째 이후 세션은 같은 영역 안의 앞 행 공간으로 넘어갈 뿐이라 보였고, 폴더 밖 세션은 목록의 위 여백(8px) 덕분에 보였다.
- 키보드 포커스 링(2px + 간격 2px)은 행 위로 5px 나오므로 같은 이유로 잘리고 있었다.

## 수정 (`SidebarCompact.css`)
- `.sidebar.compact .folder-contents` 에 `padding-top: 6px; margin-top: -6px`.
  여백이 배지와 포커스 링이 들어갈 공간을 만들고, 음수 마진이 마커의 아래 마진(4px)과 상쇄되어 마커와 첫 세션 사이 간격(4px)은 그대로다.
- 그 결과 폴더 내용 영역이 마커 아래 끝과 2px 겹치므로, `.compact-folder-marker` 에 `position: relative; z-index: 1` 을 주어 그 구간에서도 마커가 클릭을 받게 했다.
- `overflow: hidden` 자체는 접힘 애니메이션에 필요해서 그대로 두었다. 접힌 상태(높이 0)에서는 opacity 도 0 이라 여백 부분이 보이지 않는다.
- 배지 위치(`-4px`)를 `-3px` 로 바꾸는 방법도 있었지만, 행/타일 높이에 묶인 숫자라 깨지기 쉽고 포커스 링은 여전히 잘려서 택하지 않았다.

## 검증
- 실제 앱 E2E (격리 사용자 데이터 + 테스트 SSH 서버 + CDP): 폴더 `MBR` 안 첫 세션 `웹서버` 에 탭 1개를 열고 축소 사이드바로 전환
  - 배지 윗변 269 ≥ 폴더 내용 영역 윗변 264, 포커스 링 윗변 265 도 영역 안
  - 배지 윗변 위치의 elementFromPoint = 배지, 마커 아래 끝 1px 의 elementFromPoint = 마커
  - 마커와 첫 세션 사이 간격 4px (수정 전과 같음)
- 수정 전 레이아웃을 페이지에 덮어써 재현하면 영역 윗변이 270 이 되어 배지 윗변(269)이 잘리고, 캡처에서도 윗 테두리가 사라졌다. 수정 후 캡처는 네 변 모두 보인다.
