# MCP 활동 영역이 알림을 가리는 문제, 호스트 키 거부 문구에 서버 주소가 들어가는 문제

- 날짜: 2026-10-26

## 1. MCP 활동 영역 뒤로 알림이 가려짐

### 증상
MCP 활동 영역이 열려 있을 때 업데이트 알림 같은 알림이 영역 뒤에 가려져 보이지 않았다.

### 원인
활동 영역(`.mcp-activity-panel`)이 `z-index: 9200` 이라 앱의 거의 모든 요소보다 위였다. 영역은 화면 오른쪽 전체(위 32px ~ 아래 30px)를 차지한다.
- 업데이트 알림(`.update-notification`, 900, 오른쪽 아래 `bottom: 36px; right: 16px`)이 영역 뒤에 완전히 가려졌다. 앱 시작 3초 뒤 새 버전 확인 결과로 뜨므로 영역을 켜 둔 채 쓰면 놓친다.
- 같은 이유로 일반 대화상자(`.modal-overlay` 100), 우클릭 메뉴(`.context-menu` 1000), 통계·일괄 실행·명령어 기록 화면(999~1000)도 오른쪽 부분이 가려졌다.

### 수정
활동 영역을 `z-index: 95` 로 낮췄다. 터미널·SFTP(대부분 10 이하, 가장 높은 것 50) 위에는 그대로 뜨고, 대화상자(100), 메뉴(1000), 알림(900), 짧은 안내(9999) 등 떠오르는 것은 모두 영역 위에 온다.

### 왜 이렇게 했나
알림마다 값을 올리면 새 알림이 생길 때마다 같은 문제가 반복된다. 영역은 작업 중 계속 열어 두는 화면이므로 "떠오르는 것들의 아래, 작업 화면의 위" 가 맞는 자리다.

## 2. MCP 호스트 키 거부 문구에 서버 주소가 들어감

### 증상
호스트 키를 아직 확인하지 않은 세션에 MCP 로 명령을 보내면 Claude 가 받는 오류에 `10.10.10.105:2201 서버의 호스트 키를...` 처럼 주소가 들어갔다. 이 앱은 호스트 주소와 계정을 Claude 에게 넘기지 않는다.

### 원인
2.5.0 에서 호스트 키 검증을 넣을 때 앱 화면용 문구(`hostKeyMessage`, 주소 포함)를 MCP 게이트웨이의 오류(`GatewayError`)에도 그대로 썼다.

### 수정
`hostKeyMessage(err, { subject })` 로 서버를 부르는 말을 바꿀 수 있게 했다. 기본값은 지금처럼 `<주소>:<포트> 서버`(앱 화면용)이고, `sessionGateway.js` 는 "이 세션의 서버" 또는 "이 세션의 점프 호스트" 를 넘긴다. 테스트로 문구에 호스트 이름과 포트가 없는지 확인한다.
