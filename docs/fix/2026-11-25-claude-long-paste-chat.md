# Claude 채팅에서 긴 붙여넣기 보내기

Windows에서 개발 앱을 임시 Electron 프로필로 띄우고 Claude Code 2.1.332로 확인했다. 40줄을 붙여 넣으면 터미널 입력칸에 `[Pasted text #1 +39 lines]`가 표시됐다. 기본 화면에서는 일반 전송과 강제 전송이 모두 성공했다. 실제 강제 전송의 대화 기록에는 `<pasted_content>` 안에 원문이 저장됐다.

## 원인

이미 비었음을 확인한 입력칸에 색으로만 구분되는 제안이 나타나거나 강제 지우기 뒤 빈 화면이 다시 그려지지 않으면, 전송은 붙여넣은 것이 새 초안인지 정확히 확인한다. 이 경로가 Claude의 붙여넣기 표시를 제외해 새 초안이 보여도 5초 뒤 `not-drawn`과 “입력칸에 글이 그대로 들어가지 않아 보내지 않았습니다”가 나왔다. Enter가 차단돼 붙여넣기 표시가 남으면 다음 전송에서도 그 초안의 소유를 확인할 수 없었다. 두 실패는 실제 CLI에서 확인한 표시를 사용한 회귀 테스트로 재현했다.

## 수정

- 줄이 접힌 붙여넣기 표시와 여러 표시를 읽는다. 앞뒤나 사이에 보이는 글이 있으면 원문에 같은 순서로 있어야 한다. 강제 지우기 직후 빈 화면을 확인하지 못한 경우에는 이전 입력에 붙여넣기 표시가 없어야 하며, 새 화면은 붙여넣기 표시만 보여야 한다.
- 붙여넣기 뒤 실제 입력칸에서 확인한 표시를 전송 시도에 묶어 둔다. Enter 전에 중단됐으면 같은 입력칸에서 모양이 일치할 때 지우고, 빈 화면을 확인한 뒤 다음 글을 붙인다. 채팅의 Esc로 회수할 때도 앞서 관찰한 표시가 그대로 돌아오고 원문 목록까지 일치해야 지운다. 터미널 키 입력은 이 확인 정보를 버린다.
- 활성 에이전트의 입력칸에서 기존 안전 판정을 거친 뒤 Enter를 한 번 보낸다. 대화 기록 확인과 다시 보내기는 `<pasted_content>`를 풀어 전체 본문을 비교한다. 표시만 있는 기록으로는 전송을 확인하지 않는다.

Orca의 터미널 채팅도 붙여넣기 표시와 안정된 입력 화면을 Enter 시점에 사용한다. [Orca 소스](https://github.com/stablyai/orca/blob/main/src/renderer/src/components/native-chat/session/terminal/send/native-chat-paste-landed.ts)

## 검증

- 관련 단위 테스트 293개 통과. Windows에서 Unix 전용 Antigravity 테스트 1개를 건너뛰었다.
- `npm run typecheck`와 `npm run build` 통과.
- Windows `local-agent-chat` 화면 검사 294개 통과. 가짜 Claude는 강제 지우기 뒤 빈 화면을 생략하고 붙여넣기 표시를 그렸다. 사용자가 강제 전송을 고른 뒤 40줄 원문이 한 번 제출되는 것을 확인했다.
