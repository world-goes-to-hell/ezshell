# MCP 파일 전송 진행 줄이 두 번 찍히던 문제

- 날짜: 2026-11-05
- 파일: `src/mcp/activityLog.js`, `src/mcp/activityLog.test.js`

## 증상

MCP 활동에서 `upload_file`/`download_file` 의 출력 마지막 줄이 항상 두 번 보였다.

```
진행: 44.0MB / 950.0MB (4%)
진행: 49.9MB / 950.0MB (5%)
진행: 49.9MB / 950.0MB (5%)
```

다음 진행 줄이 오면 앞의 중복은 사라지고 새 줄이 다시 두 번 보였다.

## 원인

`transferTools.js` 는 1초마다 두 가지를 한다.

1. `activity.appendOutput` 으로 진행 줄을 넣는다. main 의 항목에 바로 붙고, 창으로는 50ms 뒤 묶어서 보낸다 (`pendingOutput`).
2. `activity.update` 로 진행 막대(`transfer`)를 갱신한다. 이때 항목 전체(방금 붙인 줄이 든 `outputParts` 포함)를 창으로 보내고, 창은 자기 사본을 이것으로 바꾼다.

50ms 뒤 1번의 묶음이 도착하면 창은 그 줄을 한 번 더 붙인다. 끝난 요청은 `update` 에서 묶음을 버리고 있었지만, 실행 중인 요청은 버리지 않았다.

## 수정

`update` 가 항목을 보낼 때는 상태와 관계없이 그 요청의 대기 묶음을 버린다. 보내는 항목이 지금까지의 출력을 모두 담고 있기 때문이다. `list()` 가 스냅숏 전에 묶음을 먼저 보내는 것과 같은 이유다.

실행 중인 요청을 `update` 하는 곳(전송 진행 막대 등)이 생기면 모두 같은 문제를 겪으므로, 전송 쪽이 아니라 활동 로그에서 고쳤다.

## 확인

- 새 테스트: 실행 중 `appendOutput` 뒤 `update` 하면 묶음을 보내지 않고, 그 뒤의 출력은 그대로 보낸다. 수정 전 실패, 수정 후 통과.
- 전체 1,849개 통과, 타입 검사 통과.
