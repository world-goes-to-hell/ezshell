# 자동 로그아웃 서버에서 탭이 계속 끊기고 다시 연결됨

- 날짜: 2026-11-13

## 증상
`[개발] kbr` 서버의 터미널 탭이 가만히 두면 끊겼다가 다시 연결되기를 반복했다.

## 원인
서버에 `TMOUT=300` 이 걸려 있다 (사용자가 `echo $TMOUT` 으로 확인). 입력이 5분 없으면 bash 가 스스로 로그아웃한다("timed out waiting for input: auto-logout").

앱은 셸 채널이 닫히면 이유를 가리지 않고 자동 재연결했다. 셸이 스스로 끝난 것과 연결이 끊긴 것을 구분하지 않았으므로, 5분마다 "끊김 → 새 연결 → 새 셸" 이 반복됐다. 끊긴 이유를 어디에도 남기지 않아 원인을 바로 알 수도 없었다.

새 연결을 만들 때마다 탭의 SSH 연결이 통째로 바뀌므로, 그 연결을 쓰던 DB 탭의 접속도 5분마다 끊겼다가 다음 쿼리에서 다시 붙었다.

## 수정 (`main.js`)
- 셸 채널의 `exit` 이벤트(종료 코드)를 받아 두고, 채널이 닫힐 때 셸이 종료 코드와 함께 스스로 끝난 것이면(`endedByItself`) 재연결하지 않는다. 탭에는 "셸이 종료되었습니다 …" 안내와 `재연결` 버튼을 보여 준다(`reportShellExit`: 기존 `ssh-reconnect-failed` + `ssh-closed` 를 그대로 쓴다. 화면 코드는 바꾸지 않았다).
- 신호로 죽은 셸(서버가 내려가는 중)과 종료 코드 없이 닫힌 채널(연결이 끊김)은 지금처럼 자동 재연결한다.
- SSH 연결은 닫지 않는다. 같은 연결을 SFTP 패널과 DB 탭이 쓰고 있을 수 있다. 그래서 연결이 나중에 닫힐 때 다시 재연결을 시작하지 않도록, 연결의 `close` 처리에서 상태가 `DISCONNECTED` 면 건너뛴다.
- 끊긴 이유를 콘솔에 남긴다(`traceShellEnd`: 셸 종료 코드, 연결 오류, 서버가 끝냄, 경과 시간).

## 왜 "DB 를 쓰는 동안 셸을 살려 두기" 를 하지 않았나
`TMOUT` 은 셸에 들어온 입력만 센다. 셸을 살려 두려면 앱이 주기적으로 셸에 글자를 보내야 하는데, 서버의 자동 로그아웃 정책을 우회하는 것이고 실행 중인 프로그램에 입력이 들어갈 수 있다. DB 탭은 셸이 아니라 SSH 연결을 쓰므로 셸이 끝나도 계속 동작한다(실제 앱에서 확인).

## 확인
- 실제 앱(시험 서버): 셸이 스스로 종료 → 안내가 뜨고 7초 뒤에도 재연결하지 않음, 셸이 다시 열리지 않음 → `재연결` 로 새 셸 → 연결을 끊으면 자동 재연결 → 재연결된 탭의 셸이 스스로 종료해도 반복하지 않음 (7가지).
- 셸이 종료된 탭의 연결로 DB 로그인이 되고, 몇 초 뒤에도 됨 (4가지).
- 사용자 서버(`TMOUT=300`)에서의 확인은 사용자 몫.
