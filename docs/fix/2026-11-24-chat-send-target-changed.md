# 채팅 보내기가 "CLI의 입력 대상이 바뀌었습니다" 로 막힘

2026-11-24 사용자 제보: 채팅 보기에서 Claude 에게 "안녕 오늘11월24일이야" 를 보내자 `보내지 못했습니다 — CLI의 입력 대상이 바뀌었습니다. 터미널에서 현재 대화를 확인해 주세요.` 가 떴다 (2.30.0).

## 원인
- 앱은 Claude 입력칸 위 가로줄 끝의 이름(`──── 이름 ─`)을 "입력 대상" 으로 읽는다 (`agentInboxWake.targetOf`). 서브에이전트에게 직접 보내는 기능(11-22, `dcbd517`)을 위해 만든 것이다.
- 11-23 (`d105e75`, 2.28.0) 부터 일반 보내기도 붙여 넣기 전과 Enter 직전의 이름이 같아야 Enter 를 보냈다 (`chatTargetMatches`). 시작할 때도 그 이름이 서브에이전트로 기억된 이름이 아니어야 했다 (`localShell.chatSend` 의 `parentInput`).
- 이 확인은 채팅 보기의 기준인 Orca(MIT)에 없다. Orca 의 보내기(`native-chat-runtime-send.ts`, `native-chat-paste-landed.ts`)는 대상이 PTY 하나뿐이고, 붙인 글이 보일 때까지 100ms 마다 다시 읽다가 Enter 를 보낸다.
- 제보자의 화면에서 무엇 때문에 이름이 달라 보였는지는 재현하지 못했다. 실제 Claude CLI 2.1.331 로 확인한 것: 이름 없는 세션은 가로줄에 이름이 없고, 자동 제목(ai-title)은 그려지지 않으며, `-n`/`/rename` 으로 붙인 세션 이름은 그려지지만 붙여 넣기 전후로 바뀌지 않았다.

## 함께 찾은 결함
- 세션 이름이 칸 폭에 비해 길면 Claude 가 가로줄을 `─` 없이 ` 운영 도메인 … ─` 로 그린다 (60열에서 재현). 앱은 `─` 8개 이상인 줄만 테두리로 알아봐서, 채팅·캡처 바로작업·메시지 알림이 모두 "입력칸을 찾지 못했습니다" 였다.

## 수정
- `localShell.chatSend`: 일반 보내기(`target` 없음)는 이름을 보지 않고 같은 대화인지(`sameConversation`)만 본다 (`canSend` 로 넘김). 서브에이전트 이름을 겨눈 보내기만 `verify` 로 이름을 확인한다.
- `agentInboxWake.chatTargetMatches`: 이름 비교는 `draft.verify` 가 있을 때(서브에이전트 보내기)만. 앞서 붙인 우리 글을 알아보는 비교(`ours`, `waitingForPrior`)도 같은 규칙.
- `claudeTargetRule`·`claudeRuleLabel`: `─` 가 하나 이상이거나, 없어도 이름이 `…` 로 끝나면 이름 붙은 가로줄로 읽는다. 그냥 ` ─` 로 끝나는 글줄은 테두리로 보지 않는다.

## 확인
- 단위 테스트 (`agentInboxWake.test.js`): 보내는 도중 가로줄 이름이 바뀌어도 일반 보내기가 붙여 넣기와 Enter 를 보냄(고치기 전 `target-changed`), 잘린 긴 이름 아래 입력칸을 찾음(고치기 전 `null`), ` ─` 로 끝나는 글줄은 테두리가 아님. 서브에이전트 이름 확인 테스트는 그대로 통과.
- 전체 단위 테스트 3,853개 통과, 화면 테스트 `local-agent-chat` 의 보내기 확인 통과.

## 남은 것
- 서브에이전트에게 부모를 거쳐 전달하는 경로(`routeSubagent` 의 `relay`)는 부모 입력칸의 이름을 빈 문자열로 가정한다. 이름 붙은 세션에서는 `select-parent` 로 빠져 전달하지 못한다.
