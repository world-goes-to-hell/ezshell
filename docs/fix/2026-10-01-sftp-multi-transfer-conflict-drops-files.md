# SFTP 다중 전송 중 이름이 겹치는 파일이 있으면 일부 파일이 전송되지 않던 문제

## 증상
- 8개 이상의 파일을 한 번에 업로드/다운로드(버튼, 드래그, 폴더 행 드롭)할 때, 중간에 대상 폴더에 같은 이름의 파일이 있으면 일부 파일이 전송되지 않았다.
- 같은 파일 이름으로 덮어쓰기 모달이 여러 번 반복해서 뜨는 경우도 있었다.

## 원인
`SftpPanel.tsx` / `SftpWindow.tsx` 의 `processNextTransfer` → `handleOverwriteConfirm` 흐름에 결함이 두 가지 있었다.

1. **충돌한 파일의 위치를 기록하지 않음**
   `processNextTransfer` 는 충돌을 만나면 모달만 열고 `setCurrentTransferIndex(index)` 를 하지 않았다.
   그래서 `currentTransferIndex` 는 0 으로 남고, 모달 답변은 충돌한 파일이 아니라 **0번 파일**에 적용되었다.
   - 이어서 1번부터 다시 진행하므로 충돌 앞의 파일이 중복으로 큐에 들어가고, 같은 충돌 모달이 반복해서 떴다.
   - 반복되는 모달을 사용자가 닫으면(취소) 충돌 뒤의 파일은 전송되지 않았다.
2. **"이후 충돌에도 동일하게 적용" 이 충돌이 없는 파일에도 적용됨**
   모두 적용을 고르면 남은 파일 전부에 `processTransfer(pendingTransfers[i], action)` 를 호출했다.
   - `건너뛰기` + 모두 적용 → 충돌 여부와 관계없이 남은 파일이 **전부 건너뛰어짐** (사용자가 본 증상)
   - `이름 변경` + 모두 적용 → 충돌이 없는 파일까지 `이름 (1).ext` 로 바뀜

추가로 `이름 변경` 은 항상 화면에 열린 폴더 경로로 대상 경로를 다시 만들었기 때문에, 폴더 행에 드롭한 경우 엉뚱한 폴더로 전송되었다.
`크기가 다를 때만` 도 화면에 보이는 목록과 크기를 비교해서, 폴더 행 드롭에서는 잘못된 파일과 비교했다.

## 수정
React state 로 인덱스를 들고 다니는 재귀 흐름을 없애고, 모달을 Promise 로 기다리는 단순 루프로 바꿨다.

| 파일 | 내용 |
|------|------|
| `src/renderer/lib/transferBatch.ts` | `runTransferBatch`: 순서대로 진행, 충돌한 파일에서만 질문, 모두 적용은 이후 **충돌**에만 적용, 취소 시 그 자리에서 중단. `uniqueName`, `siblingPath` |
| `src/renderer/hooks/useSftpTransferBatch.ts` | 덮어쓰기 모달을 Promise 로 감싼 `useOverwritePrompt`, 큐 등록(`이름 변경`은 대상 경로의 폴더 기준, `크기가 다를 때만`은 대상 폴더의 크기 기준) |
| `SftpPanel.tsx`, `SftpWindow.tsx` | 중복되어 있던 덮어쓰기 상태/흐름을 지우고 훅 사용. 폴더 행 드롭은 대상 폴더의 이름과 크기(`targetEntries`)를 넘김 |

### 왜 이렇게 했나
- 버그의 뿌리는 "비동기 모달 + React state 로 진행 위치 관리" 였다. 클로저에 갇힌 state 와 갱신 타이밍이 어긋나기 쉽다.
  모달 답변을 `await` 하는 루프로 바꾸면 진행 위치가 지역 변수 하나가 되어 같은 종류의 버그가 다시 생기기 어렵다.
- 판단 로직을 React 밖의 순수 함수로 빼서 단위 테스트로 고정했다.
- Panel 과 Window 에 같은 코드가 복사되어 있어 둘 다 같은 버그가 있었다. 훅 하나로 합쳤다.

### 동작 변화
- 모달 `취소` 는 "남은 파일 전송 중단" 이며, 몇 개를 보내지 않았는지 토스트로 알린다.
- 파일마다 뜨던 `Upload queued` 토스트는 없앴다 (전송 큐가 자동으로 열려 진행 상황을 보여 준다).

### 코드 리뷰 반영
- **이름 변경이 같은 배치의 다른 파일을 덮어쓰던 문제**: `a.txt` 와 `a (1).txt` 를 함께 보내는데 대상에 `a.txt` 만 있으면, `a.txt` 의 새 이름이 `a (1).txt` 가 되어 함께 보낸 파일과 같은 경로가 되었다.
  `resolveTarget` 이 대상 폴더의 이름에 더해 배치에 포함된 이름과 이미 바꾼 이름(`reserved`)도 피한다.
- **취소한 모달의 "모두 적용" 체크가 다음 배치에 남던 문제**: `OverwriteModal` 은 닫혀도 마운트된 채라 state 가 유지되었다. 모달이 열릴 때마다 `덮어쓰기` / 체크 해제로 초기화한다.
- **완료 후 새로고침이 옛 경로/로딩 state 를 쓰던 문제**: 모달을 기다리는 동안 렌더가 바뀌므로 `onDone` 을 ref 로 들고 최신 렌더의 함수를 호출한다.
- 크기 비교와 이름 변경 경로 계산을 `resolveTarget` 순수 함수로 빼서 테스트했다.
