# 새 창에서 본창으로 되돌린 탭이 세션 색을 잃는 문제

날짜: 2026-10-14

## 증상

탭을 창 밖으로 끌어 새 창으로 분리한 뒤, 새 창의 "본창으로 붙이기" 버튼으로 되돌리면 탭이 세션에 지정한 색이 아니라 기본 강조색(노란색)으로 표시된다.

## 원인

탭을 분리하면 본창은 그 탭을 목록에서 지우고, 되돌아올 때 `terminal-merge` 이벤트로 탭 정보를 새로 만든다.
이때 본창이 보관해 둔 것은 접속 설정(`connectConfig`)뿐이었고, 새로 만드는 탭 정보에 `color` 를 넣지 않았다.
탭 색은 `TerminalInfo.color` 만 보고 그리므로 색이 없는 탭이 되어 기본 강조색으로 표시됐다.

## 수정

- `src/renderer/lib/detachedTab.ts` (신규): 분리할 때 보관할 값(`detachTab`: 접속 설정과 색)과 되돌릴 때 만들 탭 정보(`restoreMergedTab`)를 순수 함수로 분리했다.
  색은 탭의 현재 색을 먼저 쓰고, 없으면 접속할 때의 색을 쓴다 (`getDuplicateConfig` 와 같은 순서).
- `src/renderer/App.tsx`: 보관 맵이 접속 설정 대신 `DetachedTab` 을 담고, 병합 처리에서 `restoreMergedTab` 을 쓴다.

## 왜 이렇게 했는가

- 색을 main 프로세스나 새 창을 거쳐 왕복시키지 않았다. 본창이 이미 접속 설정을 같은 방식으로 보관하고 있어서, 같은 자리에 색을 함께 두는 것이 가장 작은 변경이다.
- 접속 설정이 없는 탭도 색을 잃지 않도록, 접속 설정이 있을 때만 보관하던 조건을 없앴다.

## 검증

- `detachedTab.test.ts` 5개 통과, 전체 테스트 1,720개 통과, typecheck 오류 없음.
- 실제 앱에서 분리 후 되돌리는 동작은 아직 확인하지 못했다 (통합 빌드 뒤 확인).

## 남은 한계

분리된 창이 떠 있는 동안 본창을 새로 고치면 보관한 값이 사라져, 되돌린 탭에 색과 "같은 서버로 새 탭" 기능이 없다. 이전부터 있던 동작이고 이번에 바꾸지 않았다.
