# 명령어 기록이 빠지거나 잘려서 저장되던 문제

## 증상
- 연결 직후 입력한 `ls -al`, `pwd` 중 `pwd` 만 기록됨 (E2E 중 발견)

## 원인 (재현으로 확인)
기록은 사용자가 Enter 를 보내는 순간 화면의 커서 줄을 읽어 프롬프트 뒤를 저장했다. 그 줄이 그 순간 완성되어 있지 않으면 틀린다.

| 조건 | 결과 |
|---|---|
| 프롬프트가 뜨기 전에 입력 | 줄에 프롬프트가 없어 누락 (서버는 실행) |
| 에코 지연 80ms + 빠른 입력, 150ms | **잘린 명령 저장** (`ls -al /c3a` → `ls -al`) |
| 에코 지연 400ms | 누락 |
| 터미널이 13칸으로 좁아 첫 프롬프트 줄이 깨짐 | 첫 명령 누락 (지난번 현상) |
| 보통 지연(30~80ms) + 보통 속도 | 정상 |

메인 프로세스 저장(`updateCommandHistory`)은 동기 메모리 갱신이라 연속 저장 경쟁은 원인이 아니었다.

## 수정
- `useTerminalCommandHistory`: Enter 때 그 줄에 xterm marker 를 걸고, 셸이 Enter 에 답하는 줄바꿈(`onLineFeed`)이 왔을 때 그 줄을 읽어 기록. 줄바꿈이 오지 않으면 2초 뒤 읽음.
  - 셸은 Enter 를 받으면 그 전에 입력된 글자의 에코를 모두 보낸 뒤 줄바꿈을 보내므로 그 시점의 줄은 완성되어 있다
  - 프롬프트가 늦게 온 경우도 같은 줄에 프롬프트와 에코가 그려지므로 기록된다
  - 자동 줄넘김(긴 명령)은 `onLineFeed` 를 내지 않는다 (xterm `InputHandler.print` 가 아닌 `lineFeed()` 에서만 발생) → 긴 명령도 완성 후 읽음
  - 앞 Enter 가 아직 기다리는 중에 다음 Enter 가 오면 앞 것을 먼저 확정
  - Enter 직후 vim 등으로 alternate 화면이 되어도 `buffer.normal` 에서 읽음
- `commandCapture.readInputLine(buffer, row?)`: 지정한 줄을 읽을 수 있게 (테스트 추가)

### 1차 수정 후 재검증에서 나온 문제 → 2차 수정
- D: 앞 명령의 에코가 오기 전에 다음 명령을 치고 Enter → `["cmd-one /d1", "cmd-one /"]` 저장, 둘째 명령 누락.
  두 번째 Enter 가 대기 중인 앞 줄을 "먼저 확정"해서 미완성 줄이 저장됐고, 커서가 아직 앞 줄이라 둘째 표시도 같은 줄에 걸렸다.
- 2차: 기록을 `hooks/useCommandRecorder.ts` 로 분리
  - 앞 Enter 가 대기 중이면 강제로 확정하지 않는다
  - 그동안 친 글자(`appendTypedInput`: 글자·백스페이스만. Tab/화살표/Ctrl 이 섞이면 불확실)를 기억해 두고,
    이후 줄바꿈마다 완성된 줄의 프롬프트 뒤가 그 글자와 **정확히 같을 때만** 기록 (10초 유효)
    → 명령 출력의 "# 주석" 같은 줄이 명령으로 잘못 기록되지 않는다
  - 기록 팝업/자동완성으로 줄을 채우면 친 글자가 줄을 설명하지 못하므로 불확실 처리

## 남은 한계
- 프롬프트가 뜨기 전에 입력한 명령(줄에 프롬프트가 없음). 프롬프트 없는 줄을 명령으로 인정하면 `cat` 처럼 입력을 받는 프로그램에 친 내용까지 기록되므로 받아들이지 않는다
- 터미널이 아주 좁아 프롬프트가 깨진 줄은 여전히 인식하지 못할 수 있다 (화면을 읽는 방식의 한계)

## 검증
- 단위 테스트, 타입 체크, 전체 테스트 통과
- 실제 앱 (에코/프롬프트 지연을 넣은 테스트 셸, 서버 실행 로그와 기록 비교)
  - 통과: 기준, 에코 150/400ms 빠른 입력, 30/80ms 보통·빠른 입력, 205자 긴 명령, 비밀번호 줄(비밀번호는 기록 안 됨),
    두 명령/세 명령 typeahead(순서대로, 잘린 항목 없음), 여러 줄 출력("# comment", "foo$ bar" 등 포함) + typeahead 에서 출력 줄 미기록,
    Enter 직후 alternate 화면(vim 흉내)
  - 의도대로: typeahead 중 Tab 을 쓴 명령은 기록하지 않음(불확실)
  - 한계(미기록): 프롬프트 전 입력, 13칸 좁은 터미널의 깨진 첫 프롬프트
  - 자동완성 회귀 42/42
