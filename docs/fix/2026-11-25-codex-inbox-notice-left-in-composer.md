# Codex 입력칸에 남은 받은편지함 알림

안 읽은 메시지가 있는데 Codex 입력칸에 `New ezShell message: read it with read_inbox, then handle it.`가 남았다. 아래에는 `89% context left · ⚠ 1 warning · f2 to view`가 표시됐고, `inspect_agent`는 `idle`과 `draft`, `ours: false`를 반환했다.

별도 ConPTY에서 실제 Codex CLI 0.172.0을 실행해 같은 형식의 경고 바닥줄을 띄웠다. 빈 칸에서 시작한 시험에서는 기존 코드도 Enter를 요청했다. 앱이 붙여 넣은 뒤 CLI 커서를 글 앞에 두고 쉬는 상태로 바꾼 시험에서는 5초 뒤 `ours: false`가 됐다. 커서를 글 끝으로 돌려도 Enter가 가지 않았다. Enter를 CLI에 전달하지 않고 감시를 다시 붙인 시험에서도 같은 문장과 경고가 남은 채 `ours: false`가 됐다. 제보 세션에서 어느 경로로 소유 정보가 사라졌는지는 확인할 수 없었다.

- 기존 감시는 앱이 붙였다는 정보를 메모리에 보관했다. 커서가 글 끝으로 돌아오지 않은 채 5초가 지나면 이 정보를 버리고 사용자 초안으로 돌렸다. 경고 바닥줄이 초안과 바로 이어 그려질 경우에는 본문의 일부로 잘못 읽는 경로도 있었다. 두 화면을 회귀 테스트로 재현했다.
- Codex의 문맥 잔량과 경고 바닥줄은 초안에서 제외한다. 같은 입력칸에 앱이 붙인 문장이 그대로 보이면 잠시 커서가 옮겨도 소유 정보를 유지한다. 감시를 다시 붙인 경우에도 안 읽은 메시지가 있고, 실제 Codex 입력칸에서 고정 알림 세 문장 중 하나가 완전히 일치하며, 앱 Enter나 사용자 입력 뒤로 차단된 상태가 아니면 복구한다. 제출은 현재 커서가 글 끝에 있고 셸 프롬프트·확인 화면·다른 입력 대상이 없을 때 한 번만 한다.
- 쉬는 에이전트의 입력칸에 글이 있고 미독 메시지가 60초 이상 막혀 있으면 그 칸에 안내를 표시하고 PC 알림을 한 번 띄운다. 알림은 초안 내용을 포함하지 않는다. 입력칸이 비거나 미독 메시지가 없어지면 칸의 안내가 사라진다.

수정 후 실제 Codex에서 같은 두 시험을 반복했다. 커서가 돌아오거나 새 감시가 현재 입력칸을 확인했을 때 Enter 요청은 한 번이었고, 입력칸에 문장이 계속 보이는 동안에도 `ours: true`였다. 시험은 PTY로 보내기 직전의 Enter 요청을 기록했다. 숨김 화면 시험에서는 해당 칸의 안내와 앱 알림이 한 번 표시되는 것을 확인했다.

관련 단위 테스트 286개, `local-agent-messages` 화면 검사 166개, `local-agent-chat` 화면 검사 307개, `npm run typecheck`, `npm run build`가 통과했다. Windows에서는 Unix 전용 단위 테스트 1개를 건너뛰었다.
