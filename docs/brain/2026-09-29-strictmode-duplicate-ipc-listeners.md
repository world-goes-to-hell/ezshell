# App.tsx 전역 IPC 리스너는 개발 모드에서 두 번 실행된다

## 증상
탭을 분리했다가 메인 창으로 병합하면, 분리 전에 보관해 둔 접속 설정(`connectConfig`)이 사라졌다.
병합 리스너 안에서 `Map.get()` 후 `Map.delete()` 하도록 짰는데, 병합된 탭에는 설정이 없었다.

## 원인
- `main.tsx`가 `<React.StrictMode>`로 감싸져 있어서, 개발 모드에서는 effect가 두 번 실행된다.
- `App.tsx`의 전역 리스너 등록 effect(`onSshData`, `onSshClosed`, `onTerminalMerge` 등)는
  preload가 돌려주는 해제 함수를 쓰지 않는다(cleanup 없음). 그래서 리스너가 **두 개** 등록된다.
- 첫 번째 리스너가 설정을 꺼내면서 지우고, 두 번째 리스너가 설정 없이 `addTerminal`로 같은 터미널을 덮어썼다.
- 프로덕션 빌드에서는 한 번만 실행되므로 재현되지 않는다. 개발 모드에서만 깨지는 버그라서 헷갈린다.

## 대응
- 이 effect 안의 리스너는 "여러 번 호출되어도 결과가 같게"(멱등) 작성한다. 읽으면서 지우는 코드는 두지 않는다.
- 보관한 값은 탭을 닫을 때(`handleCloseTerminal`) 정리한다.
- 근본적으로는 effect가 해제 함수를 반환해야 하지만, 기존 리스너 전체를 건드리는 변경이라 이번에는 하지 않았다.
