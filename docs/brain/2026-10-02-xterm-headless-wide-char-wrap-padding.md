# headless xterm 에서 줄을 읽을 때: 줄 끝 빈칸과 두 칸 글자

## 증상
세션 로그(`src/sessionLog/lineRecorder.js`)가 좁은 터미널에서 한글이 든 줄을 잘못 기록했다. 두 번 틀렸다.
1. `echo 한글 테스트` 가 `echo 한글  테스트` 로 기록됐다 (공백이 하나 더).
2. 그것을 고치자 `배포-메모.txt` 가 `배포-모.txt` 로 기록됐다 (글자가 빠짐).

단위 테스트(80칸)에서는 둘 다 나오지 않았고, 실제 앱에서 SFTP 패널 때문에 터미널이 13~26칸으로 좁아졌을 때만 나왔다.

## 원인
터미널 너비를 넘는 줄은 여러 행(row)에 걸치고, 다음 행의 `isWrapped` 가 true 다. 논리적인 한 줄은
앞 행들을 `translateToString(false)` 로, 마지막 행을 `translateToString(true)` 로 읽어 이어 붙인다.
앞 행을 자르지 않고 읽는 이유는 줄바꿈 위치의 진짜 공백을 지키기 위해서다.

두 칸 글자(한글, 한자)가 마지막 한 칸에 들어가지 못하면 xterm 은 그 칸을 비워 두고 글자를 다음 행으로 내린다.
이 빈칸이 `translateToString(false)` 에서 공백으로 나온다 → 증상 1.

빈칸을 "글자가 없는 마지막 셀"로만 판별하면, 두 칸 글자가 행 끝에 **정확히 들어맞은** 경우의 뒤쪽 반 칸도
글자가 없는 셀이라서 같이 걸린다. 그 상태에서 마지막 글자를 잘라 내면 멀쩡한 글자가 사라진다 → 증상 2.

| 마지막 셀 | `getChars()` | `getWidth()` |
|---|---|---|
| 채워지지 않은 빈칸 (밀려난 자리) | `''` | 1 |
| 두 칸 글자의 뒤쪽 반 칸 | `''` | 0 |
| 입력된 공백 | `' '` | 1 |

## 해결
앞 행의 마지막 셀이 `getChars() === '' && getWidth() === 1` 이고, 다음 행의 첫 셀이 `getWidth() === 2` 일 때만
마지막 한 글자(공백)를 뺀다.

줄 끝 공백은 따로 `trimEnd()` 한다. `translateToString(true)` 는 채워지지 않은 셀만 잘라 내고,
글자를 지우며 덮어쓴 공백(`\b \b`)은 남긴다.

## 교훈
- 너비에 따라 달라지는 동작은 한 가지 너비로 테스트하지 않는다. 지금은 10~16칸을 모두 돌린다
  (`keeps every wide character whatever column the line wraps at`).
- 실제 앱의 터미널은 생각보다 좁을 수 있다. 접속 직후 SFTP 패널이 열리면 작은 창에서는 13칸까지 줄어든다.
- 한글이 든 출력으로 확인한다. 영문만으로는 두 칸 글자 문제가 보이지 않는다.

## 함께 알아 둘 것
- 직접 만든 필터(제어 문자 제거 + 백스페이스 처리)로는 긴 명령줄이 깨진다. readline 은 오른쪽 끝에서
  `공백 + CR` 을 보내 줄을 넘기는데, 너비를 모르면 CR 이후 글자가 줄 맨 앞을 덮어쓴다.
- `onLineFeed` 는 xterm 의 타이머 안에서 실행된다. 여기서 던진 예외는 `term.write()` 를 부른 쪽의
  try/catch 에 잡히지 않고 main 프로세스의 uncaught exception 이 된다.
