# Claude 의 AskUserQuestion 화면을 키로 다룰 때의 함정

2026-11-23, 채팅 카드로 답하기(`src/ipc/claudeQuestions.js`)를 실제 Claude Code(2.1.3xx)에 붙여 보며 겪은 것. 가짜 화면 테스트는 모두 통과했는데 실제 CLI 에서만 드러났다.

## 1. 안내 줄이 두 줄로 접힌다
- 맨 아래 `Enter to select · Tab/Arrow keys to navigate · Esc to cancel` 이 칸 폭(48열 등)에 따라 두 줄이 된다. 직접 입력 칸에 있으면 `ctrl+g to edit in Notepad ·` 가 끼어 더 길어진다.
- 접히는 자리가 매번 다르다: `… navigate · ` / `Esc to cancel`, `… · Esc ` / `to cancel`. 앞 줄 끝에 공백이 남아서, 그대로 이으면 `Esc  to cancel`(두 칸)이 되어 정규식이 맞지 않았다.
- 처리: 앞 줄은 `trimEnd()`, 뒷줄은 `trim()` 한 뒤 공백 하나로 잇는다. `agentInboxWake.claudeQuestionPrompt` 도 같은 이유로 접힌 안내를 받게 했다 (예전에는 좁은 칸에서 질문 화면을 알아보지 못했다).

## 2. 직접 입력은 입력칸이 켜진 뒤에 쳐야 한다
- `↓` 로 `Type something` 줄에 선택 표시가 간 직후 글자를 보내면 버려진다. 표시는 먼저 그려지고 입력칸은 조금 뒤에 켜진다.
- 켜졌다는 표시는 안내 줄의 `ctrl+g to edit in …` 이다. 이것이 보인 뒤(없는 버전이면 1초 상한) 화면이 멎으면 친다.

## 3. 낮은 칸에서는 질문 문장이 위로 밀려난다
- 18줄 칸에서 선택을 아래로 옮기면 목록이 스크롤되어 탭 줄과 질문 문장이 화면 밖으로 나간다. 질문 문장으로만 "같은 질문인가" 를 보면 거기서 멈춘다.
- 처리: 탭 줄이 없으면 안내 줄 위 마지막 `1.` 부터 선택지를 읽고, 선택지 이름이 모두 같을 때만 같은 질문으로 본다.
- 2026-11-24 보강: 이름이 맞는 질문이 이번 묶음 안에서 **정확히 하나**일 때만 인정한다. 질문마다 같은 선택지(예/아니오, `A) … (Recommended)` 등)를 쓰면 제목이 밀려난 칸에서는 어느 질문인지 알 수 없어, 예전에는 다음 질문을 앞 질문으로 오인해 숫자를 보냈다 (모의 화면 90×18 에서 재현). 대가로 그런 연속 질문은 낮은 칸에서 터미널로 넘어간다. 최종 검토 화면(`Review your answers`)을 읽지 못하면 제출하지 않고 `stuck` 이다 (예전에는 제출 없이 성공으로 보고했다).

## 4. 숫자 키의 뜻이 질문 종류마다 다르다
- 단일 선택: 고르고 바로 다음 질문(질문이 하나뿐이면 바로 제출).
- 여러 개 고르기: 체크만 토글하고 선택 표시(`❯`)는 옮기지 않는다. 그래서 숫자 뒤에 친 글자는 직접 입력으로 가지 않는다.

## 5. 미리보기(preview)가 달린 질문은 화면 모양과 키가 다르다 (2026-11-23 사용자 보고)
- 사용자 보고 내용: 채팅에 카드도 대기 표시도 나오지 않았고, 입력칸이 보였지만 보낼 수 없었다. 원인은 앱이 이 질문 화면을 질문으로 알아보지 못한 것이다.
- **줄 잇기 함정:** Claude 는 구분선과 미리보기 상자 줄을 칸 끝까지 공백으로 채운 뒤 줄바꿈 없이 다음 줄을 그린다. 그래서 터미널이 다음 줄에 "접힌 줄(isWrapped)" 표시를 붙인다. `agentInboxWake` 는 접힌 줄을 앞줄에 이어 붙이는데, 그러면 탭 줄(`☐ 머리말`)이 구분선 뒤에 붙고 선택지 줄끼리도 붙어서 질문을 찾지 못했다.
  - 처리: 앞줄의 글자가 오른쪽 끝(마지막 두 칸)까지 닿을 때만 잇는다. 구분선 뒤에는 잇지 않는다.
- **화면 모양:** 선택지 오른쪽에 고른 선택지의 미리보기가 상자(`┌─┐`)로 그려진다. 긴 선택지 이름은 다음 줄에 이어지고(`(Recommended)`), 설명과 `Type something` 줄은 없다. `Chat about this` 에는 번호가 없다.
  - 처리: 드라이버(`claudeQuestions.js`)가 상자가 시작되는 자리부터 줄을 자른다. 이어진 이름은 `more` 에 붙여 함께 비교한다.
- **키 동작:** 숫자는 선택 표시만 옮긴다(미리보기가 바뀐다). Enter 가 고른다. 그래서 숫자 → 표시 이동 확인 → Enter 순서로 누른다. 직접 입력은 없다(카드에서도 숨기고, main 의 `cleanAnswer` 도 거부한다).
- 확인한 칸: 110×30, 64×26 (64칸에서는 안내 줄이 두 줄로 접힌다).

## 6. 플러그인 알림 상자가 질문 문장을 덮는다 (2026-11-27 사용자 보고, 반복된 문제)
- 이 PC 의 ko-ui 알림 상자(`╭──╮ / │ ko-ui … │ / ╰──╯`)가 칸이 낮으면 대화 상자 오른쪽 위에 겹친다. 예전에는 `startsWith` 로 "같은 줄 뒤에 붙은 글자" 만 견뎠다.
- 놓친 것 두 가지: 아래 테두리 `╰──╯` 만 있는 줄이 탭 줄 아래 빈 줄에 오면 질문 문장의 첫 줄로 읽혔다. 상자가 질문 문장 줄의 끝을 덮으면 문장 일부가 아예 보이지 않는다. 카드는 첫 답 뒤에 멈추고, 채팅은 카드를 띄우지 못했다.
- 처리: 줄 끝의 상자 조각을 먼저 떼고(`src/ipc/cliOverlayBox.js`), 가려진 문장은 남은 조각이 차례대로 맞는지와 선택지 이름으로 맞춘다 (묶음에서 하나일 때만).
- 왜 어려웠나: 가짜 대화 상자는 높이와 무관하게 늘 같은 모양이라 시험이 다 통과했다. 상자는 칸 높이(110×30 은 대화 위, 110×20 은 질문 위)에 따라 놓이는 자리가 달라서, 실제 CLI 로 여러 높이를 돌려 봐야 드러났다. 실제 CLI 재현 스크립트 모양: `node-pty` 로 `claude.exe --model haiku "<AskUserQuestion 을 이 JSON 으로 한 번 부르라>"` 를 띄우고 `@xterm/headless` 화면에 `createClaudeQuestionAnswerer` 를 붙인다. Electron 을 node 로 실행한다 (`ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe`, node-pty 가 Electron ABI 로 빌드돼 있다).
- 같은 재현에서 낮은 칸(90×18, 80×16)의 검토 화면에 `↑ N more lines` 가 생기고 제목이 밀려나는 것도 드러났다.

## 그 밖
- 확인 방법: `node-pty` + `@xterm/headless` 로 실제 `claude --model haiku "<AskUserQuestion 을 부르라는 지시>"` 를 띄우고 칸 크기(`cols`·`rows`)를 바꿔 가며 드라이버를 붙였다.
