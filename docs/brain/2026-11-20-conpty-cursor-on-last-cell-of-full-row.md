# ConPTY 는 줄을 꽉 채운 뒤 커서를 마지막 칸 위에 둔다

2026-11-20, 에이전트 메시지 알림 문장을 짧게 바꾼 뒤 화면 테스트 `local-agent-messages` 의 "작업 중 알림" 이 매번 실패했다.

## 증상

- 알림 문장은 입력칸에 그대로 그려졌는데 Enter 가 가지 않았다. 판정 기록: 입력칸 글자는 일치(`text` 같음), `endsAtCursor: false`.
- 단위 재현(headless xterm 에 화면을 직접 씀)에서는 어떤 폭에서도 통과했다. 문장을 예전(171자) 것으로 되돌리면 화면 테스트도 통과했다.

## 원인

- `> ` 와 새 문장(103자)이 시험 칸의 폭(105칸)과 정확히 같았다.
- headless xterm 은 줄을 꽉 채우면 커서를 줄 밖(`cursorX === cols`, 줄바꿈 대기)에 둔다. 그래서 직접 쓴 재현에서는 "커서 뒤가 비었다".
- Windows ConPTY 는 줄바꿈 대기 상태를 표현하지 못해서, 화면을 다시 그릴 때 커서를 마지막 칸(`cols - 1`)으로 옮겨 보낸다. 앱은 마지막 글자가 커서 뒤에 남았다고 보고 "쓰는 중인 글" 로 판정했다.

## 수정과 교훈

- `agentInboxWake.js` 의 `composer()`: 커서가 마지막 칸에 있고 그 뒤가 글자 한 칸뿐이면(줄이 꽉 참) 끝으로 본다 (`fillsRow`). 붙인 글과 입력칸 글이 같은지 볼 때만 쓰이는 값이라 안전하다.
- 실제 에이전트에서도 칸 폭과 글 길이가 맞아떨어지면 생긴다 (채팅 보내기도 같은 판정).
- 터미널 화면 판정을 단위 테스트로만 확인하지 말 것: 직접 쓴 바이트와 ConPTY 를 거친 바이트는 커서 위치가 다르다. 커서 위치에 기대는 판정은 "줄을 꽉 채운 경우" 를 따로 시험한다 (`agentInboxWake.test.js` 의 ConPTY 시험).
