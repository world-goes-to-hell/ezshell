# Bash heredoc 으로 넘긴 node 스크립트로 소스를 고치면 자주 깨진다

## 증상
같은 날 세 번 겪었다. 모두 `node - <<'EOF' ... EOF` 안에서 문자열을 찾아 바꾸는 스크립트였다.

1. 테스트 소스에 `'a\r\n'` 을 넣으려 했는데 실제 줄바꿈이 들어가 문법 오류가 났다.
   `describe('... the test\'s control'` 도 따옴표가 풀려 문법 오류가 났다.
2. 스크립트에 작은따옴표·백틱·`\\n` 이 섞이자 bash 가 `unexpected EOF while looking for matching` 으로 실행 자체를 거부했다.
3. 찾을 문자열에 `\n` 을 넣었는데 대상 파일이 CRLF 여서(또는 LF 와 섞여 있어서) "anchor not found" 가 났다.
   `cat >> file` 로 덧붙인 부분은 LF 라서 한 파일 안에 줄 끝이 섞였다.

## 원인
- 도구 호출 인자 → bash → heredoc → node 템플릿 문자열로 가는 동안 백슬래시가 어느 단계에서 한 번 풀리는지
  눈으로 따지기 어렵다. `\\r\\n` 이 `\r\n`(문자 4개)이 될지 실제 CR LF 가 될지 실행해 봐야 안다.
- 이 저장소에는 CRLF 파일과 LF 파일이 섞여 있다 (`src/mcp/*.js` 는 LF, 일부 렌더러 파일은 CRLF).

## 해결
- 한두 곳 수정은 편집 도구(Edit)를 쓴다. 줄 끝을 알아서 맞춘다.
- 여러 곳을 한 번에 고쳐야 하면 스크립트를 **파일로 먼저 쓰고**(Write) `node 파일` 로 실행한다.
  Write 로 쓴 내용은 적은 그대로 저장되므로 백슬래시를 한 단계만 생각하면 된다.
- 스크립트에서 찾을 문자열에 줄바꿈이 들어가면, 대상 파일의 줄 끝을 먼저 확인하거나 한 줄짜리 문자열만 찾는다.
- 바꾼 뒤에는 해당 줄을 `sed -n` 이나 grep 으로 직접 확인한다. "updated" 출력만 믿지 않는다.
- 찾지 못하면 조용히 넘어가지 않고 예외를 던지게 한다 (이번에도 이 덕분에 잘못된 상태로 진행하지 않았다).
