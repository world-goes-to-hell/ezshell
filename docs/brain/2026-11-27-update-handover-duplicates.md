# 업데이트 인계에서 같은 것이 둘씩 보이는 문제가 반복된다

업데이트 인계는 서로 따로 움직이는 세 부분으로 되어 있다. 하나가 실패해도 나머지는 계속 진행된다.

1. 세션 보관 프로세스가 셸을 넘긴다(`localShells.adopt`).
2. 에이전트 인계 기록이 에이전트를 넘긴다(`agentMessages.importHandoff`).
3. 탭 복원이 탭을 다시 연다(`restore-tabs`, `local-shell-kept-layout`).

같은 대상이 둘씩 보인 사례는 모두 이 셋이 서로 다른 결과를 냈을 때 생겼다.

- 2026-11-26: 보관 프로세스는 셸을 넘겼는데 창이 그 사실을 늦게 알았다. 복원 안내 줄이 같은 탭을 한 번 더 열었다 (`docs/fix/2026-11-26-kept-shells-after-update.md`).
- 2026-11-27: 에이전트 인계는 성공했는데 보관 프로세스는 새로 떠서 셸이 없었다. 옛 에이전트가 번호가 겹친 새 탭에 한 번 더 붙었다 (`docs/fix/2026-11-27-ghost-agents-after-update.md`).

이 문제를 바로 찾기 어려웠던 이유는 다음과 같다.

- `list_agents` 는 연결된 에이전트만 보여 줘서 정상으로 보인다. 화면용 스냅숏(`agent-messages-state`)에만 유령이 남는다.
- 보관 프로세스가 왜 새로 떴는지 남는 기록이 없다. 프로세스의 생성 시각(`Get-CimInstance Win32_Process`)과 `%TEMP%\ezshell-agent-*` 폴더의 생성 시각을 비교해야, 셋 가운데 어느 것이 성공했는지 가릴 수 있다.

앞으로 인계를 고칠 때는 "셋 가운데 하나만 성공한 경우"마다 나머지 둘이 그 결과에 맞춰 정리되는지 확인한다. 셸 번호(`local:N`)는 새 앱에서 다시 1부터 매겨질 수 있으므로, 셸 ID 로 무언가를 이어 붙일 때는 그 셸이 정말 이번에 넘어온 셸인지 확인한다.
