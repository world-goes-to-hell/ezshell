# 에이전트 상태는 CLI 가 터미널에 쓰는 제목·신호에서 온다: 추측하지 말고 기록해서 본다

로컬 터미널의 Claude Code·Codex 상태(작업 중, 대기, 응답 필요)는 앱이 묻는 것이 아니라 CLI 가 pty 로 쓰는 OSC 0/2(제목), OSC 9;4(진행 막대), OSC 7501(상태 보고)을 읽어 정한다 (`src/localShell.js` 의 `trackAgentActivity`). CLI 가 업데이트로 제목 모양을 바꾸면 앱 코드가 그대로여도 판정이 틀어진다.

- 2026-11-19: Claude Code 가 작업 중 스피너를 점자(⠋)에서 반원(◐◑)으로 바꾼 상태였고, 상태 보고(7501)는 보내지 않아 늘 "대기"로 나왔다. 코드만 읽어서는 의심 지점이 세 군데였고, 실제로 기록하고 나서야 하나로 좁혀졌다 (`docs/fix/2026-11-19-claude-agent-status-always-idle.md`).
- 사용자 화면의 상태가 맞는지 볼 때는 그 순간 에이전트가 실제로 무엇을 하고 있었는지도 본다 (같은 화면의 Codex "대기"는 맞는 표시였다).

기록하는 법: node-pty 로 빈 임시 폴더에서 CLI 를 띄우고, 7501 `?` 질의에는 앱과 같은 답(`PROGRAM_STATUS_REPLY`)을 보내고, 짧은 질문 하나를 보낸 뒤 OSC 를 시각과 함께 남긴다. Claude 의 폴더 신뢰 질문은 "No, exit" 가 기본이라 Enter 만 누르면 끝난다 (아래 화살표 뒤 Enter). `--strict-mcp-config` 로 사용자 전역 MCP 를 끈다: 켜 두면 전역 `ezshell-cli-mcp` 가 실제 사용자 데이터 폴더의 연결 파일을 보고 실행 중인 사용자 앱에 붙는다. Claude Code 세션 안에서 실행하면 `CLAUDE*` 환경 변수를 뺀다. 임시 프로필 앱에 직접 입력한 에이전트는 전역 메시지 MCP 설정이 없어 앱에 등록되지 않는다 (그 경로로는 재현되지 않는다).
