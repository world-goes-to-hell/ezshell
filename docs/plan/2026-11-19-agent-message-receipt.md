# 에이전트 메시지 수신 확인 답장

날짜: 2026-11-19
상태: 구현 완료 (2026-11-19 승인, 커밋 전). **2026-11-20 에 없앴다** (사용자 결정): 수신 확인 대신 받는 쪽이 `read_inbox` 로 가져가면 읽음(`seenAt`)이 되고, 보낸 쪽은 `check_sent` 로 안 읽음·읽음·처리함을 본다. 지금 규칙은 CLAUDE.md 의 MCP 절과 `src/ipc/agentMessageRead.test.js`.

## 결과

- `send_receipt` 도구, 수신 확인 표지, 작업 중 알림, 끝난 뒤 다시 알림을 넣었다. `localShell.js` 는 깨우기에 `unhandledMessages`·`isRunningTask` 두 값을 넘기는 부분만 고쳤다.
- 계획에 더한 것: 작업 중 알림은 상태가 `working` 일 때만 넣는다. 기존 `isWorking` 은 시작 중·확인 대기·모름에서도 참이라, 그때 넣으면 쉬고 있는 에이전트에게 "작업 중" 문장이 갈 수 있었다. 그리고 수신 확인은 받는 쪽을 깨우지 않고 읽으면 바로 읽음이 되며 수신 확인에는 답장할 수 없게 했다. 그러지 않으면 두 에이전트가 확인을 끝없이 주고받거나 같은 확인이 받은 편지함의 미확인 목록에 계속 표시된다.
- Codex: 이 PC 의 0.170.0 은 `followUpQueueMode = "queue"` 이고 `steer` 기능이 removed 로 나온다. 작업 중 입력은 그 턴이 끝난 뒤에 처리되므로, Codex 의 작업 중 수신 확인은 그때 간다. Claude Code 는 진행 중인 작업에 끼워 넣어 바로 답한다.
- 시험: 단위 `agentMessageReceipt.test.js` 4개, `agentInboxWake.test.js` 12개(작업 중 알림, 사용자 입력 보호, 시작 중 대기, 다시 알림 한 번, 답한 요청은 다시 알리지 않음), 화면 테스트 `local-agent-messages` 통과.

## 목표

`ezshell-cli-mcp` 로 메시지(작업 요청)를 받은 에이전트가 받자마자 보낸 쪽에 짧은 답장을 보낸다.

- 쉬고 있을 때: "작업 할당 받았습니다" 같은 답장을 보낸 뒤 작업을 시작한다.
- 작업 중일 때: "지금 ○○ 작업 중이라, 마무리한 뒤 이어서 하겠습니다" 같은 답장을 보내고, 하던 일을 끝낸 뒤 요청을 처리한다.

## 지금 동작 (2026-11-19 확인)

- `agentInboxWake.js` 는 받는 에이전트가 입력을 기다리고(`!isWorking()`) 입력칸이 비어 있을 때만 안내 문장(`PROMPT`)을 붙여 넣고 Enter 를 보낸다. 작업 중에는 아무것도 넣지 않는다. 그래서 작업 중인 에이전트는 하던 일이 끝날 때까지 메시지를 모른다.
- 안내 문장과 MCP 설명(`agentMessageMcp.js` 의 `instructions`, 도구 설명)에는 "받은 즉시 답하라"는 규칙이 없다. 답장은 작업이 끝난 뒤의 결과 답장 하나뿐이다.
- `reply_to_message` 는 원래 메시지를 읽음으로 바꾼다. 읽음이 된 메시지에도 다시 답장할 수 있다 (`deliver` 는 읽음 여부를 보지 않는다).

## 설계

1. **수신 확인 도구 `send_receipt`** (`agentMessageMcp.js`, `agentMessages.js`): `message_id`, `text` 를 받아 보낸 쪽에 답장하되, 메시지에 `receipt: true` 를 붙이고 원래 메시지를 읽음으로 바꾸지 않는다. 원래 메시지는 결과 답장(`reply_to_message`)을 보낼 때 읽음이 된다. 받은 쪽이 확인만 하고 처리를 잊으면 메시지가 계속 안 읽음으로 남아 화면과 다음 안내로 드러난다.
2. **작업 중에도 알림** (`agentInboxWake.js`): 작업 중에 새 메시지가 오면 "작업 중 알림" 문장을 붙여 넣고 Enter 를 보낸다. Claude Code 는 작업 중에 입력한 메시지를 진행 중인 작업에 끼워 넣어 전달하므로, 하던 일을 멈추지 않고 확인 답장을 보낼 수 있다. 입력칸에 사용자가 쓰던 글이 있으면 지금처럼 넣지 않는다.
3. **안내 문장 두 가지**: 쉴 때는 "read_inbox 로 읽고 send_receipt 로 바로 받았다고 답한 뒤 처리하라", 작업 중에는 "read_inbox 로 읽고 send_receipt 로 지금 하는 일과 끝난 뒤 이어서 하겠다고 답한 뒤, 하던 일을 마치고 처리하라". 답장은 받은 메시지의 언어로 쓰게 한다. 같은 규칙을 MCP `instructions` 와 `read_inbox` 설명에도 적는다 (안내 문장을 놓친 경우에도 지키게).
4. **끝난 뒤 다시 알림**: 작업 중에 알렸던 메시지가 그 작업이 끝난 뒤에도 안 읽음이면, 입력을 기다리는 상태가 되었을 때 쉴 때 문장을 한 번 더 넣는다.
5. **보낸 쪽**: `read_inbox` 결과에는 `receipt: true` 가 보인다. 에이전트는 결과가 도착했다는 알림을 받으면 받은 편지함을 확인한다. 앱의 메시지 화면에는 수신 확인을 작은 표지로 구분한다. 2026-11-20에 MCP의 대기 도구를 제거하고 이 흐름으로 안내를 정리했다.

## 위험과 확인할 것

- **Codex 의 작업 중 입력**: Claude Code 는 작업 중 입력을 진행 중인 작업에 끼워 넣는다 (지금 이 대화에서도 그렇게 동작한다). Codex 는 버전에 따라 작업 중 입력을 그 작업이 끝난 뒤에 처리할 수 있다. 그러면 Codex 의 작업 중 확인 답장은 하던 일이 끝난 뒤에야 간다. 구현할 때 실제 Codex 로 확인하고, 늦게 가면 그 사실을 문서에 적는다.
- **작업 중 붙여 넣기의 안전**: 지금 코드는 붙여 넣은 문장이 입력칸에 그대로 그려졌는지 확인한 뒤 Enter 를 보낸다. 작업 중에도 이 확인을 그대로 거친다. 사용자가 입력 중이면 넣지 않는 규칙도 유지한다.
- **다른 세션과 겹침**: 에이전트 메시지 영역(`localShell.js`, `e2e/specs/local-agent-messages.js`, `e2e/support/localAgent*.js`)을 다른 세션이 커밋하지 않은 채로 고치고 있다. 그 변경이 커밋된 뒤에 시작하거나, 시작 전에 그 세션과 맞춘다.

## 시험

- 단위: 작업 중 새 메시지에 작업 중 문장을 넣는지, 사용자가 입력 중이면 넣지 않는지, 끝난 뒤 한 번 더 알리는지, `send_receipt` 가 원래 메시지를 안 읽음으로 두는지, 결과 답장이 읽음으로 바꾸는지.
- 화면 테스트: 가짜 에이전트가 작업 중일 때 메시지를 보내 작업 중 문장이 들어가는지, 수신 확인 표지가 보이는지.
