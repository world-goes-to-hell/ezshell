# MCP 명령 확인 창에 요청 사유 표시

- 날짜: 2026-10-23
- 상태: 구현 완료

## 문제

MCP 확인 창에는 명령, 위치, 위험도만 보여서 Claude 가 왜 그 명령을 실행하려는지 알 수 없다. 사용자는 앞뒤 대화를 보러 Claude Code 창으로 가야 판단할 수 있다.

## 결정 사항

1. `run_command` 와 `cd` 에 `reason`(요청 사유, 최대 500자) 인자를 추가한다.
2. 사용자 확인이 필요한 명령(위험도와 알림 수준으로 판정, 백그라운드 작업은 항상)인데 `reason` 이 비어 있으면, 확인 창을 띄우지 않고 거부한다. 거부 메시지에서 사유를 적어 다시 요청하라고 안내한다.
   스키마에서는 필수로 두지 않는다. 확인이 필요한지는 앱의 판정과 알림 수준으로 정해지므로 Claude 가 미리 알 수 없고, 조회 명령마다 사유를 강요할 이유가 없다. 대신 도구 설명에서 서버 상태를 바꾸는 명령에는 항상 적으라고 안내한다.
   이 거부는 입력 오류로 다루어 감사 로그와 활동 패널에 남기지 않는다 (명령도 실행되지 않고 확인 창도 뜨지 않았다).
3. 사유는 제어 문자를 공백으로 바꾸고 공백을 하나로 줄인 뒤 앞뒤를 자르고 500자까지만 쓴다 (`tools.js` 의 `cleanPurpose`). 스키마는 2,000자까지 받는다 (조금 넘었다고 호출 전체가 실패하지 않게).
4. 확인 창에는 "요청 사유" 를 명령 위에 보여 주고, "Claude 가 직접 적은 설명이라 실제 명령과 다를 수 있습니다. 명령을 기준으로 판단하세요." 라고 알린다. 보이지 않는 문자는 명령처럼 드러내고 경고한다.
   사유는 프롬프트 인젝션 등으로 거짓일 수 있으므로 판단 근거는 어디까지나 명령이다.
5. 감사 로그에는 사유를 남긴다 (나중에 왜 실행했는지 확인할 수 있게). Windows 알림에는 넣지 않는다 (알림 센터에 남는다).
6. 내부 필드 이름은 `purpose` 로 한다. 확인 요청에 이미 있는 `reasons`(위험도 판정 이유)와 헷갈리지 않게 하기 위해서다.
7. 파일 쓰기와 파일 전송 도구는 이번 범위에 넣지 않는다 (확인 창이 변경 내용과 경로를 보여 주므로).
