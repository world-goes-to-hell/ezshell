# 분할 터미널 칸 끌어 옮기기·탭으로 빼기

작성일: 2026-11-17
상태: 진행 중 (2026-11-17 사용자 승인, 빼낸 탭은 온전한 세션이어야 한다는 수정 반영)
구분: 큼 (main 의 SSH 연결 수명 주기를 건드린다)

## 목표

- 분할된 칸의 위쪽 가장자리에 포인터가 가면 `⋯` 손잡이가 나타나고, 끌어서 다른 칸과 자리를 바꾼다.
- 손잡이를 탭 줄에 놓으면 그 칸의 셸이 **끊기지 않고 그대로** 새 탭이 된다 (사용자 요구).
- 탭으로 빠져나간 자리는 빈 칸으로 남고, `가로로 병합` / `세로로 병합` 버튼으로 옆 칸이 그 자리를 채운다.
- 로컬 터미널 탭에도 화면 분할을 넣는다 (사용자 확인: 분할이 안 되는 것이 문제).

## 지금 구조

- 탭 = SSH 연결 하나(`sshConnections[sessionId]`). 분할 칸의 셸은 그 연결에 추가로 연 채널이고 id 는 `<sessionId>:split-...` (`sshStreams`).
- 탭을 닫으면(`ssh-disconnect`) 연결을 끝내고 그 탭의 분할 채널을 모두 닫는다.
- 칸 배치는 `splitDirection`(2분할·quad·tri 4종) + `splitSlots` 를 `TerminalPanel` 이 경우별로 grid 위치에 적어 둔 것이다. 감싸개 `w-split-1/2/3` 은 key 가 고정이라 배치가 바뀌어도 셸이 유지된다.
- 분할 칸의 xterm 과 채널은 `SplitTerminal` 이 갖고, 언마운트될 때 채널을 닫는다.

## 설계

### 1. 배치 모델 (`lib/splitGrid.ts`, 순수 함수)
- 2x2 격자에서 칸마다 사각형(행·열·걸친 수)을 갖는 배치로 바꾼다. 기존 `splitDirection`/`splitSlots` 에서 만들어 낼 수 있어 저장 형식은 그대로 두고, 자리 바꿈·빈 칸만 `TerminalInfo` 에 더한다 (`paneOrder`, `vacantPanes`).
- 함수: 배치 만들기, 두 칸 자리 바꾸기, 칸 비우기, 빈 칸을 가로/세로로 병합(옆 칸과 합친 모양이 사각형일 때만 가능), 칸이 하나 남으면 분할 해제.
- `TerminalPanel` 은 경우별 조건문 대신 이 배치로 감싸개의 grid 위치를 정한다. 감싸개 key 와 트리 위치는 바꾸지 않는다 (바꾸면 셸이 닫힌다).

### 2. 손잡이와 자리 바꾸기
- 칸 위쪽 가운데의 `⋯` 손잡이 (칸 위 가장자리 근처에 포인터가 있을 때만 보임). 손잡이만 끌 수 있다.
- HTML5 끌기, 형식 `application/x-ezshell-term-pane` (탭 id + 칸 id). 같은 탭의 다른 칸에 놓으면 자리 바꿈.
- 화면 배치만 바뀌므로 셸은 그대로다. 바뀐 뒤 각 칸의 크기를 서버에 다시 알린다.

### 3. 탭으로 빼기 (셸 유지, 온전한 세션 탭)
사용자 확인(2026-11-17): 빼낸 탭도 하나의 세션이므로 SFTP·분할·로그 저장·탭 복제·창 분리가 모두 되어야 한다. 그래서 별도 탭 종류를 만들지 않고 **일반 SSH 탭**으로 만든다.
- main `ssh-adopt-split`(본창만, 인자는 살아 있는 분할 채널 id 하나): 새 세션 id 를 만들고 `sshConnections[새 id] = { conn(원래 탭과 같은 객체), stream(그 채널), jumpConn }` 으로 등록한다. 채널의 분할용 처리기를 떼고 주 셸과 같은 처리기(출력 → `ssh-data`, 로그, 종료·재연결 판단)를 붙인다. 접속 설정과 재연결 상태는 원래 탭 것을 복사한다.
- 연결 공유: 같은 `conn` 을 쓰는 세션이 남아 있으면 탭을 닫아도 연결을 끝내지 않고 그 탭의 채널만 닫는다. 마지막 세션이 닫힐 때 연결(점프 호스트 포함)을 끝낸다. `conn.end()` 를 부르는 모든 곳(탭 닫기, 지금 재연결, 자동 재연결, 종료)을 같은 함수로 모은다.
- 연결이 끊기면 세션마다 자기 채널의 종료를 보고 자동 재연결한다. 재연결한 뒤에는 각자 자기 연결을 갖는다.
- 화면 내용: main 이 넘겨준 뒤, 옛 칸의 xterm 이 받은 출력을 다 그릴 때까지 기다렸다가 `xterm-addon-serialize` 로 뜬다. 그 글자를 새 세션의 출력 버퍼 맨 앞에 넣고 탭을 만든다 (그 사이 온 출력은 스토어의 `sshDataBuffers` 가 뒤에 쌓는다).
- `SplitTerminal` 은 넘겨준 채널을 언마운트 때 닫지 않는다.
- 탭의 주 터미널 칸은 탭 자체라서 빼기 대상이 아니다 (자리 바꾸기만).

### 4. 빈 칸과 병합
- 칸을 빼면 그 자리에 빈 칸 카드(`가로로 병합`, `세로로 병합`)가 남는다. 사각형이 되지 않는 방향의 버튼은 비활성.
- 2분할에서 하나를 빼면 고를 것이 없으므로 바로 분할을 해제한다.

### 5. 로컬 터미널 분할
- 칸마다 이 PC 의 셸 하나. 전체 10개 제한 유지.

## 바꾸면 안 되는 것 (구현 때 지킬 것)
- `ssh-adopt-split` 은 본창에서 온 것만, 이미 있는 채널 id 만 받는다. 창이 연결이나 주소를 지정하지 않는다.
- 함께 쓰는 연결은 마지막 세션이 닫힐 때 반드시 끝낸다 (주인 없는 SSH 연결이 남으면 안 된다). 앱 종료·잠금 경로도 확인한다.
- 감싸개 key·트리 위치 고정 (2026-10-01 버그).

## 단계
1. 배치 모델 + 손잡이 + 자리 바꾸기
2. 탭으로 빼기 (main 연결 공유, 넘겨주기) + 빈 칸·병합
3. 로컬 터미널 분할

## 테스트·검증
- `splitGrid` 단위 테스트 (기존 7개 배치와 같은 위치가 나오는지, 자리 바꿈, 비우기, 병합 가능 판정).
- main 의 연결 수명 판단은 순수 함수로 빼서 단위 테스트 (탭 셸이 남으면 유지, 마지막이 닫히면 종료).
- 실제 sshd 로 E2E: 4분할 → 자리 바꿈 뒤 셸 유지, 칸을 탭으로 뺀 뒤 실행 중이던 명령이 이어지는지, 원래 탭을 닫아도 탭 셸이 사는지, 마지막 탭 셸을 닫으면 서버에서 연결이 사라지는지.

## 변경 (2026-11-17): 분할 방식이 "칸을 다시 나누기" 로 바뀜

사용자가 다른 세션에서 목업(`terminal-split-by-pane`)을 승인했다: 우클릭한 칸만 좌우·상하로 나누고, 나눈 칸을 또 나눌 수 있다 (칸 6개까지). 그래서 위 설계의 2x2 격자 모델(`lib/splitGrid.ts`)은 버리고 **분할 트리**(`lib/splitTree.ts`)로 다시 짰다. 위 1·4절의 격자 설명은 아래로 대체한다.

- 모델: 잎은 칸(또는 빈 자리), 안쪽 노드는 나눔(`row` 좌우 / `col` 상하)과 비율. 칸 id 는 `main`, `split-<번호>` 이고 번호는 탭 안에서 다시 쓰지 않는다 (`TerminalInfo.paneSeq`).
- 그리기: 모든 칸·구분선·손잡이는 분할 영역의 평평한 자식이고, 트리에서 계산한 사각형으로 `position: absolute` 배치한다. 칸 감싸개의 key(`w-<칸 id>`)와 문서 안 순서(id 순)는 배치와 무관하게 고정이다.
- 메뉴(`분할`): `좌우 분할`, `상하 분할`, `칸 크기 균등화`, `이 칸 닫기`. `4분할`·`분할 해제` 와 구분선 우클릭 병합은 없앴다. 우클릭한 칸은 감싸개의 `data-pane` 으로 안다.
- 제한: 칸 6개(`MAX_PANES`), 나눈 뒤 20칸·5줄 미만이 되는 방향은 비활성(메뉴 글자에 이유), 탭의 첫 터미널은 닫을 수 없다.
- 균등화: 같은 방향으로 나란한 칸 수에 맞춘다 (세 칸은 1/3 씩). 구분선을 두 번 누르면 그 선만.
- 빈 자리 병합(`mergeVacant`): 함께 나뉘었던 쪽은 항상 가능하고, 다른 방향은 두 나눔이 2x2 블록처럼 맞물릴 때만 블록을 반대로 다시 나눠서 한다.
