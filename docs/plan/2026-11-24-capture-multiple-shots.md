# 영역 캡처를 여러 장 이어서 찍기

2026-11-24 사용자 요청: `Ctrl+Win+Alt` 캡처의 도구에 `추가 캡처` 를 두어 한 번 더 찍고, 마지막에 찍은 캡처들의 썸네일을 보며 골라 고친 뒤 한 번에 `복사` / `바로작업` 한다. 설계 승인: 같은 날 ("좋아 진행해줘").

## 흐름
- 편집 패널 아래 버튼 줄: `[취소 Esc] … [추가 캡처] [복사] [바로작업]`.
- `추가 캡처` → 덮개를 닫고, 그 모니터 위쪽 가운데에 띠 창: `캡처 N장 보관 중 · [지금 캡처] [모아 보기] [버리기]`. 띠는 포커스를 가져가지 않고(`showInactive`) 뜬다. 그동안 다른 창을 조작해 화면을 바꿀 수 있다.
- `지금 캡처` 또는 `Ctrl+Win+Alt` → 띠를 숨기고(찍히지 않게 150ms 기다림) 포인터가 있는 모니터를 새로 멈춰 영역 선택. 앞선 캡처는 그대로 이어진다.
- `모아 보기` → 새 화면을 배경으로 덮개를 열되 영역 선택 없이 마지막 캡처를 편집.
- 2장부터 패널 위에 썸네일 줄(번호, 누르면 그 캡처 편집, × 로 지움). 방금 찍은 캡처는 제자리에, 앞선 캡처는 화면 위쪽 가운데에 맞춰 띄운다. 최대 8장.
- 코멘트는 묶음에 하나. 번호 도구는 모든 캡처를 통틀어 가장 큰 번호 + 1.
- Esc: 앞선 캡처가 있는 영역 선택에서는 캡처 목록으로 돌아감. 편집에서 캡처가 2장 이상이면 두 번(3초 안) 눌러야 모두 버림.
- `영역 다시` 는 방금 찍은(지금 배경 화면의) 캡처에만.

## 결과
- 바로작업: 그림 N개를 첨부로 저장하고 코멘트 하나와 한 번에 보낸다 (`chatPrompt` 는 이미 여러 파일을 받는다). 채팅 말풍선 미리보기도 N장 (`agent-chat-capture` 의 `previews`).
- 복사: 클립보드에는 그림이 한 장이라, 위에서 아래로 이어 붙인 한 장(장마다 `캡처 N` 띠)과 코멘트. 덮개가 그려 보내고 main 은 크기가 `stackLayout` 결과와 같을 때만 쓴다. 아니면 main 이 원본(또는 검사한 표시 그림) 화소를 직접 이어 붙인다 (번호 띠 글자 없음).

## main 이 지키는 것 (`src/quickCapture.js`)
- 캡처 사이의 묶음(각 캡처의 잘라 낸 원본 화소, 표시 목록, 코멘트)은 main 의 메모리에만. 디스크에 쓰지 않음. 잠금·앱 종료·`버리기`·덮개를 사용자가 닫음 → 지움. 단축키 직후 Esc(도우미의 `capture-cancel`)나 화면을 읽지 못한 경우는 이번 캡처만 버리고 앞선 캡처와 띠를 남긴다.
- 덮개가 돌려주는 캡처 목록을 검사한다 (`resolveShots`): 1~8개, `source` 는 앞선 캡처 번호(중복 없음)나 이번 화면(-1, 한 번, 영역 검사), 표시 목록은 배열 500개·JSON 2MB 이하(넘으면 비움). 어긋나면 아무것도 하지 않고 묶음을 지운다.
- 표시 그림은 캡처마다 지금처럼 크기 검사(`markedImage`). 원본 화소는 main 이 가진 것만 쓴다.
- 띠 창은 덮개와 같은 `data:` 페이지(preload·Electron API 없음, sandbox), 고른 버튼 이름만 돌려준다.

## 바꾸는 파일
- `src/quickCaptureEditor.js`: 캡처 여러 장(`shots`) 상태, `addShot`/`loadShots`/`select`/`removeShot`/`exportShots`/`exportCombined`/`drawThumbnail`. 공용 계산 `stackLayout`, `fitBox`, `nextBadge`, `restoredHistory`, `MAX_SHOTS`.
- `src/quickCaptureOverlay.js`: 썸네일 줄, `추가 캡처`, Esc 규칙, 띠 페이지 `captureChipUrl`.
- `src/quickCapture.js`: 묶음·띠·`resolveShots`·`cleanMarks`·`composeStack`, `start({ review })`, `cancelCapture()`.
- `src/agentChat/ipc.js` `sendCapture`: 첨부 여러 개. 화면 `agentChatStore.applyCapture`·타입: `previews`.
- `main.js`: 도우미의 Esc 는 `cancelCapture`.

## 테스트
- 단위: `stackLayout`·`fitBox`·`nextBadge`·`restoredHistory`, `resolveShots`·`cleanMarks`, 묶음 이어 가기·띠 선택·잠금·사용자 닫기·도우미 Esc, 두 장 복사(검사한 합친 그림 / 크기가 틀리면 main 이 합침), 두 장 보내기, `sendCapture` 의 첨부 여러 개.
- 화면 `quick-capture`: 표시 → 추가 캡처 → 띠 → 지금 캡처 → 두 번째 영역 → 썸네일 두 개 → 첫 캡처로 돌아가 표시가 남고 되돌리기 가능, 번호 이어짐 → Esc 규칙 → 바로작업으로 그림 두 장, 복사의 합친 그림 크기.

## 구현 중 정한 것
- 덮개 창은 캡처마다 새로 만든다 (모니터가 바뀔 수 있다). 앞선 캡처는 main 이 가진 원본 그림과 표시 목록으로 다시 넣고, 되돌리기 기록은 표시를 하나씩 빼는 순서로 다시 만든다 (`restoredHistory`).
- 편집 중인 캡처는 원본 그림도 캔버스에 그린다 (앞선 캡처는 뒤의 멈춘 화면과 다른 그림이다).
- 화면 테스트에서 찾은 기존 빈틈 둘 (`docs/fix/2026-11-24-capture-esc-error-and-lost-drag.md`): Esc 로 닫을 때마다 `화면을 캡처하지 못했습니다` 알림이 뜰 수 있었다 (페이지가 `close` 로 답하게 고침). 끈 영역이 가끔 버려졌다 (붙잡기 해제 뒤 100ms 동안 `pointerup` 을 기다림). 고친 뒤 화면 테스트를 세 번 연달아 돌려 49개 모두 통과.
