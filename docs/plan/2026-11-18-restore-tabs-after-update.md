# 업데이트 뒤 탭 다시 열기

상태: 구현 완료 (2026-11-18), 배포 전

## 요청

사용 중에 업데이트가 뜨면 셸 연결이 다 끊기는 것이 귀찮아 업데이트를 미루는 사용자가 있다. 열려 있던 탭 정보를 기억했다가 업데이트 뒤 다시 띄운다.

## 결정 (사용자 승인)

- SSH 연결은 앱이 다시 시작되면 끊긴다. 탭과 배치를 기억했다가 같은 세션으로 다시 접속한다.
- 업데이트 설치 버튼을 누를 때만 남긴다. 평소에 앱을 닫을 때는 기억하지 않는다.
- 업데이트 뒤 잠금을 풀면 안내 줄 `업데이트 전에 열려 있던 탭 N개를 다시 열까요?` 와 `다시 열기` / `열지 않기`. 자동으로 접속하지 않는다 (운영 서버에 다시 접속할지는 사용자가 정한다).
- `다시 열기` 는 탭을 하나씩 차례로 접속한다 (서버에 몰리지 않게, 호스트 키 확인 창이 겹치지 않게).
- 다시 여는 것: 탭 순서·이름·색·앞의 탭, 화면 좌우·상하 나누기, 탭 안의 칸 배치(칸마다 새 셸), SFTP 패널과 그 폴더, 탭의 작업 폴더(`cd` 한 번), 로컬 터미널, 계정이 저장된 DB 탭, 분리한 터미널 창(본창의 탭으로). 자동 실행 스크립트·root 전환은 처음 열 때와 같다.
- 다시 열지 못하는 것: 실행 중이던 프로그램, 이전 화면 내용(디스크에 남기지 않음), 빠른 연결 탭(비밀번호를 디스크에 새로 남기지 않음: 안내 줄에 목록, 누르면 접속 정보가 채워진 연결 창), 계정을 저장하지 않은 DB 탭, MCP 백그라운드 작업, 진행 중이던 파일 전송.
- 파일 `userData/restore-tabs.json`: 세션 파일과 같은 마스터 비밀번호 암호화. 다음 시작 때 한 번 읽고 지운다. 24시간 지난 것은 쓰지 않는다.
- 함께 고칠 빈틈: 설치 전에 진행 중인 파일 전송이 있으면 확인받고, 저장하지 않은 서버 파일 편집이 있으면 설치하지 않고 알린다 (편집 창은 저장하지 않은 내용 때문에 닫히지 않아 설치가 멈춘다).

## 구현 계획

- main: `src/restoreTabs.js`(암호화해 쓰기, 한 번 읽고 지우기, 기한·크기 검사) + `src/ipc/restoreTabs.js`(`restore-tabs-save`, `restore-tabs-take`, `update-busy-work`, 모두 본창에서 온 것만, 잠금 중 거부).
- 렌더러: `lib/restoreTabs.ts`(지금 탭에서 기록 만들기, 읽은 기록 검사), `lib/restoreTabsRun.ts`(차례로 다시 열기), `Restore/RestoreTabsBanner.tsx`, `UpdateNotification` 의 설치 버튼, DB 탭에 저장 계정 id 기록.
- 작업 폴더: 탭의 주 터미널만 (분할 셸은 폴더를 모른다). `~` 는 따옴표 밖에 둔다. 줄바꿈·제어 문자가 든 경로는 보내지 않는다.

## 확인

- 단위 테스트: `src/restoreTabs.test.js` 4개(암호화, 한 번만, 기한·다른 비밀번호·남의 파일), `lib/restoreTabs.test.ts` 11개(기록 만들기, 비밀번호 없음, 검사, `cd` 명령). 전체 2,754개 통과.
- 화면 테스트 `ssh-restore-tabs`: 기록을 저장하고 창을 다시 불러온 뒤 잠금 해제 → 안내 줄(아직 접속 안 함) → `다시 열기` → 저장 세션 탭(이름, 칸 둘, `cd -- '/var/log'`, SFTP 패널 `/var`)과 로컬 터미널, 빠른 연결은 칩 → 계정이 채워지고 비밀번호는 빈 연결 창, 다시 불러오면 안내 없음. 두 번 통과. `local-split`, `ssh-sftp` 다시 통과.
- 확인하지 못한 것: 실제 업데이트 설치(업데이트 알림의 `재시작` → 기록 → 재시작 → 복원) 전 과정. 설치 버튼 흐름(`lib/updateInstall.ts`)은 화면 테스트로 누르지 못했다 (개발 실행에는 받은 업데이트가 없다). DB 탭 다시 열기, 분리 창의 탭, 화면 좌우 나누기 복원, 진행 중 전송 확인 창과 저장 안 한 편집 거부는 화면으로 보지 않았다 (기록 쪽은 단위 테스트).
- 설계와 다른 점: 빠른 연결 탭은 연결 창을 채우기 위해 호스트·포트·계정(·키 경로)을 기록에 넣는다 (비밀번호는 넣지 않는다). 기록 파일 전체가 마스터 비밀번호로 암호화된다. 분할 셸의 작업 폴더는 알 수 없어 탭의 주 터미널만 `cd` 한다. SFTP 분리 창은 다시 열지 않는다.
