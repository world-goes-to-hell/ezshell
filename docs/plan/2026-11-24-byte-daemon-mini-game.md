# 바이트 데몬: 상태 줄에 숨긴 미니 게임

2026-11-24 사용자 요청: 방치형 게임을 상태 줄에 작게 숨겨 두고, 눌러서 잠깐 즐긴다.

## 결정한 것

- 이름: `바이트 데몬`. 데몬은 보지 않아도 뒤에서 도는 프로세스라 방치형과 뜻이 맞다 (codex-6 제안, 사용자 승인).
- 그림체: 둥근 플랫 벡터 (시안 `mockups/byte-daemon.html`, 1차 비교 `byte-daemon.v1.html`에서 사용자가 고름).
- 테마: 창·버튼·글자·로그 색은 ezShell 테마 변수(`--bg-*`, `--text-*`, `--accent`, `--border*`, `--radius-*`, `--error-text` 등)를 따른다. Glass 표면도 따른다. 캐릭터 색만 고정이다.
- 중심은 30초 안팎의 미니 게임이고, 방치 생산은 보상이 쌓이는 바탕이다 (사용자: 방치만으로는 의미가 없다).
- Codex 의견 반영: 첫 생산자는 몇 번 클릭으로, 해금 로그 한 줄, 알림·소리 없음, `게임 로그` 표시, 방치 보상 중복 지급 방지(보상과 기준 시각을 함께 저장, 시계가 뒤로 가면 0), 키보드 접근과 포커스 복원. 실제 에이전트 작업에 묶은 2배 보너스는 뺐다 (게임 때문에 에이전트를 켜 두게 만든다).

## 구성

- 상태 줄 맨 오른쪽 16px 아이콘(전용으로 단순하게 그린 데몬, 졸다가 포인터를 올리면 눈을 뜸). 누르면 위로 팝오버가 열린다. Esc·바깥 클릭으로 닫히고, 열기 전 포커스로 돌아간다.
- 팝오버: 바이트(KB→MB→GB… 1024 단위), 데몬 클릭(+바이트), 방치 보상 받기, 미니 게임 3개, 생산자 8종, 게임 로그.
- 미니 게임
  - 오류 잡기(30초): 로그가 흐르고 ERROR(40점)·WARN(20점) 줄의 벌레를 누른다. INFO 줄은 −10점. 콤보 최대 ×9. 동작 줄이기에서는 벌레가 기어가지 않고 제자리에 나타났다 사라진다.
  - 명령어 타자(30초): 나오는 명령을 그대로 친다. 틀리면 콤보 초기화. 한글 입력 상태여도 키 자리(`code`)로 읽는다.
  - 금요일 배포: 판돈을 걸고 빌드→테스트→스테이징→운영 순서로 도전하거나 멈춘다. 롤백되면 판돈을 잃는다. 금요일 18시 이후 롤백 확률 +10%p.
- 생산자: 메모지 요정(alias) → 두루마리(셸 스크립트) → 시계 고양이(cron) → 상자 햄스터(컨테이너) → 고무 오리(CI) → 문어 선장(클러스터) → 꼬마 로봇들(에이전트 군단) → 구름 양(데이터센터). 값은 살 때마다 1.15배. 일부는 게임을 돕는다 (cron 타자 +5초, 컨테이너 벌레 속도 −15%, CI 롤백 −5%p).
- 보상: 게임 한 판은 `max(40 B, 초당 생산량 × 60)` 에 점수 비율(0~1.5)을 곱한다.

## 지켜야 할 것

- 팝오버가 닫혀 있으면 타이머가 돌지 않는다. 생산량은 마지막 정산 시각과의 차이로 계산한다 (최대 8시간). 열려 있어도 창이 가려지면 멈춘다.
- 저장은 `localStorage` 의 `byteDaemon` 한 키. 읽을 때 형식을 다시 검사한다. 화면 설정 백업에는 넣지 않는다.
- Zen 모드에서는 아이콘을 그리지 않는다. 명령 팔레트 `미니 게임 아이콘 숨기기/보이기`.
- 앱 단축키를 가로채지 않는다. 타자 게임 입력칸의 키는 그 입력칸에서 끝난다.

## 구현하며 바꾼 것

- 첫 생산자(메모지 요정)는 처음부터 보인다. 처음에 반쯤 모아야 보이게 했더니 시작 화면에 생산자가 `???` 하나뿐이었다.
- 게임 로그는 항상 세 줄 높이. 팝오버가 위로 자라서, 로그가 늘 때 버튼이 움직여 누르기가 빗나갔다 (화면 테스트에서 찾음).
- 배포 배율·확률은 시안(×1.5~×8)보다 낮췄다 (×1.2·1.5·2.5·5, 롤백 10·20·35·50%). 시안 값이면 배포만 반복하는 편이 게임보다 벌이가 나았다.
- 데몬 클릭(쓰다듬기)이 클릭 수단이다. 시안에 따로 있던 프롬프트 클릭 자리는 두지 않았다.
