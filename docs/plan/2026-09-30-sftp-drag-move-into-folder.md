# SFTP 목록 드래그: 폴더로 옮기기, 폴더로 바로 업로드/다운로드

## 요구사항
SFTP 패널의 원격 목록에서 파일(여러 개 포함)을 끌어 같은 목록의 폴더 위에 놓으면 그 폴더로 옮긴다.

## 결정 사항 (2026-09-30 사용자 확인)
| 항목 | 결정 |
|---|---|
| 확인 | 놓으면 "N개 항목을 ○○ 폴더로 옮길까요?" 확인 후 이동 (원격 삭제와 같은 방식). 로컬도 같은 방식 |
| 로컬 목록 | 같은 이동 기능 제공 |
| `..` 행 | `..` 위에 놓으면 현재 폴더의 상위 폴더로 이동 |
| 반대쪽 목록의 폴더 행 | 로컬 파일을 원격 폴더 행에 놓으면 그 폴더로 업로드, 원격 파일을 로컬 폴더 행에 놓으면 그 폴더로 다운로드 (빈 곳에 놓으면 지금처럼 현재 폴더) |

## 현재 구조
- `FileList`의 드래그는 `application/json` 에 `{ type, fileNames }` 를 싣고, 다른 쪽 목록에 놓을 때만 처리한다.
  dragover 중에는 `getData` 를 읽을 수 없어서 어떤 항목을 끌고 있는지 알 수 없다.
- 원격 이름 바꾸기 `sftpRename(old, new)` 는 경로를 바꾸므로 폴더 간 이동에 그대로 쓸 수 있다(대상에 같은 이름이 있으면 실패).
- 로컬 `renameLocal` 은 같은 폴더 안에서만 허용한다 → 로컬 이동은 메인 프로세스에 `moveLocal` 을 새로 둔다.
- 전송의 같은 이름 충돌 확인은 **현재 폴더 목록**으로 한다 → 하위 폴더로 보낼 때는 대상 폴더 목록을 먼저 읽어서 확인한다.
- 분리 창(`SftpWindow`)은 반대쪽 목록 드롭(업로드/다운로드)을 지원하지 않는다. 목록 안 이동은 `useSftpPaneActions` 로 함께 적용된다.

## 설계
- **드래그 상태**: `FileList` 모듈에 현재 드래그(`{ type, fileNames }`)를 dragstart 에서 기록하고 dragend 에서 지운다.
  두 목록이 같은 창에 있으므로 dragover 에서 이 값으로 대상 여부를 판단한다.
- **대상 행**: 폴더 행과 `..` 행. 끌고 있는 폴더 자신은 대상이 아니다. 루트에서는 `..` 가 대상이 아니다.
  같은 목록이면 dropEffect `move`, 반대 목록이면 `copy`. 대상 행을 강조한다.
- **같은 목록 이동** (`lib/sftpFileOps.ts` `moveEntries`, IPC 주입 가능하게 해서 단위 테스트)
  - 확인 창 → 항목마다 이동 → 실패는 모아서 한 번에 알림 → 하나라도 옮기면 새로고침.
  - 원격: `sftpRename`. 로컬: 새 IPC `local-move` (`localFileOps.moveLocal`: 절대 경로, 대상이 폴더인지, 자기 자신/하위 폴더로 옮기는지, 같은 이름이 있는지 확인).
- **반대 목록 폴더 행**: `onDrop(fileNames, targetDir?)`. 대상 폴더를 정하면 그 폴더 목록을 읽어 충돌을 확인한 뒤 기존 전송 흐름을 그대로 쓴다.
- `..` 계산은 `parentPath(path, side)` 순수 함수로 분리하고 `goUp` 도 이를 쓴다
  (기존 `goUp` 은 `D:\` 에서 상위로 가면 `C:\` 로 이동하던 문제가 있어 드라이브 루트에서는 멈추도록 바로잡는다).

## 진행 결과 (2026-09-30)

- 단위 테스트: moveLocal 8개, parentPath·moveEntries 7개 추가, 전체 253개 통과, 타입 체크 오류 0건.
- E2E(임시 SFTP 서버에 파일 읽기/쓰기 추가, CDP DOM 이벤트): 18개 항목 통과
  - 원격: 폴더 행 강조 → 확인 → 이동, 확인 취소 시 그대로, 여러 개 한 번에, 같은 이름 충돌 시 실패 알림 후 그대로,
    폴더 자기 자신/파일 행은 대상 아님, `..` 에 놓으면 상위로
  - 로컬 → 원격 폴더 행: 그 폴더로 업로드, 원격 → 로컬 폴더 행: 그 폴더로 다운로드, 로컬 목록 안 이동
  - 하위 폴더에 같은 이름이 있으면 덮어쓰기 확인 창
  - 폴더 행에 놓은 뒤 목록 전체 강조가 남지 않음
  - 화면 분할로 두 세션을 띄웠을 때 다른 세션 패널은 드롭을 받지 않고, 같은 세션 폴더 행은 받음

## 코드 리뷰 반영 (2026-09-30)

- [HIGH] 드래그 정보에 세션이 없어, 분할 화면에서 다른 세션 패널에 놓으면 그 세션의 같은 이름 파일을 옮기거나 전송하던 문제
  → 드래그 정보에 세션·폴더 경로를 넣고 같은 세션만 허용. 목록 전체 드롭(현재 폴더로 전송)도 payload 의 sessionId 확인
  (이 경로는 기존 코드에도 있던 문제).
- [MEDIUM] 폴더 행 위/드롭 후 목록 전체 강조가 남던 문제 → 행이 드래그를 받으면 목록 강조 해제.
- [MEDIUM] 드래그가 비정상 종료되면 드래그 정보가 남아 탐색기 파일 드롭을 오인할 수 있던 문제
  → 창 전체 dragend 에서 초기화, 앱 내부 payload(`application/json`)가 없거나 `Files` 가 있으면 거부.
- [MEDIUM] 이동 후 선택이 남던 문제 → 이동(또는 실패) 후 선택 해제.
- [LOW] 모두 실패하면 새로고침하지 않던 문제 → 실패가 있어도 새로고침.
- [LOW] `C:\` 외 드라이브 루트에서 하위 경로가 `D:\\name` 이 되던 문제 → `joinChildPath` 사용.

## 참고
- 분리된 SFTP 창은 원래 반대쪽 목록 드롭(업로드/다운로드)을 지원하지 않아서, 목록 안 이동만 동작한다.
- `main.js`/`preload.js` 가 바뀌었으므로 로컬 이동은 앱을 다시 시작해야 동작한다(개발 앱 포함).
