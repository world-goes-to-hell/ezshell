# 작업 공간 파일 검색 빠르게 하기 (2026-11-24)

상태: 완료 (사용자 승인 설계)

## 문제
- `src/localFiles/search.js` 가 폴더를 하나씩 순서대로 `opendir` 하고 폴더마다 `realpath` 를 기다렸다. 이 저장소(약 4.3만 항목, 5,200 폴더)에 2.2~2.6초.
- 훑은 목록을 끝난 뒤 10초만 쓰고 버려서, 잠시 뒤 다시 검색하면 또 2초.

## 바꾼 것 (`src/localFiles/search.js` 만)
- 병렬 훑기: 폴더 16개를 동시에 `fs.promises.readdir(withFileTypes)`. 안전 검사는 그대로: 폴더를 읽기 전에 realpath 가 루트 안이고 요청 경로와 같아야 함, 링크로 바뀐 폴더는 건너뛰고 truncated 표시, `.git` 제외, 링크 폴더는 따라가지 않음.
- 목록 유지: 10초 만료를 없애고 `fs.watch(root, { recursive: true, persistent: false })` 로 유지.
  - 첫 훑기 전에 감시를 건다 (훑는 동안의 변경은 훑기가 끝난 뒤 적용).
  - `rename` 알림만 본다 (`change` 는 내용 변경이라 이름 목록이 그대로다. 로그 파일이 계속 쓰이는 폴더를 매번 다시 읽지 않게). `.git` 아래와 루트 밖으로 풀리는 이름은 무시.
  - 알림의 이름은 "어느 폴더를 다시 읽을지"에만 쓴다: 부모 폴더를 150ms 모아 깊이 순으로 직접 다시 읽고(같은 realpath 검사), 그 폴더 항목을 통째로 바꾼다. 없어진 하위 폴더는 그 아래를 빼고, 새 하위 폴더는 그 아래를 병렬로 훑는다. 읽은 적 없는 폴더의 알림은 가장 가까운 읽은 부모가 대신한다. 폴더가 사라졌거나 링크로 바뀌었으면 그 아래와 부모 목록의 항목을 뺀다.
  - 이름 없는 알림(버퍼 넘침), 한 묶음에 바뀐 폴더 2,000개 초과, 감시 오류, 루트 읽기 실패면 목록을 stale 로 두고 감시를 닫는다. 다음 검색이 다시 훑는다.
  - `fs.watch` 를 걸 수 없으면 예전처럼 10초만 쓴다.
- 자료 구조: 폴더 → 자식 항목 표. 검색은 평평한 목록을 훑는데, 첫 훑기 동안에는 자라는 배열(지금처럼 생성 중에도 결과를 냄), 변경 뒤에는 표에서 다시 만든 새 배열이다. 결과 형식·순서·200개 상한은 그대로.
- 상한: 항목 200,000개, 8초 (훑기 한 번마다).
- 최근 루트 3개(LRU). 밀려난 루트와 `clear()`(앱 잠금, `localProjects.js` 의 `clearSearches`)는 훑기 중단(AbortController), 감시 닫기, 타이머 정리.
- `prepare(root, true)` 는 작업 공간 머리줄의 새로 고침 버튼만 쓴다 (`WorkspaceBrowser.tsx`): 다시 훑는다. 다른 사용처는 없다.

## 시험 (`src/localFiles/search.test.js`)
새로 고침, 10초가 지나도 다시 훑지 않음(가짜 시계·알림 없는 감시), 병렬 훑기·`.git` 제외, 200개 상한, clear 때 훑기 중단과 감시 닫힘, 루트 3개 LRU, 정션 폴더를 따라가지 않음, 실제 감시로 파일 추가·이름 바꾸기·삭제·폴더 삭제·새 폴더 반영, 폴더가 정션으로 바뀐 뒤 그 안을 읽지 않음.

## 남은 한계
- 한꺼번에 폴더가 많이 생기면(npm install) 알림 버퍼가 넘쳐 stale 이 되고 다음 검색이 다시 훑는다 (보통 0.3초, 백신이 새 파일을 검사하는 동안은 더 걸린다).
- 네트워크 드라이브는 루트 검사에서 이미 거부된다. 감시가 오지 않는 파일 시스템이면 알림이 없어 목록이 낡을 수 있다 (새로 고침 버튼).
- 링크로 바뀐 폴더 등으로 한 번 truncated 가 되면 새로 고침 전까지 그 표시가 남는다.

## 추가: 설치·생성 폴더 제외 (2026-11-24)

- 배경: 이 저장소의 4.3만 항목 가운데 Git 이 추적하는 파일은 1,384개다. `node_modules`(3.1만)·`release`(8천)·`e2e/.out`·`out`·`dist` 가 나머지를 차지해서, `index` 같은 검색어의 결과를 패키지 파일이 덮었다.
- 결정 (사용자): 기본으로 빼되, 상황에 따라 포함할 수 있게 한다.
- 구현: `SKIPPED_DIRS` 에 든 이름의 폴더는 목록에 폴더 자체만 넣고 안을 읽지 않는다 (어느 깊이든, 대소문자 무시). 감시 알림도 그 폴더 아래의 것은 무시한다 (폴더가 생기고 지워지는 것은 반영). 결과에 제외한 폴더 수와 이름(최대 8개)을 실어 안내 줄을 그리고, `포함해서 검색` 을 누르면 `includeAll` 로 따로 만든 목록에서 찾는다. 포함 여부는 패널 상태로만 둔다.
- `.gitignore` 를 따르지 않은 이유: `.env` 처럼 무시 목록에 있어도 찾고 싶은 파일이 빠진다.
- 측정 (이 저장소, 일치 없는 검색어로 끝까지 훑음): 기본 처음 23ms·다음 7ms, 포함 처음 314ms·다음 4ms.
