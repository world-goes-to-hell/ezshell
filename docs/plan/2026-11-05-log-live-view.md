# 로그 실시간 보기 (tail -f) 와 오류 강조

- 상태: 구현 완료 (배포 전, 검토 반영함)
- 구분: 중간 (서버에 읽기만 함, 명령 실행 없음)
- 바탕: `docs/plan/2026-11-05-sftp-file-edit-preview.md` 의 텍스트 미리보기 창

## 목표

SFTP 우클릭 `실시간 보기` (또는 텍스트 미리보기 창의 `실시간` 버튼)로 로그 끝에 쌓이는 줄을 계속 보여 주고,
오류·경고 줄에 색을 입힌다.

## 운영 서버에 부담을 주지 않기 위한 규칙

| 규칙 | 이유 |
|---|---|
| SFTP `stat` 만 1초마다 (창이 가려지거나 최소화되면 5초). 크기가 같으면 아무것도 읽지 않는다 | 서버 명령(`tail -f`) 없이, 요청 하나로 끝난다 |
| 늘어난 부분만 읽고, 한 번에 최대 1MB. 넘으면 건너뛰고 "N 건너뜀" 표시 | 로그 폭주 때 회선·서버 디스크 읽기를 늘리지 않는다 |
| 읽을 때만 파일을 열고 바로 닫는다 | 열어 둔 채면 logrotate 가 지운 옛 파일의 디스크 공간이 풀리지 않는다 |
| 다음 확인은 앞 확인의 답을 받은 뒤에 예약한다 (겹치지 않음). main 도 문서마다 한 번에 하나만 처리 | 느린 서버에서 요청이 쌓이지 않는다 |
| 쓰기·잠금·권한 변경 없음. 접속 계정 권한으로 읽기만 | |
| 앱을 잠그면 미리보기·실시간 창을 닫는다 (편집 창은 저장 안 한 내용 때문에 남김). 잠긴 동안 main 은 실시간 요청을 거부 | 잠금 화면 뒤에 로그가 계속 갱신되면 안 된다 |
| 창 안에는 최근 5MB 만, 넘으면 오래된 줄부터 지움 | 오래 켜 둬도 앱 메모리가 늘지 않는다 |

## 로테이션·잘림

- 크기가 줄었거나, 파일 앞 256바이트가 처음 본 것과 다르거나, 링크가 다른 파일을 가리키면 새 파일로 본다 (logrotate `create`, `copytruncate`). 새 파일을 처음부터(1MB 까지) 읽고 "파일이 새로 시작됨" 표시 줄을 넣는다.
- 파일이 잠시 없으면(이름 바꾼 직후) 기다린다.
- 줄바꿈이 오지 않은 조각은 main 이 붙잡아 두었다가 줄이 끝나면 보낸다 (최대 1MB). 한글이 반으로 쪼개지지 않는다.
- NUL 바이트(copytruncate 의 빈 구간)는 지운다.

## 강조 (줄 단위, `lib/logLevels.ts`)

- 오류(빨강): `ERROR` `FATAL` `CRITICAL`/`CRIT` `SEVERE` `EMERG` `ALERT` `PANIC` (대문자 단어), `[error]` `[crit]` `[alert]` `[emerg]`, `level=error`, `"level":"error"`, `Exception`/`Error:` 로 끝나는 이름, `Traceback (most recent call last)`, `Caused by:`, `panic:`, 스택 줄(`\tat x.y(...)`)
- 경고(노랑): `WARN` `WARNING`, `[warn]`, `level=warn(ing)`
- 디버그(흐림): `DEBUG` `TRACE`, `level=debug`
- 소문자 `error` 단어는 오류로 보지 않는다 ("0 errors", "no error" 같은 정상 문구가 많음).
- 화면에 보이는 줄만 꾸민다 (CodeMirror ViewPlugin). 개수는 붙인 줄과 지운 줄만 세서 고친다.

## 화면

- 상태바: `● 실시간` / `일시정지` / `연결 끊김 (다시 연결되면 이어서 봅니다)`, 오류 N · 경고 N, `이전 오류`(Shift+F8) / `다음 오류`(F8)
- 맨 아래를 보고 있으면 따라 내려가고, 위로 올리면 멈추고 "새 줄 N개 ↓" 버튼
- 창이 뒤에 있을 때 새 오류가 오면 작업표시줄 깜빡임 (알림 센터에는 아무것도 남기지 않음)

## 검토 반영 (2026-11-05)

검토 결과 CRITICAL·HIGH 는 없었다. MEDIUM 4건은 모두 고쳤다.

| 지적 | 처리 |
|---|---|
| 일시정지 중 진행 중이던 확인의 답을 화면이 버리면 그 줄이 영영 빠짐 | main 이 답마다 cursor 를 붙이고, 다음 요청이 그 cursor 를 가져올 때만 위치를 넘긴다. 아니면 같은 줄을 다시 보낸다 |
| 새로고침 순간 옛 화면의 확인이 새 위치를 먼저 가져가 줄이 빠짐 | load 마다 generation 을 바꾸고, 옛 화면의 요청은 stale 로 답한다 |
| 로그 추가가 되돌리기 기록에 쌓여 메모리 상한(5MB)이 깨짐 | `Transaction.addToHistory.of(false)` |
| 창마다 SFTP 채널을 하나씩 오래 잡아 서버의 연결당 채널 수 제한(MaxSessions)에 걸림 | 같은 탭의 파일 창이 채널 하나를 함께 쓴다. 채널을 거부당하면 "연결 없음" 과 다른 문구를 보여 준다 |

LOW 중에서 고친 것:
- 덧붙는 텍스트의 `\r` 을 편집기와 같은 방식으로 바꾼다 (줄 수·개수가 어긋나지 않게).
- 처음 텍스트 변환은 한 번만 한다.
- 확인에 30초 제한을 둔다.
- 실시간 모드에서는 처음 읽을 때도 NUL 을 지운다 (copytruncate 를 겪은 로그도 열린다).
- 마스터 비밀번호 초기화 때도 미리보기 창을 닫는다. 잠긴 동안에는 파일 창 열기와 불러오기도 거부한다.

남겨 둔 한계 (폴링 방식이라 생김):
- 연 직후 첫 확인 전(1초 안)에 파일이 교체되고 더 커지면, 교체를 알아채지 못하고 새 파일의 중간부터 보여 줄 수 있다.
- 교체된 새 파일이 옛 위치와 정확히 같은 크기이거나, 앞 256바이트가 늘 같은 로그는 교체를 늦게 알아챈다.
- 교체 직전 마지막 확인 뒤에 옛 파일에 쓰인 줄은 보이지 않는다.
- 창마다 초당 최대 1MB 를 읽는다. 파일 창은 20개까지라 이론상 합계 20MB/s 까지 갈 수 있다 (실제로는 로그가 그만큼 빨리 쌓여야 한다).
