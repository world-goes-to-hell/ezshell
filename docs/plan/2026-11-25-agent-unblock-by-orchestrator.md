# 멈춘 에이전트를 다른 에이전트가 알아보고 푸는 방법 (2026-11-25)

사용자 요청: 채팅 모드에 문제가 있으면 그 에이전트와의 대화가 멈춘다. 여러 에이전트를 오케스트레이션하는 사용자에게는 다른 에이전트(PL 등)가 활동 중일 수 있으니, 그 에이전트가 멈춘 창을 다뤄 병목을 푸는 방법.

## 1. 지금

- PL 이 알 수 있는 것은 `check_sent` 의 `unread`/`read`/`answered` 뿐이다. 왜 안 읽는지(권한 확인 대기, 열린 CLI 화면, 입력칸에 남은 글, 훅에서 멈춤, 종료)는 모른다.
- 앱은 이미 그 이유를 판정하고 있다: 확인 질문(`agentInboxWake` 의 `readApprovalScreen`), Claude 선택지 질문, 폴더 신뢰 화면(`terminalOnly: 'folder-trust'`), CLI 자기 화면(`agentPickerScreen`, 화면 복귀 띠), 입력칸의 글(`composer()`), 훅 상태(`hookState`), 종료 코드, 안 읽은 메시지(`unreadFor`).
- 바꾸면 안 되는 것 (CLAUDE.md Local Terminal Tab): MCP·휴대폰에서 로컬 셸에 직접 입력하는 경로를 만들지 않는다.

## 2. 원칙

- 다른 에이전트는 화면 원문을 받지 않는다 (비밀이 섞일 수 있다). 앱의 판정 결과만 받는다.
- 다른 에이전트는 키를 마음대로 보내지 못한다. 정해진 조치만, 앱이 화면을 다시 확인한 뒤에 한다.
- 권한 확인, 폴더 신뢰, 사용자에게 묻는 Claude 선택지 질문은 어떤 에이전트도 대신 답하지 않는다 (사용자의 확인 단계가 사라지고, 에이전트가 동료에게 권한을 대신 눌러 달라고 하는 길이 생긴다). 이런 것은 사람을 부른다.

## 3. 단계

### 1단계: 왜 멈췄는지 보기 (읽기 전용)

메시지 MCP(`src/ipc/agentMessageMcp.js`)에 `inspect_agent` 도구:

- 입력: 에이전트 id.
- 출력: `status`(상태와 출처 hook/screen), `blocked`(아래 중 하나 또는 null), `unread`(그 에이전트가 안 읽은 메시지 수), `idleFor`(쉰 시간), `exitCode`.
  - `approval`: 확인 질문. 질문 한 줄과 선택지 이름(채팅 카드에 보이는 것과 같은 범위, 각 200자).
  - `question`: Claude 선택지 질문. 질문 문장.
  - `folder-trust`, `hook-trust`(Codex 훅 승인 화면).
  - `cli-screen`: `/model` 같은 CLI 자기 화면.
  - `draft`: 입력칸에 글이 남음. 앱이 붙여 넣은 글인지(`ours`)만, 글자는 주지 않는다.
  - `hook-running`: 훅 차례가 열린 채 오래 지남.
  - `ended`: CLI 가 끝남.
- 부른 에이전트와 같은 사용자의 에이전트만 (지금 `list_agents` 와 같은 범위). 잠금 중에는 거부.
- `blocked.kind`로 종류를 구분한다. `idleFor`는 로컬 셸이 쉬는 상태일 때 마지막 활동 이후 밀리초다. `hook-running`은 열린 작업 차례의 마지막 훅 신호가 2분 이상 지난 경우다. 측정 정보가 없으면 `null`을 반환한다. 같은 앱에 등록된 로컬 셸은 메시지 MCP 연결 전에도 검사할 수 있어, 시작 중 훅 승인과 폴더 신뢰를 확인할 수 있다. 종료 기록은 앱이 보관한 동안 ID로 조회할 수 있다.

### 2단계: 사람 부르기

`escalate` 도구: 입력은 에이전트 id 와 짧은 사유(200자, 한 줄). 앱이 그 에이전트가 정말 사람의 답을 기다리는지(`approval`·`question`·`folder-trust`·`hook-trust`) 다시 확인한 뒤에만 알린다.

- PC: 작업표시줄 깜빡임과 Windows 알림 (MCP 확인 창의 `alertMcpApproval` 과 같은 방식). 알림에는 "codex-14 가 응답을 기다립니다" 와 종류만, 질문·사유 원문은 넣지 않는다 (알림 센터에 남는다). 앱 안에는 그 칸으로 가기 버튼이 달린 안내.
- 같은 에이전트의 같은 막힘은 한 번만 알린다 (반복 호출로 알림을 쏟지 않게).
- 화면을 다시 그리거나 줄바꿈해도 같은 종류의 요청이 이어지는 동안 알림을 한 번만 보낸다. 화면이 닫히거나 요청 종류가 바뀌면 다음 알림을 보낼 수 있다.
- 휴대폰 푸시는 휴대폰 화면 개편(`2026-11-25-remote-pc-like-ui.md`)이 끝난 뒤 같은 규칙으로 더한다 (본문은 종류만).

### 3단계: 안전한 조치 (1·2단계 운영 뒤)

`unblock_agent(id, action)`, 사용자가 설정에서 지정한 에이전트만 (기본 꺼짐, 예: 역할 `PL`):

| 조치 | 조건 (앱이 실행 직전에 다시 확인) |
|---|---|
| `nudge` 알림 문장 다시 붙이기 | 쉬는 중, 빈 입력칸, 안 읽은 메시지 있음 (지금 깨우기 경로) |
| `clear_draft` 남은 글 지우기 | 입력칸 글이 앱이 붙여 넣은 글과 정확히 같을 때만 (Esc 회수 규칙) |
| `close_screen` | `cli-screen` 으로 판정됐을 때만 Esc. 확인 질문에는 안 됨 |
| `interrupt` | 작업 중일 때 Esc 한 번 (멈추기만) |

조치마다 앱 안내("PL 이 codex-14 의 열린 메뉴를 닫았습니다")와 감사 기록. 1·2단계로 어떤 막힘이 자주 생기는지 본 뒤 필요한 조치만 넣는다.

### 함께: 앱이 스스로 푸는 것

같은 규칙으로 앱이 스스로 할 수 있는 것은 사람·에이전트를 기다리지 않는다 (예: 앱이 붙여 넣고 Enter 를 보내지 못한 글이 오래 남음). 3단계 때 함께 정한다.
