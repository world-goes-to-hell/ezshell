- e7 만 고치는 것: `main.js`, `src/*.js`(main 쪽 모듈), `src/preload.js`, `electron.vite.config.ts`, `package.json`, `e2e/`.

## 단계별 기준

### 1단계: 화면 테스트
- 임시 폴더에 있던 시험 스크립트와 시험용 SSH 서버를 `e2e/` 로 옮긴다. 시험용 프로필(`--user-data-dir`)만 쓰고 실제 앱 데이터는 건드리지 않는다.
- 한 명령으로: 빌드된 앱을 띄우고, 스크립트를 차례로 돌리고, 앱을 끝낸다 (남은 `electron.exe` 가 CDP 포트를 잡는 문제 포함).
- 처음에는 서버가 필요 없는 것(로컬 터미널 분할, 단축키, 로그 강조, 분리 창 위치)과 시험용 SSH 서버로 되는 것(분할·칸 옮기기)만 넣는다.

### 2단계: `main.js` 나누기
- 동작을 바꾸지 않고 옮기기만 한다. 한 묶음을 옮길 때마다 단위 테스트와 화면 테스트를 돌린다.
- 순서: 창 만들기(분리 창 다섯 종류) → 업데이트 → SFTP → SSH 연결·재연결.
- 보안 경계(본창에서 온 요청만 받는 검사, 잠금 중 거부)는 그대로 옮기고 옮긴 뒤 다시 확인한다.
- 새 파일은 `MAIN_RUNTIME_MODULES` / `MAIN_RUNTIME_DIRECTORIES` 에 넣는다.

### 3단계: Electron 업그레이드
- 시작 전에 28 이후 버전별 변경 사항을 공식 문서로 확인한다.
- 확인할 곳: `node-pty`·`oracledb` 네이티브 파일, 아크릴 창 재질(`backgroundMaterial`), `electron-builder`·`electron-vite` 호환, `safeStorage`, 자동 업데이트.
- 올린 뒤 Node 18 때문에 넣은 우회 코드를 걷어낸다 (`src/mcp/sdk.js` 의 `globalThis.crypto`, `drivers/mssql.js` 의 `loadTedious`).
- 패키징된 설치본으로 확인한 뒤에만 끝난 것으로 본다.

### 4단계: 화면 설정 내보내기·가져오기
- 설정 > 백업에 `화면 설정` 하위 탭. 테마, 단축키, 패널 크기 같은 `localStorage` 설정을 파일로 내보내고 가져온다.
- 내보낼 키는 허용 목록으로 정한다 (목록에 없는 키는 내보내지도 가져오지도 않는다). 접속 정보·계정·경로처럼 PC 나 서버를 드러내는 값은 넣지 않는다.
- 가져올 때 값의 형식을 검사한다 (각 기능이 이미 갖고 있는 읽기 함수를 쓴다).
- 결과: 허용 목록과 검사는 `lib/uiSettingsBackup.ts`(키 14개, 테스트 11개), 적용은 `lib/uiSettingsApply.ts`, 화면은 `Settings/UiSettingsBackup.tsx`. 저장은 기존 `save-export-file`, 읽기는 창의 파일 선택이라 main 쪽 변경이 없다. 창을 다시 불러오지 않고 적용한다 (다시 불러오면 열린 탭이 닫힌다): 테마·단축키·사이드바·확대 비율은 스토어로 바로, 나머지는 해당 화면을 다시 열 때 반영된다.
- 뺀 것: 접속 기록, 통계, 최근 명령, 스니펫, DB 트리 필터·콘솔·기본 스키마(키에 호스트·계정이 들어감), 터미널 찾기 설정(폴더 경로), 젠 모드(설정이 아니라 그때의 상태).
- 확인: 렌더러만 띄운 화면에서 내보내기 → 파일 고르기 → 미리 보기 → 적용까지 실행했다 (테마와 사이드바가 바로 바뀌고, 목록에 없는 키와 형식이 틀린 값은 저장되지 않음). 실제 앱에서 파일 저장 창을 거치는 흐름은 확인하지 못했다.
- 남은 것: 저장 창의 제목이 `결과 추출` 이다 (`save-export-file` 이 DB 추출용으로 만들어져서). 제목을 인자로 받게 하는 것은 main 쪽 일이라 e7 에 요청한다.

### 5단계: `globals.css` 나누기
- 규칙의 순서를 유지한 채 기능별 파일로 가른다 (순서가 바뀌면 같은 우선순위의 규칙이 뒤집힌다).
- 나누기 전후로 빌드된 CSS 의 규칙 순서가 같은지 비교한다.
- 결과: `globals.css` 는 목록만 남고(`@import` 순서가 곧 규칙 순서), 내용은 `styles/app/` 의 26개 파일과 `tailwind.css` 로 갔다. 원본을 구역 주석 자리에서 순서대로 잘랐고, 조각을 이어 붙이면 원본과 같다는 것을 스크립트로 확인했다. 렌더러를 나누기 전후로 각각 빌드한 CSS 4개가 바이트 단위로 같다 (`index-CwvlgTTq.css` 269,231바이트).

## 3단계에서 확인한 것과 못 한 것

확인한 것 (Electron 45.3.3, Windows 11):
- 단위 테스트 2,661개, 화면 테스트 12개 (개발 실행, 그리고 `electron-builder` 24.13.3 으로 만든 패키징된 앱).
- 패키징: NSIS·포터블이 만들어지고 실행된다. 로컬 터미널(`node-pty` 사전 빌드)이 패키징된 앱에서 열린다.
- 오래된 서버용 SSH 알고리즘 목록이 28 과 같다 (`ssh-dss`, `3des-cbc`, `hmac-md5`, SHA-1 키 교환).
- DB 드라이버 네 개와 `oracledb` thin, MCP SDK, 웹 푸시 모듈이 로드된다. `safeStorage` 와 세션 암호화가 한 바퀴 돈다.
- 터미널에 파일을 끌어 놓는 업로드가 `webUtils.getPathForFile` 경로로 된다.
- 서버 파일 창 (명세 `ssh-remote-file`, 개발 실행): 텍스트 미리보기(읽기 전용), 편집(CodeMirror 에 입력됨), 실시간 보기, 이미지, PDF 가 열리고 콘솔 오류와 CSP 거부가 없다. PDF 는 `blob:` 문서가 프레임 트리에 `application/pdf` 로 올라오고, 캡처에서 Chromium 뷰어가 한 쪽을 그린 것을 봤다.
- 아크릴 창의 수치 (시험용 프로필의 `appearance.json` 을 Glass 로): 본창이 재질과 함께 만들어지고(`getBackdrop` 이 `active: true`, 루트에 `data-backdrop="native"`), 최대화 버튼이 작업 영역을 채웠다가(2560x1552 화면에서 창 2576x1560 = 보이지 않는 테두리 8px 포함) 다시 누르면 원래 자리·크기로 돌아온다. `setWindowOpacity` 호출은 오류 없이 간다.
- 화면 모양 (CDP 캡처로 눈으로 훑음): `minimal-dark`·`macos-light`·`macos-dark`·`high-contrast`·`cyberpunk-neon` 의 시작 화면과 설정 창, Glass(색 번짐 배경)의 `macos-light`·`minimal-dark`, 접힌 사이드바. Chromium 120 → 156 사이에 깨진 곳을 찾지 못했다 (신호등 버튼, 둥근 모서리, 하위 탭, 슬라이더, Glass 시작 화면의 카드 포함).

확인하지 못한 것:
- 28 로 저장한 자동 잠금 해제 자료(`auto-unlock.dat`)가 45 에서 풀리는지 (새 자료의 암·복호화만 확인).
- 28 기반 설치본에서 45 기반 새 버전으로의 자동 업데이트.
- 아크릴 창이 눈에 보이는 모습: 재질이 처음부터 그려지는지, 채운 상태에서도 남는지, 창 투명도가 실제로 옅어지는지. 확인하려던 때 PC 화면이 잠겨 있어 OS 화면 캡처에 잠금 화면만 찍혔다 (CDP 캡처에는 창 뒤가 찍히지 않는다). 수치로 확인한 것은 위 목록에 있다. 우회 코드(`maximizable: false`, 작업 영역 채우기)는 그대로 두었다.
- MCP 활동 패널의 모양 (시험용 프로필은 MCP 가 꺼져 있어 상태 줄에 버튼이 없었다), 터미널·SFTP·DB 탭이 열린 상태의 테마별 모양 (명세의 캡처는 기본 테마뿐이다).
- 서버 파일 창의 저장 흐름(검토 → 저장 → 백업)과 백업 비교 화면은 새 버전에서 돌려 보지 않았다 (열기와 입력까지만).
- 실제 DB 접속(MySQL, PostgreSQL, SQL Server, Oracle thin·thick), 오래된 서버로의 실제 SSH 접속.
- 파일 대화상자의 시작 폴더(43 부터 `defaultPath` 가 없으면 다운로드 폴더), MCP 확인 창의 항상 위, 원격 접속(HTTPS, 웹 푸시).
- macOS 빌드와 실행 전부 (워크플로의 Node 를 24 로 올리고 실행 파일 받기 단계를 넣었지만 돌려 보지 않았다).
