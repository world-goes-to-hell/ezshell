## 단계별 기준

### 1단계: 화면 테스트
- 임시 폴더에 있던 시험 스크립트와 시험용 SSH 서버를 `e2e/` 로 옮긴다. 시험용 프로필(`--user-data-dir`)만 쓰고 실제 앱 데이터는 건드리지 않는다.
- 한 명령으로: 빌드된 앱을 띄우고, 스크립트를 차례로 돌리고, 앱을 끝낸다 (남은 `electron.exe` 가 CDP 포트를 잡는 문제 포함).
- 처음에는 서버가 필요 없는 것(로컬 터미널 분할, 단축키, 로그 강조, 분리 창 위치)과 시험용 SSH 서버로 되는 것(분할·칸 옮기기)만 넣는다.

### 2단계: `main.js` 나누기
- 동작을 바꾸지 않고 옮기기만 한다. 한 묶음을 옮길 때마다 단위 테스트와 화면 테스트를 돌린다.
- 순서: 창 만들기(분리 창 다섯 종류) → 업데이트 → SFTP → SSH 연결·재연결.
- 보안 경계(본창에서 온 요청만 받는 검사, 잠금 중 거부)는 그대로 옮기고 옮긴 뒤 다시 확인한다.
- 새 파일은 `MAIN_RUNTIME_MODULES` / `MAIN_RUNTIME_DIRECTORIES` 에 넣는다.

### 3단계: Electron 업그레이드
- 시작 전에 28 이후 버전별 변경 사항을 공식 문서로 확인한다.
- 확인할 곳: `node-pty`·`oracledb` 네이티브 파일, 아크릴 창 재질(`backgroundMaterial`), `electron-builder`·`electron-vite` 호환, `safeStorage`, 자동 업데이트.
- 올린 뒤 Node 18 때문에 넣은 우회 코드를 걷어낸다 (`src/mcp/sdk.js` 의 `globalThis.crypto`, `drivers/mssql.js` 의 `loadTedious`).
- 패키징된 설치본으로 확인한 뒤에만 끝난 것으로 본다.

### 4단계: 화면 설정 내보내기·가져오기
- 설정 > 백업에 `화면 설정` 하위 탭. 테마, 단축키, 패널 크기 같은 `localStorage` 설정을 파일로 내보내고 가져온다.
- 내보낼 키는 허용 목록으로 정한다 (목록에 없는 키는 내보내지도 가져오지도 않는다). 접속 정보·계정·경로처럼 PC 나 서버를 드러내는 값은 넣지 않는다.
- 가져올 때 값의 형식을 검사한다 (각 기능이 이미 갖고 있는 읽기 함수를 쓴다).

### 5단계: `globals.css` 나누기
- 규칙의 순서를 유지한 채 기능별 파일로 가른다 (순서가 바뀌면 같은 우선순위의 규칙이 뒤집힌다).
- 나누기 전후로 빌드된 CSS 의 규칙 순서가 같은지 비교한다.
- 결과: `globals.css` 는 목록만 남고(`@import` 순서가 곧 규칙 순서), 내용은 `styles/app/` 의 26개 파일과 `tailwind.css` 로 갔다. 원본을 구역 주석 자리에서 순서대로 잘랐고, 조각을 이어 붙이면 원본과 같다는 것을 스크립트로 확인했다. 렌더러를 나누기 전후로 각각 빌드한 CSS 4개가 바이트 단위로 같다 (`index-CwvlgTTq.css` 269,231바이트).
