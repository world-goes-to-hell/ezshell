# 디자인 개편: 각진 모던 스타일 + 한글 시인성

- 작성일: 2026-09-28
- 상태: 구현 완료, 사용자 확인 대기 (기본 테마 색: 무채색 + 블루. 흰 글자 대비 AA 확보를 위해 #3d7eff → #2f6fed)

## 목표 (사용자 요청)
1. 모던하고 깔끔한 디자인
2. 둥근 모서리를 모두 각지게
3. 한글을 지원하는 서체로 한글 시인성 개선

## 디자인 해석
개발자용 한국어 데스크톱 SSH 클라이언트의 개편. 레이아웃과 기능 구조(IA)는 유지하고,
모서리, 서체, 색상, 깊이 표현을 다시 설계한다.
(design-taste 스킬은 랜딩 페이지용이므로 형태 일관성, 서체, 색 절제, 대비 원칙만 적용한다)

## 현황 조사
| 항목 | 현재 상태 | 문제 |
|---|---|---|
| UI 서체 | Inter 번들 (라틴 전용) | 한글은 시스템 서체(맑은 고딕)로 대체되어 영문과 굵기/높이 불일치 |
| 터미널 서체 | JetBrains Mono 번들, D2Coding 은 대체 지정만 | D2Coding 미설치 PC 에서 한글 폭이 맞지 않는 서체로 대체 |
| font-family 선언 | CSS 에 약 45곳, 서체명 하드코딩 | 토큰(`--font-*`) 미사용 |
| border-radius | 237곳 (토큰 130, 하드코딩 px 약 80, 50% 원형 20) | 규칙 없이 4/6/8/12px 혼재 |
| 기본 테마 | Discord 색상 그대로 (`#313338`, Blurple `#5865f2`) | 개성 없는 기본값, glow/그라디언트 과다 |
| 테마 | 프리셋 20종, `data-theme` + variables.css | Dracula, Nord 등 브랜드 테마는 색 유지가 맞음 |

## 단계

### Phase 1. 서체 교체
- [x] Pretendard Variable(woff2) 과 D2Coding(woff2) 을 `assets/fonts` 에 번들, `@font-face` 정의 (Inter 제거)
- [x] `--font-sans`, `--font-mono` 토큰 정의 후 CSS 의 서체 하드코딩 약 45곳을 토큰으로 교체
- [x] 터미널 서체 체인: `"<선택 서체>", "D2Coding", monospace`. 터미널 서체 목록에 D2Coding 추가
- [x] 한글 조판 보정: 본문 `word-break: keep-all`, 행간 1.5 전후, 작은 글자의 자간 과축소 제거

### Phase 2. 모서리 전부 제거 (radius 0)
- [x] `--radius-*` 토큰을 모두 0 으로
- [x] 하드코딩 px radius 약 80곳을 토큰으로 교체 (이후 다시 둥글게 하고 싶을 때 토큰만 바꾸면 되도록)
- [x] 원형(50%) 요소 20곳: 상태 표시 점, 색상 견본, 스피너, 태그 점도 사각형으로
- [x] TSX 인라인 radius(Skeleton, TerminalPanel 등)와 framer-motion 애니메이션의 radius 값

### Phase 3. 색과 깊이 정리 (기본 테마)
- [x] 기본 다크/라이트 테마를 무채색 중심 + 단일 강조색으로 재설계
- [x] glow, 장식용 그라디언트 제거. 부드러운 그림자 대신 1px 경계선으로 층 구분 (각진 스타일과 일관)
- [x] 나머지 18개 프리셋(Dracula, Nord 등)은 색 유지, 모서리/서체/그림자 규칙만 공통 적용

### Phase 4. 검증

- [x] 주요 화면 캡처로 확인: 메인, 사이드바, 새 연결 모달, 설정 (터미널/분할/SFTP/명령 팔레트/토스트는 사용자 확인 필요)
- [x] 다크/라이트 양쪽, 한글 긴 세션명/폴더명 표시 확인
- [x] 남은 radius 전수 검색 (`border-radius` 중 0/토큰 이외 값 0건)

## 진행 중 발견/수정
- `--font-mono` 가 정의 없이 참조되고 있었음 → 공통 토큰으로 정의
- 정의되지 않은 CSS 변수 8개(`--accent-alpha`, `--danger`, `--text-tertiary` 등) → 기존 토큰 별칭으로 정의 (포커스 링 등이 보이지 않던 문제)
- button/input/select 가 본문 서체를 상속하지 않던 문제 → 공통 규칙 추가
- 하드코딩된 Blurple 반투명 색 11곳 → `color-mix(var(--accent))` 로 테마 연동
- 테마 편집기 기본값이 예전 기본 테마 복사본 → 프리셋에서 직접 파생

## 테마별 "강조색 위 글자색" (`--on-accent`)
- 문제: 선택된 버튼/탭/뱃지가 `background: var(--accent); color: white` 로 고정 → 밝은 강조색 테마(Ayu, Monokai, 고대비 등 16개)에서 흰 글자가 안 보임 (대비 1.1~3.7).
- 조치
  - 테마마다 `--on-accent` 추가: 강조색과의 WCAG 대비가 높은 쪽(흰색 / #16181c) 자동 선택. 흰색 4개, 짙은 색 16개.
  - 강조색 배경 위 흰 글자 26곳, 배경색을 글자색으로 쓰던 곳(`color: var(--bg-primary|bg-tertiary)`) 15곳 → `var(--on-accent)`.
  - 명명 테마의 `--gradient-accent` 를 강조색 단색으로 변경 (그라디언트 두 번째 색에서 글자 대비가 무너짐).
  - 세션 색으로 채운 분할 탭 글자: `lib/colorContrast.ts` 의 `readableTextColor()` 로 계산.
  - `.btn-create` 의 하드코딩 파랑(#3b82f6) → 테마 강조색.
- 검증: 실행 중 앱에서 20개 테마를 순회하며 "새 연결" 버튼 대비 측정. 19개 4.5:1 이상, Ocean Deep 4.3:1 (강조색이 중간 밝기라 두 후보 모두 4.5 미만, 굵은 글씨 기준 3:1 은 충족).
