# 로그인 후 root 전환 (su) — 터미널과 MCP

- 날짜: 2026-11-04
- 상태: 1단계(터미널) 구현 완료 · 2단계(MCP) 진행 예정

## 요구

root 로 바로 접속할 수 없는 서버는 일반 계정으로 로그인한 뒤 `su -` 로 root 가 된다. 이 과정을 앱이 해 주고, MCP 로 보내는 명령도 root 로 실행할 수 있어야 한다.

## 결정 사항

### 1. 세션 설정
- 세션 편집 > 고급 설정에 "로그인 후 root 로 전환 (su -)" 와 root 비밀번호를 둔다. root 비밀번호는 다른 비밀번호처럼 세션 파일에 마스터 비밀번호로 암호화되어 저장된다.
- MCP 용으로 "MCP 명령도 root 로 실행" 을 따로 둔다 (기본 꺼짐). 위 전환을 켠 세션에서만 켤 수 있다. 터미널에서 root 를 쓰는 것과 Claude 에게 root 를 주는 것은 다른 결정이라 나눈다.

### 2. 터미널
- 셸이 열리면 main 이 `su -` 를 보내고, 비밀번호 입력 문구(`Password:`, `암호:`, `비밀번호:`)가 10초 안에 나오면 비밀번호를 보낸다. 문구가 나오지 않으면 비밀번호를 보내지 않는다 (이미 root 이거나 su 가 묻지 않는 경우, 비밀번호가 명령으로 화면에 찍히지 않게).
- 실패 문구(`Authentication failure`, `인증 실패` 등)가 나오면 탭에 "root 전환 실패" 를 알린다. 터미널은 로그인 계정으로 그대로 쓸 수 있다.
- 재연결(자동, 재연결 버튼) 뒤에도 다시 전환한다.
- 비밀번호는 main 에서만 다룬다. 터미널 출력, 세션 로그, 명령어 기록에 남지 않는다 (su 는 비밀번호를 화면에 찍지 않는다).

### 3. MCP (`run_command`, `cd`)
- "MCP 명령도 root 로 실행" 을 켠 세션의 명령은 `su - root -c '<cd 와 명령>'` 으로 실행한다. su 는 터미널에서만 비밀번호를 받으므로 이 명령만 가상 터미널(pty)로 열고, 비밀번호 문구가 나오면 비밀번호를 보낸다. 문구 앞의 출력과 비밀번호 줄은 결과에서 뺀다.
- 가상 터미널이라 stdout 과 stderr 가 합쳐져 한 출력으로 온다. 종료 코드는 그대로 받는다.
- 확인 창: root 로 실행되는 명령은 창에 "root 권한으로 실행" 을 크게 보여 준다. 알림 수준이 "위험만" 이어도 root 명령은 "중간" 이상이면 항상 묻는다 (일반 계정보다 한 단계 엄격).
- `list_sessions` 에 `runs_as: "root"` 를 넣어 Claude 가 알게 한다.
- 감사 로그에 root 로 실행했는지 남긴다. 비밀번호는 어디에도 남기지 않는다.

### 4. 이번에 root 로 하지 않는 것
- 백그라운드 작업(`background: true`): 중지할 때 일반 계정으로는 root 프로세스를 죽일 수 없고, 가상 터미널에서는 작업 PID 를 따로 받을 수 없다. root 세션에서 요청하면 "root 세션에서는 아직 지원하지 않음" 으로 거부한다.
- 파일 쓰기(`write_file`, `edit_file`)와 전송(`upload_file`, `download_file`): SFTP 는 su 와 상관없이 로그인 계정 권한이다. 지금처럼 로그인 계정으로 동작하고, 도구 설명과 `list_sessions` 에 이 점을 적는다. (root 파일이 필요하면 Claude 는 `run_command` 로 다룬다.)

## 위험과 대응
- Claude 가 root 권한을 갖게 된다 → 세션별 별도 스위치(기본 꺼짐), root 명령 확인 기준 강화, 확인 창 표시.
- 비밀번호가 엉뚱한 곳에 입력됨 → 비밀번호 문구를 본 뒤에만, 한 번만 보낸다. 10초 안에 문구가 없으면 보내지 않는다.
- 비밀번호 노출 → main 에서만 쓰고 렌더러 이벤트·로그·Claude 응답에 넣지 않는다 (테스트로 확인).
