# SSH 터널 DB 클라이언트 (1단계: 조회)

- 상태: 구현 완료 (배포 전, 검토 반영함)
- 구분: 높음 (운영 DB 에 접속함, 계정 비밀번호를 다룸)
- 요청: SSH 연결이 되면 그 서버에서 도는 DB 를 자동으로 찾아 보여 주고, 계정을 넣으면 접속해서 쿼리로 데이터를 조회한다.

## 범위

| 1단계 (이번) | 2단계 (나중) |
|---|---|
| 연결 후 DB 자동 탐색 (포트 목록만) | 쓰기 모드 (트랜잭션, 커밋/롤백 버튼, 실행 전 확인) |
| MySQL / MariaDB, PostgreSQL | Oracle, MSSQL |
| 계정 입력, 선택해서 암호화 저장 | CSV 내보내기, 자동 완성 |
| 읽기 전용 접속 (DB 서버가 강제) | MCP 에서 DB 조회 |
| 스키마 트리, SQL 편집기, 결과 표 | |

## 동작 흐름

1. 탭의 SSH 연결이 수립되면 main 이 실행 채널 하나로 한 번만 명령을 보낸다.
   `(ss -ltnH || netstat -ltn) 2>/dev/null; echo ---; ps -eo comm= 2>/dev/null`
2. 열린 포트 중 DB 포트(3306·3307·5432·5433, 1521·1433 은 "지원 예정" 으로 표시)와 프로세스 이름(mysqld, mariadbd, postgres)을 맞춰 목록을 만든다. 결과는 메모리에만 둔다.
3. 상태바에 `DB 2` 표지가 붙는다. 누르면 목록(`MySQL 추정 · 127.0.0.1:3306`)과 `직접 추가`(내부망의 다른 DB 호스트)가 나온다.
4. 하나를 고르면 계정 창(사용자, 비밀번호, 기본 DB, "이 세션에 저장")이 뜬다.
5. 접속하면 DB 창(`?dbMode=true`)이 열린다. 왼쪽 스키마 트리, 위 SQL 편집기(CodeMirror, Ctrl+Enter 실행), 아래 결과 표.

## 터널

- 로컬 포트를 열지 않는다. 탭의 SSH 연결에서 `conn.forwardOut` 으로 받은 스트림을 드라이버에 바로 넘긴다 (`mysql2` 의 `stream`, `pg` 의 `stream`). PC 의 다른 프로그램이 localhost 포트로 DB 에 붙을 수 없다.
- 점프 호스트를 쓰는 세션도 탭 연결이 이미 점프를 거쳤으므로 그대로 된다.
- SSH 가 끊기면 DB 연결도 끊긴다. 다시 연결된 뒤 다음 쿼리 때 새로 접속한다.

## 운영 DB 보호 규칙

| 규칙 | 이유 |
|---|---|
| 자동 탐색은 포트·프로세스 목록만 본다. DB 에 접속해 보지 않는다 | MySQL 은 끝까지 가지 않은 접속을 세다가 `max_connect_errors` 를 넘으면 그 호스트를 막는다. 사용자가 고를 때만 접속한다 |
| 탐색은 연결마다 한 번, 설정에서 끌 수 있음 | 서버에 남는 흔적을 최소로 한다 |
| 읽기 전용은 DB 서버가 강제한다: MySQL `SET SESSION TRANSACTION READ ONLY`, PostgreSQL `SET default_transaction_read_only = on` | 앱이 SQL 글자를 보고 막는 방식은 우회된다. 서버가 쓰기를 거부한다 |
| 문장마다 자동 커밋. 트랜잭션을 열어 두지 않음 | 열린 트랜잭션은 MySQL undo / PostgreSQL vacuum 을 막는다 |
| 쿼리 제한 시간 30초 (MySQL `MAX_EXECUTION_TIME`, MariaDB `max_statement_time`, PostgreSQL `statement_timeout`) + 취소 버튼 (`KILL QUERY` / `pg_cancel_backend`) | 실수로 큰 조인을 돌려도 서버에서 멈춘다 |
| 결과는 1,000행·50MB 까지만 받고 나머지는 버림 (PostgreSQL 은 커서, MySQL 은 스트림을 끊고 다시 접속) | 앱 메모리와 회선, DB 의 결과 전송을 제한한다 |
| 접속은 DB 창마다 하나, 동시에 쿼리 하나 | DB 접속 수를 늘리지 않는다 |
| 앱을 잠그면 DB 창을 닫고 접속을 끊는다. 결과는 디스크에 쓰지 않는다 | 잠금 화면 뒤에 데이터가 남지 않게 |

## 계정 저장

- "이 세션에 저장" 을 켜면 세션 데이터(마스터 비밀번호로 암호화)에 `dbConnections` 로 남긴다. 끄면 메모리에만 두고 창을 닫으면 지운다.
- DB 오류 문구는 그대로 보여 주되 비밀번호는 넣지 않는다.

## 파일 (예정)

- main: `src/dbClient/` — `discovery.js`(탐색 결과 해석, 순수 함수), `drivers/mysql.js`, `drivers/postgres.js`(읽기 전용 설정, 제한, 취소), `connections.js`(창별 접속), `ipc.js`
- renderer: `components/DbClient/`(창, 스키마 트리, 결과 표), `lib/dbDiscovery.ts`
- 의존성: `mysql2`, `pg`, `pg-cursor` (모두 순수 JS, Electron 28 / Node 18 에서 동작)
- 새 `src/` 폴더라 `MAIN_RUNTIME_DIRECTORIES` 에 추가

## 테스트 / 검증

- 단위: 탐색 출력 해석(ss·netstat 형식, IPv6, 0.0.0.0/127.0.0.1), 읽기 전용 설정 문장, 행 제한, 시간 초과, 잠금 시 정리
- 실제: Docker 의 MySQL 8 · MariaDB · PostgreSQL 에 SSH 서버를 거쳐 접속, 읽기 전용에서 INSERT 거부, 30초 제한, 1,000행 제한, 취소

## 검토 반영 (2026-11-09)

독립 검토에서 HIGH 1건, MEDIUM 6건, LOW 5건이 나왔고 모두 고쳤다.

| 지적 | 처리 |
|---|---|
| HIGH: PostgreSQL 에서 `SELECT set_config('default_transaction_read_only','off',false)` 로 세션 기본값을 끄면 다음 쿼리 `WITH ... DELETE` 가 실행됨 | 쿼리마다 `BEGIN TRANSACTION READ ONLY` … `ROLLBACK` 으로 감싼다. 기본값과 상관없이 그 트랜잭션은 읽기 전용이고, 쿼리가 바꾼 설정은 ROLLBACK 으로 되돌아간다. 검사기도 `set_config` 를 거부한다 |
| MySQL 실행되는 주석 `/*! INTO OUTFILE ... */` 이 OUTFILE 검사를 피함 | `/*!`, `/*M!` 을 거부한다. MySQL 의 `--` 는 뒤에 공백이 있을 때만 주석으로 본다 |
| 시간 초과 처리의 안쪽 타이머가 지워지지 않아 3초 뒤 다음 쿼리의 접속을 끊음 | 타이머를 붙잡아 두고 끝날 때 지운다 |
| 접속하는 사이에 앱이 잠기면 잠긴 뒤에 DB 창이 열림 | 접속 뒤에 잠금을 다시 보고, 잠겼으면 접속을 닫는다 |
| 창을 못 만들면 접속이 남음, 동시에 열면 10개 제한을 넘음 | 창을 못 만들면 접속을 닫는다. 로그인 중인 것도 개수에 넣는다 |
| 다시 접속하는 중에 창을 닫으면 새 접속이 남음 | 세션에 닫힘 표시를 두고, 닫힌 뒤 만들어진 접속은 바로 끊는다 |
| DB 창이나 다른 페이지도 `db-open` 으로 SSH 서버가 임의 주소에 접속하게 할 수 있음 | `db-discover` / `db-open` 은 본창에서만 받는다 |
| LOW: 다른 세션·파일·잠금에 영향을 주는 함수 | `dblink*`, `pg_terminate_backend`, `pg_advisory_*`, `lo_*`, `pg_stat_reset*`, `GET_LOCK`, `LOAD_FILE` 등을 거부한다 (따옴표·스키마를 붙여도) |
| LOW: 끊긴 터널에서 PostgreSQL `end()` 가 끝나지 않음 | 채널도 함께 닫는다 |
| LOW: 취소가 겹치거나, 쿼리가 끝난 직후의 취소가 다음 쿼리를 멈춤 | 취소는 한 번에 하나, 접속한 뒤 그 쿼리가 아직 실행 중일 때만 보낸다 |
| LOW: mysql2 의 `error` 이벤트를 듣지 않는 틈 | 접속을 만들 때부터 끝까지 듣는다 |
| LOW: PostgreSQL `E'...'` 문자열 | 백슬래시 이스케이프를 읽는다 |
| (추가) MySQL 은 세션을 다시 읽기·쓰기로 바꾸는 `SET` 을 앱 검사만 막고 있었음 | PostgreSQL 과 같이 쿼리마다 `START TRANSACTION READ ONLY` … `ROLLBACK`. 검사를 거치지 않고 `SET SESSION TRANSACTION READ WRITE` 를 보낸 뒤에도 다음 INSERT 를 서버가 거부함을 확인 |

## 자동완성 (2026-11-09 추가)

- 키워드: `@codemirror/lang-sql` 의 MySQL/PostgreSQL 방언 (서버 요청 없음). `이름.` 뒤에서는 키워드를 내지 않는다.
- 테이블: 기본 스키마(MySQL 은 현재 DB, PostgreSQL 은 `current_schema()`)의 목록을 처음 한 번 읽는다.
- 열: 문장의 FROM/JOIN 에 나온 테이블(최대 4개), 또는 `별칭.`/`테이블.` 뒤에서 그 테이블 하나만 읽는다. 읽은 것은 창이 열린 동안 기억한다. 스키마 전체의 열은 읽지 않는다.
- 쿼리 실행 중에는 새로 읽지 않고, 창의 요청은 `serialQueue` 로 한 줄로 세운다.
- 글자를 치면 자동으로 뜨고(150ms), Ctrl+Space 로 연다. Enter/Tab 으로 고른다.
- 검증: PostgreSQL 16·MySQL 8 실제 DB 로 테이블 이름, 별칭 뒤 열, 점 뒤 키워드 제외, Ctrl+Space 목록을 확인했다. 자동완성이 서버에 보낸 요청은 테이블 목록 1번, 열 1번이었다.

## 여러 DB 보기·다중 계정·연결 테스트 (2026-11-09 추가)

요청: 관리자로 접속하면 DataGrip 처럼 모든 DB 를 보고 보일 DB·스키마를 고르고 싶다. 관리자 계정을 모르면 DB 마다 계정이 다르므로 여러 계정을 등록하고 싶다. DB 도 연결 테스트가 필요하다.

- 트리 맨 위 단계는 DB 목록 (PostgreSQL: 접속 권한 있는 DB, 템플릿 제외 / MySQL: 볼 수 있는 DB). 시스템 DB·스키마(`information_schema`, `pg_*`, `mysql`, `sys`, `performance_schema`)는 ⚡ 표시, 기본으로 숨김.
- 거르기 메뉴: 보일 DB, PostgreSQL 은 DB 별 보일 스키마. 노드에 `보이는 수/전체 수`. 선택은 계정별로 이 PC 의 localStorage.
- PostgreSQL 의 다른 DB 는 펼칠 때만 그 DB 에 짧게 접속해 목록을 읽고 끊는다 (창의 접속은 하나 그대로).
- 쿼리 DB 바꾸기: MySQL `USE`, PostgreSQL 재접속(읽기 전용 다시 확인). 실패하면 원래 DB 로 돌아간다. 이름은 서버가 준 목록에 있어야 한다.
- 다중 계정: 서버별로 묶은 목록, 계정 이름, 저장만, 삭제. 같은 사용자라도 기본 DB 가 다르면 다른 계정.
- 연결 테스트: 한 번 로그인해 제품·버전·DB·읽기 전용을 확인하고 바로 닫는다. 본창에서만 받는다.
- PostgreSQL 기본 DB 를 비우면 `postgres` → 사용자 이름 DB 순서로 접속 (실제 시험에서 관리자 계정 `admin` 으로 접속하지 못한 문제를 고침).
- 검증: 실제 DB 시험 19가지 통과 (관리자의 전체 DB, 다른 DB 펼치기 뒤 서버 접속 1개 유지, 전환 뒤 읽기 전용, 모르는 DB 거부, DB 별 계정은 권한 없는 DB 가 목록에 없음, 연결 테스트 뒤 남은 세션 0개, MySQL root/일반 계정). 기존 보안 시험 57개 다시 통과. 화면: 트리, 거르기 메뉴(스키마 하위 메뉴), 저장된 선택, 선택 상자로 전환.

남겨 둔 한계:
- 읽기 전용은 테이블 변경을 막는 것이다. 관리자 계정은 거부 목록에 없는 관리 함수를 실행할 수 있다. 운영 DB 에는 조회 권한만 있는 계정을 쓰기를 권한다 (릴리스 노트에 적음).
- `SELECT ... FOR UPDATE`(MySQL) 는 자동 커밋이라 문장이 끝날 때까지만 잠근다. 30초 제한 안에서 다른 쓰기를 기다리게 할 수 있다.
- SSL 로만 받는 DB(`hostssl`, `require_secure_transport`)는 아직 접속하지 못한다.
- 탐색은 Linux 의 `ss`/`netstat`/`ps` 를 쓴다. 다른 OS 나 실행 채널을 막은 서버에서는 목록이 비고 `직접 추가` 만 된다.

## 검증

- 테스트: 전체 1,990개 통과, 타입 검사 0 오류, 빌드 성공
- 실제 DB (Docker MySQL 8.0.46, MariaDB 11.8.9, PostgreSQL 16.15) 를 ssh2 SSH 서버의 포트 포워딩으로 접속해 엔진마다 시험했다: 틀린 비밀번호·닫힌 포트 문구, 터널 접속, 값 그대로 읽기, 1,000행 제한(더 큰 LIMIT 포함), 앱의 DELETE 거부, 서버의 쓰기 거부(MySQL INSERT·DDL, PostgreSQL WITH DELETE·FOR UPDATE), set_config 우회 차단과 되돌림, 실행되는 주석 거부, 3초 제한, 취소, 끝난 뒤의 취소는 무시, 스키마 트리, 창을 닫은 뒤 서버에 남은 세션 0개
- 화면 (실제 main 코드와 preload 로 DB 창을 띄움, PostgreSQL·MySQL): 미리보기 실행, Ctrl+Enter 로 커서 문장 실행, 1,000행 안내, 쓰기 거부 문구, 실행 중 취소, 표 스크롤
- 시험하지 못한 것: 실제 운영 서버(OpenSSH)에서의 탐색 명령, 상태바 표지·계정 창 화면 (본창은 잠금 해제가 필요해 타입 검사로만 확인)
