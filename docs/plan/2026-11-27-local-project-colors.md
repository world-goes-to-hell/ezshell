# 로컬 작업 카드 색: 직접 고르기와 자동 배분

상태: 완료 (2026-11-27)
요청: 2026-11-27 사용자. "사용자가 직접 색상 설정할 수 있도록, 자동 색상 배분도: 프로젝트 개수를 파악해서 알아서 색감을 배분"

## 지금 동작

`LocalProjectsTree.tsx` 의 `projectHue` 가 폴더 경로의 해시로 8가지 색상(hue) 중 하나를 고른다. 색은 CSS 의 `oklch(66% 0.14 <hue>)` 로 그려진다. 개수와 무관하게 해시로 고르므로 이웃한 작업끼리도 같은 색이 자주 나온다 (화면: saero3039-java·new, ai-brain·mbris-new).

## 설계

### 1. 자동 배분: 세 가지 방식

사용자 추가 요구(2026-11-27): 비슷한 색이 이웃하지 않는 것만큼, **이상한 색 조합이 나오지 않는 것**이 중요하다. 모든 작업을 **같은 색**으로 두는 기능도 둔다.

색상환을 기계적으로 N 등분하면 탁한 올리브·누런 연두 같은 색이 섞이고, 무지개처럼 어수선해진다. 그래서 색을 계산으로 만들지 않고 **고른 팔레트**에서 꺼낸다 (`lib/localProjectColors.ts` 의 `assignProjectHues`, 순수 함수).

- **조화로운 여러 색 (기본)**: 앱이 정한 10색 팔레트(파랑·청록·산호·보라·하늘·호박·장미·초록·남색·옥색)를 정해진 순서로 쓴다. 이 순서는 앞에서 몇 개를 잘라 써도 고르게 퍼지도록 짰다 (2개면 파랑·청록, 3개면 산호까지). 그래서 작업 개수에 맞춰 앞에서부터 꺼내면 이웃 카드는 서로 다른 계열이 되고, 탁한 색 구간(올리브·누런 연두)은 아예 쓰지 않는다. 10개를 넘으면 같은 순서를 반복한다.
- **비슷한 계열**: 사용자가 고른 기준 색을 가운데 두고 ±45° 안에서 개수만큼 나눈다. 이웃 카드는 그 범위의 양 끝을 번갈아 받아, 같은 계열 안에서 가장 멀어진다. 색 조합이 어긋날 일이 없다.
- **모두 같은 색**: 모든 작업이 기준 색 하나를 쓴다.

직접 고른 색이 있는 작업은 어떤 방식에서도 그 색을 쓴다. 조화 방식은 직접 고른 색과 25° 안쪽인 팔레트 색을 건너뛴다 (남은 색이 모자라면 건너뛰지 않음).

### 2. 직접 고르기와 방식 고르기

작업 머리줄의 우클릭 메뉴에 **색상…** 을 더한다 (모든 작업에서 메뉴가 뜨게 한다). 창은 두 부분이다.

- **이 작업**: 팔레트 10색 견본과 색상 슬라이더(0~359°). 고르는 즉시 카드에 반영. **자동으로** 는 이 작업의 직접 고른 색을 지운다.
- **모든 작업**: 자동 방식(조화로운 여러 색 / 비슷한 계열 / 모두 같은 색)과, 뒤의 두 방식에 쓰는 기준 색. **직접 고른 색 모두 지우기**.

색은 색상(hue)만 저장한다. 밝기와 채도는 지금처럼 앱이 정해서, 밝은·어두운 테마 모두에서 글자가 읽히게 한다.

### 3. 저장

`localStorage` 의 `ezshell.localProjectColors` 에 `{ scheme, baseHue, manual: { 폴더 키(pathKey): hue } }` 로 둔다 (작업 목록 `ezshell.localProjects` 와 같은 방식). 읽을 때 0~359 정수만 받고, 목록에 없는 폴더의 값은 무시한다. 바뀌면 창 이벤트로 알려 다른 화면도 다시 그린다.
