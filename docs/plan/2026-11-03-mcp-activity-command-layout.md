# MCP 활동: 긴 한 줄 명령을 읽기 쉽게 표시

- 날짜: 2026-11-03
- 상태: 구현 완료

## 문제

AI 는 `echo ...; docker exec ... sh -c '... | tail -4' | sed ... | cut ...; echo ...` 처럼 여러 명령을 `;` `&&` `|` 로 이어 붙인 한 줄 명령을 보낸다. 활동 패널은 이것을 폭에 맞춰 줄바꿈만 해서, 어디서 명령이 나뉘는지 알기 어렵다.

## 결정 사항

1. 표시만 바꾼다 (`lib/shellFormat.ts` 의 `formatShellCommand`). 실행되는 명령, 감사 로그, 확인 창은 원문 그대로다. 확인 창은 판단하는 화면이라 원문을 바꿔 보여 주면 안 된다. (2026-11-10 변경: 사용자 요청으로 확인 창도 정렬해서 보여 준다. 대신 `원문 보기` 버튼을 두고, 정렬 결과에서 공백을 뺀 글자가 원문과 다르면 정렬하지 않는다 (`isFaithfulLayout`). 실행·감사 로그는 여전히 원문이다.)
2. `;` `&` 와 원래 줄바꿈에서 새 줄로 나누고, `|` `|&` `&&` `||` 다음 명령은 들여쓴 줄에 놓는다. 연산자는 줄 끝에 남긴다. 그래서 화면에서 복사해 붙여 넣어도 bash 에서 같은 뜻으로 실행된다 (줄 맨 앞의 `|` 는 문법 오류다).
3. 따옴표, `$( )`, 백틱, `( )` 묶음 안에서는 나누지 않는다. `sh -c '...'` / `bash -c '...'` 처럼 `-c` 뒤의 작은따옴표 스크립트는 같은 규칙으로 한 단계 더 들여써서 나눈다 (작은따옴표 안의 줄바꿈은 그대로 같은 스크립트다).
4. 명령 이름, 옵션, 문자열, 변수, 연산자·리다이렉트, 주석을 색으로 구분한다. `2>&1` 같은 리다이렉트는 한 덩어리로 본다.
5. heredoc(`<<EOF`, `<<-EOF`): 여는 줄까지는 위 규칙대로 나누되, 그 줄에서 `<<EOF` 뒤의 연산자로는 나누지 않는다 (본문은 그 줄이 끝난 다음부터라서, 내리면 본문이 된다). 본문은 줄마다 글자·앞 공백까지 그대로 두고 문자열·# 주석·흔한 키워드(Python·셸·SQL)에만 색을 입힌다 (`highlightCodeLine`, 2026-11-04 추가). 끝 줄이 없거나 ( ) 안에 있는 heredoc 은 원문 그대로 둔다.
6. `sh -c '...'` 은 한 줄짜리 스크립트만 나눈다. 이미 여러 줄인 스크립트를 들여쓰면 그 안의 heredoc 본문이나 여러 줄 문자열이 바뀐다.
7. 닫히지 않은 따옴표·괄호는 원문 그대로 둔다.
8. 줄바꿈과 들여쓰기 말고는 글자를 더하거나 빼지 않는다 (테스트로 확인).
