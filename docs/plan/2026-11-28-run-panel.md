# 실행 패널과 사이드바 실행 요약 (2026-11-28)

사용자 결정: 실행 구성이 많은 프로젝트(MSA 30개)는 전체 목록을 오른쪽 작업 공간 패널의 `실행` 탭에 둔다(A 방식). 사이드바에는 요약만 둔다. 사이드바 우클릭으로 패널에서 할 수 있는 동작을 모두 할 수 있게 한다. 시안: `mockups/run-list-placement.html`(A), `mockups/run-list-many.html`(장면 3·4·7·8).

결정 4가지 (2026-11-28):
- 접는 기준은 사용자가 정한다 (설정, 기본 8개).
- 실행 중인 구성은 패널에서 모두 펼친다.
- ★ 고정 기능이 필요하다.
- 응답 없음 표시가 필요하다.

## 규칙
- 여러 에이전트가 같은 작업 폴더의 main 에서 일한다. 커밋하지 않는다. 테스트는 CLAUDE.md 의 "테스트 범위" 를 따른다. `npm run build` 전에는 electron-vite dev 가 떠 있지 않은지 확인하고, 함께 일하는 에이전트에게 알린다.
- 동작은 한곳에서 정의해 패널과 사이드바 우클릭이 같은 목록을 쓴다 (아래 "공통 동작").
- 에이전트(MCP `run_list` 등)와 기존 동작은 화면 배치와 무관하게 그대로다.

## 공통 동작 (`src/renderer/lib/runPresetActions.ts`, 담당 개발D가 먼저 만든다)
구성 하나에 대한 동작과 프로젝트 전체에 대한 동작을 설명 객체(라벨·아이콘·사용 가능 여부·실행 함수)로 만든다. 패널의 버튼·메뉴와 사이드바 우클릭 메뉴가 모두 이것을 쓴다.
- 구성 하나: 실행, 중지, 재기동, 로그 보기, 실행 진단, 에이전트에게 보내기(비정상 종료 때), 수정, 복제(있으면), 삭제, ★ 늘 보이기 / 고정 풀기, 패널에서 보기, 폴더 열기.
- 단계: 이 단계만 실행, 이 단계 중지.
- 프로젝트: 모두 실행, 모두 중지, 묶음 실행·중지·만들기·수정, 기동 순서 정하기, 구성 추가, 실행 패널 열기, 상태별 일괄 동작(실행 중 모두 중지, 종료한 것 모두 다시 실행).
- 실제 동작은 지금 있는 store 함수(`runPresetAction`, `requestAddRunPreset`, 묶음·기동 순서 창 열기 등)를 부른다. 새 IPC 는 꼭 필요할 때만 만든다.

## 1부: 실행 패널 (담당 개발D, codex-6)
- 작업 공간 패널(`Workspace/WorkspacePanel.tsx`, `lib/workspacePanel.ts` 의 섹션)에 `실행` 섹션을 더한다.
- 대상 프로젝트: 패널의 폴더(`useWorkspaceDirectory`)가 속한 로컬 작업. 사이드바의 "패널에서 보기"는 패널을 열고 그 프로젝트(와 그 구성)로 맞춘다. 패널 머리에 프로젝트 이름과 바꾸기(등록된 로컬 작업 목록)를 둔다.
- 표: 단계 번호·상태 점·이름(+상태 글)·포트·브랜치(하위 저장소가 있으면 그 저장소 브랜치, 공통과 다르면 강조)·동작 버튼. 문제 줄(비정상 종료·응답 없음)을 맨 위에 둔다. 나머지는 기동 단계별 무리로 묶는다 (무리 머리: 실행 수/전체, ▶ 이 단계만). 단계가 없으면 하위 저장소 폴더 → 이름순으로 묶는다.
- 머리: 거르기 칸(이름·폴더·포트), 상태 숫자(● 실행 중, ⚠ 종료, ◐ 응답 없음, 누르면 그 상태만), 묶음 고르기, 모두 실행/중지, 기동 순서 진행(n/m단계, 진행 막대).
- 키보드: ↑↓ 고르기, Enter 메뉴, Space 실행·중지, L 로그, R 재기동, Esc 거르기 지우기.
- 줄 고정: 포인터나 키보드 포커스가 표 안에 있으면 줄 순서를 바꾸지 않고 상태만 바꾼다.
- 줄 우클릭 메뉴는 공통 동작 그대로.

## 2부: 사이드바 실행 요약 (담당 개발F, codex-7)
- `Sidebar/RunPresetsSection.tsx`: 구성 수가 기준(설정 `실행 구성 접기 기준`, 기본 8, 설정 > 개발 탭) 이하면 지금과 똑같다. 넘으면 요약 모드로 바뀐다.
- 요약 모드: 요약 한 줄 `실행 30 · ● 12 · ⚠ 1 · ◐ 1 · [패널 ›]`, 그 아래 문제 줄(비정상 종료·응답 없음)과 ★ 고정 구성만. 숫자를 누르면 패널을 그 상태 거르기로 연다.
- 우클릭: 요약 줄과 빈 곳은 프로젝트 동작 전체 + "구성 고르기 ›"(하위 메뉴: 단계별 무리로 모든 구성, 고르면 그 구성의 동작 메뉴). 문제 줄·★ 줄은 구성 동작 전체. 그래서 패널을 열지 않고도 모든 동작이 된다. 하위 메뉴가 길면 메뉴 안에서 스크롤된다(`TerminalContextMenu.css` 의 max-height 가 이미 있다).
- ★ 고정: 프로젝트·구성 id 별로 저장(`runPresetStore` 저장 파일에 `pinned` 를 더하거나 renderer localStorage. 다른 PC 로 옮길 필요는 없으니 localStorage 로 충분). 기준 이하일 때는 ★ 가 표시만 된다.
- 기준 설정은 `SettingsModal.tsx` 개발 탭, localStorage.

## 3부: 응답 없음 (담당 개발C, codex-5)
- main(`src/ipc/runPresets.js`, `runStartOrder.js`): 실행 중인 구성 가운데 기동 순서에 기준이 `url`(헬스 URL) 또는 `ready`(포트)인 것을 30초마다 확인한다. 연속 2번 실패하면 `unresponsive: { since }`, 다시 응답하면 지운다. 확인은 루프백만(기존 `url` 기준 검사와 같은 제한), 동시에 4개까지, 요청마다 시간 제한 3초.
- 상태 전달: 기존 run 상태 이벤트에 필드를 더한다. `runPresetStore`·타입에 반영. MCP `run_list` 에도 `unresponsive` 를 싣는다.
- 단위 테스트(가짜 시계·가짜 확인 함수)와 문서(`docs/architecture/local-project-run.md`).

## 순서와 협업
1. 개발D가 `runPresetActions.ts` 의 모양(타입과 함수 이름)을 먼저 정해 개발F에게 알린다. 개발F는 그것을 기다리는 동안 기준 설정·요약 줄·★ 저장을 만든다.
2. 개발C는 독립적으로 3부. 끝나면 상태 필드 이름을 개발D·F에게 알린다.
3. 각자 끝나면 다른 Codex 한 명에게 리뷰를 받는다 (D↔F, C 는 D 가 리뷰).
4. 화면 테스트: 패널은 `e2e/specs/local-run-panel.js`(새로), 요약은 기존 `local-start-order`·`local-run-bundles`·`local-development-tasks` 를 고치거나 `local-run-summary.js`(새로). 구성 9개 이상인 시험 프로젝트가 필요하다.
5. 끝나면 개발B(claude-1)에게 결과(바꾼 파일, 테스트 결과, 남은 문제)를 보낸다.
