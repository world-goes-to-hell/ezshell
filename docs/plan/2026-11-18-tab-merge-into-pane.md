# 탭을 다른 탭의 칸으로 병합

상태: 구현 완료 (2026-11-18), 배포 전

## 요청

`탭으로 빼기` 의 반대 방향. 탭을 다른 탭의 칸으로 합친다. 같은 세션의 탭만 병합되고, 다른 세션의 탭을 병합하려 하면 병합할 수 없다고 안내한다.

## 결정 (사용자 승인)

- 끌어서 병합: 탭을 다른 탭의 터미널 칸 가운데에 놓으면 그 칸이 반으로 나뉘고 끌어온 탭의 셸이 새 칸(넓으면 오른쪽, 아니면 아래)이 된다. 본 탭 줄에서 끌 때 터미널 영역의 가장자리 30% 는 지금처럼 화면 나누기다.
- 빈 자리(`탭으로 옮긴 칸입니다`)에 놓으면 그 자리를 채운다.
- 탭 줄에서 다른 탭 위에 놓으면 그 탭으로 병합한다 (사용자 추가 요청, 2026-11-18). 자리는 메뉴와 같다. 탭 줄에서 탭 위에 놓는 동작은 원래 없었다 (순서 바꾸기도 없음). 분할 화면에서 다른 쪽 탭 줄의 빈 곳에 놓으면 지금처럼 탭이 그쪽으로 옮겨 가고, 탭 위에 놓으면 병합한다.
- 탭 우클릭 메뉴 `칸으로 병합: <탭 이름> (N번째 탭)`: 같은 세션의 다른 탭마다 한 줄. 자리는 빈 자리가 있으면 그곳, 없으면 가장 큰 칸.
- 같은 세션: 같은 저장 세션에서 연 탭(여러 번 연 것, 탭 복제, 탭으로 뺀 칸). 저장하지 않은 빠른 연결은 서버·포트·계정이 같을 때. 로컬 터미널은 로컬 터미널끼리.
- 병합할 수 없는 경우는 놓는 자리 표시(붉은색)와 알림으로 이유를 알린다: 다른 세션, 6칸이 찬 탭, 칸을 나눈 탭, 끊긴 탭, 그 탭의 연결을 쓰는 DB 탭·포트 포워딩, 너무 작은 칸.
- 병합되는 탭의 SFTP 패널과 로그 저장은 탭을 닫을 때처럼 끝난다.

### 놓을 위치 고르기 (사용자 추가 요청·승인, 2026-11-18)

- 탭을 칸에 놓을 때: 칸을 대각선으로 네 조각 내어 포인터에 가까운 쪽 절반에 들어간다 (이전에는 칸 모양으로 자동). 끄는 동안 그 절반을 칠하고 `이 칸의 왼쪽에 병합` 처럼 보여 준다.
- 칸 손잡이로 칸을 옮길 때: 가운데 40% 는 자리 바꾸기(이전과 같음), 가장자리 쪽은 끌던 칸을 빼서 놓은 칸의 그쪽 절반으로 옮기기.
- 본 탭 줄 탭의 `화면 나누기` 영역은 터미널 영역 가장자리 30% → 48px 띠 (그 안쪽을 칸 병합이 쓰도록). 띠에 들어가면 미리보기는 화면 절반.
- 탭 줄에서 탭 위에 놓을 때는 칸이 보이지 않으므로 자동 그대로.
- 구현: `lib/paneDropZones.ts`(+테스트 11개), `SplitChrome.tsx` 의 칸 놓기, `useTabDropOnPane.ts`, `tabToPane.ts` 의 `treeWithArrival`(`MergePlace.side`).

## 구현

- main `ssh-merge-tab` (`src/ipc/splitShells.js`): 탭의 셸 채널을 대상 탭의 분할 셸로 바꾼다 (탭 세션은 목록에서 빠지고 채널은 그대로). 본창에서 온 것만, 열린 탭 id 둘만 받고, 같은 연결이거나 서버·계정·점프 호스트가 같은지 다시 본다 (`sharedConn.sameServer`).
- 따로 연 탭의 연결은 병합 뒤 어느 탭의 것도 아니다. `sharedConn` 의 손님 목록(`addGuest`/`releaseGuest`)이 붙잡고 있다가 그 셸이 닫힐 때 연결과 점프 호스트를 끝낸다.
- 화면: 규칙은 `lib/tabMerge.ts`, 실행은 `lib/tabToPane.ts`, 끌어 놓기는 `hooks/useTabDropOnPane.ts`. 새 칸의 `SplitTerminal` 은 셸을 열지 않고 넘겨받는다 (`lib/incomingShells.ts`: 칸이 그려지기 전에 온 출력과 탭의 화면을 붙잡아 둔다).
- 로컬 터미널: 탭의 셸 id 가 새 칸의 셸이 된다 (`localPaneShells.adoptLocalPaneShell`).

## 확인

- 단위 테스트: `tabMerge.test.ts` 15개, `sharedConn.test.js` 에 손님 셸·같은 서버 판정 7개. 전체 통과.
- 화면 테스트 `ssh-tab-merge`(43항목, 탭 줄에서 탭 위에 놓기 포함: 터미널 영역을 벗어났다 와도 창으로 분리되지 않음): 따로 연 두 탭을 끌어서 병합(화면·셸 유지, 양쪽 입력), 가장자리는 화면 나누기 그대로, 다시 탭으로 빼기, 메뉴로 빈 자리에 병합, 로컬 탭을 SSH 탭에 놓으면 거부 표시와 알림, 병합된 칸 닫기 뒤 탭 유지. `local-split` 에 로컬 탭끼리의 병합.
- 다시 돌린 것: `ssh-panes`, `ssh-detach`, `ssh-split-retry`, `ssh-reconnect`.
- 확인하지 못한 것: 분할 화면(주·보조 패인)에서 탭 줄의 탭을 끌어 병합, 점프 호스트를 쓰는 세션, 병합된 칸의 연결이 끊겼을 때의 모습(칸에 `분할 터미널 연결 종료` 와 `재연결`: 재연결하면 대상 탭의 연결에 새 셸을 연다), 병합된 칸을 닫은 뒤 서버에 그 연결이 남지 않는지(연결 종료 호출은 단위 테스트로만 확인), 6칸·작은 칸 거부의 화면, 실제 서버.
