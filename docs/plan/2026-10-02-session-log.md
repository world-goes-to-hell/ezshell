# 세션 로그 저장

- 날짜: 2026-10-02
- 구분: 중간 (터미널 출력을 디스크에 쓰는 기능. 사용자가 켠 탭만 기록)
- 상태: 구현·검증 완료, 설치본 반영 대기

## 목적
탭의 터미널 출력을 일반 텍스트 파일로 남긴다. 지금은 화면을 벗어난 내용을 따로 보관할 방법이 없다.

## 결정
- main 프로세스에서 기록한다. 화면이 다시 그려지거나 탭이 창으로 분리되어도 SSH 출력은 main 을 지나간다.
- 터미널 해석은 `@xterm/headless`(5.5.0)에 맡기고, 줄바꿈이 처리될 때 완성된 줄을 읽어 기록한다.
  직접 만든 필터는 터미널 너비를 넘는 명령줄에서 깨진다(readline 이 오른쪽 끝에서 `공백 + CR` 을 보낸다).
- 전체 화면 프로그램(대체 화면 버퍼) 구간은 기록하지 않고 표시 한 줄만 남긴다.
- 수동 시작/중지. 탭의 주 터미널만 기록한다(탭 안 분할 셸 제외).
- 파일: `문서\ezShell Logs\<세션 이름>_<YYYYMMDD-HHmmss>.log`. 이름의 경로 문자는 `_` 로 바꾼다.
- 자동 재연결되면 같은 파일에 이어 쓴다. 연결이 완전히 끊기거나 탭을 닫으면 기록을 끝낸다.
- 쓰기는 200ms 묶음으로 동기 기록한다. 앱 종료 때 남은 내용을 바로 내려쓸 수 있어야 한다.

## 테스트 (로직만)
- `lineRecorder`: 색상 제거, 백스페이스 수정, CR 덮어쓰기, 너비를 넘는 줄, 한글 지우기, 대체 화면 구간, 끝나지 않은 마지막 줄, 조각으로 나뉜 여러 바이트 문자
- `logFile`: 경로 문자·예약 이름·빈 이름·긴 이름, 폴더 밖으로 나가지 않음, 시각 형식
- `sessionLogger`: 머리글·꼬리글, 기록 중이 아닐 때 쓰기 무시, 중복 시작, 같은 초에 두 번 시작, 쓰기 실패 시 기록만 중단, 중지 뒤 쓰기 무시
- 화면과 main 연결: typecheck + 실제 앱 확인 1회

## 검토 반영
- 쓰기 실패로 끝난 로그에 줄이 더 들어오면 닫힌 파일 번호에 쓸 수 있었다 → 항목에 `closed` 표시를 두고 이후 쓰기를 막는다. 실패 알림은 한 번만 보낸다.
- 쓰기 실패와 중지가 겹치면 `stop()` 이 끝나지 않을 수 있었다 → recorder 가 폐기되면 기다리던 `finish()` 를 풀어 준다.
- 출력이 너무 많아 xterm 대기열이 가득 차면 조용히 빠졌다 → 기록을 중단하고 알린다.
- `onLineFeed` / `onBufferChange` 처리부를 try/catch 로 감쌌다 (xterm 의 타이머 안에서 실행되어 호출자의 try/catch 밖이다).
- recorder 를 만들지 못하면 연 파일을 닫는다.
- 창을 새로 고친 뒤 표시 동기화: 목록을 받는 동안 바뀐 탭만 이벤트 쪽을 따르고 나머지는 목록을 따른다.

## 알려진 한계
- 로그를 켜기 전에 이미 출력된 프롬프트는 기록되지 않으므로, 첫 명령 줄에는 프롬프트가 없다.
- 앱을 끌 때는 recorder 가 아직 해석하지 못한 출력과 끝나지 않은 마지막 줄이 기록되지 않는다 (headless xterm 에 동기 쓰기가 없다).
- 탭 안 분할 셸, 분리된 터미널 창의 표시는 범위 밖이다. 분리된 창의 탭도 기록 자체는 계속된다.
- 문서 폴더가 OneDrive 나 네트워크 드라이브면 200ms 마다의 동기 쓰기가 main 을 지연시킬 수 있다.
- 분할 레이아웃의 탭에는 우클릭 메뉴가 없어 명령 팔레트(`로그 저장 시작/중지`)로만 켜고 끈다.
