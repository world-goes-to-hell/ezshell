# 분리 창의 위치 기억

상태: 구현 완료 (2026-11-17), 배포 전

## 요청

SFTP 패널처럼 창으로 분리할 수 있는 기능들이, 사용자가 쓰던 위치를 기억했다가 다음에 분리할 때 그 자리에 열리게 한다.

## 결정 (사용자 승인)

- 종류별로 하나씩 기억한다: SFTP, 터미널, MCP 활동, 서버 파일(미리보기·편집·실시간 보기·컨테이너 로그), DB.
- 기억하는 것: 위치, 크기, 최대화 여부. `userData/detached-window-state.json` 에 숫자와 플래그만 쓴다.
- 같은 종류의 창이 그 자리에 이미 열려 있으면 30px 씩 오른쪽 아래로 비켜서 연다 (최대 10번, 화면 밖으로 나가면 저장된 자리 그대로).
- 저장된 자리가 지금 연결된 화면에 보이지 않으면 기본 크기로 열고 위치는 OS 가 정한다.
- 끌어서 분리: 코드 확인 결과, 놓은 위치에 창을 여는 동작은 원래 없었다 (창은 항상 OS 기본 위치에 열렸다). 그래서 끌어서 분리할 때도 기억한 자리에 연다.

## 구현

- `src/detachedPlaces.js`: `placeFor`(열 자리 계산), `readPlaces`/`writePlace`(종류별 저장, 목록에 있는 종류만), `trackWindow`(옮기거나 크기를 바꾼 뒤 0.5초, 그리고 닫을 때 저장).
- `src/windowState.js` 의 `usableState` 에 최소 크기 인자를 더했다 (분리 창은 본창보다 작을 수 있다).
- `main.js` 의 `detachedWindowPlace`: 다섯 `create*Window` 함수가 `open` → `options` → `track` 을 부른다. 아크릴 창은 최대화 대신 화면 채우기(`fill`)로 복원한다.

## 확인

- 단위 테스트 10개 (`detachedPlaces.test.js`), 전체 통과.
- 실제 앱(MCP 활동 창): 처음에는 기본 크기, 옮기고 크기를 바꾸면 저장, 닫았다 다시 열면 같은 자리·크기, 최대화 기억, 화면 밖 자리는 기본값.
- 확인하지 못한 것: SFTP·터미널·서버 파일·DB 창 (같은 세 함수를 붙였지만 화면으로 보지는 않았다), 같은 종류 두 창의 비켜 열기(계산은 단위 테스트), Glass(아크릴) 창의 채우기 복원, 모니터 두 대.
