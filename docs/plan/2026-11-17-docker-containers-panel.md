# 도커 컨테이너 패널과 컨테이너 로그 보기

작성일: 2026-11-17
상태: 1·2단계 구현 완료 (2026-11-17 사용자 승인), 3단계 남음
구분: 중간 (운영 서버에 명령을 보내는 기능이라 그 부분만 엄격히)

## 목표

SSH 탭에서 그 서버의 실행 중인 도커 컨테이너를 보고, 컨테이너의 로그를 실시간으로 본다. 사용자가 패널을 열었을 때만 서버에 묻는다.

## 지금 있는 것

- 터미널 머리줄의 `서버 모니터링`(`ServerMonitor.tsx`)은 열려 있는 동안 5초마다 `ssh-exec-command` 로 명령 4개를 보낸다. 이 IPC 는 창이 준 명령 글자를 그대로 실행한다.
- DB 탐색(`src/dbClient/discovery.js`)은 연결마다 한 번 `timeout 3 docker ps --format ...` 를 실행한다 (도커가 멈춰 있어도 3초 안에 끝남).
- 파일 실시간 보기(`RemoteLogView.tsx`, `remoteFiles/logTail.js`)는 SFTP `stat` 으로 늘어난 부분만 읽는다. 컨테이너 로그는 파일로 읽을 수 없어(root 전용 경로) 이 경로를 쓸 수 없다.

## 설계

### 1. 컨테이너 패널
- 터미널 머리줄에 `컨테이너` 버튼을 더한다 (포트 포워딩·서버 모니터링 옆, 같은 방식으로 터미널 영역 오른쪽에 뜨는 패널, `Terminal/ContainerPanel.tsx`).
- 열 때 한 번 조회한다. 그 뒤는 `새로고침` 버튼이 기본이고, `자동 새로고침`(10초, 기본 꺼짐)을 켜면 패널이 열려 있고 창이 보이는 동안만 다시 묻는다. 닫으면 멈춘다.
- 목록: 이름, 이미지, 상태(`Up 3 days` 등), 내보낸 포트. `중지된 것도 보기` 를 켜면 `-a`.
- 도커가 없으면 "이 서버에는 도커가 없습니다", 권한이 없으면 "이 계정은 도커를 쓸 권한이 없습니다 (docker 그룹)" 한 줄. `sudo` 는 쓰지 않는다 (1차).
- 줄마다 동작:
  - `로그 보기`: 컨테이너 로그 창을 연다 (2절).
  - `셸 들어가기`: `docker exec -it <이름> sh` 를 터미널 입력줄에 넣는다. 실행하지 않는다 (사용자가 Enter).
  - `이름 복사`, `ID 복사`.
  - `재시작`/`중지`: 명령을 입력줄에 넣기만 한다 (운영 서버에서 앱이 대신 실행하지 않는다).

### 2. 컨테이너 로그 보기
- 창 하나에 컨테이너 하나 (`?containerLogMode=true&logId=...`, 파일 창과 같은 틀). 처음에 마지막 500줄, 그 뒤로 새 줄을 이어 붙인다.
- 방식: 서버에서 `docker logs -f` 를 띄워 두지 않는다. 짧은 조회를 되풀이한다: `timeout 5 docker logs --timestamps --since <마지막으로 받은 시각> --tail 2000 <컨테이너>`. 각 조회는 끝나면 서버에 아무것도 남지 않는다 (`-f` 는 채널을 닫아도 다음 출력이 있을 때까지 프로세스가 남을 수 있고, 연결당 채널 하나를 계속 차지한다).
- 간격: 새 줄을 받으면 1초, 조용하면 2 → 3 → 5초, 창이 가려지면 15초, 실패하면 5초. 답을 받은 뒤에만 다음 조회를 예약한다 (겹치지 않음). 파일 실시간 보기의 0.2초보다 느린 것은 조회마다 서버에서 도커 명령 하나가 실행되기 때문이다.
- 중복 없이 잇기: 줄마다 붙는 시각(`--timestamps`, 나노초)을 main 이 기억하고, 그 시각 이하의 줄은 버린다. 화면에는 시각을 뗀 줄을 보낸다 (`시각 보기` 토글로 다시 보이게).
- 한 번에 1MB 까지, 넘으면 "N 건너뜀" 표시. 창에는 최근 약 5MB 만 둔다.
- 화면은 파일 실시간 보기의 것을 재사용한다: 수준별 강조(`lib/logLevels.ts`), 찾기, 기준점, 일시정지, 맨 아래 따라가기. `RemoteLogView` 가 파일 문서에 얼마나 묶여 있는지는 구현 때 확인하고, 묶여 있으면 공통 부분을 떼어 낸다.
- stderr 로 나온 줄도 함께 보여 준다 (도커는 컨테이너의 stderr 를 stderr 로 돌려준다).

### 3. main (`src/containers/`)
- `container-list`(본창만): 인자는 세션 id 와 `all` 여부. 명령은 main 에 고정: `timeout 5 docker ps [-a] --format '{{json .}}'`. 결과는 줄마다 JSON 으로 읽고 필요한 필드만 창에 보낸다 (200개까지).
- `container-log-open`(본창만): 세션 id 와 컨테이너 이름. 이름은 `[A-Za-z0-9][A-Za-z0-9_.-]{0,127}` 만 받고, 직전 `container-list` 결과에 있던 이름이어야 한다. 로그 창을 만들고 `logId` 를 준다.
- `container-log-poll`: 그 로그 창(webContents id 가 맞아야 함)만 부를 수 있다. main 이 명령을 조립한다. 창은 명령 글자를 보내지 않는다.
- 실행은 탭의 SSH 연결에 `exec` 채널을 열어서 하고, 출력 상한(1MB)을 넘거나 8초가 지나면 채널을 닫는다.
- 앱을 잠그면 로그 창을 닫고 조회를 거부한다 (로그에 비밀이 섞일 수 있다). 로그 내용은 디스크에 쓰지 않는다.
- 새 `src/` 폴더라서 `MAIN_RUNTIME_DIRECTORIES` 에 `containers` 를 더한다.

## 바꾸면 안 되는 것 (구현 때 지킬 것)
- 앱이 스스로 조회를 시작하지 않는다: 패널이나 로그 창을 사용자가 연 동안에만 묻는다.
- 창은 서버에서 실행할 명령 글자를 보내지 않는다. 컨테이너 이름은 형식 검사와 목록 대조를 모두 거친다 (이름이 명령줄에 들어간다).
- 컨테이너를 바꾸는 명령(재시작·중지·삭제·exec)은 앱이 실행하지 않는다. 입력줄에 넣기까지만.
- 조회는 겹치지 않고, 모든 명령에 `timeout` 이 있다 (멈춘 도커 데몬이 채널을 붙잡지 않게).

## 함께 알릴 것 (이번 범위 밖)
- 기존 `ssh-exec-command` 는 보낸 창을 확인하지 않고 받은 명령을 그대로 실행한다. 서버 모니터링이 쓰는 통로인데, 이 기능은 거기에 얹지 않고 고정 명령 IPC 를 따로 둔다. 기존 통로를 본창 전용·고정 명령으로 좁히는 것은 별도 작업으로 제안한다.

## 단계
1. 컨테이너 패널 (목록, 새로고침, 입력줄에 넣는 동작)
2. 컨테이너 로그 창
3. 세션 설정 `접속하면 컨테이너 패널 열기` (세션 편집 > 고급 설정)

## 테스트·검증
- 단위: `docker ps` JSON 줄 해석(깨진 줄·필드 누락), 컨테이너 이름 검사, 로그 줄의 시각 분리와 "이 시각 이하 버리기", 조회 간격 계산.
- 실제 확인: 로컬 도커가 있는 서버로 E2E (목록, 로그가 이어 붙는지, 같은 줄이 두 번 나오지 않는지, 창을 닫으면 서버에 `docker logs` 프로세스가 남지 않는지).
