# Agent Chat View (에이전트 칸을 채팅으로 보기)

[공통 작업 규칙과 기능별 목록](../../CLAUDE.md)

로컬 터미널 칸에서 돌고 있는 Claude Code·Codex 를 그 칸 위에 덮는 채팅 화면으로 본다 (`AgentChat/AgentChatCover.tsx`). 셸·에이전트는 그대로 돌고 xterm 도 아래에 마운트된 채라, 언제든 터미널로 돌아간다. 전환은 우클릭 `채팅으로 보기`, 단축키 `Ctrl+Shift+F11`(`toggle-agent-chat`, 설정에서 바꿈. 터미널·채팅 입력칸 안에서 눌리므로 앱 전체 처리기가 아니라 칸이 직접 받는다: `lib/shortcutMatch.ts`), 머리줄 `터미널` 버튼. Orca(MIT) 의 terminal-backed native chat 을 참고했고, Orca 와 달리 한 탭의 모든 칸이 동시에 채팅일 수 있다. 설계·진행: `docs/plan/2026-11-19-agent-chat-view.md`. 시험: `local-agent-chat` 명세 (`e2e/support/agentChatApp.js`).
- 보기 상태는 칸이 아니라 셸 id 에 둔다 (`stores/agentChatStore.ts`). 칸 자리 바꾸기·탭으로 빼기·병합·창 새로고침 뒤에도 따라간다. 잠그면 모두 터미널로 돌아가고 대화를 지운다 (`App.tsx` 의 잠금 effect, main 은 `agentChats.closeAll()`).
- main 은 `src/agentChat/`: 셸 → 에이전트(메시지 목록) → 세션 id(사용량 보고: Claude 상태 줄의 `session_id`, Codex 는 `codexUsageWatcher.fileOf`) → 기록 파일. 끝 2MB 를 읽고, 0.5초마다 `stat` 해서 늘어난 부분만 읽고, 위로 올리면 앞 2MB 씩 더 읽는다. 줄 해석은 허용 목록 방식이다 (Claude 는 같은 `message.id` 의 블록이 한 줄씩, Codex 는 `item_completed` 만): 모르는 줄 종류는 버린다. 화면에는 잘라 낸 항목만(`items.js` 의 `LIMITS`) `agent-chat-frame` 으로 간다. 파일 경로는 보내지 않는다.
- 슬래시 명령(`claudeTranscript.js` 의 `commandText`): Claude 는 `/compact` 같은 명령을 끝난 뒤에야 `<command-name>/compact</command-name>…` 로 기록한다. 채팅은 그 줄을 사용자 말풍선 `/compact`(인자가 있으면 함께)로 보여 주고, 명령 출력(`<local-command-stdout>`)은 보이지 않는다. 압축은 경계 줄만 "이전 대화를 요약했습니다"이고 뒤따르는 요약 줄(`isCompactSummary`)은 표시하지 않는다 (요약이 중복 표시되지 않게 한다). Claude 는 경계를 먼저, 그것을 요청한 `/compact` 를 맨 나중에 쓰므로, 파서가 표시를 들고 있다가 `/compact` 다음에 내보낸다 (자동 압축은 다음 항목 앞에. 아무것도 안 오면 `flush`: 처음 읽기는 바로, 따라 읽기는 1.5초 뒤). 채팅에서 보낸 글은 기록에 오기 전에도 바로 말풍선으로 보이고(`echoSend`, 기록과 맞으면 `reconcileChatEchoes` 가 바꿈), 터미널 보기로 갔다 와도 셸별로 30분 남는다 (`agentChatStore` 의 `keptEchoes`, 그 글의 "답변 생성 중" 표시(`reply`)도 함께, 잠그면 지움).
- 답변 속 링크(`src/agentChat/links.js`): 이 PC 의 파일·폴더와 웹 주소만, 대화에 나온 링크만(`knowsLink`) 연다. 에이전트가 쓰는 두 형식을 읽는다: 줄 번호(Codex `D:/…/README.md:187`, `:12:5`, `#L42`)는 떼어 내 파일 창을 그 줄에서 열고(`openLocalFile` 의 `line` → `registerLocal` 의 `revealLine`, 열린 창은 `remote-file-reveal-line`), 상대 경로(Claude `docs/x.md`, `../plan/a.md`)는 그 에이전트의 작업 폴더(`chats.cwdOf`, `resolve` 의 `cwd`)를 기준으로 푼다. 화면의 `LOCAL_PATH_LINK` 도 상대 경로를 링크로 그린다. 바꾸면 안 되는 것: 마크다운 라이브러리는 링크를 인코딩한 뒤 검사하므로 상대 경로 판정은 `%5C`·`%2F` 로 시작하는 것을 뺀다 (안 그러면 `\\host\share` 가 통과한다). 인라인 코드로 적은 경로(`D:\…\a.sql`, `src/a.js:12`, `docs/plan/`)도 링크다: 화면은 `markdownRender.ts` 의 `CODE_PATH`, main 은 `links.js` 의 같은 정규식 (둘을 같게 유지. 폴더 없는 파일 이름·확장자 없는 `a/b` 는 글자로 둔다). 인라인 코드로 적은 폴더 링크(`mockups/`)를 누르면 작업 공간의 `파일` 트리가 열리고 그 폴더까지 펼쳐 잠깐 강조한다: main 은 `how: 'workspace'` 로 폴더의 실제 경로만 돌려주고, 화면이 `workspacePanelStore.revealFolder` 로 요청을 둔다. 패널의 폴더가 그 채팅 셸의 폴더로 읽힌 뒤에 `WorkspaceFiles` 가 트리를 펼친다 (`TreeRevealContext`, 경로 계산 `lib/workspaceDetails.ts` 의 `relativeInside`·`revealStep`). 패널 폴더 밖이거나 3초 안에 그 셸의 폴더가 읽히지 않으면 예전처럼 파일 탐색기로 연다. 마크다운 링크로 적은 폴더는 링크 미리보기가 받고, 우클릭 메뉴에 `작업 공간에서 보기` 가 있다.
- MCP 도구(Claude 의 `mcp__…`, Codex 의 `McpToolCall`)의 인자와 결과는 JSON 이라, 들여쓴 목록으로 바꿔 보여 준다 (`items.js` 의 `readableOutput`·`readableValue`: 여러 줄 글은 `key: |` 아래에 제 줄바꿈대로). 결과 전체가 JSON 객체·배열일 때만 바꾼다. 명령 출력(`Bash`, Codex 명령)은 바꾸지 않는다: `cat package.json` 의 출력이 원래 모양과 달라 보이면 안 된다. `read_inbox` 같은 도구 결과의 `\n` 은 줄바꿈으로 표시한다.
- 바꾸면 안 되는 것 (보내기): 에이전트가 살아 있고 확인 대기 화면이 없으며 자신의 입력칸이 비었을 때만 괄호 붙여넣기로 채팅 글을 넣는다 (`agentInboxWake.submitText`). 일반 채팅은 붙인 뒤 500ms 부터 입력칸을 본다. 원문이나 CLI 의 붙여넣기 표시가 보이고 100ms 뒤에도 같거나, 다르게 그려진 입력칸이 바뀐 뒤 300ms 동안 그대로면 Enter 를 한 번 보낸다. 5초가 되면 붙인 뒤 입력칸에 흐린 제안이 아닌 글이 나타났을 때, 같은 에이전트의 입력칸인지, 승인 질문과 사용자 키 입력·Esc 가 없는지 확인하고 한 번 보낸다. 바꾸면 안 되는 것: 일반 보내기는 Orca 처럼 그 셸(PTY)에 보낸다. Claude 입력칸 위 가로줄의 이름(세션 이름 등, `targetOf`)이 붙여 넣기 전후로 달라도 거절하지 않는다. 이름 비교는 서브에이전트 이름을 겨눈 보내기(`chatSend` 의 `target`, `draft.verify`)에만 한다. 참고: `docs/fix/2026-11-24-chat-send-target-changed.md`. 이름이 길면 Claude 가 가로줄을 `─` 없이 ` 이름… ─` 로 그리는데, 이것도 입력칸 테두리로 읽는다 (`claudeRuleLabel`). 입력칸 바깥의 진행 출력은 대기에 영향을 주지 않는다. 붙인 뒤 짧은 칸에서 Claude 의 프롬프트가 가려지면 `↑ N more`·`↓ N more` 구분선이나 아래 구분선과 바닥줄로 입력칸을 확인한다. 스크롤 구분선으로 찾은 입력칸 안에 셸 프롬프트로 보이는 행이 있으면 Enter 를 보내지 않는다. 속도 명령·확인 시험·이미지 첨부는 기존의 판정을 쓴다. 한 PTY 의 채팅은 순서대로 처리하며 다음 전송은 직전 Enter 뒤 입력칸이 빌 때까지 기다린다. Enter 를 보내지 못한 앱의 글은 전체가 일치할 때만 지운 뒤 빈 칸을 확인한다. 셸 프롬프트에 Enter 가 가면 글이 명령으로 실행될 수 있다. `cleanChatText` 는 붙여넣기를 일찍 종료할 수 있는 ESC 등의 제어 문자를 거부한다. 작업 중에도 보낸다 (Claude 는 다음 차례에 읽는다). 시점은 Orca(MIT)의 `native-chat-paste-landed.ts` 와 같다 (일치는 Enter 시점을 고르는 용도이지 관문이 아니다). 원문 일치를 요구하면 CLI가 바꿔 그린 이모지·결합 문자나 자동 줄바꿈으로 `not-drawn` 이 날 수 있다 (`docs/fix/2026-11-23-chat-send-not-drawn.md`). 바꾸면 안 되는 것: Codex 는 붙여넣기를 다 처리하기 전의 Enter 를 줄바꿈으로 삼키므로 500ms 전에는 Enter 를 보내지 않는다. 5초 마감에도 빈 입력칸·흐린 제안에는 보내지 않는다 (Claude 는 대기열이 있을 때 빈 입력칸 Enter 로 대기열을 바로 보낸다). Enter 는 한 번뿐이고 다시 보내지 않는다 (재시도는 중복 위험이 있어 뺐다, 대신 아래 전송 확인).
- Claude `강제로 보내기`는 사용자가 전송 요청 때 봤던 같은 Claude 입력칸에서 초안을 지운다. 140ms 뒤 이전과 다른 초안이 남아 있으면 같은 칸에서 한 번 더 지우고 빈 칸을 확인한다. 빈 화면 없이 새 붙여넣기가 보이면 이전 이미지·본문 표시가 남아 있지 않은지 확인한다. 이미지가 있으면 첨부 수만큼 서로 다른 `[Image #N]` 과 본문 또는 `[Pasted text #N]` 을 함께 확인한다. 확인 질문, 셸 프롬프트, 바뀐 입력 대상에서는 제출하지 않으며 Enter 는 한 번만 시도한다. 재현과 수정은 `docs/fix/2026-11-25-claude-force-send-images.md`에 있다.
- 새 붙여넣기 뒤에는 깨우기와 같은 입력칸 경계를 읽고 본문 전체 또는 CLI가 그린 붙여넣기 표시를 대조한다. 완전한 입력칸을 확인하면 커서가 첫 줄에 있거나 바깥 안내가 다시 그려져도 전송한다. 경계가 분명하지 않은 화면에서는 커서와 입력칸의 변화를 함께 본다. Codex 속도 확인과 이미지 단계별 붙여넣기는 키가 삽입될 위치까지 계속 확인한다. [실제 CLI 표본](../../src/ipc/fixtures/agent-inbox-pty/README.md)
- Claude 대기 항목 아래에 `Press up to edit queued messages`가 표시되면 채팅도 빈 입력칸에 붙여넣을 수 있다. 새 본문이 그려지는 것을 확인한 뒤 Enter를 보내 기존 대기열 뒤에 추가한다. [재현과 수정](../fix/2026-11-25-claude-inbox-notice-with-queued-messages.md)
- 질문별 토큰: 턴의 마지막 항목 아래에 `토큰 입력 12.3만 · 출력 3,412 · 캐시 98% · 52초` 가 붙는다 (`.agent-chat-usage`, 포인터를 올리면 정확한 수, `lib/agentTurnUsage.ts`). main 의 `src/agentChat/turnUsage.js` 가 턴을 시작한 사용자 항목에 `usage` 를 붙여 다시 보낸다. Claude 는 응답의 `message.usage`(한 응답이 블록 줄마다 같은 값을 되풀이하므로 `message.id` 로 한 번만, 입력은 캐시 쓰기·읽기 포함)와 `system/turn_duration`, Codex 는 `token_count` 의 `last_token_usage`(같은 이벤트가 두 번 올 수 있어 누계 `total_tokens` 로 한 번만)와 `task_complete` 의 `duration_ms`. 출력에는 생각 토큰이 들어 있다. 하위 에이전트(Claude 의 별도 기록 파일)는 세지 않는다. 같은 줄 끝에 그 질문이 쓴 한도(`5시간 +2% · 주간 <1%`)도 붙는다: 질문 전과 마지막 답변 뒤의 계정 사용률 차이라, 같은 계정의 다른 세션이 그동안 쓴 것도 들어간다 (툴팁에 적음). 창이 끝나면(`resetsAt` 이 1분 넘게 뒤로) 새 창의 값을 그대로 쓴다 (`turnUsage.js` 의 `windowUsed`). Codex 는 `token_count` 의 `rate_limits` 로 기록에서 바로 계산한다 (Codex 는 정수 %라 작은 질문은 `<1%`). Claude 기록에는 한도가 없어서, main 이 상태 줄 보고(`agent-usage`)의 한도를 바뀔 때마다 시각과 함께 메모리에 모으고(`src/agentChat/limitHistory.js`, 에이전트가 아니라 계정 값이라 종류별로 하나), `chats.js` 가 질문 시각 직전 값과 마지막 답변 10초 뒤 값을 비교한다 (`claudeLimits`). 상태 줄 보고는 답변이 기록된 뒤에 오므로 마지막 질문은 2분 동안 틱마다 다시 계산해 바뀌면 다시 보낸다 (`refreshLimits`). 그래서 Claude 의 한도는 앱이 켜져 있는 동안 물은 질문에만 보인다. 위로 올려 앞부분을 읽을 때 그 부분의 첫 줄들은 앞 부분의 마지막 질문 몫이라, 다음으로 읽는 부분에서 그 질문을 찾을 때까지 들고 있다 (`beginOlder`/`endOlder`, `chats.js` 의 `older`).
- 슬래시 명령. 입력칸이 `/` 와 낱말 하나이면 명령 목록이 뜬다 (`AgentChat/SlashCommandMenu.tsx`, ↑↓·Enter·Tab·Esc). CLI 의 명령은 `lib/slashCommands.ts` 에 적어 두었고, 사용자가 만든 명령은 main 의 `src/agentChat/slashCommands.js` 가 이름과 설명만 준다 (Claude `commands/**/*.md`·`skills/*/SKILL.md`, 사용자 폴더와 `<작업 폴더>/.claude`. Codex `prompts/*.md` 는 `/prompts:<이름>`). 목록에 없는 명령도 그대로 쳐서 보낼 수 있다. 보낸 뒤 main 이 그 에이전트 화면을 보고 결과를 정한다 (`src/agentChat/commandScreen.js`, `agent-chat-command-watch`).
  - 빈 입력칸이 돌아오면 실행된 것이다. Claude 는 명령이 찍은 글(`<local-command-stdout>`)을 기록에 남겨서, 채팅이 그 글을 회색 출력 상자(`output` 항목)로 보여 준다. `/compact` 의 보고는 빼고, 요약 안내 줄만 보여 준다. Codex 는 슬래시 명령을 기록하지 않는다. 터미널에서 자동으로 접힌 줄을 이어 명령 에코를 찾고 그 다음 줄부터 입력칸 위까지 출력으로 읽는다. 에코를 놓쳤으면 명령 전후 화면의 차이를 표시한다. 보낸 말풍선에는 `실행함` 을 붙인다 (`agentChatStore.settleCommand`, 출력은 말풍선과 함께 30분 남음: `echoOutputId`).
  - Codex `/mcp` 출력에서 서버 목록을 읽을 수 있으면 서버 이름·상태·도구 수를 카드에 그린다 (`lib/codexMcpOutput.ts`). 최신 결과의 카드 ID로 `자세히 보기`와 `로그인`을 요청하고, main은 같은 에이전트와 최신 결과인지, 입력 대기 상태인지 붙여넣기와 Enter 전에 확인한다. `자세히 보기`는 `/mcp verbose`를 보낸다. `로그인`은 프롬프트가 붙은 새 명령 에코로 확인한 결과에서 인증이 필요한 서버에 대해 `/mcp login <이름>`을 보낸다. 화면 차이로 읽은 결과에서는 로그인 버튼을 비활성화하고 터미널 확인을 안내한다. 출력 전체는 `원문 보기`에서 볼 수 있고, 목록을 읽을 수 없는 형식은 기존 출력 상자로 보여 준다.
