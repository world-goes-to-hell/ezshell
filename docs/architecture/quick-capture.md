# Quick Capture (영역 캡처·표시·바로작업)

[공통 작업 규칙과 기능별 목록](../../CLAUDE.md)

Windows에서 기본값 `Ctrl+Win+Alt` 또는 `Ctrl+Alt+Shift`를 쓰거나 명령 팔레트에서 `영역 캡처`를 선택한다. 설정 > 키보드 단축키에서 전역 조합 두 개를 각각 바꾸거나 끌 수 있다. 조합의 동작 시점과 검증 규칙은 [전역 캡처 단축키](global-shortcuts.md#quick-capture-shortcuts-영역-캡처)를 읽는다. 포인터가 있는 모니터를 멈춘 그림으로 덮고(`src/quickCaptureOverlay.js`: `data:` 페이지, preload·Electron API 없음, sandbox), 영역을 끌어 고르면 바로 표시할 수 있다: 화살표(기본)·사각형·펜·글자·번호·모자이크, 색 5개·굵기 3단계, 되돌리기·다시(`Ctrl+Z`/`Ctrl+Y`), 도구 키 `A R P T N M`, `모두 지우기`, `영역 다시`. 번호는 누를 때마다 ①②③ 이 붙고 코멘트 칸에 `n. ` 줄이 생긴다. 모자이크는 비밀번호·토큰을 가리고 보내기 위한 것. 그 아래 코멘트와 `복사`(그림+코멘트를 클립보드) / `바로작업`(프로젝트 → 에이전트를 골라 그림 파일과 코멘트를 그 에이전트의 입력칸으로). 2026-11-23 사용자 요청(표시하고 수정 요청). 설계: `docs/plan/2026-11-23-capture-annotation-editor.md`. 화면 테스트 `quick-capture`.
- 수정키 전용 조합은 마지막 수정키를 떼면 시작한다. 주 키 조합은 주 키를 누르면 화면을 읽고 수정키를 모두 떼면 덮개를 표시한다. 수정키 전용 조합에서 마지막 수정키를 떼기 전에 Esc를 누르면 조합이 성립하지 않는다. 시작 뒤의 Esc는 화면을 읽거나 덮개에 포커스가 오기 전에도 후크의 `capture-cancel` 신호로 취소한다. 도우미는 소유 프로세스를 확인하고 덮개 핸들을 기억한 뒤 그 창을 앞으로 가져온다. 덮개가 앞에 오면 Esc는 페이지가 처리한다. 글자 도구는 쓰던 글자를 버리고, IME 조합 중에는 IME가 Esc를 처리한다.
- 표시 편집기는 `src/quickCaptureEditor.js` 의 함수들을 원문 그대로 페이지에 넣는다 (`EDITOR_SCRIPT`: 덮개 페이지는 템플릿 문자열이라 역슬래시가 든 코드를 직접 쓰기 어렵고, 이렇게 하면 계산을 Node 에서 시험할 수 있다). 그 함수들은 서로와 DOM 말고는 쓰면 안 된다. 표시는 캡처 그림의 원래 화소 위에 그리고(`pixelRegion` 을 main 과 함께 씀), 축마다 따로 좌표를 바꾼다.
- 캡처 도구와 입력칸은 본창 테마의 색·글꼴·모서리를 쓴다. 바꾸면 안 되는 것: 본창의 주 프레임에서 받은 테마 값만 main에서 형식과 길이를 각각 검사한 뒤 덮개의 정해진 CSS 변수로 넣는다. 컨트롤 배경은 불투명하게 두어 캡처 내용 위에서도 읽을 수 있게 한다.
- 바꾸면 안 되는 것: 덮개가 돌려준 표시된 그림은 main 이 다시 본다 (`markedImage`: `data:image/png;base64,`, 48MB 이하, `nativeImage` 로 읽히고 크기가 고른 영역의 화소 크기와 같아야 함). 아니면 표시 없는 원본 영역을 쓴다. 바로작업을 다시 시도할 때는 표시가 바뀌었을 때만 그림 파일을 새로 저장한다.
- 여러 장 이어 찍기: 편집 패널의 `추가 캡처` 는 덮개를 닫고 그 모니터 위쪽에 띠 창(`캡처 N장 보관 중 · 지금 캡처 · 모아 보기 · 버리기`, 같은 모듈의 `captureChipUrl`)을 `showInactive` 로 띄운다. 그동안 사용자가 화면을 바꿀 수 있다. `지금 캡처` 나 단축키는 띠를 숨기고 150ms 뒤 포인터의 모니터를 새로 멈춰 앞선 캡처를 이어 간다 (`start({ review })`, 덮개 창은 캡처마다 새로 만든다). 2장부터 패널 위 썸네일 줄로 골라 고치고, 앞선 캡처는 화면 위쪽 가운데에 띄운다 (`fitBox`). 코멘트는 묶음에 하나, 번호 도구는 묶음 전체의 가장 큰 번호 + 1, 8장까지. 바로작업은 그림 N개를 한 메시지로(`sendCapture` 의 첨부 목록, 말풍선 `previews`), 복사는 위아래로 이어 붙인 한 장(`stackLayout`: 장마다 32px 번호 띠, 사이 16px). 설계: `docs/plan/2026-11-24-capture-multiple-shots.md`.
  - 바꾸면 안 되는 것: 캡처 사이의 묶음(각 캡처의 잘라 낸 원본 화소, 표시 목록, 코멘트)은 main 의 메모리에만 둔다. 잠금·종료·`버리기`·사용자가 덮개를 닫음(Esc·취소, 2장 이상이면 Esc 두 번)·띠 창을 닫음이면 지운다. 도우미의 Esc(`cancelCapture`)와 화면을 읽지 못한 경우는 이번 캡처만 버리고 띠를 다시 띄운다. 덮개가 돌려준 캡처 목록은 `resolveShots` 로 다시 본다 (앞선 캡처 번호는 한 번씩, 이번 화면은 한 번과 검사한 영역, 표시 목록은 `cleanMarks` 로 500개·2MB). 화소는 언제나 main 이 가진 것을 쓰고, 표시 그림·이어 붙인 그림은 크기가 맞을 때만 쓴다 (안 맞으면 main 이 `composeStack` 으로 직접 잇는다. 둘 다 6,400만 화소까지이고, 넘으면 한 장만 복사하지 않고 덮개에 이유를 띄운다: `captureNotice`). 표시 목록이 상한을 넘으면 표시를 그린 그림을 원본 대신 보관한다 (그 표시는 되돌릴 수 없다). 앱을 쓸 수 없는 순간(잠금 직전, 단축키 녹화)에는 띠를 띄우지 않고 묶음을 지운다. 덮개 페이지 코드는 모듈의 템플릿 문자열 안이라 역따옴표·`${`·역슬래시를 쓰지 않는다.
  - 시험할 때: 화면 테스트의 고정 앱(`e2e/support/quickCaptureApp.js`)은 복사한 PNG 를 `capture-copied` 에, 캡처 오류를 `capture-error` 에 남긴다 (앱 출력은 버려진다). Electron main 의 `ClipboardItem` 은 `getType()` 으로만 꺼낸다 (`contents` 없음). 바꾸면 안 되는 것: main 이 덮개의 답을 기다리는 동안의 Esc·취소는 페이지가 창을 직접 닫지 않고 `{ action: 'close' }` 로 답하고 main 이 창을 닫는다 (`window.close()` 는 main 이 조회·전송 중일 때만). 페이지가 스스로 닫으면 기다리던 `executeJavaScript` 가 창의 `close` 이벤트보다 먼저 `Render frame was disposed` 로 실패해 Esc 마다 "화면을 캡처하지 못했습니다" 알림이 떴다 (화면 테스트가 이제 오류 0건을 본다). 영역 끌기는 `lostpointercapture` 를 받아도 100ms 동안 같은 끌기의 `pointerup` 을 기다린다: Chromium 이 붙잡기 해제를 `pointerup` 직전에 알리는 일이 있어, 바로 취소하면 끈 영역이 가끔 버려졌다. 설명: `docs/fix/2026-11-24-capture-esc-error-and-lost-drag.md`.
- 새 `src/*.js` 라서 `quickCapture.js`·`quickCaptureOverlay.js`·`quickCaptureEditor.js` 가 `MAIN_RUNTIME_MODULES` 에 있다 (빠지면 앱이 시작하지 않는다).
