# 서버 파일과 설정 정의

## Server File Window (SFTP 미리보기·편집)

SFTP 패널(본창·분리 창)의 서버 파일 우클릭 메뉴 `미리보기` / `편집` 으로 파일마다 창 하나(`?remoteFileMode=true&docId=...`, `RemoteFileWindow.tsx`)를 연다. main 은 `src/remoteFiles/` (`documents.js` 가 문서 상태, `ipc.js` 가 IPC, `remoteRead.js` 가 읽기, `backups.js` 가 백업). 같은 탭의 파일 창들은 그 탭 SSH 연결의 SFTP 채널 하나를 함께 쓰고(`documents.js` 의 `channels`, 마지막 창이 닫힐 때 닫음), SFTP 패널을 닫아도 쓸 수 있다. 창마다 채널을 열면 서버의 연결당 채널 수 제한(OpenSSH `MaxSessions`, 기본 10)에 걸려 분할 터미널이 열리지 않을 수 있다. 설계: `docs/plan/2026-11-05-sftp-file-edit-preview.md`.
- 편집기는 CodeMirror 6, Windows 단축키(Ctrl+F/H/G/S/Z/Y). Vim/Emacs 키는 사용자가 원하지 않았다. 편집기 코드는 파일 창에서만 불러온다 (`App.tsx` 의 `lazy`).
- 터미널 왼쪽 파일 탐색기(`FileExplorer.tsx`)도 SFTP 목록과 같은 우클릭 메뉴를 쓴다 (`FileListContextMenu`, `buildContextMenuItems`). 이름 바꾸기·새 폴더는 트리 안 입력칸, 다운로드는 저장 위치를 묻고, 바뀐 폴더만 다시 읽는다 (`lib/fileExplorerTree.ts`). 탐색기에는 F2·Delete 키가 없어 메뉴에 단축키를 표시하지 않는다. 메뉴는 `document.body` 에 그리고 실제 크기를 재서 놓는다 (`fitMenu`): 탐색기·SFTP 패널은 transform 이 걸린 상자 안이라 그 안에 그리면 잘린다.
- 편집: 5MB 이하 UTF-8 텍스트. CRLF 파일은 CRLF 로 저장하고, 섞인 줄바꿈은 LF 로 통일된다 (`lib/remoteFileText.ts`). 쓰기 권한은 열 때 `r+` 로 열어 보고 닫아서 판단한다.
- 미리보기: 이미지·PDF 는 50MB 까지 `blob:` URL (PDF 는 iframe 의 Chromium 뷰어, CSP 에 `img-src blob:` `frame-src blob:`), 그 밖은 텍스트로 5MB 까지 전체, 넘으면 마지막 1MB.
- 바꾸면 안 되는 것: 저장은 `review`(diff 와 토큰) → `save`(같은 내용의 SHA-256) 순서로만 된다. 저장 직전에 서버 내용을 PC 에 백업하고(`문서\ezShell Backups\<세션> (<계정>@<호스트>)\<서버 경로>\<이름>.<시각>.bak`, 파일마다 20개), 백업을 못 쓰면 저장하지 않는다. 쓰기는 MCP 와 같은 `remoteFile.writeIfUnchanged` (한 핸들로 비교 후 덮어쓰기, 소유자·권한 유지). 서버에 `.bak` 을 만들지 않는다 (`conf.d`, `cron.d` 처럼 폴더의 모든 파일을 읽는 곳에서 적용될 수 있음).
- 보안 검토 반영 (바꾸지 말 것): 오래된 백업 정리는 저장이 성공한 뒤에만 한다 (충돌로 거부될 때마다 정리하면 기록이 사라진다). 저장 중인 창을 닫으면 저장이 끝난 뒤 채널을 닫는다 (쓰는 도중 끊으면 서버 파일이 잘린다). 검토 토큰은 검토마다 새 난수이고 한 번만 쓴다. diff 가 잘리면 "나머지를 보지 않고 저장" 을 체크해야 저장된다. 백업 폴더 이름은 세션 이름을 40자로 자른 뒤 main 이 가진 `(계정@호스트)` 를 붙인다. 파일 창은 20개까지.
- 큰 폴더: SFTP 목록(`FileList.tsx`)은 보이는 줄만 그린다 (`hooks/useListWindow.ts`, 계산은 `lib/listWindow.ts`). 줄 높이가 모두 같다는 전제이고, 줄로 이동할 때는 `scrollIntoView` 대신 `listWindow.scrollToIndex` 를 쓴다 (그려지지 않은 줄에는 DOM 요소가 없다). 2만 개 폴더를 통째로 그리면 화면이 5초 멈췄다. 터미널 왼쪽 탐색기는 트리라서 폴더마다 300개씩 그리고 `더 보기` 로 잇는다. main 의 `sftp-list` 는 폴더를 나눠 읽으며(`src/sftpListing.js`) 500개마다 `sftp-list-progress` 로 개수를 알리고, 화면은 "불러오는 중… N개" 로 보여 준다.
- 문법 강조(`codeEditorSetup.ts` 의 `languageFor`): 백업 이름(`compose.yaml.bak_20261020`)은 표시를 떼고 원래 파일의 언어를 쓴다. 기본 목록에 없는 설정 파일(`.env`, `.conf`, systemd 유닛, `hosts` 등)은 `configLanguage.ts` 가 줄 단위로 주석·`[섹션]`·키·값을 칠한다 (`#` 은 줄 처음이나 공백 뒤에서만 주석: 값 안의 `#fff` 를 주석으로 칠하지 않게).
- 마크다운 파일(`.md` 등)은 편집 창 제목줄의 `일반 | 나란히 | 마크다운` 으로 보기를 바꾼다 (`markdownView.tsx`, `MarkdownPreview.tsx`, 변환 `lib/markdownRender.ts`, `markdown-it` 은 화면에 묶이는 devDependency). `나란히` 는 왼쪽 편집기·오른쪽 문서이고, 입력이 0.15초 멈추면 문서를 다시 그린다 (편집기에 처음 한 번 준 `updateListener`). 가운데 선을 끌어 편집기 폭을 20~80% 로 바꾸고 두 번 누르면 반반, 폭은 `localStorage` 의 `remoteMarkdownSplit` (화면 설정 백업 목록에 있다, `lib/markdownSplit.ts`). 바꾸면 안 되는 것: 편집기는 어느 보기에서나 같은 부모·같은 자리에 마운트된 채로 둔다 (감싸개를 바꾸면 React 가 편집기를 새로 만들어 저장하지 않은 글자와 되돌리기 기록이 사라진다). 그래서 구분선과 문서는 편집기의 형제로 그리고, 폭은 편집기 칸의 `flex` 로 준다. 바꾸면 안 되는 것: 파일 속 HTML 은 글자로 보이고(`html: false`), 링크는 http(s)·mailto·`#` 만 남기며 누르면 창을 옮기지 않고 주소를 복사한다. 이미지는 대체 글자로 바꾼다 (CSP 가 막고, 원격 이미지는 파일을 열었다는 것을 그 서버에 알린다).
- 강조 색(`codeEditorSetup.ts` 의 `highlightStyle`): `.properties`·`.ini` 의 키(`definition(variableName)`)·값(`quote`), YAML 의 값(`content`), 마크다운의 굵게·기울임·코드·링크에도 색을 둔다. 화면 표시 규칙은 `highlighting.test.ts`에서 검사한다.
- 백업 목록에는 앱 백업(PC 아이콘)과 서버의 백업 파일(서버 아이콘, `compose.yaml.bak_20261020_1516` 처럼 같은 폴더에 사람이 남긴 것)이 시간순으로 섞인다 (`lib/backupCompare.ts`). 서버 파일 판정과 목록은 main 의 `serverBackups.js` (readdir 한 번, 일반 파일만, 50개, 이름의 날짜가 없으면 수정 시각). 백업 이름은 파일 이름에 표시(백업을 뜻하는 낱말, 날짜, 번호)가 붙은 것으로 보고 세 자리를 모두 본다: 뒤(`index.jsp.261102`, `index.jsp_bak`, `index.jsp.1`), 확장자 앞(`index_261102.jsp`, `index (1).jsp`), 앞(`bak_index.jsp`, `Copy of index.jsp`). 날짜는 8자리와 6자리(연월일)를 읽는다. 확장자 앞·이름 앞 자리는 표시만으로 이루어져야 한다 (`index_admin.jsp`, `index2.jsp` 는 다른 파일이다). 바꾸면 안 되는 것: 창에는 이름만 보내고, 읽기(`remote-file-read-server-backup`)는 main 이 마지막으로 만든 목록에 있는 이름만 받는다. 읽은 실제 경로가 목록의 경로와 다르면(그 사이 링크로 바뀜) 거부한다. 설계: `docs/plan/2026-11-11-backup-compare-and-server-backups.md`.
- 백업 좌우 비교(`RemoteCompareView.tsx`, `@codemirror/merge` 의 MergeView): 왼쪽 백업(읽기 전용), 오른쪽 현재 내용, 가운데 » 로 그 부분만 백업 내용으로 바꾼다. 바꾸면 안 되는 것: 오른쪽은 편집기의 거울이다. 오른쪽의 모든 변경을 그대로 본 편집기(숨겨 두고 마운트 유지)에 보내므로, 저장·닫기 확인·Ctrl+Z 는 본 편집기 기준으로 동작한다. 편집기 내용을 통째로 바꾸는 동작(서버에서 다시 불러오기)은 비교를 먼저 닫는다.
  - 위아래 스크롤은 MergeView 가 하나라서 항상 같이 움직인다. 좌우는 `스크롤 동기화`(기본 켬, `localStorage` 의 `remoteCompareSyncScroll`)가 양쪽 `.cm-scroller` 와 화면 아래의 공용 가로 막대(`.remote-compare-hscroll`)를 묶는다 (`linkHorizontalScroll`). 각 편집기의 가로 막대는 파일 맨 끝에 있어 긴 파일에서는 보이지 않기 때문에 공용 막대를 둔다. 바꾸면 안 되는 것: 우리가 옮긴 쪽이 내는 scroll 이벤트는 다시 전달하지 않는다 (짧은 쪽은 자기 끝에서 멈추는데, 그 위치를 되돌려 보내면 긴 쪽이 끌려온다).
- 같은 초에 백업이 여러 개면 번호를 가장 큰 번호 다음으로 붙인다. 정리로 비운 번호를 다시 쓰면 새 백업이 가장 오래된 것으로 정렬돼 바로 지워진다 (테스트로 잡은 버그).
- 요청마다 `docId` 와 보낸 창(webContents id)이 맞아야 답한다 (`documents.js` 의 `own`). 저장하지 않은 변경이 있으면 main 이 창 닫기를 막고 창에 묻는다 (`remote-file-close-requested` → `remote-file-close`).
- 새 `src/` 폴더라서 `MAIN_RUNTIME_DIRECTORIES` 에 `remoteFiles` 가 있다. MCP 모듈(`../mcp/remoteFile.js` 등)을 상대 경로로 쓴다.
- 실시간 보기(로그 따라가기): 우클릭 `실시간 보기`(모드 `tail`, 이미지·PDF 제외) 또는 텍스트 미리보기 창의 재생 버튼. main 의 `logTail.js` 가 한 번 볼 때마다 SFTP `stat` 하나만 보내고, 크기가 바뀌었을 때만 파일을 열어 늘어난 부분(최대 1MB, 넘으면 "N 건너뜀")을 읽고 바로 닫는다. 화면(`RemoteLogView.tsx`)은 답을 받은 뒤에만 다음 확인을 예약한다. 간격은 로그를 따른다 (`lib/logPollPace.ts`): 새 줄을 받으면 0.2초, 조용하면 0.4 → 0.8 → 1초로 늘리고, 가려지면 5초, 실패하면 3초. 조용한 로그의 서버 부담은 예전(1초마다 stat 하나)과 같다. 설계: `docs/plan/2026-11-05-log-live-view.md`.
  - 바꾸면 안 되는 것: 운영 서버 부담 때문에 서버에서 `tail -f` 같은 명령을 실행하지 않고, 파일을 열어 둔 채로 두지 않는다 (logrotate 가 지운 옛 파일의 디스크 공간이 풀리지 않는다). 확인 요청은 겹치지 않는다 (`documents.js` 의 `isTailing`, 진행 중이면 `busy`). 30초 안에 답이 없으면 포기한다.
  - 줄이 빠지지 않게: main 은 답마다 `cursor` 를 붙이고, 다음 요청이 그 cursor 를 가져와야 위치를 넘긴다 (아니면 마지막으로 받은 위치에서 다시 읽어 같은 줄을 보낸다). 일시정지·창 닫기로 화면이 버린 답 때문이다. `load` 마다 `generation` 이 바뀌고, 새로고침 전 화면의 요청은 `stale` 로 답한다. 로그 추가는 되돌리기 기록에 넣지 않는다 (`Transaction.addToHistory.of(false)`, 넣으면 지운 줄이 기록에 쌓여 메모리 상한이 깨진다).
  - 새 파일 판단: 크기가 줄었거나, 앞 256바이트가 달라졌거나, 링크가 다른 파일을 가리키거나, 없다가 다시 생기면 처음부터 읽는다 (logrotate `create`·`copytruncate`). 줄바꿈 전 조각은 main 이 최대 1MB 까지 붙잡는다. NUL 바이트는 지운다.
  - 강조는 `lib/logLevels.ts` 가 줄마다 첫 로그 수준 단어로 정한다 ("INFO ... ERROR" 는 오류 아님). 수준 단어가 없으면 예외 이름·스택 줄·Traceback 만 오류로 본다. 소문자 `error` 단어는 오류로 보지 않는다. 화면에 보이는 줄만 꾸민다(ViewPlugin). 창에는 최근 약 5MB 만 둔다 (`lib/logAppend.ts`).
  - 오류·경고의 개수와 이동은 줄이 아니라 묶음 단위다 (`lib/logProblems.ts`): 수준 낱말이 있는 오류·경고 줄은 새 묶음을 시작하고, 수준 낱말이 없는 충돌 줄(예외 이름, `at ...`, `Caused by:`)은 바로 앞줄이 오류·경고이면 그 묶음에 붙는다. 스택 트레이스 50줄은 오류 한 건이다. `Caused by: ...: ERROR: ...` 처럼 수준 낱말이 든 이어지는 줄도 새 묶음으로 치지 않는다 (`logLevels.ts` 의 `CONTINUATION_LINES`). 묶음 목록은 편집기 상태 필드(`logProblemField`)이고, 문서가 바뀌면 바뀐 줄과 그 다음 줄만 다시 읽는다 (다음 줄이 묶음의 시작인지는 윗줄에 달려 있다). 줄 색은 지금도 줄마다 정한다.
  - 이동(`RemoteFile/logView.ts`): 오류·경고는 `F8`/`Shift+F8`, 맨 아래 `Ctrl+F8`, 맨 위 `Ctrl+Shift+F8`. 기준점은 같은 조합의 `F9`. `Alt+휠` 은 오류·경고, `Shift` 를 더하면 기준점을 한 칸에 한 건씩 옮기고 끝에서 멈춘다. `Ctrl+휠`은 분리 창의 UI 배율에 사용한다. 일부 PC에서는 `Alt`를 누른 동안의 휠에서 `altKey`가 빠지고 키 이벤트가 뗄 때 한꺼번에 온다 (`lib/logWheel.ts`: 터치패드의 작은 움직임은 한 칸이 될 때까지 모은다. Shift 를 누르면 휠이 가로 값으로 오는 시스템이 있어 두 값을 다 본다). 바꾸면 안 되는 것: 다음·이전의 기준은 커서 줄이 화면에 보일 때만 커서이고, 아니면 화면의 첫 줄·끝 줄이다 (`referencePos`). 휠로 스크롤해도 커서는 움직이지 않아서, 커서만 보면 보고 있지 않은 곳으로 간다. 커서가 화면에 없을 때는 화면에 보이는 묶음을 건너뛰고 화면 밖의 묶음으로 간다 (보이는 줄로 가면 화면이 움직이지 않아 아무 일도 없는 것처럼 보인다: 로그 끝을 따라가는 중에는 매번 그랬다). 도착한 줄은 1초쯤 강조한다.
  - 목록 패널(`LogOutlinePanel.tsx`, 자료는 `lib/logOutline.ts`): 로그 오른쪽에 기준점(이름, 시각, 뒤 줄 수, 뒤 오류·경고 수)과 오류·경고(최근 200건, 최근 순, 수준 필터)를 보여 주고 누르면 그 줄로 간다. 패널 열림과 줄바꿈 여부는 `localStorage` 의 `remoteLogViewPrefs` (화면 설정 백업 목록에 있다). 패널의 수준 선택(전체/오류/경고)은 목록만이 아니라 이동에도 적용된다: `F8`·휠·화살표가 고른 수준 사이로만 움직이고, 상태 줄의 `3/15`(커서가 몇 번째 묶음에 있는지)도 그 수준 기준이다 (`오류 3/12`). 상태 줄의 `오류 N`·`경고 N` 버튼은 선택과 무관하게 자기 수준의 다음 건으로 간다. 기준점의 `뒤 N줄` 버튼은 목록과 오류·경고 이동을 그 기준점 이후로 제한하고, 상태 줄의 범위를 누르면 해제된다. `새 오류`는 로그 끝을 따라갈 때도 미확인 오류를 남기고, 누르면 첫 오류로 이동해 강조한다. `새 줄`은 로그 끝으로 돌아간다. 설계: `docs/plan/2026-11-18-log-view-navigation.md`.
  - 최근 1초 동안 100줄 이상을 받으면 상태 줄에 이번 급증의 줄 수를 표시한다. 시작할 때만 테마 강조색으로 한 번 밝아지고, 숫자는 300ms 간격으로 묶는다. 급증이 잠잠해지면 표시를 접는다 (`lib/logBurst.ts`).
  - 기준점(`lib/logMarkers.ts`, 화면은 `logMarkerView.ts`): 깃발 버튼·`Ctrl+M` 은 지금 로그 끝, 줄 번호 클릭은 그 줄 위에 `기준점 N · 시각` 띠를 둔다 (최대 10개, 저장 안 함, 새로고침하면 사라짐). 띠는 블록 위젯이라 복사·찾기·오류 개수에 섞이지 않는다. 상태 줄에 가장 최근 기준점 뒤의 줄 수와 오류 수. 목록 패널의 연필로 이름(30자)을 붙이면 띠에도 보인다. 바꾸면 안 되는 것: 위치는 `mapPos(pos, -1, MapMode.TrackAfter)` 로 옮긴다 (끝에 찍은 기준점이 새로 붙는 줄보다 앞에 남아야 하고, 정리로 그 줄이 지워지면 기준점도 빠져야 한다). 설계: `docs/plan/2026-11-12-log-view-markers.md`.
  - 앱을 잠그면 미리보기·실시간 창은 닫고(`ipc.js` 의 `closeViewWindows`), 잠긴 동안 `remote-file-tail` 을 거부한다. 편집 창은 저장하지 않은 내용 때문에 닫지 않는다. 창이 뒤에 있을 때 새 오류가 오면 작업표시줄만 깜빡인다 (알림 센터에는 남기지 않음).

## Config Placeholder Definitions (설정 파일 `${NAME}` 의 정의 찾기)

파일 창 편집기(로컬·서버 파일)에서 `${이름}` / `${이름:기본값}` 에 점선 밑줄이 그어지고, `Ctrl+클릭` 하면 그 이름을 정하는 곳을 찾는다 (`RemoteFile/placeholderLinks.ts`, 목록 `DefinitionList.tsx`). 한 곳이면 바로 그 파일을 그 줄에서 열고(줄 잠깐 강조), 여러 곳이면 목록(기본값, 파일·줄·그 줄의 글자). 찾는 규칙은 main 의 `src/remoteFiles/configRefs.js`: `.env*`, compose(`environment` 두 형태), `Dockerfile`(`ENV`/`ARG`), yml 키(점 이름은 들여쓰기 경로, Spring 느슨한 이름), properties, `*.sh`/`*.service`/`*.conf`. 범위는 로컬이면 그 파일을 연 작업 폴더 전체(`node_modules`·`.git`·`build` 등 건너뜀, 링크 따라가지 않음, 깊이·개수·크기 상한), 서버면 같은 폴더와 위로 3단계에서 후보 파일만 SFTP 로 (명령 실행 없음). 바꾸면 안 되는 것: 창은 이름만 보내고 결과는 key 로만 연다 (`documents.js` 의 `findDefinitions`/`openDefinition`, main 이 마지막 결과의 key → 경로를 갖는다). 줄로 열기는 새 창이면 `load` 답의 `revealLine`, 이미 열린 창이면 `remote-file-reveal-line`. 편집기 확장은 마크다운 보기의 `followTyping` 과 같은 `useMemo` 배열에 있다 (`CodeEditor` 는 extensions 를 마운트 때 한 번만 읽는다). 설계: `docs/plan/2026-11-19-config-placeholder-definitions.md`. 시험: `local-config-definitions`.
