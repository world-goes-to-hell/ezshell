# MCP Server (Claude Code)

[공통 작업 규칙과 기능별 목록](../../CLAUDE.md)

`src/mcp/` 에 SSH용 MCP 서버가 있다. Claude Code 등록 이름은 `ezshell-ssh-mcp` 다. "Claude Code 자동 설정"에서 같은 설정 파일의 옛 이름 `ez-shell` 과 `my-ssh-client` 를 갱신한다 (`controller.js` 의 `LEGACY_SERVER_NAMES`). `~/.claude.json` 의 프로젝트별 등록은 화면에 표시한다. 설정 > MCP > SSH MCP 에서 켜면 `127.0.0.1:<포트>/mcp` (Streamable HTTP, stateless) 로 열린다.

설정 > MCP > 에이전트 메시지에서 `ezshell-cli-mcp` 를 등록하면 일반 터미널에서 실행한 Codex·Claude Code도 `src/ipc/agentMessages.js` 의 메시지함을 쓴다. 사용자 설정은 앱의 사용자 데이터 폴더에 있는 연결 파일을 참조한다. 앱을 시작할 때 실행 파일과 인증 정보를 갱신하고, 살아 있는 MCP 연결만 `list_agents` 에 표시한다.

- `inspect_agent(id)`는 같은 앱의 에이전트 상태·출처, 막힘 종류, 안 읽은 수, 유휴 시간과 종료 코드를 조회한다. 확인 질문 한 줄과 선택지 이름만 제한해 보여 준다. `escalate(id, reason)`는 화면에서 사용자 응답 대기를 다시 확인해 해당 막힘에 PC 알림과 `그 칸으로 가기`를 한 번 띄운다. 잠금 중에는 두 도구 모두 거부한다. 새 도구는 메시지 MCP 프로세스를 다시 띄울 때 등록된다. 설계와 응답 범위는 `docs/plan/2026-11-25-agent-unblock-by-orchestrator.md`에 있다.

Windows 의 ezShell 로컬 PowerShell 에서 `claude` 를 직접 실행하면 셸의 `claude` 함수가 그 실행에 `agent-shell-mcp.json` 을 넘긴다. 사용자 등록 없이 동작한다. 명시한 MCP 설정, 엄격한 MCP 모드, 관리 명령과 비대화형 실행은 호출자의 인자를 따른다. main 은 셸 토큰과 CLI 프로세스 계보가 같은 셸을 가리킬 때 등록한다. 재연결에는 기존 자격 증명 규칙을 쓰고, 잠재우기 복귀에는 별도의 `agent-wake-mcp.json` 을 쓴다. 화면 테스트 `local-agent-chat-manual`.

앱과의 메시지 소켓이 끊겨도 `agentMessageMcp.js`의 stdio 서버는 계속 동작한다. 연결을 다시 시도하는 간격은 1·2·5·10·30초이고, 연결 전 도구 호출은 `ezShell과 다시 연결하는 중입니다.`를 바로 반환한다. 일반 터미널의 등록은 시도할 때마다 연결 파일을 다시 읽으므로 앱 재시작 뒤에도 다시 붙는다. 일반 브리지의 기존 에이전트 ID는 현재 셸의 CLI 계보와 마지막 연결이 발급한 일회용 재연결 자격 증명으로 복구한다. Claude Code의 `/mcp`처럼 새 MCP 프로세스가 시작돼 자격 증명이 없으면 이전 연결이 닫힌 뒤에만 동일 CLI의 PID와 OS 시작 시각을 확인해 같은 ID로 복구한다. 이 경로는 사용자가 정상적으로 재연결할 때 받은편지함을 유지한다. 파이프 상대와 신고된 PID를 직접 대조할 수 없어 동일 OS 사용자의 다른 프로세스에 의한 신원 위조 위험은 남는다. MCP는 자격 증명을 메모리에 두고 main은 해시만 보관한다. 발급 뒤 24시간 또는 연결 종료 뒤 5분 중 먼저 오는 시각에 만료되고, 정상 재연결 때는 새 자격 증명을 발급하며 남아 있던 이전 연결과 도구 토큰을 폐기한다. OS 계보 조회가 실패하면 등록을 미루고 재시도한다. 앱이 띄운 에이전트는 그 앱의 전용 토큰과 파이프를 사용하고, 파이프가 빠지면 설정 오류를 반환한다. 앱을 다시 띄울 때는 셸과 에이전트도 다시 열어 새 토큰을 받는다. 앱이 요청한 잠재우기 복귀는 해당 셸의 전용 토큰으로 한 번 인증하고, 이후에는 발급한 재연결 자격 증명을 사용한다. CLI가 stdin을 닫으면 서버와 재시도 타이머도 끝난다.

메시지는 읽음 표시로 상태를 알린다: 받는 에이전트가 `read_inbox` 로 가져가는 순간이 "읽음"(`seenAt`)이고, 보낸 에이전트는 `check_sent` 로 내가 보낸 메시지의 `unread`(안 읽음)·`read`(읽음, 답 없음, `readAt`)·`answered`(답장·읽음 표시로 처리)를 본다 (지정한 id, 없으면 최근 20개, 본문은 앞 200자). 오래 `unread` 인 요청은 `inspect_agent` 로 받는 쪽 상태를 먼저 본 뒤 다시 보낸다 (쉬는데도 안 읽었을 때만, 사람의 결정을 기다리면 `escalate`). 메시지 패널은 말풍선마다 `안 읽음`·`읽음`·`답함`과 보낸 시각을 표시한다. `read` 필드는 예전처럼 "처리함"(답장·`acknowledge_message`)이다. 2026-11-20 에 수신 확인(`send_receipt`, 설계: `docs/plan/2026-11-19-agent-message-receipt.md`)을 이것으로 바꿨다 (사용자 결정). 업데이트 전에 띄운 에이전트가 `send_receipt` 를 부르면 main 이 거부하고 `reply_to_message` 를 쓰라고 답한다 (받으면 일반 답장이 되어 결과 없이 요청이 처리됨으로 바뀐다). 시험: `agentMessageRead.test.js`.

에이전트 메시지 창(명령 팔레트 `에이전트 메시지 열기`, `Terminal/AgentMessages.tsx`)은 `관계도 | 목록` 두 보기다 (기본 관계도, 마지막 선택은 `localStorage` 의 값으로 기억하고 화면 설정 백업 목록에 있다). 관계도(`Terminal/AgentMessageMap.tsx`, 계산 `lib/agentMessageMap.ts`)는 에이전트마다 카드(이름·종류·상태·작업 폴더), 메시지를 주고받은 쌍마다 SVG 화살표와 방향별 개수·읽음 상태 표를 그린다. 카드나 표를 누르면 오른쪽(좁으면 아래) 패널에 그 에이전트 또는 두 에이전트 사이 메시지가 시간순으로 나온다. 메시지가 없는 연결된 에이전트도 카드로, 기록에만 남은 끝난 에이전트는 흐린 카드에 회색 점. 카드는 끌어 옮긴다. 숫자 표는 선 위 여러 자리와 양옆을 찾아 카드·다른 표와 겹치지 않게 두고, 피할 수 없으면 카드 위 층에 그린다. 배치와 상태는 에이전트 메시지 스냅숏을 쓴다. 화면 테스트 `local-agent-messages`.
- 크게 보기·확대: 창 머리줄의 `크게 보기` 는 대화상자가 앱 창을 거의 채운다 (`localStorage` 의 `ezshell.agentMessageMapLarge`). 관계도는 자기 좌표를 `translate`·`scale` 로 그린다 (`lib/agentMapView.ts`): Ctrl+휠은 포인터 자리를 중심으로 50~200% (앱 전체 배율의 Ctrl+휠보다 먼저 받아 멈춘다), 휠만은 이동, 빈 곳을 끌면 이동, 오른쪽 아래 도구의 축소·배율(누르면 100%)·확대·`화면에 맞추기`(Ctrl+0, 100% 를 넘겨 키우지 않음)·`배치 초기화`·메시지 패널 접기. 관계도에 포커스가 있으면 방향키가 이동, 카드에서는 Alt+방향키가 카드를 옮긴다. 접은 패널은 카드나 연결선을 고르면 다시 열린다 (고르는 것은 그 메시지를 보려는 것). 카드·숫자 표 겹침 피하기는 관계도 좌표에서 계산하므로 배율과 무관하다.
- 배치 기억: 사용자가 끌어 놓은 카드 위치를 범위(관계도의 프로젝트나 폴더)마다 `localStorage` 의 `ezshell.agentMessageMapLayout` 에 둔다 (`lib/agentMapLayout.ts`: 범위 → `layoutKey` → `{x, y, usedAt}`, 그리고 범위의 배율). 바꾸면 안 되는 것: 카드의 키는 에이전트 id(실행마다 다시 매겨진다)가 아니라 main 이 스냅숏에 싣는 `layoutKey` 다 (`agentMessages.js` 의 `layoutKeyOf`: 역할 저장과 같은 대화 키 `종류:UUID` 의 SHA-256 앞 16자. UUID 는 창에 보내지 않는다). 대화 id 를 아직 모르는 에이전트는 이번 실행 동안만 에이전트 id 로 메모리에 두었다가(`sessionPositions`) `layoutKey` 가 오면 옮긴다. 읽을 때 형식(16자 hex 키, 0~50,000 의 유한한 좌표, 50~200% 배율)을 다시 보고, 30일 쓰지 않은 것을 버리고 최근 500개만 둔다 (보이는 카드는 하루에 한 번 사용 시각을 갱신). 이동 위치는 기억하지 않는다: 열 때 기억한 배율로 카드 가운데를 맞추고, 배율이 없으면 화면에 맞춘다. 위치가 없는 카드는 자동 배치의 자리 중 옮겨 둔 카드와 겹치지 않는 곳에 놓는다 (`placeAgentMessageMap`, 모자라면 아래로 줄을 더함). `배치 초기화` 는 그 범위의 위치만 지운다 (배율은 남음). 화면 설정 백업 목록에는 넣지 않는다: 키가 이 PC 의 대화에만 뜻이 있다. 대화를 새로 시작하면(`/clear` 등) 키가 바뀌어 그 카드는 자동 배치로 돌아간다.

관계도와 목록의 메시지는 `Terminal/AgentMessageThread.tsx`의 공용 말풍선으로 표시한다. 에이전트를 고르면 머리줄에 `리뷰어 · claude-1 의 메시지` 또는 `claude-1 의 메시지`가 나오고, 탭 이름·칸 번호와 `그 칸으로 가기`는 아래 한 줄에 둔다. 카드와 머리줄의 위치에는 숫자만 붙인다. 보낸 메시지는 오른쪽에 보낸 에이전트의 역할(역할이 없으면 ID)만 표시하고, 받은 메시지는 왼쪽에 보낸 사람을 표시한다. 연결선 머리줄은 두 에이전트 이름과 ID를 `⇄`로 잇고 기존 좌우 배치를 유지한다. 같은 송신자와 수신자의 연속 메시지는 머리표를 공유한다. 날짜 구분선, 답장 원문 첫 줄, 검색 강조, 긴 본문 펼치기를 제공한다. 본문은 일반 텍스트로 렌더링한다. 화면 테스트 `local-agent-messages`.

역할은 관계도 카드 또는 목록의 연필로 지정한다. MCP `set_role`은 호출한 에이전트의 역할을 정한다. 양쪽 모두 20자까지 가능하고 줄바꿈, 제어·서식·사적 사용·미할당 문자, 단독 서로게이트를 거부한다. 에이전트가 정하는 역할은 NFKC 정규화와 구분 기호 제거 뒤 `user`, `ezShell`과 같거나 이들과 시각적으로 혼동되면 거부하고, 에이전트 ID 모양(`claude-1` 과 그 혼동 문자)은 역할 안 어디에 있어도 거부한다 (`PL · claude-1` 은 다른 에이전트처럼 읽힌다: 리뷰에서 찾음). `나` 또는 `사용자`로 시작하는 역할도 거부한다. 사용자 지정이 우선이고, 지우면 에이전트가 정한 역할로 돌아간다. `list_agents`에는 현재 적용된 `role`이 나온다. 역할은 사용자 데이터의 `agent-roles.json`에 에이전트 종류와 대화 UUID를 키로 저장한다. 사용자 지정과 에이전트 지정은 각각 보관하고, 지운 값은 저장에서도 지운다. 대화 UUID가 생기기 전의 수정은 메모리에 두었다가 세션이 확인되면 적용한다. 같은 대화를 다시 열면 이전 역할이 돌아온다. 같은 프로세스에서 `/clear` 등으로 바뀐 대화를 확인하면 새 대화에 저장된 역할을 쓰고, 저장된 역할이 없으면 기존의 사용자·에이전트 역할을 각각 복사한다. 이전 대화에도 역할을 보관한다. 대화 기록에서 사용자가 재개한 대화가 같은 키를 자동 감지한 에이전트보다 우선한다. 충돌은 콘솔에 기록하고, 밀려난 에이전트는 다음 확인에서 다시 판정한다. Claude는 OS 프로세스 계보로 확인한 CLI의 PID에 대응하는 세션 파일을 사용한다. Windows FILETIME 형식의 `procStart`가 있으면 OS 생성 시각과 1초 이내여야 한다. 이 필드가 없으면 `startedAt`이 프로세스 시작 1초 전부터 60초 뒤까지인 경우에 확인한다. 확인하거나 거부한 파일은 PID와 시작 시각으로 기억하고, 같은 파일에서 대화 ID만 갱신되면 다시 프로세스 목록을 읽지 않는다. Codex의 명시적 재개는 UUID와 파일명이 맞는 롤아웃으로 역할을 연결한다. 실행 인자를 확인할 때는 바인딩할 Codex의 인자만 읽으며, CLI와 셸 사이에 다른 Codex나 런타임이 있으면 인자로 세션을 확인하지 않는다. 새 Codex는 그 셸의 인증된 첫 훅 UUID와 시작 이후 같은 작업 폴더에서 독립적으로 찾은 유일한 루트 롤아웃의 파일명·메타데이터 UUID가 같을 때 역할을 저장한다. 앱이 실행한 Codex는 main에 등록된 실행 폴더를 쓰고, 셸에서 직접 실행한 Codex는 요청한 폴더가 main이 받은 셸의 현재 폴더 또는 현재 폴더 보고가 없을 때 셸의 실행 폴더와 같아야 한다. 명시적 재개나 두 신호로 이미 확인된 다른 에이전트의 파일만 후보에서 제외한다. 저장 직전 같은 파일 핸들에서 파일 식별자와 메타데이터를 다시 확인한다. 검색 범위 전체를 확인할 수 없거나, 후보가 여럿이거나, 파일 또는 훅 대화가 바뀌면 역할을 메모리에 보관한다. 관계도 배치 키도 확인된 역할 키를 쓴다. 사용량 보고는 역할 확인에 쓰지 않는다. Antigravity의 역할과 채팅은 같은 확인된 UUID를 사용한다. OS 프로세스 계보로 도우미와 같은 셸의 agy를 연결하고, 첫 UUID부터 agy 시작 이후에 brain 폴더가 생성됐거나 해당 폴더 안의 대화 기록이 수정됐는지 확인한다. 파일시스템에서 생성 시각을 제공하지 않으면 폴더 수정 시각을 쓴다. 오래된 대화를 재개할 때는 CLI가 기록을 갱신한 뒤 연결된다. main의 `src/ipc/agentRoleStore.js`가 읽을 때 역할과 UUID를 다시 검사하고, 최근 30일 내에 사용한 최대 500개 대화를 임시 파일에서 이름을 바꾸는 방식으로 보관한다. 파일에는 역할과 사용 시각만 들어가며 대화 본문과 경로는 저장 범위 밖이다. 잠금 중에는 역할 지정과 새 Codex의 역할 키 확정을 거부한다. 잠금에 걸친 새 Codex의 증거 확인은 해제 뒤 다시 수행한다. 다른 대화 확인에 따른 키 갱신은 계속한다. 관계도 카드 제목은 역할이나 에이전트 ID를 쓰고 위치는 아래에 한 번 표시한다. 역할을 표시할 때는 ID를 같이 표시한다. 예외: 메시지 도착 카드는 역할이 있으면 역할만, 없으면 ID 를 보인다 (`AgentIdentityBadge` 의 `nameOnly`, `lib/agentIdentity.ts` 의 `agentShortName`). 툴팁 첫 줄은 그대로 `역할 · ID` 다. 에이전트 툴팁은 첫 줄에 이 이름, 둘째 줄에 종류와 상태, 셋째 줄에 칸 위치나 작업 폴더를 넣는다. CLI 가 그 이름을 더 이상 보여 주지 않으면 `missing` 과 최신 목록). 두 CLI 모두 인자로 바꾸는 명령이 없어서, main 이 채팅 보내기와 같은 `submitText` 로 `/model`(Claude 노력 수준은 `/effort`)을 넣고 CLI 가 그린 선택 화면에서 선택지를 읽어 메뉴로 준다. 고르면 화살표로 선택을 옮기며 키마다 화면이 바뀐 것을 확인하고, 화면 안내가 "이 세션에만"이라고 이름 붙인 키로 끝낸다 (보통 `s`, Claude 노력 수준 `max` 에서는 Enter). Codex 노력 수준은 `/model` 에서 지금 모델을 고른 뒤의 목록이다. 메뉴를 닫거나 60초 동안 고르지 않으면 Esc 로 화면을 닫는다. 선택지는 화면의 줄 위치가 아니라 번호(`1.`, `2.` …)로 알아본다: 칸이 낮으면 CLI 가 목록을 스크롤한다 (Claude `↓ 3 more`, Codex `↓`). 그런 목록은 끝까지 내려가며 모든 선택지를 모은 뒤 원래 자리로 돌아온다 (`collect`). 화면이 바뀐 뒤에는 출력이 0.09초 멎은 뒤에 읽는다 (`settle`: Codex 가 노력 수준 목록에서 모델 목록으로 돌아갈 때 조각조각 다시 그려 두 목록이 섞였다). 선택 화면은 8초까지 기다리고(대화가 긴 CLI 는 늦게 그린다), 그 뒤에 늦게 뜬 화면도 찾아 닫는다. 고르는 동안에는 채팅 보기가 그 목록을 확인 질문 카드로 보여 주지 않는다 (`approvalPrompt` 가 `held` 동안 null). `More models`·`More reasoning…`(다른 목록을 여는 줄)은 다루지 않는다. 바꾼 뒤 CLI 가 찍는 확인 문구(Codex `Model changed to gpt-6.2-astra low for this session only`, Claude `Set model to … for this session only`·`Set effort level to … (this session only)`)를 읽어 사용량 줄에 바로 반영한다 (`appliedFromScreen` → `agentMessages.applyPicked`). Codex 의 자체 보고는 다음 차례에야 바뀌어서, 바뀌었는데도 사용량 줄이 예전 값이라 안 된 것처럼 보였다. 설계: `docs/plan/2026-11-20-agent-model-effort-picker.md`.

- 도구: `list_sessions`, `cd`, `run_command`, `write_file`, `edit_file`, `upload_file`, `download_file`, `job_output`, `stop_job`, `list_jobs`. 세션 편집 > 고급 설정의 "MCP 접근 허용"(`mcpEnabled`)을 켠 세션만 보인다. 사이드바 세션 우클릭 메뉴의 `MCP 접근 허용` 으로도 같은 값을 켜고 끄며, 켠 세션은 목록에 플러그 표지(`.session-mcp-mark`)가 붙는다.
- 파일 쓰기(`write_file`, `edit_file`, `fileTools.js`)는 셸을 거치지 않고 SFTP 로 한다. 알림 수준과 무관하게 항상 확인 창을 띄우고, 창에는 명령 대신 변경 내용(diff)과 실제 경로(심볼릭 링크를 푼 경로)를 보여 준다. 제한 시간은 180초. 허용한 뒤 파일이 확인 창에 보여 준 내용과 달라졌으면 쓰지 않는다(`remoteFile.js` 의 `writeIfUnchanged`). 기존 파일은 같은 파일에 덮어써서 소유자·권한을 유지하고, 실패하면 이전 내용으로 되돌린다. 256KB·10,000줄 이하 UTF-8 텍스트만, 접속 계정 권한으로만 쓴다. 감사 로그에는 도구 이름, 경로, 승인 여부, 내용의 SHA-256 만 남고 내용은 남지 않는다. 설계와 보안 검토 반영: `docs/plan/2026-10-02-mcp-file-tools-design.md`.

- 확인 창은 세션 색(`sessionColor`)을 세션 이름 옆 네모와 창 왼쪽 띠로 보여 준다 (어느 세션 요청인지 한눈에 보려는 것). 색은 `toolShared.js` 의 `effectiveColor(session, folders)` 가 정하고, 요청을 만들 때(`tools.js`·`fileTools.js`·`transferTools.js` 의 `approvals.request`) 붙인다. 규칙은 사이드바의 `getFolderEffectiveColor` 와 같다: 세션 자체 색(`session.backgroundColor`)이 있으면 그것, 없으면 상위 폴더로 올라가며 처음 만나는 `backgroundColor`, 둘 다 없으면 `null`. 세션 색 필드는 `color` 가 아니라 `backgroundColor` 다 (`color` 로 읽으면 항상 비어 2.18.1 에서 네모가 안 떴다). 감사 로그·활동·`list_sessions` 에는 넣지 않는다 (정해진 필드만 골라 쓰므로 자동으로 빠진다).

- 백그라운드 작업(`run_command` 의 `background: true`, `job_output`, `stop_job`, `list_jobs`)은 30초를 넘는 명령을 위한 것이다. main 이 실행 채널을 요청과 분리해 붙잡고(`jobChannel.js`), 출력은 메모리에만 둔다(`jobStore.js`, 작업당 마지막 1MB). 판정은 `run_command` 와 같은 경로(`tools.js` 의 `guarded`)를 지나고, 알림 수준과 무관하게 항상 확인 창을 띄워 "백그라운드 실행 · 최대 N분" 을 보여 준다 (낮음 명령도 한 시간 동안 돌 수 있어서). 기본 10분·최대 60분, 세션당 3개·전체 6개, 총 출력이 16MB 를 넘으면 중지한다. 앱을 잠그거나 MCP 를 끄면 모든 작업을 중지하고 목록을 지운다 (앱을 닫아도 이어지는 작업은 일부러 만들지 않았다). 설계: `docs/plan/2026-10-02-mcp-background-jobs-design.md`.

- 파일 전송(`upload_file`, `download_file`, `transferTools.js`)은 PC 와 서버 사이에서 파일 하나(1GB 까지, 바이너리 포함)를 옮긴다. 앱이 PC 의 파일을 읽고 쓰는 유일한 MCP 도구다. 설정 > MCP 의 "파일 전송 허용 폴더"(`mcp.json` 의 `transferRoots`, 기본은 빈 목록) 안에서만 동작하고, 알림 수준과 무관하게 항상 확인 창(방향, 양쪽 실제 경로, 크기, 60초)을 띄운다. 받는 쪽에는 `.<이름>.ezshell-part-<난수>` 임시 파일로 쓰고 다 끝난 뒤 이름을 바꾼다. 20초 안에 끝나지 않으면 기존 작업(job)으로 넘어가 `job_output` / `stop_job` 으로 다루고, 제한은 60분이다. 감사 로그에는 양쪽 경로, 크기, 승인 여부, SHA-256 만 남는다. 설계와 보안 검토 반영: `docs/plan/2026-10-13-mcp-file-transfer-design.md`.
  - 바꾸면 안 되는 것: 전송 폴더는 main 의 폴더 선택 창으로만 추가한다 (`mcp-add-transfer-folder` 는 경로를 인자로 받지 않고, `mcpConfig` 의 일반 `update` 는 `transferRoots` 를 거부한다). 앱 데이터 폴더를 포함하는 폴더는 등록할 수 없다.
  - PC 경로 판정(`localPath.js`)은 글자만 보고 폴더 밖이면 파일 시스템을 건드리지 않고 거부한 뒤, 실제 경로로 다시 본다. 등록 폴더는 실제 경로로 저장하고, 지금 풀어 본 경로가 저장값과 다르면 무시한다 (폴더를 지우고 같은 이름의 정션을 만들면 정션이 가리키는 곳이 허용 범위가 된다). 디스크를 본 뒤의 거부는 모두 같은 문구다 (정션으로 임의 경로의 존재 여부를 알아낼 수 있어서).
  - 올리는 PC 파일은 확인 창 전에 한 번 열고 그 핸들만 읽는다. 연 뒤에 경로를 다시 풀어 파일 ID 가 같은지 보고, 이름이 둘 이상인 파일(하드 링크)은 거부한다 (경로 검사를 모두 통과하면서 내용은 폴더 밖 파일이다).
  - 전송은 세션의 명령 대기열과 별도의 SFTP 채널(`sessionGateway.openTransfer`)을 쓰고, 작업처럼 그 연결의 작업으로 센다. 임시 파일 정리가 끝난 뒤에 작업 종료를 보고한다 (먼저 보고하면 잠글 때 정리 전에 연결이 닫힌다).
  - 서버의 기존 파일 덮어쓰기는 `posix-rename` 확장이 있어야 한다. 없으면 거부하고, 지우고 다시 쓰는 방식으로 바꾸지 않는다 (중간에 끊기면 원래 파일을 잃는다).
- 호스트 주소와 계정은 Claude 에게 넘기지 않는다. 대신 `list_sessions` 가 `server` 표지(`서버-1`, ...)를 붙여 같은 서버에 접속하는 세션을 알려 준다 (호스트+포트, 점프 호스트를 쓰면 그 주소까지 같아야 같은 서버). 표지는 목록 순서 번호이고 주소의 해시가 아니다 (IP 해시는 역산할 수 있음).
- 명령은 `commandPolicy.js` 가 낮음/중간/위험/절대 차단으로 판정한다. 처음 보는 명령은 위험. 위험은 항상 앱 확인 창(60초 안에 응답 없으면 거부), 절대 차단은 실행 불가.
- `run_command`, `cd` 는 `reason`(요청 사유)을 받는다. 확인 창이 필요한 명령인데 사유가 없으면 창을 띄우지 않고 거부한다 (감사 로그에도 남기지 않음). 사유는 한 줄로 정리해 500자까지 쓰고, 확인 창에 "Claude 가 직접 적은 설명" 이라는 안내와 함께 보여 준다. 판단 기준은 명령이다 (사유는 거짓일 수 있음). Windows 알림에는 넣지 않는다. 설계: `docs/plan/2026-10-23-mcp-command-reason.md`.
- 설정은 `userData/mcp.json`(main 전용), 감사 로그는 `userData/mcp-audit.log`(명령, 판정, 요청 사유만. 출력은 기록하지 않음).
- 상태바의 "MCP 활동" 패널이 요청과 상태(대기/실행/완료/거부/취소/차단)를 실시간으로 보여준다. 이 목록과 명령 출력은 메모리에만 있고 디스크에 쓰지 않는다 (출력에 비밀이 섞일 수 있음).
- 패널에는 `목록 | 터미널` 두 보기가 있다 (기본은 터미널). 터미널 보기(`McpActivityTerminal.tsx`)는 명령과 출력을 시간순으로 잇는 읽기 전용 화면이고 xterm 이 아니다. 실행 중 출력은 `sessionGateway` 의 `onOutput` → `activityLog.appendOutput`(50ms 묶음) → `mcp-activity-output` 채널로 온다. 요청이 끝날 때 오는 `mcp-activity` 항목이 `outputParts` 전체를 담고 있어 그쪽이 기준이다. 실행 중에도 `update` 로 항목을 보내면 그 요청의 대기 중인 출력 묶음은 버린다 (창이 항목으로 사본을 바꾸므로, 묶음까지 보내면 줄이 두 번 보인다. `docs/fix/2026-11-05-mcp-transfer-progress-line-twice.md`). 탭으로 만들지 않은 이유: 탭은 모두 SSH 연결 하나를 전제로 한다.
- 터미널·서버별 보기의 출력은 줄을 접지 않고 블록마다 좌우로 스크롤한다 (`.mcp-term-output`, `white-space: pre`). psql·`docker ps` 처럼 칸을 맞춰 찍은 표가 그대로 보인다. 패널 머리줄의 `줄바꿈` 버튼(`mcpActivityPrefs` 의 `isOutputWrapped`, 기본 꺼짐)으로 예전처럼 창 너비에서 접는다. 한글 같은 두 칸 글자는 글꼴이 그리는 폭이 두 칸과 달라서, 그런 글자가 이어진 구간을 터미널이 주는 칸 수만큼의 너비로 감싼다 (`lib/terminalCells.ts` 의 `splitWideRuns`, `.mcp-term-wide`). 바꾸면 안 되는 것: 한 칸의 너비는 CSS 의 `ch` 가 아니라 그 글꼴로 실제로 재서 `--mcp-cell` 에 둔다 (`cellWidthOf`). `ch` 는 7.2px, 실제 글자는 7.12px 이어서 한글이 많은 줄에서 칸 구분선이 4px 넘게 어긋났다. 20만 자를 넘는 출력은 감싸지 않는다 (요소가 너무 많아진다).
- 세 번째 보기 `서버별`(`McpActivityLanes.tsx`)은 세션마다 영역을 나눠 같은 형식의 기록을 보여 준다 (`lib/mcpActivity.ts` 의 `groupBySession`). 영역마다 스크롤이 따로이고, 영역 순서는 첫 요청 순서로 고정이다 (활동 때마다 바꾸면 읽던 영역이 움직인다). 기준은 서버 주소가 아니라 세션이고, 요청을 보낸 에이전트는 구분하지 못한다 (stateless, 토큰 하나).
  - 영역 머리줄의 X 로 영역을 숨긴다. 숨길 때의 가장 최근 요청 ID 를 기억하고(`mcpActivityStore` 의 `hiddenLanes`, 판정은 `lib/mcpActivity.ts` 의 `isLaneHidden`), 그 세션에 새 요청이 오면 다시 보인다. 이미 있던 요청의 출력·상태 변화로는 다시 뜨지 않는다. 메모리에만 두고 목록을 지우면 함께 지운다. 상단 막대의 "모두 보기" 로 되돌린다. 설계: `docs/plan/2026-10-24-mcp-lane-hide.md`.
- 패널은 `z-index: 95` 다. 터미널·SFTP 위, 대화상자(100)·메뉴(1000)·업데이트 알림(900)·안내(9999) 아래다. 다시 높이지 말 것: 9200 이던 때 업데이트 알림과 대화상자가 패널 뒤에 가려졌다 (`docs/fix/2026-10-26-mcp-panel-layer-and-host-key-message.md`).
- 패널이 열린 채로 앱 화면(`#root`)의 다른 곳(셸, SFTP, 사이드바)을 누르면 패널이 화면 밖으로 완전히 밀려나고(`transform: translateX(100%)`) 하단 상태바에 MCP 활동 버튼과 대기·실행 건수가 표시된다. 상태바 버튼을 누르면 패널을 다시 펼친다 (`togglePanel`). 접힘은 `lib/mcpActivity.ts` 의 `collapsesMcpPanel` 이 캡처 단계에서 판정하며, 누른 동작은 셸로 그대로 간다. 확인 창·메뉴처럼 `#root` 밖에 그려지는 것과 알림은 접지 않는다. 접힌 패널은 스크롤 위치를 유지한 채 `inert` 이며, Esc 키는 셸에서 받는다. 설계: `docs/plan/2026-10-24-mcp-panel-collapse.md`.
- 서버별 보기의 영역은 머리줄을 끌어서 순서를 바꾼다 (HTML5 끌기, 형식 `application/x-ezshell-mcp-lane` 만 받음). 순서는 `mcpActivityStore` 의 `laneOrder`(메모리)이고 `lib/mcpActivity.ts` 의 `orderLanes`, `moveLane` 이 계산한다. 처음 보는 세션은 끝에 붙는다. 개별 기록은 시간순이라 옮기지 않는다.
- 파일 전송 요청은 활동 항목의 `transfer`(방향, 크기, 보낸 크기, 복사 시작 시각)로 진행 막대를 그린다 (`McpTransferBar.tsx`, 계산은 `lib/mcpTransfer.ts`). `transferTools.js` 가 1초마다 갱신하며 감사 로그에는 넣지 않는다. 속도는 복사 시작부터 센다 (확인 창 대기 시간 제외).
- 패널 머리줄의 "새 창으로 열기" 로 MCP 활동 창(`?mcpActivityMode=true`, `McpActivityWindow.tsx`, 패널의 `window` 형태)을 연다. 창은 하나이고 main 의 `sendToActivityViews` 가 활동 갱신을 본창과 이 창에 보낸다. 앱을 잠그면 닫고, 잠긴 동안에는 열 수 없다 (명령 출력이 잠금 화면 뒤에 남지 않게). 확인 창은 본창에만 뜬다. 설계: `docs/plan/2026-10-24-mcp-activity-window-progress-reorder.md`.
- 터미널·서버별 보기의 명령 줄은 `lib/shellFormat.ts` 가 `;` `&&` `|` 마다 줄을 나누고 색을 입혀 보여 준다 (`sh -c '...'` 안 스크립트는 한 단계 더 들여씀). 표시만 바꾸고, 감사 로그·실행은 원문이다. 확인 창(`McpApprovalDialog`)도 같은 정렬로 보여 주되(`ShellCommandText.tsx`), `원문 보기` 로 바꿀 수 있고, 정렬 결과에서 공백을 뺀 글자가 원문과 다르면 원문만 보여 준다 (`isFaithfulLayout`, 바꾸면 안 되는 것: 판단하는 화면이 실행될 명령과 다른 글자를 보여 주면 안 된다). 연산자를 줄 끝에 두어 복사해도 같은 뜻으로 실행된다. heredoc 은 여는 줄까지만 나누고(그 줄의 `<<EOF` 뒤로는 나누지 않음) 본문은 글자 그대로 두며 문자열·주석·키워드에만 색을 입힌다. 끝 줄 없는 heredoc·닫히지 않은 따옴표는 원문 그대로 둔다. 설계: `docs/plan/2026-11-03-mcp-activity-command-layout.md`.
- 시작한 지 3초가 지나도 진행 중인 요청은 패널 위에 고정한다 (`McpPinnedRequests.tsx`, 계산은 `lib/mcpPinned.ts`). 터미널·목록 보기는 기록 위, 서버별 보기는 영역마다 위에 둔다. 카드는 명령 한 줄(길면 말줄임), 접기/펼치기, 출력 마지막 3줄이고 오래 실행된 순서다. 기록에서는 빼지 않는다 (전체 출력은 기록에서 본다). 3초 기준을 없애면 바로 끝나는 명령마다 카드가 나타났다 사라져 기록이 흔들린다. 설계: `docs/plan/2026-11-02-mcp-activity-pinned-requests.md`.
