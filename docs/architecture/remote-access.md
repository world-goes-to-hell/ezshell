# Remote Access (휴대폰 브라우저, Tailscale)

[공통 작업 규칙과 기능별 목록](../../CLAUDE.md)

설정 > 원격 접속에서 켜면 main 이 이 PC 의 Tailscale 주소(100.64.0.0/10, fd7a:115c:a1e0::/48)의 8722 포트에 HTTP·WebSocket 서버를 열고, 휴대폰 브라우저가 저장된 세션의 터미널을 쓴다 (`src/remoteAccess/`: `controller.js` 가 main 연결·IPC, `server.js` 서버, `accessStore.js` 기기·인증, `shells.js` SSH 셸, `web/` 휴대폰 화면). SSH 접속은 PC 가 하고 저장 세션의 이름·폴더·색과 열린 탭 상태, 셸 입출력을 휴대폰에 보낸다. 기본은 꺼짐. 설계와 메시지 형식: `docs/plan/2026-11-13-remote-access-over-tailscale.md`.
- 2단계(휴대폰 화면을 PC 수준으로): 세션 목록은 PC 사이드바와 같은 폴더 구조·색·순서·펼침 상태·열린 탭 수(`controller.js` 의 `sessionTree`, 이 함수가 복사하는 것 말고는 휴대폰으로 가지 않는다). MCP 확인 요청은 PC 창과 함께 인증된 기기에도 가고(`main.js` 의 `showMcpApproval` → `remoteAccess.showApproval`), 기기의 답은 `mcpController.respondApprovalFrom` 으로 들어가 PC 창을 닫는다. MCP 활동은 활동 화면을 보고 있는 기기(`activity-watch`)에만, 요청당 출력 마지막 16KB 로 보낸다. 설정의 `휴대폰에서도 확인 요청에 답하기`(`answerMcp`)로 끈다.
  - 바꾸면 안 되는 것: 기기의 답은 그 기기에 보낸 요청에 대해서만, 보낸 뒤 0.8초가 지나야 받는다 (`APPROVAL_ARM_MS`, 화면의 버튼 비활성과 같은 규칙을 서버가 다시 본다). 답한 기기는 답이 적용되기 전에 감사 로그(`mcp-audit.log` 의 `phase: 'remote-answer'`)에 남기고, 쓰지 못하면 답을 받지 않는다.
  - 확인 대기 시간: 요청이 휴대폰에 닿을 수 있는 동안만 4분으로 늘린다 (`controller.js` 의 `canReachDevice`: 접속 중인 기기가 있거나, HTTPS 이고 알림을 켠 기기가 있을 때. `approval.js` 의 `minTimeoutMs`). 등록만 되어 있고 닿을 수 없는 휴대폰 때문에 늘리지 말 것: 자리를 비운 PC 에 확인 창만 4배 오래 떠 있게 된다. 5분 이상으로 올리지 말 것: Claude Code 는 5분 동안 응답이 없는 HTTP MCP 호출을 끊는다.
  - 2단계 보안 검토 반영 (바꾸지 말 것): 활동 항목은 정해진 필드만 보낸다 (`server.js` 의 `ACTIVITY_FIELDS`, 결과 글자도 16KB 로 자름. 항목을 통째로 보내면 파일 변경의 내용까지 간다). 읽지 않은 자료가 1MB 넘게 쌓인 기기에는 활동을 보내지 않는다. Tailscale 주소가 아닌 접속은 TCP 단계에서 끊는다 (HTTPS 에서는 요청을 보기 전에 TLS 핸드셰이크가 먼저다). 이름 없는 세션은 주소 대신 `이름 없는 세션` 으로 보낸다. 기기에서 한 중지도 감사 로그에 남긴다 (`phase: 'remote-stop'`). Windows 에서는 `tailscale.exe` 를 설치 경로에서만 찾고, 이름은 글자·숫자로 시작해야 하며 `--` 뒤에 넘긴다. 원격 접속을 끄면 인증서와 키 파일을 지운다.
  - 알림은 웹 푸시다 (`webPush.js`, 라이브러리 없이 RFC 8291·8292 구현, 표준의 예제와 바이트 단위로 같은지 테스트한다). 푸시는 HTTPS 페이지에서만 되므로 Tailscale 인증서(`tailscaleCert.js`, `tailscale cert`)를 받을 수 있으면 이 PC 의 `*.ts.net` 이름으로 HTTPS 를 열고, 못 받으면 HTTP 로 열고 알림만 없다. PC 에서 15초 안에 답하지 않았을 때(PC 를 1분 넘게 안 쓰고 있으면 바로) 보낸다.
  - 바꾸면 안 되는 것: 알림 본문에는 요청 종류와 위험도만 넣는다 (명령·경로·세션 이름·주소 없음). 기기가 등록하는 푸시 주소는 브라우저 회사의 푸시 서비스만 받는다 (`isAllowedEndpoint`: 기기가 정한 주소로 PC 가 요청을 보내게 되므로). 서명 키의 개인 키는 인증 키처럼 봉인한다. `tailscale` 은 전체 경로로 먼저 찾아 인자 배열로 실행하고, 이름은 `*.ts.net` 형식만 넘긴다.
  - 휴대폰 화면 파일은 `web/` 의 `app.js`(연결·화면 전환), `sessions.js`, `approvals.js`, `activity.js`, `push.js`, `sw.js`(알림 표시). 서버는 `server.js` 의 `STATIC` 에 적힌 파일만 내준다.
- 3단계(PC 탭 이어 보기·에이전트 채팅). `휴대폰에서 PC 탭 이어 보기`(`tabs`)와 `휴대폰에서 에이전트 쓰기`(`agents`)는 각각 기본 꺼짐이다 (`accessStore.js`). `ready.features`와 설정이 바뀔 때의 `features`로 작업 목록의 기능을 보이거나 숨긴다 (`web/app.js`). 끄면 휴대폰의 열린 탭 이어 보기나 채팅도 닫는다. 설계와 메시지 형식은 `docs/plan/2026-11-24-remote-access-tabs-and-agents.md`.
  - 너비 45rem·높이 40rem 이상이면 연결 목록·로컬 작업·PC 탭을 왼쪽에 배치하고, 휴대폰은 같은 목록을 왼쪽 서랍에 둔다. 데스크톱 타이틀바·탭 스타일·아이콘·글꼴을 가져온다. 상단 탭을 바꿔도 SSH 셸을 유지하며 PC 탭·채팅 구독은 앞에서만 붙인다. PC 탭 이어 보기(터미널·브라우저)는 기기당 6개(`MAX_TABS_PER_DEVICE`)까지다. 재접속하면 탭 목록과 앞 탭을 복원하고, SSH는 종료된 화면에서 사용자가 다시 열 수 있다. 설계는 `docs/plan/2026-11-25-remote-pc-like-ui.md`.
  - PC 탭은 열었던 순서대로, SSH 탭의 주 터미널만 이어 본다 (`controller.js` 의 `tabList`·`tabAccess`, `web/tabs.js`). 저장 세션 탭에는 입력할 수 있다. 빠른 연결은 이름을 `빠른 연결`로 보내고 `inputAllowed: false`라 보기만 된다. `sshSessions.js`가 보낸 출력은 `tabMirror.js`에 탭당 최대 256×1024자(`MAX_KEPT_CHARS`)까지 청크로 메모리에만 보관한다. 바꾸면 안 되는 것. 탭을 닫거나 앱을 잠그거나 해당 기능을 끄면 보관한 출력을 지운다. 휴대폰은 붙을 때 받은 PC 행·열로 그리고 가로로 스크롤한다. 휴대폰이 크기를 바꾸거나 xterm의 자동 응답을 `tab-input`으로 보내면 안 된다 (`bindTerminalInput`). 실제 키 이벤트가 만든 시퀀스, 보조 키와 일반 텍스트 입력만 전달한다 (붙여넣기 구분자는 브라우저의 실제 붙여넣기에서만 허용).
  - `agentBridge.js`는 기기가 연 채팅의 글만 `localShell.js`의 `chatSend`로 보낸다. 바꾸면 안 되는 것. 로컬 셸 직접 입력, `/`·`!`로 시작하는 글, 이미지·첨부는 받지 않는다. 확인 질문이 없고 CLI 입력칸이 비어 있으면 작업 중에도 PC와 같은 경로로 보낸다. 번호 답은 그 기기에 보낸 `signature`와 0.8초 대기(`ANSWER_ARM_MS`)를 확인하고, PC에서 읽은 현재 선택지가 맞는지 다시 본다. `계속 허용`·`다시 묻지 않기` 같은 지속 권한은 `STANDING_GRANT`로 거부한 뒤 나머지만 `answerApproval`에 넘긴다. Antigravity는 입력 대기 중에만 글을 받고, 확인·중지는 PC 터미널에서 처리한다.
  - 원격 채팅 확인 카드의 지속 권한은 서버에서 표시를 붙여 보내고, 휴대폰에는 비활성 선택지와 `PC에서만` 표지로 표시한다. 서버는 응답을 받을 때 현재 선택지를 다시 검사한다.
  - 채팅은 기기당 4개(`agentBridge.js` 의 `MAX_CHATS_PER_DEVICE`), 전체 8개(`chats.js` 의 `MAX_REMOTE_CHATS`)까지다. 바꾸면 안 되는 것. 셸에 묶인 에이전트 종류·id와 확인된 대화의 `sessionId`가 바뀌거나 사라지면 후속 프레임을 보내기 전에 구독을 닫는다 (`isSameAgent`, `open`의 `onFrame`). `remote-access.log`에는 시각·작업·기기·대상, 채팅 동작 결과(`ok`)와 보내기 글자 수(`chars`)를 남긴다. `tab-attach`와 `tab-input`도 기기·탭을 기록한다. 입력·출력·대화 원문은 기록하지 않는다.
  - 원격 채팅(`web/agents.js`·`agents.css`)은 PC처럼 시각이 붙은 말풍선, 접는 도구 요약, 번호가 분리된 확인 카드와 입력 위 작업 상태를 표시한다. 질문별 토큰·시간·한도는 기존 채팅 프레임의 숫자에서 그리며, 대화와 카드 내용은 DOM 텍스트로 넣는다.
  - 바꾸면 안 되는 것 (전송 밀림). 탭 출력이 2MiB 넘게 밀린 기기는 `tab-error`로 이어 보기만 끊어 PC 셸을 계속 쓴다 (`TAB_BACKLOG_BYTES`). `server.js`의 `sendTo`는 보낼 메시지를 포함한 기기별 대기량이 4MiB를 넘으면 탭·채팅 구독과 연결을 닫는다 (`MAX_BACKLOG_BYTES`, `cutOff`).
  - 테마는 본창의 주 프레임에서 온 `quick-capture-theme`를 받는다 (`main.js` → `remoteAccess.setTheme`). `controller.js`의 `remoteThemeOf`는 캡처와 같은 검사로 화면 색·모서리·글꼴·밝기와 터미널 ANSI 16색·고정폭 글꼴만 `ready.theme`과 실시간 `theme`에 싣는다. 휴대폰은 `web/theme.js`에서 정해진 값만 기억해 로그인 화면부터 적용하고, 열린 SSH·PC xterm 두 종류의 색과 글꼴을 함께 갱신한다.
  - 원격 연결 목록은 `sessionTree`가 보내는 폴더·세션의 색, 연결 상태, 탭 수로 그린다. 연결된 탭이 있으면 초록 점, 끊긴 탭만 있으면 빨간 점이며 탭 수는 상태별 배지로 표시한다.
  - 태블릿은 사이드바의 폭과 접힘을 기억한다. 로컬 프로젝트의 한 줄에 이름과 에이전트 칩을 표시하고, 길게 누르면 에이전트 이름과 상태가 보인다. 접힌 띠에는 연결·끊김 SSH 탭(PC 세션과 원격 셸), 로컬 에이전트, 공유 PC 탭, MCP 대기를 아이콘과 개수로 표시한다. 0건인 표시는 숨기고, 작업 중 에이전트가 있으면 해당 아이콘의 둘레에 작업 중 빛이 돈다. 아이콘을 누르면 사이드바를 펼친다.
  - 화면을 둘로 나누면 가로에서 좌우, 세로에서 위아래로 배치하고 각 화면의 탭 줄에서 선택한 탭을 동시에 구독한다. 탭을 화면 가장자리나 다른 탭 줄로 끌거나 길게 누르기 메뉴를 쓴다. 화면별 탭과 포커스, 분할 비율은 재접속 때 복원한다. 같은 기기 연결의 브라우저 미리보기는 `viewId`별로 분리되며 기존 PC 탭·채팅 상한을 공유한다.
  - 휴대폰·태블릿 탭 줄에는 앞 탭의 작업만 표시하고, 작업 선택 상자로 마지막 탭과 분할을 되살린다. 연결 목록에서 연 SSH는 일반, 프로젝트의 `서버` 줄에서 연 SSH는 해당 작업이다. 채팅과 공유 PC 탭은 PC의 프로젝트를 따른다. 본창 주 프레임의 `remote-access-local-projects`에는 탭의 묶음과 연결한 세션 ID도 실린다. `controller.js`는 형식을 검사하고 프로젝트 키를 익명 ID로 바꿔, 원격 기기에 표시용 묶음과 저장 세션 ID·이름을 보낸다.
  - OTP는 6자리 입력 시 제출한다. 하드웨어 `Ctrl+Tab`·`Ctrl+숫자`는 열린 탭을 고르고, `Ctrl+W`는 터미널에 포커스가 있으면 셸로 보낸다. 길게 누르기 메뉴가 제공하는 PC 탭 붙여넣기는 실제 클립보드 텍스트와 입력 허용 상태를 확인한다.
- 인증은 둘 다 필요하다: 등록된 기기 토큰(설정 화면의 QR 로 등록, 1회용 코드 2분, PC 에는 SHA-256 만 저장)과 인증 앱의 6자리 코드(TOTP, 기기마다 같은 코드는 한 번만). 코드를 5번 틀리면 그 기기만 5분 동안 막고, 15분 입력이 없으면 끊는다. 기기는 5대, 동시 접속 4개, 셸 6개까지.
- 하루 동안 기기 기억(`rememberDevice`, `resume`, 상수 `TRUST_MS`=24시간): 로그인 화면의 `하루 동안 이 기기 기억`(기본 켬)을 켜고 코드로 접속하면, 서버가 32바이트 무작위 재접속 표를 발급한다(PC 에는 SHA-256 해시와 만료시각만 기기 레코드에 저장, 휴대폰은 `localStorage`). 24시간 안에는 `resume`(토큰+표)으로 코드 없이 들어온다. 설계와 보안 검토: `docs/plan/2026-11-13-remote-access-remember-device-for-a-day.md`.
  - 바꾸면 안 되는 것: 표는 두 번째 요소를 대신할 뿐 기기 토큰은 여전히 필요하다. `resume` 은 `signin` 과 똑같은 모든 검사(Tailscale 주소, 앱 잠금, 기기 등록·잠금 상태, `MAX_CLIENTS`, 주소별 제한)를 공통 함수 `enter` 로 지난다. 표가 없거나 만료면 실패로 세지 않고(benign) 코드 입력으로 넘기지만, 표가 있고 만료 전인데 값이 틀리면 실패로 세어 기존 잠금 보호를 적용한다. 만료된 표는 지우고, 기기를 해제하면 표도 사라진다. 평문으로 저장하지 않는다.
  - 표는 `enter()` 가 성공한 뒤에 발급해 별도 `trust` 메시지로 보낸다 (`ready` 에 싣지 않는다: 표를 먼저 만들고 `enter` 가 `MAX_CLIENTS` 로 막히면, 전달 못 한 표가 유효한 옛 표를 덮어썼다). `기억` 을 끄고 로그인하면 옛 표를 지운다. 원격 접속을 끄면(`setEnabled(false)`) 모든 기기의 표를 지운다 (껐다 켠 뒤 분실한 폰이 들어오지 못하게). 앱 잠금은 포트만 닫고 표는 남긴다 (잠금 해제 뒤 코드 없는 재접속이 이 기능의 목적).
- 바꾸면 안 되는 것: Tailscale 주소에만 포트를 열고(`0.0.0.0`·LAN 으로 여는 선택지를 만들지 않는다), 들어온 접속의 주소도 Tailscale 대역인지 다시 본다. WebSocket 은 Origin 이 이 서버 주소(HTTPS 면 `https://<이름>:<포트>`)일 때만 받는다 (다른 사이트 페이지가 소켓을 열지 못하게). 앱이 잠겨 있으면 포트를 닫고, 잠그면 모든 기기와 셸을 끊는다. `remote-access-*` IPC 는 본창에서 온 것만 받는다.
- 보안 검토 반영 (바꾸지 말 것):
  - 주소는 Tailscale 인터페이스(Windows·Linux 는 이름에 tailscale, macOS 는 `utunN`)의 것만 쓴다. 100.64.0.0/10 은 통신사 NAT·테더링도 쓰는 대역이라, 대역만 보면 그 망에 포트를 연다.
  - WebSocket 의 Origin 과 Host 는 서로 비교하지 않고 서버가 연 주소(`http://<주소>:<포트>`)와 비교한다 (이 주소를 가리키게 만든 도메인의 페이지는 둘이 서로 같다). 다른 이름으로 온 페이지 요청은 주소로 돌려보낸다.
  - 실패 횟수는 모두에게 걸지 않는다: 같은 tailnet 의 아무 기기가 틀린 값을 보내 주인을 막을 수 있었다. 인증 코드 실패는 기기별(토큰이 맞을 때만), 그 밖의 실패는 연결별(5번이면 끊음)·주소별(5분에 10번이면 접속 거부)로 센다.
  - 기기가 보낸 값은 어떤 글자든 예외 없이 처리해야 한다: 비밀 비교는 양쪽을 해시한 뒤 한다 (`timingSafeEqual` 은 바이트 길이가 다르면 던진다), 소켓의 `error` 처리기는 맨 먼저 붙인다, 메시지 처리 전체를 try/catch 로 감싼다. main 에는 잡히지 않은 예외를 받는 처리기가 없다.
  - 인증하지 않은 연결은 동시 접속 수(4)에 세지 않고 따로 제한한다 (주소당 3개, 전체 12개). 같이 세면 인증 없이 자리를 채워 주인을 막는다.
  - 셸 출력은 20ms 마다 묶어 보내고, 휴대폰이 1MB 넘게 밀리면 셸 읽기를 멈춘다 (`shells.setPaused`). 멈추지 않으면 느린 휴대폰 앞에서 main 의 메모리가 끝없이 는다.
- 바꾸면 안 되는 것: 저장된 호스트 키만 받는다 (PC 앞에 사람이 없다: MCP 와 같은 규칙). 휴대폰으로 가는 오류 문구에 서버 주소를 넣지 않는다. 셸 입력·크기 변경·닫기는 그 셸을 연 연결만 할 수 있다 (`shells.js` 의 `owned`).
- 셸이 열리는 중에 기기가 끊기거나 앱이 잠기면 `closeAll` 이 닫을 대상이 아직 없다. 그래서 열리는 셸이 준비된 뒤 `goneOwners`·`epoch` 를 보고 스스로 닫는다. 이 확인을 지우면 주인 없는 SSH 연결이 남는다.
- 인증 앱 비밀 키는 `userData/remote-access.json` 에 safeStorage 로 봉인해 둔다 (`totpSecretSealed`, 앱이 준비된 뒤 처음 쓸 때 연다). 평문으로는 쓰지 않는다: 봉인할 수 없는 PC 에서는 원격 접속을 켤 수 없다. 끊는 소켓은 2초 뒤 강제로 닫고(`closeSocket`), 닫히는 중인 소켓의 메시지는 처리하지 않는다 (끈 뒤에 온 `open` 이 셸을 열면 안 된다). 기록은 `userData/remote-access.log` 에 시각·기기·한 일만 남기고 입력과 출력은 남기지 않는다 (1MB 를 넘으면 뒤쪽 절반만 남김, 시작할 때와 200줄마다 확인).
- QR 은 main 이 `qrcode` 로 칸 배열만 만들고 화면이 SVG 로 그린다 (`lib/qrSvg.ts`, 페이지 CSP 가 data: 이미지를 막는다). 테마와 상관없이 흰 바탕에 검정이다.
- 휴대폰 화면(`web/`)은 빌드 단계가 없는 일반 스크립트다. xterm 은 devDependency 라 설치본에 없으므로 `electron.vite.config.ts` 가 `web/vendor` 로 복사한다 (`REMOTE_ACCESS_VENDOR`, 이름은 `server.js` 의 `VENDOR` 와 같아야 한다). 새 `src/` 폴더라서 `MAIN_RUNTIME_DIRECTORIES` 에 `remoteAccess` 가 있다.
- 시험할 때: 개발 실행(`npx electron out/main/index.js`)은 `app.getVersion()` 이 Electron 버전이라 `업데이트 내용` 창이 뜨지 않지만 패키징된 앱은 뜬다. 창이 가려져 있으면(`document.hidden`) 닫힘 애니메이션이 끝나지 않아 배경이 클릭을 막는다.
