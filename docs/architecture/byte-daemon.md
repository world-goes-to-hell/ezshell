# Byte Daemon (상태 줄에 숨긴 미니 게임)

[공통 작업 규칙과 기능별 목록](../../CLAUDE.md)

상태 줄 맨 오른쪽의 16px 데몬 아이콘(`ByteDaemon/ByteDaemonStatus.tsx`)을 누르면 위로 팝오버가 열린다 (2026-11-24 사용자 요청, 이름·그림체·구성은 시안 `mockups/byte-daemon.html` 에서 사용자가 고름). 바이트(1024 단위)를 모으는 방치형이고, 중심은 30초 안팎의 미니 게임 셋이다: 오류 잡기(`CatchBugGame`, 로그 줄의 벌레를 누름), 명령어 타자(`TypingGame`), 금요일 배포(`DeployGame`, 판돈을 걸고 단계마다 도전·멈춤). 생산자 8종(메모지 요정 alias → … → 구름 양 데이터센터)은 값이 1.15배씩 오르고 일부는 게임을 돕는다. 계산은 `lib/byteDaemon.ts`(경제·정산·저장 형식)와 `lib/byteDaemonGames.ts`(게임 규칙), 그림은 `lib/byteDaemonArt.ts`(코드로 그린 SVG 문자열, 외부 그림 없음), 상태는 `stores/byteDaemonStore.ts`(`localStorage` 의 `byteDaemon`, 2초에 한 번 저장). 설계: `docs/plan/2026-11-24-byte-daemon-mini-game.md`. 화면 테스트 `byte-daemon`.
- 테마: 창·버튼·글자·로그 색과 모서리는 ezShell 테마 변수(`--bg-*`, `--text-*`, `--accent`, `--border*`, `--radius-*`, `--error-text` 등)와 Glass 표면을 따른다 (사용자 요청). 캐릭터 색만 고정이다.
- 바꾸면 안 되는 것 (부담): 팝오버가 닫혀 있으면 타이머가 하나도 돌지 않는다. 생산량은 마지막 정산 시각과의 차이로 계산한다 (`settle`, 최대 8시간, 5분 넘게 비면 `받기` 줄로). 정산 결과와 기준 시각은 한 번에 함께 바꾸고, 시계가 뒤로 가면 0이다 (중복 지급 방지). 열려 있어도 창이 가려지면 멈춘다.
- 바꾸면 안 되는 것 (화면): 게임 로그는 항상 세 줄 높이다. 팝오버는 아래에 붙어 위로 자라므로, 로그가 늘면 위의 버튼이 누르려는 순간 움직였다 (화면 테스트에서 찾음). 금요일 배포를 도중에 나가면(닫기 포함) 그때까지 오른 단계로 받고, 첫 단계 전이면 판돈을 돌려준다. 배포의 기대 배율은 어디서 멈춰도 약 1.1배다: 게임보다 나은 벌이가 되면 안 된다 (테스트가 본다). 실제 에이전트 작업에 보상을 묶지 않는다 (게임 때문에 에이전트를 켜 두게 된다: Codex 의견).
- 키: 타자 게임은 한글 입력 상태여도 키 자리(`code`)로 글자를 읽는다 (`keyChar`). Ctrl·Alt·Meta 조합과 Esc 는 가로채지 않는다. Esc 는 팝오버를 닫고 열기 전 포커스로 돌려준다 (바깥 클릭으로 닫을 때는 돌려주지 않는다: 누른 곳이 포커스를 가져간다).
- Zen 모드에서는 그리지 않고, 명령 팔레트 `미니 게임 아이콘 숨기기/보이기` 로 감춘다 (진행 상황은 남음). 화면 설정 백업 목록에는 넣지 않는다.
