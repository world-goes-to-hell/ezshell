# 화면과 터미널 칸 나누기

[공통 작업 규칙과 기능별 목록](../../CLAUDE.md)

## Two Split Systems

1. **Per-Terminal Split** (TerminalPanel 내부): 탭의 터미널 영역을 칸으로 나눈다. 칸마다 `SplitTerminal` 이 추가 셸 채널을 연다. 배치는 분할 트리(`TerminalInfo.splitTree`, `lib/splitTree.ts`)다. 같은 문서의 `Split Panes` 절 참고
2. **Screen Split** (App.tsx): 탭을 나란히 보는 화면 나누기. 화면 목록 `LayoutState.panes`(1~4개, `sizes` 몫, `activePane` 포커스, 한 방향)이고 계산은 `lib/screenPanes.ts`. `primary`·`secondary`·`activePaneType` 은 앞 두 화면의 보기로 스토어가 매번 다시 계산해 남긴다 (두 화면용 옛 코드 호환). 스토어 동작은 화면을 번호로, 또는 옛 이름으로 받는다. 나뉘지 않은 화면의 탭을 가장자리 띠(48px)에 놓으면 둘로 나누고, 나뉜 화면의 탭 줄에서 끌어 나눈 방향의 끝 띠에 놓으면 그쪽 끝에 새 화면을 더한다. 4개이거나 다른 방향의 끝이면 띠를 칠하지 않고 이유를 알린다. 화면 사이 구분선을 끌면 이웃한 둘만 바뀌고(최소 12%), 두 번 누르면 모두 같은 폭. 설계: `docs/plan/2026-11-19-screen-split-up-to-four.md`, 화면 테스트 `local-screen-split`.
   - 바꾸면 안 되는 것: 나뉜 화면에서 가장자리 띠는 화면 나누기 몫이다 (`useTabDropOnPane` 의 `hasEdgeZones` 를 나뉜 동안 항상 켬). 4개일 때 띠를 칸 병합에 돌려주면, 끝에 놓은 탭이 말없이 셸 분할로 합쳐진다.
   - 화면 번호 0 은 거짓 값이다: `findTabPane` 등의 결과는 `!== null` 로 본다 (`if (pane)` 로 보다가 첫 화면의 탭에 포커스가 가지 않았다).

## Split Panes (칸 나누기·자리 바꾸기·탭으로 빼기)

탭의 터미널 영역은 분할 트리로 나뉜다 (`lib/splitTree.ts`): 잎은 칸(또는 빈 자리), 안쪽 노드는 나눔(`row` 좌우 / `col` 상하)과 비율. 우클릭 `분할` 의 `좌우 분할`/`상하 분할` 은 우클릭한 칸만 반으로 나누고(새 칸은 오른쪽·아래), 나눈 칸을 또 나눌 수 있다. `이 칸 닫기` 는 함께 나뉘었던 쪽이 자리를 채우고, `칸 크기 균등화` 는 나란한 칸 수에 맞춰 모든 경계를 다시 둔다 (세 칸은 1/3 씩, 구분선을 두 번 누르면 그 선만). SSH 탭은 6칸까지다 (`SSH_MAX_PANES`, 서버의 연결당 채널 제한을 SFTP·DB 와 함께 쓴다). 실행 중인 로컬 탭에는 칸 개수 상한이 없다. 로컬 배치를 복원할 때는 저장 기록을 최대 64칸과 깊이 63까지 읽는다 (`lib/restoreTabs.ts`). 나누면 20칸·5줄 미만이 되는 방향은 비활성, 탭의 첫 터미널(`main`)도 칸으로 나뉘어 있으면 `이 칸 닫기` 로 닫힌다: 남은 셸 중 연결이 끝난 하나가 먼저 주 셸을 이어받고(`lib/paneToTab.ts` 의 `closeTabPane`, 탭으로 빼기·Alt 끌기 병합과 같은 `ssh-promote-pane`/로컬 승격 경로) 옛 주 셸을 닫는다. 그래서 탭의 SFTP·포트 포워딩·이름이 그대로다. 남은 셸이 아직 연결 중이면 닫지 않고 알린다. 칸이 하나뿐인 탭에서는 메뉴가 비활성이다 (탭 닫기로 닫는다). 예전의 고정 배치(2분할·4분할·tri, `splitDirection`/`splitSlots`)와 `4분할`·`분할 해제`·구분선 우클릭 병합은 없앴다. 설계: `docs/plan/2026-11-17-terminal-pane-drag.md`.
- 그리기: 칸·구분선·손잡이·빈 자리는 모두 분할 영역(`.terminal-split-container`)의 평평한 자식이고, 트리에서 계산한 사각형으로 `position: absolute` 배치한다 (`paneBox`, `dividerBox`). 터미널이 아닌 것들은 `Terminal/SplitChrome.tsx` 가 그리고 SSH 탭과 로컬 터미널 탭이 함께 쓴다.
- 로컬 탭에서는 평소 구분선을 투명하게 그려 6px 틈의 배경이 보인다. 틈은 어두운 앱에서 검은색에 가까운 색, 밝은 앱에서 회청색으로 칠한다. 구분선은 같은 위치에서 드래그와 두 번 클릭을 받는다. 손잡이·빈 자리·Alt 드래그 미리보기는 칸과 같은 배치 기준을 쓴다.
- 바꾸면 안 되는 것: 칸 감싸개의 key(`w-<칸 id>`)·부모·문서 안 순서(id 순)는 배치와 무관하게 고정이다. 감싸개가 다른 부모나 key 로 가면 React 가 새로 만들고 그 칸의 셸이 닫힌다. 칸 id(`split-<번호>`)는 탭 안에서 다시 쓰지 않는다 (`TerminalInfo.paneSeq`). 구분선의 끝은 다른 나눔과 맞닿는 쪽에서 반 선만큼 짧다: 겹치면 선이 만나는 곳을 잡을 때 다른 선이 잡힌다.
- 손잡이: 칸 위 가장자리 28px 안에 포인터가 오면 `⋯` 가 나타난다 (터미널 본문은 글자 선택에 쓰므로 손잡이만 끌 수 있다). 다른 칸의 가운데(가로·세로 40%)에 놓으면 두 칸의 자리가 바뀌고, 가장자리 쪽에 놓으면 끌던 칸이 제자리에서 빠져(함께 나뉘었던 쪽이 그 자리를 채움) 놓은 칸의 그쪽 절반으로 들어간다 (`lib/paneDropZones.ts` 의 `zoneAt`·`movePaneBeside`, 칸을 대각선으로 네 조각 낸 뒤 가까운 쪽). 끄는 동안 들어갈 절반을 칠하고(`.pane-drop-preview`) 절반이 180px·100px 보다 작아지는 쪽은 붉게 막는다 (`canHalve`). 트리의 잎만 바꾸므로 셸은 그대로. 끄는 동안에는 칸마다 놓을 자리(`.pane-drop-zone`)를 덮는다: xterm 이 끌기 이벤트를 삼킨다. 끌기 형식은 `application/x-ezshell-term-pane` (`lib/paneDrag.ts`).
- 탭으로 빼기: 손잡이를 탭 줄(`.terminal-tabs`, 분할 화면은 `.split-pane-header`)에 놓으면 그 칸의 셸이 그대로 새 탭이 된다 (`hooks/usePaneDropOnTabs.ts` → `lib/paneToTab.ts`). 문서에 캡처 단계로 건 처리기다: 탭 줄의 자체 놓기 처리(탭 이동)가 칸의 놓기를 보면 안 된다. 빠져나간 자리는 빈 칸으로 남고 `가로로 병합`/`세로로 병합` 으로 옆 칸이 채운다 (`mergeVacant`: 함께 나뉘었던 쪽은 항상, 다른 방향은 두 나눔이 2x2 블록처럼 맞물릴 때만).
  - SSH: main 의 `ssh-adopt-split` 이 그 채널에 새 세션 id 를 주고 `sshConnections[새 id] = { conn(원래 탭과 같은 객체), stream, jumpConn }` 으로 등록한다. 그래서 옮긴 탭은 일반 SSH 탭이다 (SFTP, 분할, 로그, 탭 복제, 재연결). 화면은 main 이 넘겨준 뒤에 옛 칸의 xterm 이 받은 출력을 다 그리고 나서 `xterm-addon-serialize` 로 떠서 `setPendingSnapshot(새 id)` 로 넘긴다 (그 사이 온 출력은 스토어의 `sshDataBuffers` 가 뒤에 쌓는다). `SplitTerminal` 은 넘겨준 채널을 닫지 않는다 (`lib/splitShells.ts`).
  - 바꾸면 안 되는 것 (연결 공유, `src/sharedConn.js`): 같은 `conn` 을 쓰는 세션이 남아 있으면 탭을 닫거나 다시 연결해도 연결을 끝내지 않고 그 탭의 채널만 `close()` 한다 (`end()` 는 PTY 셸이 무시해 서버에 남는다). 마지막 세션이 닫힐 때 연결과 점프 호스트를 끝낸다. `conn.end()` 를 직접 부르지 말고 `sharedConn.release` 를 쓴다 (`ssh-disconnect`, `ssh-reconnect-now`, `reconnectOnce`). `ssh-adopt-split` 은 본창에서 온 것만, 살아 있는 분할 채널 id 하나만 받는다. 연결이 끊기면 탭마다 자기 채널의 종료를 보고 따로 재연결하고, 그 뒤에는 각자 자기 연결을 갖는다. 두 탭이 연결을 함께 쓰는 동안에는 연결당 채널 제한도 함께 센다.
  - 로컬 터미널: 칸마다 이 PC 의 셸이 따로다 (`lib/localPaneShells.ts`, 전체 개수 제한 없음). 셸은 칸의 요소보다 오래 살므로 탭·칸 기준으로 기억했다가, 칸이 분할에서 빠지거나 탭이 닫힐 때 닫는다 (`closeLocalPaneShells`). 탭으로 빼면 새 탭이 그 셸의 id 를 그대로 갖는다.
- `Alt`를 누르고 셸 본문에서 구분선 너머의 칸으로 끌면 맞은편 셸이 닫히고 드래그를 시작한 칸은 공유하는 경계만큼 넓어진다. 높이나 폭이 다른 칸의 나머지 영역은 빈 칸으로 둔다. 끄는 동안 테마 강조색으로 경로와 결과 영역을 표시한다.
- 같은 셸 안에서 `Alt` 드래그로 세로선 또는 가로선을 그리면 그 위치에서 좌우 또는 상하로 분할한다. 구분선을 미리 표시하고 작은 칸이나 짧은 제스처는 무시한다.
- 같은 셸 안에서 `Alt` 드래그로 지그재그로 문지르면(한 축으로 3번 이상 방향을 바꿈, 한 번에 30px 이상: `lib/paneScribble.ts`) 그 칸을 닫는다. 칸을 붉게 칠해 미리 보이고, 놓으면 `이 칸 닫기` 와 같은 `closeTabPane` 으로 닫는다 (함께 나뉘었던 칸이 자리를 채우고, 주 셸이면 다른 셸이 이어받음). 칸이 하나뿐이면 닫지 않고 알린다. 확인 창은 병합과 같이 에이전트가 작업 중일 때만. 닫기 미리보기에서 시작점으로 돌아와 놓거나 Esc를 누르면 취소한다 (`usePaneGesture`). 시작점을 지나 계속 그리면 닫기 미리보기가 다시 표시된다. 한 번 꺾어 시작점으로 돌아와 놓으면 분할도 취소된다. 획이 칸 밖으로 나갔다 오면 그 뒤의 점만 센다 (`scribbleFrom`). 분할 판정은 시작점과 끝점만 보므로 지그재그 판정을 먼저 한다. 설계: `docs/plan/2026-11-24-pane-scribble-close.md`, 화면 테스트 `local-split`.
- 메인 셸을 탭으로 옮길 때는 남는 분할 셸 하나가 원래 탭 ID의 메인 역할을 이어받는다. SSH의 `ssh-promote-pane`은 원래 탭의 SFTP·포트 포워딩 연결을 유지하고, 화면을 바꿀 때까지 승격된 셸의 출력을 잠시 보류한다. 로컬 탭은 이때 탭 ID와 메인 프로세스의 셸 ID를 따로 갖는다.
- 탭을 칸으로 병합 (탭으로 빼기의 반대): 탭을 다른 탭의 칸 가운데나 빈 자리에 끌어 놓거나, 탭 줄에서 다른 탭 위에 놓거나(그 탭의 빈 자리, 없으면 가장 큰 칸. 칸 위에 놓을 때는 포인터에 가까운 쪽 절반으로 들어간다: `paneDropZones.zoneAt`, 가운데 구역 없음), 탭 우클릭 `칸으로 병합: <탭>` 을 고르면 그 탭의 셸이 그대로 대상 탭의 칸이 된다 (`hooks/useTabDropOnPane.ts` → `lib/tabToPane.ts`, 규칙과 안내 문구는 `lib/tabMerge.ts`). 같은 세션의 탭만: 같은 저장 세션(`savedSessionId`), 빠른 연결은 서버·포트·계정, 로컬 터미널은 로컬끼리. 안 되는 경우(다른 세션, 6칸, 칸을 나눈 탭, 끊긴 탭, 그 연결을 쓰는 DB 탭·포트 포워딩)는 놓는 자리 표시와 알림으로 이유를 말한다. 설계: `docs/plan/2026-11-18-tab-merge-into-pane.md`.
  - main 의 `ssh-merge-tab` 이 탭의 셸 채널을 대상 탭의 분할 셸(`<대상 id>:split-…`)로 바꾸고 탭 세션을 목록에서 뺀다. 본창에서 온 것만, 열린 탭 id 둘만 받고, 같은 연결이 아니면 서버·계정·점프 호스트가 같은지 main 이 다시 본다.
  - 바꾸면 안 되는 것 (연결 수명): 따로 연 탭의 연결은 병합 뒤 어느 탭 세션의 것도 아니다. `sharedConn` 의 손님 목록(`addGuest`)이 붙잡고, 그 셸이 닫힐 때(`releaseGuest`) 다른 탭이나 손님이 쓰지 않으면 연결과 점프 호스트를 끝낸다. `isShared` 가 손님도 세므로, 연결을 함께 쓰던 탭이 닫혀도 병합된 칸은 살아 있다. 이 목록을 거치지 않으면 연결이 서버에 남거나 칸이 함께 끊긴다.
  - 바꾸면 안 되는 것 (넘겨받기): 새 칸의 `SplitTerminal` 은 셸을 열지 않고 `lib/incomingShells.ts` 에서 넘겨받는다. main 이 답한 그 틱부터 그 채널의 출력을 붙잡아 두고(칸이 아직 화면에 없다), 칸은 탭의 화면을 먼저 그린 뒤 그 출력을 잇는다. 넘겨받은 셸은 칸의 effect 가 정리될 때 바로 닫지 않고 1.5초 기다린다: 개발 실행의 StrictMode 는 effect 를 한 번 정리했다가 다시 실행하는데, 바로 닫으면 병합하자마자 셸이 닫힌다.
  - 끌어 놓기 처리기는 문서의 캡처 단계에 있고, 병합은 끌기가 끝난 뒤(`setTimeout`)에 한다: 끌던 탭의 요소가 끄는 도중에 사라지면 `dragend` 가 오지 않아 끌기 상태가 남는다.
  - 본 탭 줄의 탭을 끌 때 `화면 나누기`(두 탭을 나란히 보기)는 터미널 영역 가장자리 48px 띠에서만 잡힌다 (`SCREEN_SPLIT_BAND_PX`). 그 안쪽은 칸 병합에 쓴다. 띠가 넓으면 칸 하나짜리 탭의 왼쪽·오른쪽 절반을 고를 수 없다. 띠에 들어가면 미리보기는 화면 절반을 칠한다.
  - 바꾸면 안 되는 것: 병합(또는 거부)으로 처리한 놓기는 `mergeDropTaken` 을 세우고, `App.tsx` 의 `handleTabDragEnd` 가 그것을 보고 아무것도 하지 않는다. 탭 줄은 터미널 영역 밖이라, 끌던 탭이 터미널 영역을 한 번 벗어나면 `dropZone` 이 `popout` 이 되어 끌기가 끝날 때 탭이 창으로 분리된다. 탭 요소는 `data-tab-id` 로 찾는다 (본 탭 줄 `.terminal-tab`, 분할 화면 `.split-pane-tab-item`).
- 시험할 때: 시험용 앱 창이 다른 창에 가려지면 화면 갱신이 멈춰 xterm 글자를 읽지 못한다. `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling` 으로 띄운다. 구분선·손잡이의 HTML5 끌기는 CDP 포인터로 일어나지 않아 `DragEvent` 를 직접 보낸다.
