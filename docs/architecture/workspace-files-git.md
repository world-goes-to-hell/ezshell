# Workspace Files and Git Details (작업 공간의 파일 열기·편집과 Git 변경 내용)

[공통 작업 규칙과 기능별 목록](../../CLAUDE.md)

Git 대상 목록은 사이드바와 같은 하위 저장소 탐색을 사용한다. 작업 공간 패널은 깊이 제한 없이 최대 512개 폴더를 탐색한다. [사이드바 하위 저장소](sidebar.md)

`Git 기록`의 `원격과 비교`는 패널에서 선택한 저장소의 현재 브랜치를 원격 추적 브랜치와 비교한다. 마지막으로 가져온 원격 정보를 기준으로 보낼 커밋과 받을 커밋의 수와 최근 목록을 보여 준다. 커밋을 열면 바뀐 파일과 diff를 볼 수 있다. `새로 고침`으로 로컬에 저장된 원격 추적 정보를 다시 읽는다.

작업 공간의 `파일` 은 폴더 트리다: 폴더를 누르면 그 자리에서 펼치고(처음 펼칠 때 한 번 읽음, `.git` 은 뺌), 파일을 누르면 서버 파일 창과 같은 창에서 연다 (텍스트는 편집기, 이미지·PDF 는 미리보기). 우클릭 메뉴(`useWorkspaceFileMenu`)는 파일이면 `브라우저로 열기`(웹 문서만)·`파일 탐색기로 열기`·`ezShell로 열기`, 폴더면 `파일 탐색기로 열기` 만이다. main 의 `local-file-reveal` 은 루트 안의 파일과 폴더를 받고 루트 자신은 거부하며, 열지 않고 `shell.showItemInFolder` 로 위치만 보인다. 패널이 열려 있으면 어느 탭에서든 작업 폴더를 읽고, 그 폴더가 정해지고 0.25초 뒤 `변경`·`Git 기록` 탭이 처음 보여 줄 Git 기록과 변경 목록을 미리 읽어 `gitReads` 에 둔다 (`lib/workspaceGitReads.ts` 의 `prefetchWorkspaceGit`, 이미 있으면 읽지 않음). `변경` 탭은 기록으로 저장소를 안 뒤 변경을 읽는 두 단계라, 미리 읽기 전에는 처음 열 때 Git 명령 둘을 기다렸다 (화면 테스트에서 약 0.8초 → 6ms). 탭과 미리 읽기는 같은 읽기 함수(`loadGitLog`·`loadGitStatus`)를 써야 같은 캐시 값이 된다. Git 은 탭 둘이다 (2026-11-24 사용자 요청으로 나눔): `변경`(`Workspace/WorkspaceChanges.tsx`)은 `커밋하지 않은 변경`을 폴더 트리로 둔다 (폴더마다 바뀐 파일 수, 파일마다 HEAD 대비 `+추가 −삭제` 줄 수와 상태 글자, 머리줄에 전체 줄 수, upstream 이 있으면 `브랜치 → upstream`: `lib/gitChangeTree.ts`, main 은 `git.js` 의 `status` 가 `diff --numstat -z` 와 새 파일 줄 수(5MB·NUL·저장소 밖·합계 64MB 상한)를 준다), `Git 기록` 은 검색과 커밋 목록만이다. 두 탭은 머리줄의 저장소 선택(워크트리·하위 저장소)을 함께 쓴다 (`Workspace/useGitTarget.tsx`, 탭을 옮겨도 남음, `전체 브랜치` 는 기록 탭에만). 파일 줄을 누르면 HEAD 와의 diff 를 그 자리에 펼치며 옆 버튼으로 파일 창을 연다. 커밋 줄을 누르면 바뀐 파일 목록, 파일을 누르면 그 커밋의 diff (첫 부모 기준). 화면은 `Workspace/WorkspaceDetails.tsx`·`WorkspaceGitChanges.tsx`(스타일 `WorkspaceDetails.css`), 계산 `lib/workspaceDetails.ts`. main 은 `src/localFiles/` (`roots.js` 루트 검사, `localRead.js` 읽기·쓰기, `git.js` 조회). 설계: `docs/plan/2026-11-19-workspace-files-and-git-details.md`. 화면 테스트 `local-workspace-files`.
- 파일 창 재사용: `documents.js` 의 `registerLocal` 문서(`local`)는 SFTP 채널·PC 백업 없이 `fs` 로 읽고 쓴다. 저장은 서버 파일과 같은 `review` → `save` 이고 `localRead.writeIfUnchanged` 가 한 핸들로 비교한 뒤 덮어쓴다. 백업 목록 자리에는 `Git (HEAD)` 항목이 나온다 (`listServerBackups` 가 `timeFrom: 'git'` 인 `HEAD` 하나를 돌려줌, 비교 화면은 그대로).
- 바꾸면 안 되는 것 (보안): 창은 아무 경로나 열지 못한다. 루트는 main 이 아는 폴더(열린 로컬 셸의 시작·현재 폴더, 그 Git 저장소 최상위와 워크트리) 안이어야 하고(`roots.resolveRoot`, 저장소 조회는 10초 기억), 파일은 루트 기준 상대 경로로만 받아 링크를 푼 실제 경로가 루트 안이어야 한다 (`resolveInside`). 네트워크 경로(`\\host\share`)는 거부한다. 커밋은 `^[0-9a-f]{7,40}$`, git 의 파일 경로는 `--` 뒤나 검사한 `<rev>:<path>` 로만 넘긴다. git 은 `core.fsmonitor=false`·`diff.external=` 로 부른다 (저장소 설정이 조회 때 프로그램을 띄우지 못하게). `local-file-open`·`workspace-*` 는 본창·잠금 해제 상태에서만 받는다.
- 선택한 파일 커밋 (`변경` 탭, 2026-11-24 사용자 요청): 파일·폴더 줄의 체크박스로 고르고 메시지를 써서 `선택한 N개 파일 커밋`(또는 Ctrl+Enter). 고른 파일의 지금 내용만 커밋하고(`git commit --only`) 고르지 않은 파일은 스테이징 여부와 관계없이 그대로 남는다. 스테이징 상태로 바뀐 파일은 저절로 체크되고(처음 읽을 때는 스테이징된 파일 전부), 사용자가 푼 것은 다시 체크하지 않는다 (`lib/gitCommitSelection.ts`). 메시지·선택·진행 중 표시·오류는 저장소별로 메모리에만 둔다 (`stores/gitCommitStore.ts`, 잠그면 지움). 충돌 파일은 고를 수 없다. 화면은 `WorkspaceGitChanges.tsx` 의 `ChangeList`, `GitCommitBox.tsx`. 설계: `docs/plan/2026-11-24-workspace-git-commit.md`.
  - 바꾸면 안 되는 것 (보안, main 의 `src/localFiles/gitCommit.js`, IPC `workspace-git-commit`): 본창의 메인 프레임에서, 잠금 해제 상태에서만 받는다. 루트는 `roots.resolveRepoRoot` 로 검사한다: 열린 로컬 셸의 저장소(최상위·워크트리)와 그 안의 저장소만 (읽기는 셸 폴더 아래 어디든 되지만, 홈 폴더에서 연 셸 하나로 그 아래 모든 저장소에 커밋할 수 있으면 안 된다: 보안 검토). 창은 루트·경로·메시지만 보내고, main 이 `git status` 를 다시 읽어 지금 변경 목록에 있는 경로만 받는다 (하나라도 없으면 아무것도 하지 않음, 무시된 파일·바뀌지 않은 파일 거부). 스테이징된 이름 바꿈의 옛 경로는 main 이 자기 status 에서 붙인다. 경로는 stdin 의 `--pathspec-from-file --pathspec-file-nul` 과 `--literal-pathspecs` 로만 넘긴다 (글롭·`:(` 매직·명령줄 길이). 메시지는 CR → LF, 줄바꿈·탭 말고 제어 문자 거부, 5,000자, `--cleanup=whitespace`(`#` 로 시작하는 줄을 지우지 않게). `git.js` 는 계속 읽기 전용이다 (쓰기는 `gitCommit.js` 에만).
  - 바꾸면 안 되는 것: 작업 공간은 `.git` 폴더 안의 어떤 것도 열지 않는다 (`roots.resolveInside`, 요청한 경로와 링크를 푼 실제 경로 둘 다). 파일 창으로 `.git/hooks/pre-commit` 이나 `.git/config` 를 쓴 뒤 커밋을 누르게 하면 창이 프로그램을 실행시키는 통로가 된다 (보안 검토). 중첩 저장소(`sub/`, 끝이 `/` 인 경로)와 복사(`C`)의 원본은 커밋에 넣지 않는다.
  - 훅(pre-commit, commit-msg)은 터미널에서 커밋할 때처럼 실행한다 (제한 2분, 출력은 색 코드·제어 문자를 빼고 4,000자까지 오류 상자에). 실패하면 이번에 `git add` 한 새 파일을 인덱스에서 다시 뺀다 (`rm --cached`, 파일은 그대로). 바꾸면 안 되는 것: 커밋 명령이 실패로 끝나도 HEAD 가 커밋 전과 달라졌으면 되돌리지 않고 경고와 함께 성공으로 답한다 (post-commit 훅이 멈추면 커밋은 이미 된 뒤다. 되돌리면 새 파일의 삭제가 스테이징된다: 보안 검토). 한 저장소에 커밋은 한 번에 하나. `core.safecrlf=false` 는 줄 끝 경고가 훅 출력을 가리지 않게 하려는 것이다 (변환은 그대로).
- 프로젝트 검색 (`components/ProjectSearch/ProjectSearch.tsx`, `docs/plan/2026-11-26-project-search.md`): Shift 두 번은 파일 이름(아래 색인 검색, 파일만), Ctrl+Shift+F 는 내용(`src/localFiles/contentSearch.js`, IPC `workspace-content-search`). 범위는 앞 로컬 탭의 셸 폴더가 든 저장소·워크트리 최상위(`localProjectInspect`), 저장소가 아니면 그 폴더. 내용은 저장소면 `git grep -F`(무시·이진 파일 제외, 새 파일 포함, 설치·빌드 폴더는 `:(exclude,glob,icase)` 로 제외), 아니면 직접 읽는다(1MB 넘거나 이진이면 건너뜀). 결과 500줄·파일 200개·파일당 50줄·8초에서 멈추고 "더 있음". Enter 는 `openWorkspaceFile` 로 파일 창을, 내용 결과는 그 줄(`local-file-open` 의 `line` → `revealLine`)로 연다. 바꾸면 안 되는 것: 검색어는 1~200자 한 줄이고 `-e` 뒤 인수로만 넘긴다(셸 없음, 옵션·패턴으로 읽히지 않음). 새 검색은 이전 `git grep` 을 끝낸다. 검색어는 창을 닫아도 남아 다시 열면 같은 검색과 결과를 보인다(`projectSearchStore` 의 `lastQuery`, 화면에서 고른 글이 있으면 그것이 먼저). 결과를 연 검색어는 모드별로 최근 20개를 `ezshell.projectSearch` 에 저장한다(`lib/projectSearchHistory.ts`, 여러 줄·200자 초과는 넣지 않음). 빈 검색칸은 그 목록을 보이고(Enter 로 다시 검색, × 로 지움), 끝에서 입력하면 그 글로 시작하는 가장 최근 검색어로 나머지를 채워 선택해 둔다(브라우저 탭 주소창과 같은 방식: 지우기 입력과 IME 조합 중에는 채우지 않음). 2026-11-26 사용자 요청.
- 파일·폴더 검색(`src/localFiles/search.js`, IPC `workspace-directory-prepare`·`-search`): 루트 아래를 폴더 16개씩 동시에 읽어 목록을 만들고(4.3만 항목 약 0.27초, 예전 순차 읽기는 2초), 목록은 버리지 않고 `fs.watch(root, { recursive: true })` 로 유지한다. 알림(`rename` 만, `.git` 아래 무시)은 150ms 모아 바뀐 폴더를 직접 다시 읽어 그 폴더 항목을 바꾸고, 사라진 폴더는 그 아래를 빼고, 새 폴더는 그 아래를 훑는다. 알림이 넘치거나(이름 없는 알림, 한 번에 2,000폴더 초과) 감시 오류면 목록을 stale 로 두고 다음 검색 때 다시 훑는다. 상한 항목 200,000개·8초, 최근 루트 3개(밀려나면 감시를 닫음), 새로 고침 버튼은 다시 훑기. 설치·생성 폴더(`node_modules`·`build`·`dist`·`out`·`target`·`release`·`coverage`·`.gradle`·`.next`·`.venv` 등, `search.js` 의 `SKIPPED_DIRS`)는 기본으로 폴더 이름만 목록에 넣고 안은 읽지 않으며, 그 안의 변경 알림도 무시한다 (2026-11-24 사용자 결정: 이 저장소 4.3만 항목 중 3.9만이 그런 폴더라 결과를 덮었다. 처음 훑기 0.3초 → 0.02초). 결과 아래 안내 줄의 `포함해서 검색` 을 누르면 그 패널이 열려 있는 동안 안까지 검색한다 (IPC 의 `includeAll`, main 은 포함 여부별로 목록을 따로 둔다. 기억하지 않는다). 바꾸면 안 되는 것: 폴더를 읽기 전에 realpath 가 루트 안이고 요청 경로와 같은지 본다 (링크로 바뀐 폴더는 읽지 않음, 링크 폴더는 따라가지 않음). 알림의 파일 이름은 어느 폴더를 다시 읽을지에만 쓴다. 앱을 잠그면 `clearSearches` 가 모든 감시·목록·진행 중 훑기를 멈춘다. 설계: `docs/plan/2026-11-24-workspace-file-search-index.md`.
- 범위 밖: push, amend, 되돌리기, 줄 단위 커밋, 파일 만들기·이름 바꾸기·지우기.
