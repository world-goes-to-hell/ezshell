# Agent State From Official Signals (훅으로 받는 에이전트 상태)

[공통 작업 규칙과 기능별 목록](../../CLAUDE.md)

ezShell 이 띄우거나 로컬 셸에서 직접 실행한 Claude Code·Codex 는 CLI 의 훅으로 작업 시작·끝·대화 상자를 알린다. 상태는 훅을 먼저 따르고, 화면·창 제목 판독은 대체 경로다. 설계·실측(T0)·규칙 번호: `docs/plan/2026-11-24-agent-state-via-official-signals.md`. 화면 테스트 `local-agent-hooks` (가짜 Claude 가 `--settings` 의 명령 그대로 리포터를 부른다: `e2e/support/localAgentFixture.js` 의 `<id>-hooks`).
- 신호 경로: Claude 는 실행마다의 `--settings` 파일(메시지 폴더의 `agent-settings.json`, `agentMessages.js` 의 `CLAUDE_HOOKS`)에, Codex 는 `-c hooks.<이벤트>=…` 인자(`codexHookLaunch.js` 의 `CODEX_HOOK_ARGS`, `command_windows` 포함)로 훅을 넣는다. 훅 명령은 `src/agentHookReport.js` 를 Electron-as-node 로 띄우고(`HOOK_COMMANDS`), 리포터가 stdin 의 훅 입력에서 허용 목록의 필드만(`agentHookInput.js`: 이벤트 이름, 세션·차례·도구 id, 알림 종류, `stop_hook_active`, 시작 출처) 꺼내 에이전트 파이프로 `agent-event` 를 보낸다. main 이 다시 검사하고(`agentHookEvent.js` 의 `validateAgentHookEvent`) 셸마다 `hookState` 에 적용한다 (`agentHookState.js`, `localShell.js` 의 `reportAgentHook`). 사용자의 `~/.claude/settings.json`·`~/.codex/config.toml`·`hooks.json` 은 고치지 않는다.
- 우선순위 요약: 화면의 확인 질문(`screenApproval`) → 훅 상태(`hookStatus`: 열린 대화 상자면 `blocked`, 아니면 차례의 `working`/`idle`) → 예전 판독(OSC·창 제목·Codex rollout). 훅 보고는 `async` 라 순서가 바뀌므로 차례(`promptId`)와 도구(`tool_use_id`)의 열림·닫힘과 리포터 시작 시각(`startedAt`)으로 정렬한다 (닫힌 차례의 늦은 보고는 버림: B1). Claude 는 Esc 로 멈춘 차례에 Stop 이 오지 않으므로(T0 ②) 사용자 Esc·Ctrl+C(한 글자 `\x1b`·`\x03`, 채팅 `중지` 포함) 뒤 1초 안에 창 제목이 `✳` 이 되거나, 훅 working 인데 제목 idle 이 3초 이어지면 차례를 닫는다. Stop 뒤 2초 넘게 제목 스피너가 돌면(다른 Stop 훅이 block) 다시 연다. 훅이 blocked 인데 화면에 대화 상자가 5초 없으면 화면 판독으로 돌아간다. 창으로 가는 스냅숏은 `statusSource`(`'hook'`/`'screen'`)만 싣고, 화면에는 보이지 않는다 (표시할 필요가 없는 내부 상태 출처).
- 작업 중 메시지 (Stop block): 훅이 working 인 에이전트에는 입력칸에 붙여 넣지 않는다. Stop 훅의 리포터가 `stop-check` 를 묻고, main 이 아직 알리지 않은 안 읽은 메시지(없으면 미룬 요청)가 있으면 `decision: block` 과 `PROMPT`(`REMIND_PROMPT`)를 돌려준다 (`agentInboxWake.js` 의 `prepareStopWake`). 쉬는 에이전트는 예전처럼 빈 입력칸에 `PROMPT`.
  - 바꾸면 안 되는 것 (안전 규칙): A1 최근 10초 안에 사용자 Esc·Ctrl+C·채팅 `중지` 가 있었으면 block 하지 않는다 (사용자가 멈춘 에이전트를 앱이 다시 움직이면 안 된다. 메시지는 쉴 때 `PROMPT`). StopFailure 와, 화면에 Claude 대기열 안내(`claudeQueueVisible`)가 있는 Stop 도 막지 않는다. A2 "알렸음"은 block 뒤 15초 안에 그 메시지의 `seenAt`, 같은 `promptId` 의 PreToolUse 나 `stop_hook_active` Stop 이 올 때만 남기고, 없으면 지워 쉴 때 `PROMPT` 가 맡는다. 메시지마다 한 번만 알리므로 `stop_hook_active` 로 이어진 Stop 에서 새 메시지가 없으면 막지 않는다. block 한 Stop 은 차례를 닫지 않는다 (working 유지).
- Codex 승인 (사용자 결정 2): Codex 는 신뢰하지 않은 훅을 실행하지 않고 시작할 때 "Hooks need review" 를 묻는다. 칸 위에 안내 띠(`AgentChat/CodexHookReviewBar.tsx`, 문구 `lib/codexHookReview.ts`, 화면 판독 `codexHookLaunch.js` 의 `observeCodexHookReview`)가 뜬다. 바꾸면 안 되는 것: "Trust all and continue" 는 새 훅 수가 우리가 넣은 수와 같고 main 이 프로젝트 훅 가능성을 보지 않았을 때(`projectHooks` 가 참이 아님)만 안내한다 (Trust all 은 사용자의 다른 미신뢰 훅까지 신뢰한다: 규칙 10). 앱은 신뢰를 대신 기록하지 않고 `--dangerously-bypass-hook-trust` 를 쓰지 않는다. 승인 기억은 `userData/codex-hook-mode`(`pending`/`approved`/`disabled`): 우리 Codex 훅이 한 번 오면 `approved`, 띠의 `묻지 않기`·화면의 `3`/Esc·첫 질문 뒤 10초 무훅이면 `disabled`(다음부터 넣지 않음, 앱 전체 토스트 한 번). 앱이 대신 띄우는 실행(재개·깨우기)은 `approved` 일 때만 넣는다 (`injectCodexHooks` 의 `automatic`). 승인 전·거절한 Codex 는 예전 경로(`BUSY_PROMPT`, rollout 보정)다.
- 설정 토글: 설정 > MCP > 에이전트 메시지의 `에이전트 상태 알림` (`Settings/AgentHooksSettings.tsx`, `localStorage` 의 `agentHooks`, `lib/agentHooksPrefs.ts`, 화면 설정 백업 목록에 있음). 창이 시작할 때와 바꿀 때 `agent-hooks-configure` 로 보낸다 (`stores/agentHooksStore.ts`). 끄면 main 이 훅 상태를 바로 지워 화면 판단으로 돌아가고 settings·Codex 인자에서 훅을 뺀다. 켜면 다음에 띄우는 에이전트부터다. 바꾸면 안 되는 것: Codex 의 `disabled` 를 푸는 `resetCodexDecline` 은 사용자가 설정 화면에서 끔→켬으로 바꿀 때만 붙인다 (시작 때 전송·백업 적용에 붙이면 앱을 켤 때마다 사용자의 거절이 풀린다).
- 바꾸면 안 되는 것 (보안):
  - 훅 명령 문자열은 고정이다 (`HOOK_COMMANDS`: 설치 경로 없이 환경 변수만). Codex 의 신뢰 해시가 명령 문자열에 걸리므로, 바꾸면 업데이트마다 다시 승인을 묻는다. 해시에는 `async` 도 든다 (`timeout` 은 안 든다, 2026-11-25 실측: `async` 를 바꾼 SessionEnd 만 다시 물었다). Codex 0.171 은 SessionEnd·Interrupt 를 3초로 줄이고 SessionEnd 를 항상 동기로 돌리며, 그보다 크게 주면 시작할 때마다 경고한다. 그래서 `codexHookLaunch.js` 는 그 둘을 3초, SessionEnd 를 동기로 준다. 실측 기록: 설계 문서 §1 "앱으로 한 실측".
  - 훅 입력 원문(프롬프트, 도구 인자·결과, 기록 경로)은 main 에도 보내지 않는다. 리포터는 허용 목록의 짧은 값만 읽고(문자열 100자, 깊이 256) 나머지는 버린다. 보고는 에이전트 토큰이나 셸 토큰으로만, 그 셸에 묶인 같은 종류의 에이전트 것만 받는다. 잠금 중에는 받지 않는다.
  - 훅의 세션 UUID 는 사용량·기록 파일 짝짓기에 쓴다. 새 Codex 의 역할 저장 키에는 인증된 첫 훅의 UUID 와 main 이 확인한 작업 폴더에서 독립적으로 찾은 유일한 루트 롤아웃의 UUID 가 일치해야 한다. 재개(`--resume`)와 잠재우기 복귀에는 명시적 재개 경로의 확인을 쓴다. 훅 입력은 같은 OS 사용자의 다른 프로세스도 흉내 낼 수 있다.
  - `src/agentHookReport.js` 는 `MAIN_RUNTIME_MODULES` 에 있고, 리포터가 쓰는 `src/ipc/` 모듈은 `MAIN_RUNTIME_DIRECTORIES` 의 `ipc` 로 함께 간다. 리포터는 1.5초 안에 끝나고, 실패하면 아무것도 찍지 않는다 (CLI 의 차례를 막지 않는다).
- 실제 CLI 로 시험할 때: `npm run build` 뒤 Electron 실행 파일로 `out/main/index.js --user-data-dir=<임시 폴더>` 를 띄우면 설치본과 단일 실행 잠금·메시지 연결 파일이 겹치지 않는다 (같은 프로필로 띄우면 연결 파일을 새로 써서 설치본의 에이전트들이 개발 앱에 붙는다). Claude Code 의 셸에서 띄울 때는 `EZSHELL_*`·`CLAUDECODE`·`CLAUDE_CODE_*` 와 `NO_COLOR` 를 지운다: `NO_COLOR=1` 이 넘어가면 그 안의 Claude 가 색 없이 돌아 다음 질문 제안이 쓰던 글로 읽힌다. 환경을 정리한 뒤 `EZSHELL_TEST_HIDDEN_WINDOWS=1`을 켜고 실행한다. 창을 실제 화면에 띄워야 하면 먼저 사용자에게 확인한다.
