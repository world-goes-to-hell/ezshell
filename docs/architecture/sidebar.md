## Sidebar Tree and Folded Rail

사이드바 목록 모양은 `Sidebar/SidebarTree.css` 에 있다. 줄에는 배경색을 칠하지 않는다: 폴더 색은 폴더 왼쪽의 선 하나(`--folder-color`), 세션 자체 색은 줄 옆의 짧은 선(`--session-color`)이다. 기본 아이콘 자리에는 상태 점(`.session-dot`, 연결된 탭이 있으면 초록, 끊긴 탭만 있으면 빨강)을 둔다. 세션 이름은 입력한 그대로 보여 준다.
접힌 상태(`sidebarMode === 'compact'`, 클래스 `.sidebar.rail`)는 46px 띠에 상태만 보인다: 아이콘과 숫자만 둔다 (글자 표지는 사용자가 원하지 않았다): 목록 아이콘 아래 연결된 탭 수(초록)·끊긴 탭 수(빨강, 둘 다 SSH 탭만: `isSshTab` 으로 세어 브라우저·DB 탭은 빠진다. 2026-11-24 까지 브라우저 탭이 연결된 세션으로 세어졌다), 로컬 터미널이 있으면 PC 아이콘과 그 수, 로컬 작업에 묶인 세션(`ezshell.localProjectServers`)의 탭은 세션 쪽이 아니라 PC 아이콘 옆에 초록·빨강 수로 (`lib/sidebarRail.ts`), MCP 요청이 진행 중이면 플러그 아이콘과 그 수(노랑) (`.rail-summary`). 목록도 버튼도 그리지 않는다 (목록은 이름 없는 화살표·점만 줄지어 알아볼 수 없었고, 버튼은 포인터를 올리는 순간 사이드바가 열려 누를 수 없었다), 마우스를 올리거나 키보드 포커스가 들어오면 전체 사이드바가 터미널 위로 겹쳐서 열린다 (`hooks/useSidebarPeek.ts`, `.peek-open`, 자리를 차지하지 않으므로 터미널 크기가 바뀌지 않는다). 사이드바의 메뉴·호버 카드·이름 입력칸을 쓰는 동안에는 닫지 않는다. 줄임말 타일은 없앴다 (사용자가 원하지 않았다). 띠와 열린 상태는 같은 DOM 이고 CSS 로만 다르다.
사이드바 버튼 줄 아래의 검색칸(`Sidebar/SessionSearchBox.tsx`, 계산은 `lib/sessionSearch.ts`)은 세션을 찾되 목록을 거르지 않는다: 낱말이 모두(AND) 이름·호스트·계정·폴더 이름에 들어 있는 세션 줄과 글자를 강조하고, 그 세션이 든 폴더를 검색하는 동안만 펼쳐 보인다 (저장된 `expandedFolders` 는 바꾸지 않는다). `↑`/`↓` 로 현재 일치 항목을 옮기며(입력은 칸에 남음) 그 줄을 화면에 보이게 하고, `Enter` 는 그 세션에 접속, `Esc` 는 지운다. 바꾸면 안 되는 것: 일치하지 않는 세션을 숨기지 말 것 (사용자 요구). 탭 줄 `+` 메뉴와 시작 화면의 찾기 창(`SessionPickerModal`)은 사이드바를 접었을 때를 위해 남겨 두었다. 설계: `docs/plan/2026-11-19-sidebar-session-search.md`.
사이드바 맨 아래의 버튼 줄(에이전트 메시지·로컬 작업·배치 명령·세션 통계)은 2026-11-19 에 없앴다 (사용자 결정). 네 가지는 명령 팔레트(`Ctrl+P`)의 `에이전트 메시지 열기`·`로컬 작업 열기`·`배치 명령 실행`·`세션 통계` 로 열고, 로컬 작업 창은 탭 줄 왼쪽 작업 목록(`TabGroupChips`)을 펼쳤을 때 제목 줄 오른쪽의 `+` 로도 연다 (탭 줄 `+` 메뉴의 `로컬 작업…` 은 2026-11-20 에 뺐다: 사용자 결정. 작업 목록은 일반 탭만 있으면 보이지 않으므로 그때는 명령 팔레트로 연다). 창은 두 모양이다 (`LocalProjectDialog` 의 `mode`): `+` 는 `add`(폴더가 비어 있고 `폴더 선택…` 으로 고르며, 연 뒤에야 목록에 등록), 명령 팔레트는 `open`(등록한 폴더 목록). 실행 도구(Codex·Claude) 선택은 없다: 항상 사용자 셸을 열고 에이전트는 그 셸에서 직접 입력한다 (사용자 결정, 2026-11-20). 화면 테스트는 가짜 에이전트를 `driver.openLocalAgent`(창 안 이벤트 `OPEN_LOCAL_TERMINAL_EVENT`, `lib/localProjectList.ts`)로 띄우고, 로컬 작업 창은 `driver.openLocalProject`(명령 팔레트)로 연다. 화면 테스트는 `driver.openLocalProject` 를 쓴다.
접기 버튼은 펼친 사이드바(`«`)와 겹쳐 열린 사이드바(핀)에만 있다. 접힌 띠에는 버튼을 두지 않는다 (포인터를 가져가면 사이드바가 먼저 열려 누를 수 없었다). 아이콘을 돌리는 애니메이션을 다시 넣지 말 것: 좌우 대칭 아이콘을 180도 돌리면 두 상태가 같은 모양이 된다.

## Sidebar Local Work Tree (로컬 작업: 저장소 → 워크트리 → 탭)

개발 서버를 기동한 워크트리나 그 아래 탭 줄은 `DevelopmentRunStatus.tsx`의 종류 아이콘, 실행 상태, 로컬 포트 칩을 표시한다. 탭 줄의 점도 같은 main 상태를 쓴다. 칩에 포인터를 올리거나 우클릭하면 재기동·중지·브라우저로 열기·로그 보기를 선택할 수 있다. 실행 중이고 주소가 표시된 서버는 앱의 브라우저 탭에서 연다. 로그 보기는 그 서버의 같은 탭과 칸으로 이동한다. 탭 우클릭에도 재기동·중지가 있다. [개발 서버 기동 탭](local-terminal.md#개발-서버-기동-탭)

아래 절의 로컬 터미널 칸은 이제 `로컬 작업` 트리다 (`Sidebar/LocalProjectsTree.tsx`, 칸은 `LocalTerminalList.tsx`). 등록한 작업 폴더(`로컬 작업` 창과 같은 `ezshell.localProjects`, `lib/localProjectList.ts`) → 그 저장소의 Git 워크트리(`hooks/useLocalProjects.ts` 가 `local-project-inspect` 로 읽음: 목록이 바뀔 때·새로 고침·창 포커스 30초 간격, 타이머로 돌리지 않음) → 그 워크트리에서 연 로컬 터미널 탭(셸을 연 폴더가 워크트리 안인지, `lib/localWorkspaceTree.ts`)과 그 탭의 에이전트 칩, 그리고 그 작업 묶음의 브라우저·SSH·DB 탭(`lib/tabGroups.ts` 의 `workTabsByWorktree`: 브라우저 탭은 열 때 기록한 폴더 `browser.cwd` 의 워크트리, 폴더가 없는 탭은 프로젝트의 기본 체크아웃 아래). 워크트리의 로컬 터미널이 하나이면 그 탭이 워크트리 줄 자체이고(배지·에이전트 칩·닫기), 같은 워크트리의 SSH·브라우저·DB 탭만 그 아래 줄로 둔다. 로컬 터미널이 둘 이상이면 모두 아래 줄이고, 이름이 폴더·프로젝트 이름과 같으면 `터미널 N` 으로 보인다 (예: `터미널 1`, 화면 테스트 `ssh-project-servers`). 지난 Claude·Codex 대화는 트리에 넣지 않는다 (오른쪽 패널의 에이전트 기록에서 본다). 나머지 탭은 `다른 로컬 터미널`. 워크트리를 누르면 열린 탭으로 가거나 그 폴더에서 새 로컬 터미널을 연다. 등록 폴더나 로컬 탭이 있을 때만 보이고, 절반 높이 제한은 없다 (세션 목록에 96px 를 남김). 접힘은 `ezshell.localTreeFolded`. 작업 폴더 목록을 쓸 때는 `writeLocalProjects` 를 거친다 (이벤트로 트리와 대화상자가 함께 갱신된다). 프로젝트 줄에 포인터를 올리면 X(`목록에서 빼기`)가 나온다: 그 저장소로 등록된 폴더를 모두 목록에서 빼고(`ProjectNode.folders`), 폴더·열린 터미널·묶인 서버(프로젝트 키로 남아 다시 더하면 돌아옴)는 그대로다. 저장소는 기본 체크아웃(`git worktree list` 의 첫 항목)으로 묶는다 (`buildProjectNodes`). 바꾸면 안 되는 것: `repo.root` 로 묶지 말 것. 워크트리 폴더를 등록하면 `--show-toplevel` 이 그 워크트리를 돌려줘서, 한 저장소가 프로젝트 둘로 보이고 그 워크트리에 `기본` 이 붙었다 (탭 묶음도 둘로 나뉘었다). 설계·다음 단계: `docs/plan/2026-11-19-sidebar-local-work-tree.md`. 시험: `local-workspace` 명세.

등록한 로컬 작업과 각 워크트리 아래에서 하위 Git 저장소를 찾아 사이드바에 함께 표시한다. Git이 아닌 작업 폴더는 작업 제목 아래 실행 구성과 저장소 목록을 두고, Git 작업은 기존 워크트리 아래에 둔다. 작업 제목에 공통 브랜치와 저장소 수, 받을 커밋이 있는 저장소 수를 표시한다. 실행 구성의 폴더가 하위 저장소에 속하면 브랜치 차이·받을 커밋·수정 상태를 구성 줄에 표시한다. 별도 로컬 작업으로 등록한 하위 저장소는 부모 목록에서 빠진다.

- 작업 공간 Git 패널과 탐색을 공유한다 (`src/ipc/localProjects.js`). 사이드바는 두 단계, 최대 50개를 찾고 숨김 폴더와 링크를 건너뛴다. `build`·`target`·`dist` 폴더 자체는 확인하고 그 아래로 내려가지 않는다. Git porcelain v2로 상태를 읽고, 읽기 오류도 목록에 표시한다. 최대 네 저장소의 Git 작업을 실행하고 창에 포커스가 온 뒤 3초 후 상태를 갱신한다.
- 기본으로 로컬 상태를 읽는다. 저장소 목록의 `원격 확인`을 누르면 즉시 가져올 커밋을 확인할 수 있다. `자동으로 원격 확인`은 본창 주 프레임이 요청하고 사용자가 네이티브 창에 표시된 프로젝트를 승인한 뒤에만 켜진다. main은 실제 프로젝트 폴더의 신뢰를 사용자 프로필에 저장한다. Git 설정의 위험 키 목록만으로는 새 설정과 간접 실행 경로를 모두 판단할 수 없어 자동 실행에 명시적인 신뢰를 요구한다. 신뢰한 프로젝트의 자동 fetch는 포커스가 돌아왔을 때 10분에 한 번까지 현재 브랜치의 업스트림 ref 하나를 갱신하고 태그는 가져오지 않는다. 설정의 개발 도구에서 자동 원격 확인을 일괄로 끌 수 있다.
- 자동 fetch의 대상은 폴더 식별을 다시 확인한 승인 경로 안의 저장소다. 따로 떨어진 워크트리는 수동으로 확인할 수 있다. 로컬 조회에는 `GIT_NO_LAZY_FETCH=1`을 적용한다. 이전 Git도 지원하기 위해 신뢰 범위 밖의 부분 복제 저장소는 수동 원격 확인을 안내한다. 신뢰 파일 형식이 깨지면 모든 승인을 무효로 처리한다.
- 받기는 한 번 fetch하고 확인한 업스트림 커밋을 `git merge --ff-only --no-verify-signatures`로 적용한다. 수정 중, 업스트림 없음·삭제, 분리된 HEAD, 브랜치가 갈라진 경우에는 이유를 남긴다. main은 잠금 해제된 본창 주 프레임의 요청을 받아 직접 발견한 상대 경로를 확인한다. 원격은 HTTPS·SSH·검사된 로컬 경로를 허용한다. 위험한 로컬 Git 설정은 줄에 표시하고 수동 갱신 시 네이티브 창에서 키를 보여 주고 확인받는다. 다른 설정 파일을 불러오는 로컬 설정은 안전하게 검사할 수 있어야 Git을 실행할 수 있다. 시험 명세는 `local-nested-repos`다. [설계](../plan/2026-11-26-multi-repo-and-start-order.md)

- 하위 저장소 줄의 브랜치나 우클릭 메뉴 `브랜치 바꾸기…`에서 로컬 브랜치와 마지막 fetch 기준 원격 추적 브랜치를 검색한다. Enter 또는 더블클릭으로 전환한다. 원격에만 있는 브랜치는 같은 이름의 로컬 추적 브랜치를 만든다. main은 목록과 변경 상태를 다시 확인하고, 진행 중인 Git 작업이나 덮어쓸 파일이 있으면 이유를 알린다. 위험한 로컬 설정은 수동 받기와 같은 확인을 거친다. 전환에 필요한 Git 객체가 이 PC에 없으면 오류를 표시한다.

## Sidebar Local Terminal List (세션 목록 아래의 로컬 터미널 목록)

로컬 터미널 탭이 하나라도 열려 있거나 작업 폴더가 등록돼 있으면 사이드바의 목록 영역(`.sidebar-lists`)이 위아래로 나뉘어, 아래에 로컬 작업 칸이 생긴다 (`Sidebar/LocalTerminalList.tsx`, 계산은 `lib/localTerminalPane.ts`). 높이는 내용만큼 늘어나되 세션 목록에 96px 를 남기고(CSS `max-height: calc(100% - 96px)`, 예전의 절반 제한은 2026-11-19 에 풀었다), 가운데 손잡이를 끌면 그 높이로 고정한다 (세션 목록에 96px 은 남김, 두 번 누르면 자동 높이). 줄을 누르면 그 탭으로 이동(`focusTerminal`), X 는 탭 닫기와 같은 경로, + 는 새 로컬 터미널. 높이·접힘은 `localStorage` 의 `sidebarLocalPane`. 접힌 띠에는 PC 아이콘과 개수를 더한다. 설계: `docs/plan/2026-11-17-sidebar-local-terminal-list.md`.
- 탭 안을 분할한 로컬 터미널 줄에는 `N세션` 표지(`Sidebar/PaneLayoutBadge.tsx`)가 붙는다. 포인터를 올리거나 누르면 그 탭의 분할 배치를 작은 그림으로 보여 주고(`splitTree.layoutOf`), 칸을 누르면 그 탭으로 가서 그 칸에 키보드를 준다 (탭의 DOM 노드 `tabHost(id)` 안에서 `[data-pane]` 으로 찾는다. 스토어를 바꾸지 않는다). 지금 입력 중인 칸은 강조색. 그림은 `document.body` 에 그리고 `.sidebar-popover` 클래스로 접힌 사이드바가 닫히지 않게 한다 (`useSidebarPeek`).
- 클래스 이름은 `local-terms*` 다. 처음에 `local-pane` 으로 지었다가 SFTP 로컬 패인(`sftp-pane local-pane`)에 규칙이 적용돼 파일 목록이 절반 높이로 잘렸다 (전역 CSS 라서 새 클래스 이름은 먼저 검색해 본다).
- 바꾸면 안 되는 것: 포인터를 뗄 때 저장하는 높이는 끄는 동안 ref 에 둔 최신 값이다. 뗄 때의 처리기는 직전 렌더의 state 를 갖고 있어서, state 를 저장하면 한 단계 전 높이가 남는다.
- 프로젝트의 서버(`lib/localProjectServers.ts`): 저장된 SSH 세션을 로컬 프로젝트에 묶어 프로젝트 카드 위쪽 `서버` 줄에 보여 준다. 묶는 방법은 세 가지다: SSH 탭을 프로젝트 카드에 끌어 놓기, 사이드바 세션 줄을 끌어 놓기(둘 다 `text/plain`: 탭 id / `session:<id>`), 세션 우클릭 `로컬 작업에 묶기`(`Sidebar/LinkToProjectSubmenu.tsx`). 줄을 누르면 열린 탭으로 가고, 없으면 세션 목록에서 두 번 누른 것과 같은 접속을 한다. X 는 묶음만 푼다. 그 프로젝트 트리에 탭이 열려 있는 서버는 `서버` 줄에서 빠지고 워크트리 아래 탭 목록에만 보인다. 탭을 닫으면 `서버` 줄로 돌아온다. `서버` 줄과 워크트리 아래의 SSH·DB 탭 줄은 그 세션의 색(세션 자체 색, 없으면 폴더에서 물려받은 색: `lib/sessionEffectiveColor.ts`)을 왼쪽 막대와 아이콘으로 보여 준다 (2026-11-22 사용자 요청, `--server-color`). 탭 줄은 지금 저장된 세션의 색을 먼저, 없으면 탭을 연 때의 색(`TerminalInfo.color`)을 쓴다. 프로젝트 키는 저장소의 기본 체크아웃 경로(`projectKeyOf`, `pathKey`). 저장은 `localStorage` 의 `ezshell.localProjectServers`(프로젝트 키 → 세션 id 목록, 바뀌면 `ezshell:local-project-servers-changed`). 화면 테스트 `ssh-project-servers`. 설계: `docs/plan/2026-11-19-local-project-servers.md`.
  - 바꾸면 안 되는 것: 세션 id 만 저장한다 (주소·계정 없음). 화면 설정 백업 목록에 넣지 않는다 (id 는 이 PC 의 세션 파일에만 뜻이 있다). 앱을 켤 때 묶인 서버에 자동으로 접속하지 않는다. 빠른 연결·로컬·DB 탭은 묶지 않고 이유를 알린다.
  - 바꾸면 안 되는 것: 탭을 프로젝트 카드에 놓으면 `ezshell:tab-drop-taken` 을 보내 `App.tsx` 의 `mergeDropTaken` 을 세운다. 사이드바는 터미널 영역 밖이라, 세우지 않으면 끌기가 끝날 때 그 탭이 창으로 분리된다. 이 표시는 창의 `dragend` 뒤에 지운다 (분할 화면 탭 줄의 끌기는 지우지 않아서, 남은 표시가 다음 끌기를 막았다).

## Sidebar Session Tab Badge

사이드바 세션 옆에 그 세션에서 열린 탭 개수를 배지로 표시한다 (초록 테두리 = 연결됨, 빨강 테두리 = 끊김, 섞이면 둘 다).
탭 ID 는 메인 프로세스가 연결마다 만드는 값이라 사이드바 세션 ID 와 다르다. 둘은 `TerminalInfo.connectConfig.savedSessionId` 로만 이어진다 (`lib/sessionTabs.ts`).
배지의 탭이 1개이고 분할되지 않았으면 바로 이동, 그 밖에는 목록에서 고른다. 이동은 `terminalStore.focusTerminal` 을 쓴다 (분할 유지, 터미널에 키보드 포커스).
분할된 탭은 목록에서 `N세션` 표지와 함께 그 아래에 배치 그림이 나오고, 칸을 누르면(방향키·Enter 로도) 그 탭으로 가서 그 칸의 셸에 키보드를 준다. 로컬 터미널 목록의 배치 그림(`PaneLayoutBadge`)과 같은 동작이고, 칸 이동·지금 칸 읽기·칸 위치는 `lib/paneFocus.ts`, 칸 모양은 `Sidebar/PaneMap.css` 를 함께 쓴다. 칸은 `DropdownMenu.Item` 이라 방향키가 닿는다. 지금 입력 중인 칸은 배지를 누르는 순간(`pointerdown`)에 읽는다: 목록이 열리면 포커스가 목록으로 가서 그 뒤에는 알 수 없다.
별도 창으로 분리한 탭과 저장하지 않은 빠른 연결은 세지 않는다.
세션 행이 Tooltip Trigger 라서 배지/목록의 이벤트가 포털을 통과해 행까지 올라간다. 처리 내용은 `docs/brain/2026-10-01-react-events-bubble-through-portals-into-tooltip-trigger.md` 참고.
