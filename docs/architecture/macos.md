# Cross-platform / macOS build

[공통 작업 규칙과 기능별 목록](../../CLAUDE.md)

지금 정식 패키징은 Windows 전용(`--win`, NSIS·portable)이지만, macOS 에서도 실행되도록 코드와 빌드를 맞추는 중이다. 설계·결정·진행: `docs/plan/2026-11-17-macos-support.md`.
- 많은 main 모듈이 이미 `platform` 파라미터로 플랫폼을 구분한다: `localShell.js`(win→PowerShell, 그 외→`$SHELL`), `localPlaces.js`, `remoteAccess/tailnet.js`(darwin→`utunN`), `sessionImport/sources.js`(PuTTY·Xshell 은 win 전용), `mcp/tokenEnv.js`(win 외 `unsupported`), `dbClient/oracleClient.js`(Instant Client 는 `win32 && x64` 만). macOS 는 Oracle thin(12.1+) 전용이고 thick(구버전) 접속은 미지원이다.
- `window-all-closed` 는 플랫폼과 무관하게 종료한다 (`main.js`). 이 핸들러가 MCP 종료·SSH 정리까지 하므로, macOS 기본값(창을 닫아도 유지)으로 두면 정리가 끝난 반쯤 죽은 상태로 Dock 에 남는다 (단일 창 앱이라 되살릴 경로도 없다). 바꾸면 안 되는 것: darwin 예외를 되살리려면 `activate` 처리기와 MCP 재시작을 함께 넣어야 한다.
- macOS 빌드(비서명): `package.json` 의 `build.mac`(dmg+zip, arm64+x64, `identity: null`), 스크립트 `build:mac`. GitHub Actions 워크플로 `.github/workflows/mac-build.yml`(`macos-latest` 러너, `CSC_IDENTITY_AUTO_DISCOVERY=false`. 고정한 이미지 `macos-14` 는 없어져서 작업이 시작되지 못했다. 수동 실행에 릴리스 태그를 주면 그 릴리스에 파일을 붙인다)가 산출물을 만든다. Windows 개발기에서는 mac 바이너리를 만들 수 없어 CI 로 돌린다. 인증서 서명·공증을 하지 않으므로 Gatekeeper 가 막는다 (우클릭 열기 또는 `xattr -dr com.apple.quarantine`). 바꾸면 안 되는 것: `build.afterPack` 의 `scripts/mac-adhoc-sign.cjs` 가 앱을 임시(ad-hoc) 서명한다. 포장 과정이 Electron 의 원래 서명을 깨뜨리는데, Apple Silicon 은 서명이 없거나 깨진 앱을 "손상되었다"며 실행하지 않는다. 같은 스크립트가 서명 전에 `node-pty` 의 `spawn-helper` 에 실행 권한을 준다 (npm 패키지의 그 파일에는 실행 권한이 없어, 없으면 로컬 터미널이 `posix_spawnp failed` 로 열리지 않는다). 서명 뒤에 파일을 바꾸면 서명이 다시 깨지므로 순서를 바꾸지 말 것. electron-updater mac 자동 업데이트는 서명이 필요해 쓰지 않는다.
- macOS 업데이트 안내(`src/manualUpdate.js`, `main.js` 의 `USES_MANUAL_UPDATE`): darwin 에서는 electron-updater 대신 GitHub 의 최신 릴리스를 같은 주기(시작 3초 뒤, 30분, 포커스)로 확인하고, 더 새 버전이면 알림의 `다운로드 페이지` 버튼이 릴리스 페이지를 브라우저로 연다 (`open-update-page`). 앱은 아무것도 내려받거나 실행하지 않는다. 워크플로는 릴리스가 공개되면(`release: published`) 빌드해서 그 릴리스에 `.dmg`/`.zip` 을 붙인다. 바꾸면 안 되는 것: 이 PC 아키텍처의 `ezShell-<버전>-<arch>.dmg` 가 릴리스에 붙기 전에는 알리지 않는다 (Windows 배포 직후 몇 분은 mac 파일이 없다). 여는 주소는 검사한 버전 번호로 main 이 만들고(응답의 `html_url` 을 쓰지 않는다), 창은 주소를 보내지 않는다. 새 `src/*.js` 라서 `MAIN_RUNTIME_MODULES` 에 있다.
- macOS 앱 메뉴(`src/macMenu.js`, `main.js` 의 `whenReady`): darwin 에서만 종료·편집·창 메뉴를 단다. 바꾸면 안 되는 것: 메뉴를 달지 않으면 Electron 기본 메뉴가 붙는데, macOS 에서는 그 단축키가 앱 전체에서 동작한다. `Cmd+R`(새로고침)은 열린 탭과 셸을 모두 끊고 `Cmd+W`(창 닫기)는 앱을 종료한다. `reload`·`close`·개발자 도구·확대 역할을 메뉴에 넣지 말 것 (`FORBIDDEN_ROLES`, 테스트가 본다).
- macOS 의 키: 앱 단축키의 `Ctrl` 은 Command 키다 (`lib/shortcutModifiers.ts` 의 `primaryModifiersMatch`). Control 키는 셸의 것으로 남긴다. Tab 만 Control 을 유지한다 (`Cmd+Tab` 은 시스템의 앱 전환). 터미널의 붙여넣기 가로채기(`isPasteShortcut`)는 mac 에서 끈다 (붙여넣기는 메뉴의 `Cmd+V`, `Ctrl+V` 는 셸로). 글자 크기 조절은 `Cmd +/-/0`.
- macOS 로컬 터미널의 기본 셸은 `SHELL` → 로그인 셸(`os.userInfo().shell`) → `/bin/zsh` 순이다 (Dock 에서 실행하면 환경 변수에 `SHELL` 이 없다).
- 아직 안 된 것: 네이티브 신호등 버튼(`titleBarStyle`) 전환, DB 결과 표처럼 자체 `Ctrl+C` 처리가 있는 곳의 Command 대응.
